# 出库管理前端Demo版PRD

版本：WMS-V0.1｜2026-10-15。业务真源为[主PRD](出库管理主PRD.md)。布局与占位须符合[需求文档PRD约定](../AGENTS.md)“布局硬规则”；复用原型的入库单／上架单详情样板。

## 一、路由与组件

| 路由 | 页面 |
| --- | --- |
| `/wms/outbound/orders`、`/:no` | 出库单列表／详情 |
| `/wms/outbound/waves`、`/:no` | 波次列表／详情 |
| `/wms/outbound/pick-tasks`、`/:no` | 拣货任务列表／详情 |
| `/wms/outbound/return-putaway`、`/:no` | 返库上架列表／详情 |
| `/pda/pick?no=…` | 拣货 |
| `/pda/verify?no=…` | 复核 |
| `/pda/return-putaway?no=…` | 返库上架 |
| `/wms/inventory/counts` | 支撑待核对解除的简版盘点 |

管理列表用PageContainer、Panel、FilterBar columns=6、DataTable和createDataColumns。编码固定左侧，操作固定右侧，用DocNo／CodeName／Num／DateTime显示。详情用DetailTitle、DetailOverview、Descriptions columns=3、SummaryCard、DetailTabs param=tab。新增与交接用Dialog＋FormGrid／FormField，不另造布局体系。状态色集中config/status.ts，出库单、拣货任务、返库上架单、波次、指令消息与回传结果各自的状态一并在此定义meta并用StatusBadge展示；所有文案使用outbound命名空间，中英文同步。

| 出库单筛选 | 控件 | 默认与占位 |
| --- | --- | --- |
| 仓库 | OptionSelect | 当前仓库；common.selectPlaceholder |
| 货主 | OptionSelect，含全部 | 全部；common.selectPlaceholder |
| 单号 | Input | 空；common.inputPlaceholder |
| 业务类型 | OptionSelect，含全部 | 全部；common.selectPlaceholder |
| 状态 | OptionSelect，含全部 | 全部；common.selectPlaceholder |

常显顺序按上表：业务类型在状态之前。其他列表对应仓库、货主、编号、状态及任务来源／返库原因，不足5项不留空列。输入先保存draft，查询才应用；重置回到当前仓库。

## 二、共用数据与动作

使用现有Zustand持久化库，类型在types/outbound.ts，业务计算在mock/outbound-actions.ts，mock/db.ts统一提交结果；管理端、PDA调用同一动作。继续使用inventory与inventoryLogs，不另建出库库存账。

| 动作 | 输入 | 返回／刷新 |
| --- | --- | --- |
| 接收Mock | 消息、指令、版本、类型、仓货主、商品行／指定库存 | 成功单号或可读拒收原因，保留处理记录 |
| 变更／取消Mock | 新消息标识、预期对象版本（等于原单当前版本）、原单号、变更内容 | 更新同单并推进版本或拒收，不重复建单 |
| 分配／组波 | 原单号或有序成员单号 | 任务号／波次号；失败无部分分配 |
| 确认拣货 | 任务行、来源码、商品码、批次／SN、本次数量、确认标识 | 新增实拣、原单归属、来源与暂存库存 |
| 缺货／提交 | 行、数量、原因；或任务号 | 换位结果、待核对状态；任务结束 |
| 复核／删除 | 原单、实拣分项、数量、容器信息；或记录号 | 有效复核数量与历史记录 |
| 补包裹信息 | 复核号、包裹号、模拟重量 | 更新原复核记录，Mock运单生成；不再累计复核量 |
| 退拣 | 原单实拣、数量／SN、原因 | 返库单号、有效数量减少 |
| 出库／交接 | 原单号；交接资料（可随确认出库带出） | 实发结果；交接记录（确认时或已出库后补登） |
| 出库结果重交 | 原单号；可模拟失败 | 沿用结果序号和商品结果，只增加重交次数，不再次扣库；已是Mock已接收时提示无需重交 |
| 返库保存／提交 | 行、目标、数量；或返库单号 | 草稿或已提交移库 |
| 盘点创建／确认／取消 | 仓货主SKU、各库存实盘数及SN | 冻结、调整、确认解除待核对；取消仅解除盘点冻结 |

业务动作返回ok或errorKey及参数，页面显示具体原因。扫描确认使用一次确认标识，重复确认不再扣；出库、任务结束、返库提交由状态阻止重复。纯函数先校验和计算完整patch，再一次提交；本机演示不能据此宣称服务端事务或多设备并发通过。

## 三、种子、角色与模拟

每个演示仓提供两张可组波的B2C单、FBA缺量、调拨／退货、SN批发样例及可创建其他出库的不良品库存，包含普通、批次效期、SN库存。字段从同一商品与库存资料解析，模拟扫描候选来自当前任务和库存，不由按钮直接跳过校验。

角色用组织者、现场人员、主管切换；动作仍校验对应角色。继承当前操作人，重要动作记录UTC时间。Mock可以新建六类指令、重发、变更和取消，按现有消息身份与版本口径处理；运单号与承运结果明确标记Mock。无需真实登录、打印、称重设备或网络后端。

交接资料含交接方式、对象、物流渠道、凭证号、件箱托数、时间与备注；确认出库弹窗可同时登记，已出库后仍可补登，两次入口共用同一动作与字段。

数据保存到当前浏览器localStorage。新增出库模型随数据库种子版本更新；旧版数据升级按现有Demo重置约定处理，页头“重置演示数据”可以重建样例。

## 四、反馈与草稿

列表无数据用共用空态，深链单号不存在显示找不到并可返回列表。校验失败就近保留输入并显示具体错误；按钮提交成功才清草稿／跳转。PDA拣货确认已是业务记录，返回不撤销；复核未提交、返库已保存的目标与数量按作业说明持久化，刷新恢复。切仓后按新仓重新定位对象，不能在旧仓页面操作新仓数据。

## 五、检查与交付

执行主PRD第七节的关键数量场景与共用动作测试；再检查管理端列表→详情→PDA→库存查询，取消→返库→盘点，以及英语与德国仓。构建、lint和测试通过后记录浏览器实际走查结果。静态检查、Mock及浏览器模拟均不替代真实接口和设备验收。

本机运行：进入`09-产品原型/qs-wms-demo`，执行`npm install`（依赖已有时跳过）、`npm run dev -- --host 127.0.0.1`，使用终端给出的地址，管理端`#/wms/outbound/orders`，PDA`#/pda`。字段和消息样例见[字段目录](../../字段清单合集/03-出库管理/)与[OMS Mock样例](../../字段清单合集/05-系统集成与对接/OMS-Mock/样例/)。
