# 出库管理主PRD

版本：WMS-V0.1｜2026-10-15｜状态：按确认稿执行。本轮走查修订：结果回传收敛为各行实发、未发（容器明细留在仓内），盘点创建角色补入现场人员，指令版本字段落在上游消息记录。

本模块让仓库组织者接单、分配和组织拣货，现场人员按原单复核，主管确认出库，取消或退拣的货通过返库上架回到存储库位。六类出库共用出库单、波次、拣货任务、复核记录、返库上架单、出库交接记录，不另建出库异常单。

业务依据：[出库宏观架构](../../../../01-全局背景信息/05-出库模块宏观系统架构.md)、[库存宏观架构](../../../../01-全局背景信息/07-库存模块宏观系统架构.md)。数量与对象的统一定义见[实体对象关系](../../系统架构设计/02-实体对象关系.md)，状态与允许操作见[单据与状态流转](../../系统架构设计/03-单据与状态流转.md)。本稿说明页面操作怎样落实这些规则。

## 一、范围与类型差异

| 业务类型 | 创建入口 | 接单预占 | 确认出库 |
| --- | --- | --- | --- |
| B2C出库 | OMS Mock | 所有SKU足量才接单；一行不足则整单拒收 | 全部需求拣齐、复核齐 |
| FBA转运出库 | OMS Mock | 可按可用量部分预占，最低为0 | 可缺量一次结案，实发至少1件 |
| 批发出库 | OMS Mock | 同上 | 同上 |
| 调拨出库 | OMS Mock | 可部分预占 | 必须足量 |
| 采购退货出库 | OMS Mock，引用原入库单 | 可部分预占 | 必须足量 |
| 其他出库 | OMS Mock或主管凭邮件手工创建 | 指定已上架不良品库存与数量，立即计已分配；不加订单占用 | 按指定数量足量出库 |

普通出库不提供管理端手工建单。上游单的数量变更、取消从Mock进入；手工其他出库可在详情取消。一个出库单只有一个仓库和货主。商品、渠道、库位按当前有效资料校验，旧单保留已有引用。

## 二、接单与分配

### 2.1 接收、变更、取消指令

Mock提供消息标识、上游指令号、预期对象版本、业务类型、仓库、货主、明细及收件资料。首次预期版本0，变更或取消携带原单当前版本，接受后推进；消息重发返回原处理结果，同标识改内容拒收。预期对象版本与处理前后对象版本由[上游消息记录](../../字段清单合集/05-系统集成与对接/上游消息记录/)维护，出库单不另设版本字段。业务指令重发也不能重复占用。失败展示具体SKU、需求与可用量，不生成半张单。变更只允许没有生成拣货任务的待拣货单，释放原预占后按新需求重新准入，失败时原单与原占用均保留。其他出库改指定实物需取消后重建。

接单看SKU可用量：正常品收货暂存、出库暂存都计在实际中；实际减订单占用和不良品，负数照实展示。待核对或盘点中仍可按可用量接普通新单。

### 2.2 生成任务、组波与重新分配

组织者在出库单详情生成按单任务；仅从同仓同货主、存储或拣货位的正常品分配，排除过期件，效期商品优先到期日较早的批次，其余按库位顺序。收货暂存、出库暂存不参与分配。其他出库直接使用已指定的不良品库存，生成任务时不重复计已分配。

B2C首次拣货要求整单预占全部分配足；补拣只要求本次剩余待拣量分配足。其他普通出库可把当前可分配部分生成任务。无可分配量时说明缺少SKU与数量，不生成空任务。

波次只接纳同仓同货主、没有任务的待拣货B2C单，组波同时生成一张任务。汇总行按来源库存归并，保留每张原单的行号和份额。组波失败整批保持原样。

重新分配先补本单需求与预占的缺口，再分配尚未拣到的数量。已有未完成任务时返回该任务，避免重复补拣。待核对或盘点中暂停新的分配、组波、补拣和其他出库指定。

## 三、现场拣货

现场人员定位任务，扫描来源库位、商品、批次或SN，再确认本次数量。数量必须为正整数，不超过该行剩余应拣量。SN商品逐件采集，SN必须属于本来源库存，同一确认中的SN不得重复。

**每次确认立即下架**：来源库存实际和已分配减少，出库暂存实际增加，原单已拣增加。波次按成员顺序把本次新增实拣归属给有效原单，并保存对应SN。归属确定后不重排。扫码草稿未确认前不搬库存。

上报库位缺货须填写无货或残损原因、缺货量。释放该部分分配，按既有规则尝试一次换位，与标记仓库＋货主＋SKU待核对一并完成。此后不继续分配或反复换位；已有分配继续做完或取消，返库允许完成。残损品质转换由主管确认；现场上报不直接把整行库存改成不良品。

任务各行已拣足或已上报未拣原因后才能提交。提交确定短拣、释放剩余分配，结束任务进度，**不再次移库**。有扫描确认时任务为拣货中；任务关闭或完成后不能继续确认。

## 四、复核、退拣与出库

### 4.1 按原单复核

复核定位原单，按其有效实拣核对商品、批次、SN和数量。支持随分拣、随打包装箱；一次提交一条复核记录，包裹、箱、托或无容器按现场选择。复核不动库存。已复核的SN不能重复计数；非SN批次复核不能超过该批次尚未复核的实拣。

包裹、箱、托内的商品数量以该条复核明细为准；同一实拣不能在箱、托两条记录重复计数。随分拣每单一条记录，随打包装箱可分容器提交。B2C一单一包、托仅分组仍为后续容器方案建议，本次不作为限制，不增加拆包合包流程。B2C随分拣复核后可在原记录补包裹号、模拟重量与Mock运单；随打包时一起填写，出库前须齐备。

确认出库前可删除复核记录重做。退拣时相应有效复核量失效，历史复核事实保留。退拣录入数量、原因与对应实拣／SN，减少有效已拣并生成返库单；少件标记待核对。残损需要主管转不良后返库。

### 4.2 确认出库与交接

主管确认时必须无未完成拣货任务，已拣已全部复核；再按第一节的类型条件判断足量或缺量。确认一次扣出库暂存实际，实发定型，普通出库清本单预占，未发按需求减实发记录。零实发不结案；缺量结案后不再补发，后续补发由新指令承接。

已拣暂存期间沿用已确认的效期简化，不增加再次转品质或出库前效期复检。

交接可在确认时登记，或已出库后补登交接方式、对象、时间与凭证。登记不再次扣库。一期确认出库只在管理端提供（架构允许管理端或 PDA，本期不做 PDA 入口），确认出库弹窗可同时登记交接。上游来源形成包含各行实发、未发的结果；复核容器明细留在仓内复核记录，一期不回传；一期在本机Mock查看处理与回传记录。

## 五、取消、返库与差异解除

确认出库前受理取消后，出库单立即已取消；释放本单预占、未拣分配，已确认实拣按原单归属自动退拣并生成返库单。波次其他成员的份额、已拣和SN保持原归属。未扫、未确认的实物由现场人工放回，无额外库存动作。已取消详情仍展示未完成返库。

返库人员选应返库行，扫描目标库位、录本次数量保存草稿，可分次保存到不同库位；累计填足后整单提交，才从出库暂存移回合法存储、拣货位。须符合目标库位启用、品质、货主与商品混放规则。保存不搬库存，重复提交不再搬。

少件沿用简单处理：仍按应返库量填完并提交，再通过盘点扣掉实物差异。该SKU待核对期间不参与新分配。完成既有任务和返库后才能创建盘点快照，现场人员可发起、管理端也可按计划创建；主管确认盘点（差异为0也需确认）后解除待核对；补货、取消原单或取消盘点不自动解除。

## 六、权限、反馈与留痕

| 人员 | 操作 |
| --- | --- |
| 仓库组织者 | 查询、按单分配、组波、重新分配 |
| 现场人员 | 拣货确认、缺货上报、复核、退拣、返库保存与提交、登记交接、发起盘点快照 |
| 主管 | 确认出库、手工其他出库创建／取消、残损转不良、盘点确认 |
| OMS Mock | 普通出库新建／合法变更／取消、其他出库指令、查看结果 |

沿用[全局机制与权限配置](../../系统架构设计/05-全局机制与权限配置.md)。Demo用明确角色切换展示按钮与动作校验，记录操作人和UTC时间；不把本机角色选择视为生产鉴权。

错误就近显示对象、数量与下一步，失败动作不留下部分占用或库存变化；关闭、取消、出库、提交后刷新页面可查到同一记录。列表、详情、PDA、库存查询使用同一份数据，双击确认不能重复生效。

## 七、验收场景

| 场景（均为演示样例） | 可判定结果 |
| --- | --- |
| B2C需求3，分次拣1和2 | 每次立即来源减／暂存增；提交任务不再搬；复核3后确认扣3 |
| B2C多SKU一行不足 | 整单拒收，其他行没有残留预占 |
| FBA需求10，仅可用8 | 接单预占8；实拣复核8后实发8、未发2；再确认不扣库 |
| 调拨仅拣8／需求10 | 拒绝确认，补足再出库 |
| 其他出库不良品5指定2 | 不增加订单占用；指定时分配2，拣走时释放，出库后剩3 |
| 波次A需3、B需2，已拣4取消A | 归属A3、B1；A3返库、B1保留；B还能拣剩余1 |
| 已拣3，少1 | 退拣1、待核对；应返库1后盘亏1解除；再补拣1 |
| 已有补拣任务再次重新分配 | 复用原未完成任务，无重复分配 |
| 同SKU不同仓／货主 | 预占、分配、待核对与SN均不串用 |
| 已拣取消、返库保存后刷新 | 取消立即生效，返库草稿保留；提交一次移库 |
| 相同指令或消息重发 | 返回原处理结果，无重复单与占用；失败消息可按新消息重交 |
| 拣货前已过期、近效期；已拣后过期 | 分配排除过期、允许近效期；已拣不追加效期阻断 |

字段按[六类对象详细稿](../../字段清单合集/03-出库管理/)维护；界面与实际实现范围见[Demo PRD](出库管理前端Demo版PRD.md)。
