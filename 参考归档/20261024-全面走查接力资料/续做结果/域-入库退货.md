# 第2批：入库与退货走查结果

更新日期：2026-10-25。范围：2A 收货与资料采集、2B 上架与容器、2C 退货。

## 结论

收货时记录拒收、实收和品质，不设独立质检任务；上架保存只记录进度，整张单提交后才移库存；退货按上游预报或原出库事实识别，不把超量、错 SKU、无主货伪造成正常库存。这些边界基本自洽，建议保留。

初审发现的退货多容器超量与跨SKU SN核对问题已按现行规则修复；容器库存维度已接通库存、查询、盘点、移库与分配候选。用户确认订单不按容器预占；容器号只作可选追溯引用，在库部分移出可转为散件，散件移库不依赖或自动修改容器档案状态。效期商品可手工录入生产日期或失效日期，系统按保质期互算另一日期；收货和盘点新增行已同步。已知货主的错SKU、超量和无预报实物在线下暂存并由货主补报或退回，不生成WMS记录或库存。新品量方符合最新版PRD，商品质检配置已从原型移除。初审基线与当前整改状态见[整改进度与待确认事项](整改进度与待确认事项.md)。

## 发现与判断

### 1. 高：退货同一 SKU 的多容器数量未按本次提交合计

**整改状态：已修复。** 当前动作在写入任何记录前按 SKU 汇总本次所有容器的良品、不良品和拒收数量，并与剩余预计量比较；任何 SKU 超量时整次拒绝。尚未执行浏览器或新的内存场景复核。

**已核实事实：**《退货单主 PRD》第160行规定历史实收＋拒收＋本次提交各容器数量不得超过预计；第105–115行要求 E=R+J+U。当前 09-产品原型/qs-wms-demo/src/mock/return-actions.ts 第184–193行逐个容器行都与同一个剩余量比较，没有按 SKU 先累加本次各容器数量。复现用预计5、两个容器各收4，动作成功，实收和库存均增加8。对照入库动作 inbound-receive-actions.ts 第146–197行，已按 SKU 汇总后再校验。

**竞品步骤与原文：**领星 PDA 批量收货先扫多个箱并保留扫描进度，再在提交节点提交；超收是否允许由设置开关控制（02-竞品调研和分析/领星WMS/01-原始页面/LX-WMS-022_使用PDA实现收货.md，第30–45行）。这不是 QS 应放宽超收的依据，而是说明多箱作业应在提交边界做整批数量判定。

**适用条件：**一次退货提交中，同一 SKU 出现在两个及以上容器；每个单独容器未超过剩余量，但合计超量。

**具体后果：**预计5件可记成实收8件，增加8件暂存库存，退货剩余量被归零，退货结果、库存与上架单携带过量事实。

**最小调整建议：**在任何状态更新前，按 SKU 汇总本次各容器的良品、不良品、拒收，再与历史实收／拒收后的剩余量比较；任一 SKU 超限，整次不写入。保留同一退货单内容器不能重复使用的限制。

**验证类型：**源码静态核对＋内存复现；未做浏览器验收。修正后复核预计5、两容器4+4的整次拒绝，以及两容器合计5的成功路径，检查订单、收货记录、异常、库存、上架单均无部分写入。

### 2. 高：退货 SN 原出库校验把不同 SKU 的 SN 合并比较

**整改状态：已修复。** 原出库 SN 现按 SKU 分组，只接受与当前退货 SKU 匹配的 SN。尚未执行浏览器或新的内存场景复核。

**已核实事实：**字段详细稿规定 SN 身份是货主＋SKU＋SN；退货主 PRD 第172–180行要求有原出库依据时，实收 SN 与原出库不一致只能拒收。当前 return-actions.ts 第45–56行把原出库复核／实发 SN 合为 Set<string>，丢失 SKU；第213–218行只检查 SN 是否曾在该单发出。内存复现确认原出库中 AUDIT-Y-001 属于 OTHER-SKU，却可登记到 CABLE-01。

**竞品步骤与原文：**领星序列号原文的退货步骤是扫描 SKU、再扫描 SN，并要求良品／不良品数量与 SN 数相符（LX-WMS-039_使用OMP_WMS_OMS实现序列号管理.md，第53–63行）。它说明逐件采集与数量核对，没有说明原 SKU 比对，不能作为 QS 放宽 SKU 身份核验的依据。极风 PDA 退货是扫退货运单、扫描商品标签后确认入库（JF-PDA-014-PDA扫描退货.md，第25–35行），也未描述原出库 SN 绑定细节。

**适用条件：**退货单关联原出库，原出库有多个启用 SN 的 SKU；某 SN 属于 SKU-B，却提交在 SKU-A 退货行。无可对核原单时仍采集 SN 的既有规则不应改变。

**具体后果：**错误 SKU 下的 SN 进入退货记录和 SN 台账，削弱防调包与单件追溯。

**最小调整建议：**将原出库 SN 按 SKU 建立 Map<skuCode, Set<SN>>，只与当前退货行 SKU 比较；其它 SKU 中存在该 SN 也判不一致，只允许按现有规则拒收。保留无原单可核时的提示与采集路径。

**验证类型：**源码静态核对＋内存复现；未做浏览器验收。修正后覆盖正确 SKU、跨 SKU、无原单、重复提交和拒收计数。

### 3. 高：容器关联了收货／上架任务，但不是库存明细维度

**整改状态：已修复。** `containerId` 已贯通库存余额、流水及收货/退货/上架、查询、容器盘点、整容器和部分移库与分配候选；旧数据只按唯一业务证据回填。用户确认在库容器号只作可选追溯引用；部分移出可转散件，无需绑定新容器。散件移库不依赖或自动修改容器档案状态。以下事实保留初审时的实现状态。

**已核实事实：**项目定位要求容器内容等于该容器下批次库存的 SKU、批次、品质汇总，并可按容器查询、预占、分配、盘点（01-全局背景信息/01-项目定位与范围.md，第66、78行；07-库存模块宏观系统架构.md，第32、44–56行）。但原型 types/wms.ts 的 InventoryRecord（第270–290行）没有 containerNo；收货暂存库存键 inbound-receive-actions.ts 第283–303行、退货库存键 return-actions.ts 第302–313行、上架来源及目标库存键 putaway-actions.ts 第142–178行也都不含容器号。因此相同 SKU、品质、批次、效期的不同容器会并入同一库存行。container-derive.ts 第19–91行按收货记录或已完成上架单推导内容，不是当前库存账的容器明细。

**竞品步骤与原文：**极风 PDA 上架时扫箱唛或入库单，选整箱同位或手动拆多货位，再扫 SKU 和货位确认（JF-PDA-018-PDA收货、上架.md，第36–48行）。万里牛容器原文说明收货清点后暂存周转箱，后续扫周转箱可看货品及数量并上架（万里牛WMS拆解/00-源文件/操作手册/基础信息/设备管理/容器管理.md，第39–40、60–61行）。这些步骤把搬运容器与内容放在同一作业路径；QS 架构也要求如此，原型库存账尚未保留关系。

**适用条件：**同一暂存库位有相同 SKU、品质、批次、效期但来自不同容器；或同一容器拆至多个货位后需按容器查库存、盘点、分配或移动。

**具体后果：**容器专属上架单只能从合并库存行扣数量，账面无法证明扣的是哪只箱；容器查询也无法与当前批次库存核对。档案有内容、状态和轨迹页，不等于容器库存能力已完成。

**最小调整建议：**在批次库存及流水中保留容器号，贯通收货、上架、移库、退货、分配、盘点；容器详情按当前库存账显示内容和各货位。若暂不建设，应明确 Demo 中容器只作业单分组键，不可表述为库存维度已交付。

**验证类型：**架构文档与源码静态对照；未在浏览器验证容器库存查询、分配或盘点，因为代码库存键没有容器号。修正后用同 SKU／批次分装两个容器，先上架一个、再拆分多货位，验证盘点和出库分配隔离。

### 4. 中高：效期商品的生产日期规则、表单与校验没有对齐

**整改状态：已按用户确认的日期互算规则同步。** 入库、退货Web/PDA收货和管理端/PDA盘点新增行均可手工录入生产日期或失效日期；系统按保质期计算另一日期，计算值允许手动调整。生产日期贯穿库存流转。受保护的详细字段TSV未修改。以下事实记录整改前状态。

**已核实事实：**收货字段详细稿第20–22行要求效期商品生产日期、失效日期均条件必填，允许按生产日期＋保质期计算失效日期。商品模型只有 expiryEnabled、shelfLifeDays（types/wms.ts 第198–203行），无独立生产日期开关。入库 Web 和 PDA 有两项日期，但 PDA line-step.tsx 第117–124行及 inbound-receive-actions.ts 第170–174行只校验失效日期。退货字段稿第25–26行包含生产日期；但 Web return-receive-page.tsx 第489–505行和 PDA return-receive-page.tsx 第487–495行只显示失效日期，return-actions.ts 第197–201行也只校验失效日期。

**竞品步骤与原文：**领星效期收货允许只填失效日期，或填生产日期＋有效期（02-竞品调研和分析/领星WMS/01-原始页面/LX-WMS-043_使用WMS和OMP实现批次库存管理.md，第23–28行）。这是竞品提供的可选录入路径，不代表应直接删掉 QS 字段；必须先明确日期事实及计算口径。

**适用条件：**商品启用效期管理，当前字段规范要求生产日期。退货尤其会漏字段，因为表单没有该项。

**具体后果：**库存保留失效日期却缺少生产日期，无法从本次收货事实核对生产时间；不同作业员可能录入互不一致的生产、失效日期，或误以为系统会按保质期推算。

**整改结果：**PRD、业务设计、管理端和PDA Demo统一按“生产日期＋保质期天数＝失效日期”互算，校验生产日期不得晚于失效日期。管理端盘点新增效期库存也录入日期对；保存时按现有库存处理写入并传递生产日期。

**验证类型：**字段稿、页面与动作静态对照；未执行收货提交。修正后分别验证四个入口的缺日期、日期倒置、效期计算及无效来源组合。

### 5. 中：已知货主但 SKU／数量对不上时，系统缺少实物保管记录

**已核实事实：**退货 PRD 第94–97行规定有货主但无预报先催补；错 SKU 不造明细行；超过预计的部分线下暂存或拒收，不能超量入实收。退货业务设计第99–104行同样把超量线下暂存、错 SKU 拒收／无主货登记列为边界。当前 return-actions.ts 第186–187行遇到非订单 SKU 直接报错；超量也不能转成正常实收。无主货流程用于货主不明实物，不覆盖“已知货主但实物错配”的保管过程。

**竞品步骤与原文：**领星退件先选“到仓清点”或“到仓暂存”；暂存需选择位置，清点可录与预报不一致的 SKU／数量并记录备注、照片（LX-WMS-006_使用WMS处理退件.md，第22–32行）。极风 PDA 遇到无单时，SKU 可识别则创建退货单后再扫描；不可识别则建认领单（JF-PDA-014-PDA扫描退货.md，第37–49行）。这说明可单独记录到仓保管事实，但不应直接移入 QS 的正常收货或认领范围。

**适用条件：**包裹已进仓，货主可识别但无有效预报；或关联退货单出现错 SKU／超量且未能当场拒收。

**具体后果：**若实物被仓库暂存却没有单据、库位、凭证、责任人和处置状态，系统无法追溯现存位置与交接结果。这是流程风险推断，无访谈或丢件数据证明发生率。

**最小调整建议：**不放宽正常退货数量、不自动建库存、不代货主补造指令；单独评估异常实物保管记录，最少记录已知货主、关联单号／运单、实物 SKU 与数量（可待识别）、暂存位置、照片/备注、交接人与时间、拒收／补报／退回等处置结果。

**验证类型：**规则静态核对与竞品原文步骤对照；未生成演示记录。后续分别验证错 SKU、已知货主无预报、超量未拒收的保管留痕。

### 6. 中低：PDA 在扫描新品时就中断收货，早于准入需要

**复核结论：不构成缺陷，保留当前交互。** 原初审只依据较早版本描述，未完整对照最新版应用规则。当前[新品维护主 PRD](../../../05-应用设计方案/20261002-MVP版本/需求文档PRD/2-入库管理/新品维护/新品维护主PRD.md)和[PDA新品量方 Demo PRD](../../../05-应用设计方案/20261002-MVP版本/需求文档PRD/7-PDA作业端/新品量方作业/PDA新品量方前端Demo版PRD.md)明确规定：扫描到未完成量方的新品后立即进入量方页，完成后返回收货；提交时仍再次校验。当前 `box-step.tsx` 与该规则一致。

领星在提交时引导量方仅是竞品路径，不能覆盖 QS 已确认的交互要求。此次不修改代码或 PRD；原初审的“延后到提交时”建议撤销。此结论基于最新版文档与源码静态核对，未执行 PDA 扫码操作。

### 7. 中低：商品编辑器仍保存并展示未接入收货的质检配置

**整改状态：已修复。** 商品类型、表单、校验、保存、列表筛选、详情和 Mock 种子已移除 `qcRequired`／`qcFlowType`。未执行浏览器保存复核。

**已核实事实：**入库业务设计第61行及商品资料 PRD 第84–85行明确一期不设质检配置或任务，品质在收货时录入。但 Demo 商品表单仍展示质检字段（sku-form-fields.tsx 第164–179行），校验并保存（sku-master.ts 第78–80行、master-actions.ts 第366行），列表和详情也展示。入库、退货动作没有读取 qcRequired 或 qcFlowType。因此是表单与持久化残留，不是质检工作流。

**竞品步骤与原文：**万里牛入库质检原文按货主、单据及数量配置流程；启用质检要同时启用清点，随后创建质检任务并录结果（00-源文件/专题功能介绍/其他/WMS-入库质检.md，第41–62、66–85行）。这不是一个商品开关即可成立的功能。

**适用条件：**维护或演示商品时，操作者可能以为质检开关会改变收货步骤，或代表已支持检验任务。

**具体后果：**一期“收货时录品质、没有质检任务”的规则和商品页显示不一致，并增加无消费者的必填配置。

**最小调整建议：**移除 Demo 表单、筛选、详情和保存链路中的质检字段；如需保留后续版本信息，应禁用并标明未启用。真正引入质检时须另行设计来源、任务、结果及不合格处置。

**验证类型：**PRD 与代码引用关系静态检查；未执行表单保存。修正后检查新增、编辑、筛选、详情均无未启用入口，收货品质规则不变。

### 8. 2B 判断：容器×品质拆单和整张提交有理由；切换成本尚未实测

**已核实事实：**入库主 PRD 第349–357行按容器×品质生成上架单；保存只记进度，整张提交要求每条应上架行录满后一次移库（上架单主 PRD 第19–33行）。putaway-actions.ts 第117–133行校验每行录满，第142–225行才移库存。PDA 上架 PRD 第19–25、62–89行支持推荐库位、按站扫描、人工改位、拆多库位、撤销和继续。归档 pda-putaway.txt 第18–66行只显示任务卡片与已录／应上架数，不是任务操作验收。

**竞品步骤与原文：**极风 PDA 扫箱唛或入库单，选整箱同位或手动拆多货位，扫 SKU 和货位后确认（JF-PDA-018-PDA收货、上架.md，第36–48行）。领星允许按产品或按箱上架，但同一单只能固定一种方式；可分批上架，订单显示“上架中”（LX-WMS-032_使用WMS操作上架管理.md，第24–40、49–53行）。竞品说明这些作业组织方式存在，不证明 QS 必须照搬。

**适用条件：**同容器有良品和不良品，或同一品质要分到多个库位；一张单作业中断或部分货物不能确认。

**具体后果：**按品质拆分可以分别进入存储区和不良隔离区，但可能增加队列查找或往返；目前没有现场数据证明切换偏重。整张提交能避免账面提前移动；缺件时则不能缺量完成，既有取舍是按应上架数量提交后通过库存盘点处理，可能短时账实不符（上架单主 PRD 第51行、入库业务设计第227–231行）。

**专业判断与最小建议：**保留品质拆分和整单库存提交。队列可标出同容器是否还有另一品质任务、已录／待录数，并支持从容器定位未完成的关联单。是否加整箱快捷落位或局部提交，先观察真实多 SKU、多批次、混合品质及缺件场景；当前可扫一件再填余量，但不能称为与整箱作业等效。新增局部提交会改变库存边界，需单独评审。

**验证类型：**业务设计、PRD、动作代码静态核验＋归档队列/详情 DOM 只读检查；未执行现场搬运、推荐／改位／撤销／提交页面操作。

## 建议保留的规则

1. 收货时记录良品、不良品和拒收，不新增质检任务；万里牛质检资料显示完整策略与任务链，不能只恢复一个商品开关。
2. 不允许入库、退货超量进入正常库存。修复退货校验应保证守恒，不照搬竞品的可配置超收。
3. 无预报退货与无主货继续分流：货主已知须补有效预报；未知货主走无主货；FBA 移除退仓不进入一期正常收货。异常保管记录不等于扩展正常退货单。
4. 保留保存不动库存、整张上架单提交后移库；缺件、损坏、误记的处置不同，不能简单放开部分提交。
5. 保留有容器与无容器收货；一箱可多 SKU、多批次，容器号不能替代 SKU 件数或 SN 身份。当前主要缺口是库存账贯通。
