# 第5批：PRD套件、组件与模板精简（走查基线）

更新日期：2026-10-24。状态：以下为初审基线；用户授权后已修复组波条件、一期权限条款和波次字段投影，并将 WMS 页面骨架模板的共用布局规则改为引用 PRD 目录约定。完整整改状态见[整改进度与待确认事项](整改进度与待确认事项.md)。

执行依据：[QS-WMS全面走查执行计划](../../../QS-WMS全面走查执行计划.md)。本批检查了 PRD 套件的职责划分、业务规则重复、字段初稿与详细稿、WMS/ERP 模板边界和前端公共组件引用。

## 结论

当前产出物不能按文件数判为过重。入库、退货和出库等流程需要分别表达业务规则、页面位置、Demo交互和字段定义，现有 PRD 总览也明确区分了这些职责。代码侧有多项业务组件在多个管理端页面中实际复用，暂未发现“只有抽象、没有调用”的证据。

可确定的问题集中在重复规则的维护漂移：出库组波的状态条件在主 PRD、页面骨架和 Demo 自检中互相冲突；部分基础资料 PRD 仍列出一期已确认不做的账号权限验收；出库波次字段初稿与详细稿也不再是同一字段集的五列投影。建议保留有必要的文档层次，收紧重复规则，并明确唯一维护位置。

## 有证据的问题

### 1. 组波资格在三份出库文档中冲突

**整改状态：已修复。** 页面骨架与 Demo 自检的资格条件已统一为“待处理 B2C”，与主 PRD 一致。

[出库单主PRD](../../../05-应用设计方案/20261002-MVP版本/需求文档PRD/3-出库管理/出库单/出库单主PRD.md) §6.4 将“勾选组波”限定为待处理状态的 B2C 单；[出库单 Demo PRD 列表页](../../../05-应用设计方案/20261002-MVP版本/需求文档PRD/3-出库管理/出库单/前端Demo版PRD/出库单前端Demo版PRD_列表页.md) §6 也写明仅 `PENDING_HANDLE` 行可勾选。但同一 Demo 文档 §8 自检和[出库单页面骨架](../../../05-应用设计方案/20261002-MVP版本/需求文档PRD/3-出库管理/出库单/出库单页面骨架.md) UI-05 都写成“只有待拣货 B2C 可勾选”。这会让实现与验收人员误把状态入口后移一段。

建议以主 PRD 的状态—功能矩阵作为资格规则唯一来源；Demo PRD保留控件表现、调用和反馈，资格条件链接主 PRD；骨架只保留列表存在勾选列和组波入口的布局，不另写状态条件。修正前应先由责任人确认当前主 PRD 的“待处理”口径是最终决定。

### 2. 一期无账号权限的决定没有同步到部分主数据 PRD

**整改状态：已修复。** 已清理本批列出的基础资料及出库文档旧授权条件，并按当前仓库范围和业务状态规则表达一期行为。

[系统架构设计：全局机制与权限配置](../../../05-应用设计方案/20261002-MVP版本/系统架构设计/05-全局机制与权限配置.md) §4 明确一期 Demo 不提供登录、账号、角色、权限点或用户仓库授权校验；[项目定位与范围](../../../01-全局背景信息/01-项目定位与范围.md)也明确了相同边界。但[物流承运商主PRD](../../../05-应用设计方案/20261002-MVP版本/需求文档PRD/1-基础资料/物流承运商资料/物流承运商资料主PRD.md)仍列 R05、AC06 和“商品/资料维护权限”等验收；[商品资料主PRD](../../../05-应用设计方案/20261002-MVP版本/需求文档PRD/1-基础资料/商品资料/商品资料主PRD.md)仍把仓库授权写入上下游影响与上线准备；同类表述也出现在货主、仓库、库区、库位和物流渠道 PRD。与此同时，[出库单主PRD](../../../05-应用设计方案/20261002-MVP版本/需求文档PRD/3-出库管理/出库单/出库单主PRD.md)的追溯表仍写“多货主归属与仓库权限”，但 R16 明确一期不做仓库授权与角色裁剪。

这些条款与已确认的一期边界冲突，会把后置的生产权限能力误带入一期验收。建议将一期行为统一写为“按顶栏当前仓库筛选；不检查用户授权”；真实账号、角色、动作权限和仓库授权只在系统边界或上线准备中作为后续事项，不保留为一期 AC、功能依赖或联调阻塞项。

### 3. 波次字段初稿与详细稿存在实质差异

**整改状态：已修复。** 波次初稿已同步为详细稿的五列投影；详细稿仍为唯一字段真源，未修改其他受保护字段清单。

[字段清单合集说明](../../../05-应用设计方案/20261002-MVP版本/字段清单合集/README.md)称出库对象详细稿为权威版本，初稿是五列投影、不独立维护。实际对照[波次初稿](../../../05-应用设计方案/20261002-MVP版本/字段清单合集/03-出库管理/波次/波次（初稿）.tsv)和[波次详细稿](../../../05-应用设计方案/20261002-MVP版本/字段清单合集/03-出库管理/波次/波次（详细稿）.tsv)：初稿仍有“波次拣货任务号”，详细稿改为“波次拣货任务数”；详细稿新增“创建时间”和“成员单数”等字段，初稿未包含；“仓库/所属仓库”“成员出库单号”类型与来源也不一致，波次状态来源、备注类型和说明不一致。两份表若同时交付，会给页面和实现传递不同定义。

建议详细稿继续作为字段真源；初稿若只用于评审，明确标注由详细稿生成，并在导出或交付前校验字段名、分组、类型、来源和说明。若无法自动生成，应停止把过期初稿作为独立执行资料发放。

## 文档职责和模板判断

| 产出物 | 建议保留的唯一职责 | 本轮判断 |
| --- | --- | --- |
| 01 全局背景与宏观架构 | 项目范围、系统边界、单据/状态关系和全局机制 | 保留；不能由原型现状反向改写已确认规则 |
| 03 需求分析 | 业务需求、取舍及需求来源 | 保留；不在多份应用设计材料重抄需求论证 |
| 04 业务设计 | 角色任务、前置条件、数量变化、异常和恢复路径 | 保留；复杂流程的业务动作在这里展开 |
| 主 PRD | 功能、业务规则、状态动作、对象边界和可验收结果 | 作为本模块规则与验收的唯一应用设计真源 |
| 页面骨架 | 页面/弹窗清单、入口和信息布局；只保留必要条件摘要 | 保留；删去会与主 PRD 竞争的规则矩阵和重复验收条件 |
| Demo PRD | 路由、控件交互、文案、调用映射、Mock种子与实现限制 | 保留；业务条件引用主 PRD，不另做一套规则裁决 |
| 详细字段稿 | 对象字段、类型、来源、必填和展示定义 | 保留并指定为字段唯一真源 |
| 字段初稿 | 快速评审的精简视图 | 有实际评审用途才保留；作为派生视图生成或校验，不独立修改 |
| 业务组件 | 页面布局、表格、表单、状态展示等可复用实现 | 暂无过度抽象证据；应按实际跨页调用维护 |

**整改状态：部分收口。** WMS 页面骨架模板现引用 PRD 目录约定维护全局布局硬规则；页面级 Demo PRD 和骨架仍保留满足具体对象验收所需的布局信息，不批量删除。

## 可执行的精简顺序

1. 先修正文档漂移：确认并统一组波状态；清理一期权限 AC 与旧依赖；更新或派生波次字段初稿。
2. 固定每类信息的真源位置。业务规则和验收在主 PRD；字段元数据在详细稿；布局在骨架；交互和 Demo 调用在 Demo PRD。其他文档只写必要摘要并链接到真源。
3. 以对象复杂度决定单独文档。包含多状态、上下游约束、差异处理或多个页面动作的对象保留三件套；简单只读资料或单弹窗资料可在主 PRD 中嵌入简短页面要求，只有当页面/交互需要独立细化时才拆骨架或 Demo 分册。不要合并对象不同、由不同流程维护的资料。
4. 不删除现有材料；由项目维护人确认哪些文档已停止使用后，再按版本归档。初稿字段表不作为第二个字段源。
