# 第7批：QS-WMS全面走查统一结论（走查基线）

更新日期：2026-10-24。状态：走查评审已完成；之后已按用户授权开始整改。本报告保留初审时的发现与证据，整改后的当前状态和业务待确认项以[整改进度与待确认事项](整改进度与待确认事项.md)为准。

执行依据：[QS-WMS全面走查执行计划](../../../QS-WMS全面走查执行计划.md)。计划有 **8个编号批次（0—7）**；第2、3、4批分别拆成三个域内小批次。按执行单元计共14项，现已完成。第6批与各域工作穿插完成定向核验。

## 总体判断

> 以下能力表、问题表和处理顺序描述的是整改前的评审基线。已修复的问题不代表当前仍有缺陷；请先查阅上方整改进度链接。

QS-WMS一期以课程演示为目标，覆盖四仓、多货主、入库、六类出库、退货、库存与结果交接，范围宽，但主要能力均服务“仓内实物动作、库存结果核对、异常恢复和上下游交接”。现有资料明确把真实 OMS、实际承运商/设备、用户角色权限、自动补货、性能验收、FBA逆向等放在后续或范围外；这些应记录为未来运营条件。

当前主要风险集中在数据正确性、例外恢复和设计/代码同步。两项退货边界已用独立内存数据复现为错误结果；多项高影响问题由源码静态链路确认，尚未做完整页面操作复现。容器、FBA箱托和形态配置方面存在设计深度与实现进度差异。文档套件的层次有实际用途，重复规则的漂移和多处维护才是需要精简的重点。

综合判断与模块结论来自[第1批：项目定位与模块深度](第1批-项目定位与模块深度.md)、[第2批：入库与退货](域-入库退货.md)、[第3批：出库](域-出库.md)、[第4批：库存与基础资料](域-库存基础资料.md)、[第5批：文档与模板](第5批-文档套件与模板精简.md)及[第6批：页面与源码核验](第6批-页面与源码定向验证.md)。

## 已确认问题与证据状态

### 内存复现确认的数据正确性问题

1. **退货多容器合计超收：**预计5件、两个容器分别录4件，动作成功并实收8、库存增加8。

两项均使用计划存档的独立内存种子数据复现；没有更改浏览器演示数据。详情见[入库与退货报告](域-入库退货.md)。

### 源码或页面证据确认的实现/规则差异

| 问题 | 判断依据 | 验证状态 |
| --- | --- | --- |
| SN商品数字零盘改变整行SN状态 | 盘点动作将未扫描的SN列表作为数量差异依据，可能把账面SN改成“丢失” | 源码静态链路；未内存复现 |
| 过期库存进入SKU可用/预占，效期判定不一致 | 展示、SKU汇总、接单预占与拣货候选使用不同日期/阈值口径 | 源码静态链路；未运行边界场景 |
| 库位和货主停用漏查未完结单据 | 校验主要看现存库存，未覆盖全部来源/目标作业引用 | 源码静态链路；未运行边界场景 |
| 波次成员及原单份额顺序冲突 | 页面按创建时间/单号倒序、选择回调保留该顺序、后端未按PRD再排序 | 源码静态链路；未新建波次复核 |
| FBA容器与箱托关系缺失 | 复核可留空容器；记录类型无容器父子关系；确认出库未要求FBA箱托完整性 | PRD、字段和动作静态对照；未执行FBA操作 |
| 波次PDA缺实体分播目标 | 页面有任务/库位/SKU数量，未见按订单箱号/格位扫码投放的目标确认 | PRD、页面源码与入口快照；未执行PDA作业 |
| 商品编辑仍有可维护的质检开关 | 本地页面确认“是否质检”可编辑并被保存、列表/详情展示；一期PRD已清除质检配置，动作未读取 | 当前浏览器只读观察＋源码搜索 |
| 商品形态、库位适配、顺序与货主推荐时机未驱动作业 | 保存链路存在，推荐/排序路径没有读取相关设置 | 源码静态链路；未跑推荐场景 |
| 关键主数据版本历史不完整 | 页面只显示最后修改人/时间，更新覆盖当前值，无法查看前后值和多次变更 | 源码静态链路；未做保存操作 |
| 入库/退货生产日期字段不统一 | 字段详细稿要求与页面、PDA和动作校验不一致 | 文档/页面/动作静态对照；未提交收货 |

### 评审中发现的文档冲突

- 出库主PRD规定**待处理**B2C可以勾选组波；Demo列表自检和页面骨架UI-05却写“待拣货 B2C 可勾选”。当前页面DOM的勾选状态符合待处理规则。
- 一期系统架构和项目范围明确无登录/角色/用户仓库授权；承运商、商品、仓库、库区、库位等部分主PRD还保留一期权限验收。出库追溯表也将“仓库权限”列为功能来源，而同篇 R16 又明确不做权限裁剪。
- 出库波次“初稿”字段表与“详细稿”不一致：字段存在与否、名称、类型、来源和说明均有差异。文档README将初稿定义为详细稿的五列投影。

另有低优先级风险：盘点发现记录对同一事件的重试可能重复追加依据；当前没有事件级去重证据。

## 应明确保留的决定

- 收货时录良品/不良品和拒收；不增设一期质检任务或商品质检配置。
- 入库、退货异常数量不能进入正常库存；修复超收逻辑时按SKU整批校验，保持原规则。
- 退货异常来源继续与无主货分开；已知货主错SKU/超量的保管事实可另行评估，不直接扩大正常退货准入。
- 上架保存记录进度，整张上架单提交后才移库存；不因竞争产品支持局部上架而改变库存时点。
- B2C按单/基础手工波次、B2B按件或容器、FBA部分实发结案、出库确认与交接分开，按当前项目边界保留。
- 无真实业务样例前不增加自动补货、自动派工、自动播种墙、实体标签打印、称重设备、FBA退货、生产级权限和性能指标。

## 需要业务责任人后续确认的取舍

1. **效期事实与录入模式：**生产日期是否必填；能否通过生产日期与保质期计算失效日期；入库、退货和Web/PDA统一采用哪种方式。
2. **已知货主异常实物：**无预报、错SKU或超量的实物需不需要独立保管记录，记录哪些责任人、位置、凭证和处置状态。
3. **容器与FBA交付：**一期验收是否要求容器作为库存账维度；FBA是否必须保存箱内容和箱托关系。无论选择何种方案，都不自动扩成箱重、体积、预约、标签或承运商集成。
4. **SN数量盘点：**不逐件核实SN时，数量差异如何与仓级SN身份保持一致；避免以某库位数字为0推定仓内所有SN丢失。
5. **波次顺序与实体分播：**确认唯一成员排序规则，并定义纸单/周转箱/格位或PDA目标，保证原单份额与现场放货一致。
6. **真实仓运营输入：**库位批量维护频率、波次任务规模、整箱作业、异常恢复时限、角色责任、四仓时区和性能目标目前均无现场数据，纳入未来运营调研。

## 建议处理顺序

| 顺序 | 工作 | 验收重点 |
| --- | --- | --- |
| 1 | 修复退货按SKU汇总的多容器超收校验、原出库SN按SKU核对 | 超量整次拒绝且无部分库存变化；跨SKU SN拒绝并保留正确拒收路径 |
| 2 | 统一效期判定、过期预占与可分配口径，并实现/说明过期转换触发 | 按仓库本地日期和商品效期策略核对查询、预占、分配、品质转换 |
| 3 | 修正SN数字零盘对身份的影响 | 数量盘点不推定具体SN离仓；逐件身份更正须有明确作业依据 |
| 4 | 按PRD统一波次成员排序；补充轻量实体分播目标 | 多单同品、混品场景中现场分播与原单数量/SN归属一致 |
| 5 | 收口容器库存、FBA箱托和库位/货主停用条件 | 容器内容能与库存账核对；FBA按约定还原箱托；停用阻止未完结作业引用 |
| 6 | 统一批次/生产日期/失效日期规则与所有入口 | Web/PDA入库/退货字段、校验和库存结果一致 |
| 7 | 清理一期已移除的质检配置及遗留权限条款，补充必要主数据历史 | 页面、保存和验收条件与已确认范围一致；历史变更可追查或收窄文档承诺 |
| 8 | 解决文档漂移：波次勾选条件、字段投影、公共布局规范单一来源 | 同一规则只在真源维护，骨架/Demo引用或表达界面职责 |
| 9 | 评估出库列表默认列与Mock入口布局 | 依据实际操作任务调整默认密度；保留列设置和可查字段，不按列数机械删减 |

## 文档、模板和组件处理方案

本轮没有删除或改写项目文档。

- 业务需求与取舍留在需求分析，业务角色、数量、异常和恢复留在业务设计，应用主PRD维护状态、功能规则和验收；其他层只保留摘要并指向真源。
- 详细字段稿作为对象字段唯一真源；初稿仅在有评审用途时作为派生视图，由详细稿生成或校验，不手动并行修改。
- 页面骨架维护入口、页面/弹窗清单和布局；Demo PRD维护控件交互、Mock调用、字段反馈和技术限制。组波资格等业务规则只在主PRD维护。
- ERP与WMS模板已有专门区分，保留各自适用边界；公共布局硬规则由前端规范/PRD目录约定维护，模板只保留链接和必要核对项。
- 简单资料对象按独特状态、上下游依赖与异常分支决定是否单独拆骨架和Demo PRD；不对货主、承运商、库位等有生命周期/关联逻辑的对象一刀切。
- 当前核心业务组件在许多原型页面被实际调用；没有证据支持批量删除公共组件或因抽象数量判定过度设计。
