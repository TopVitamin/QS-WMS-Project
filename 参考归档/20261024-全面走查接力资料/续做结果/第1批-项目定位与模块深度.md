# 第1批：项目定位与模块深度

更新日期：2026-10-24。状态：本批初步评审完成；业务域深查、页面/源码定向验证及文档套件评审仍在并行进行。

执行依据：[QS-WMS全面走查执行计划](../../../QS-WMS全面走查执行计划.md)。本批只写评审结论，不修改项目规则、PRD、原型代码或演示数据。

## 1. 总体判断

QS-WMS一期的目标是一个可运行、可操作的海外仓课程演示系统。它需要用模拟数据演示四仓、多货主、不同商品属性、收存发业务和异常数量结果。文件规定分批开发可以交付，但一期完成仍需覆盖全部一期主链。因此，“某个页面已实现”不能代替业务覆盖验收。

目前产品范围较宽，关键理由是课程要求展示完整仓内链路和不同业务类型。复杂度主要集中在库存口径、容器、异常恢复、消息交接和文档产出。简化点集中在不做真实OMS、承运商、打印秤、用户权限、FBA逆向、计费、派工及性能验收。

评价时需要分开看两种目标：

| 目标 | 本轮采用的判断尺度 |
| --- | --- |
| 课程演示系统 | 每类一期主流程都能用代表性案例跑通；单据、库存、状态和结果能相互核对；不要求真实仓库规模、真实外部系统、真实设备或生产性能验收 |
| 未来运营型WMS | 上线前还需确认真实仓库布局、订单结构、业务频率、岗位与授权、OMS/物流接口、设备和性能指标；当前资料没有这些现场数据，不能把未确定内容写成一期功能缺陷 |

一期范围和演示交付方式见[项目定位与范围](../../../01-全局背景信息/01-项目定位与范围.md)第二节、[阶段规划与一期交付标准](../../../01-全局背景信息/03-阶段规划与一期交付标准.md)第二、三节。公司、仓网、规模均为课程沙盘，没有真实访谈、作业样表或生产记录支持现状判断，见[公司背景与业务概况](../../../01-全局背景信息/00-公司背景与业务概况.md)第一、二、五节及[需求调研总览](../../../03-需求调研和分析/00-项目总览/01-需求调研总览.md)第一、四节。

## 2. 范围基线

本批核实到的目标覆盖为：正常/调拨入库、三类非FBA退货、六类出库、库存与库内、基础资料、系统集成和公共能力。四个海外仓属于规划及课程演示范围，深圳国内仓尚未确定接入阶段。

一期产品重点是仓内实物执行和结果交接。自营ERP及外部货主业务提供货物归属、收发要求和异常决定；WMS记录收货、位置、库存、拣出和出库结果。OMS Mock及承运商Mock用于演示外部协作。真实OMS客户端、身份授权、真实设备、商业计费、FBA退货与换标属于明确后续或暂不覆盖范围。

阶段验收明确要求正常入库、调拨入库、六类出库、三类退货、四仓主链、多货主、商品差异、容器、消息重试、双端一致及关键库存结果可核对。数量规模和大促场景仅供设计参考，不能据此宣称系统已通过性能验证。

## 3. 模块深度总表

“未来运营型WMS”列是范围判断，不代替真实业务调查。带“待核”的项目由对应域报告继续查证。

| 能力 | 课程演示系统的判断 | 未来运营型WMS的差异 | 本批分类 |
| --- | --- | --- | --- |
| 基础资料 | 四仓、货主、商品、库区、库位、容器、承运商和渠道为作业案例提供身份与位置基础；商品属性须能驱动后续流程 | 实际准入、变更、停用及数据同步需按各仓岗位和上游接口验证 | 合理保留；配置是否真正被作业读取，待4C核验 |
| 入库 | 收货、品质、差异、库存暂存和结果反馈是完整演示链的入口。收货时记录良品/不良品，不设独立质检单，是已确认简化 | 实际收货标准、抽检和拒收责任需业务样例；不因成熟产品有质检单就扩入一期 | 合理保留；收货分支复杂度待2A核验 |
| 上架 | 实收先进入暂存库存，提交上架才改变位置，便于演示“收货事实”和“实际落位”差异 | 现场任务切分、分批保存和容器搬运频率需实仓验证 | 库存边界合理；“容器×品质”拆单与整张提交有偏重风险，待2B核验 |
| 退货 | 派送失败、客户退货和非FBA平台退件覆盖主要逆向入口；FBA退货、换标明确后置 | 真实货主预报、原运单识别、错件暂存与退货频率需后续验证 | 合理保留三类；FBA逆向明确后置；异常保管和SN待2C核验 |
| 库存查询 | SKU汇总与库位/批次明细可展示“接单可用”和“现场可分配”的区别 | 运营人员常用筛选、列表密度和SKU规模尚无样表 | 模型合理保留；页面信息密度和字段语义待4A/6核验 |
| 容器 | 箱托作为作业容器，既帮助收发搬运，也参与库存定位；课程场景需要展示容器内容与SKU件数相符 | 容器是否必须作为每次预占、分配、盘点粒度，需货主、仓型和整箱作业样例支撑 | 模型有必要性；全链路未贯通属于实现缺口候选，待4A核验 |
| 移库与补货 | 基础移库可支持位置调整；自动补货建议和存拣分离方案已后置 | 高峰仓可能需要补货触发、路径、优先级和任务进度，需布局与动销数据 | 手工移库合理保留；自动补货明确后置，不据此判缺陷；细节待4A/4C核验 |
| 盘点与品质 | 盘点、差异调整、正常品转不良及过期处理用于展示账实纠正和可售资格 | 冻结范围、盘点授权、差异责任、效期策略需与真实控制制度确认 | 核心控制合理保留；自动转换/恢复路径存在实现验证项，待4B核验 |
| B2C出库 | 接单预占、波次或按单拣货、复核、确认出库和返库形成完整履约案例 | 单量、订单组合、分播方式、扫描路径和包裹称重要求未调查 | 业务主链合理保留；原单绑定时点、先拣后分作业和异常恢复待3A/3B/3C核验 |
| B2B与FBA转运 | 六类出库中保留批发与平台仓备货；平台仓转运允许有实发后缺量结案 | 实际装箱、称重、箱托明细、换标、装车交接应按货主渠道需求确认 | 出库准入和结果类型合理保留；若缺少真实装箱事实则偏薄，待3B核验 |
| 物流交接 | 承运商和渠道资料、模拟交接可展示出库结果边界；真实打印/称重明确不在本期 | 真实面单、预约、称重、签收及承运商接口需另行验收 | 演示范围合理；真实接口属于明确后置；箱/托交接细节待3B核验 |
| 系统集成 | OMS Mock需演示指令接受/拒绝、变更取消、重复消息和既有结果重交；现有文档指出完整输入/结果样例仍不足 | 真实消息协议、监控、故障恢复、客户隔离和部署需另行设计验证 | Mock范围合理；样例不足是演示实现/验收缺口；文档和接口机制负担待5批核验 |
| 公共能力 | 中文/英文、仓库当地日期、关键操作留痕有助于跨仓演示；一期不设置登录和角色权限是明确边界 | 真实多用户、角色、仓库授权和安全审计是运营上线前提 | 演示简化合理；权限与真实用户体系明确后置，不按一期缺陷处理 |
| 产出物 | 主PRD、页面骨架、Demo规格、字段清单及系统设计各自承接不同读者任务 | 变更需跨规则、页面、字段和实现同步；重复维护会拉高维护成本 | 不能按文件数直接判重；实际重复、漂移和模板负担由第5批核验 |

## 4. 关键判断与证据边界

### 4.1 不能用功能数量代表成熟度

比较领星、极风或其他成熟产品时，需对齐其服务的仓型、订单和操作步骤，再判断是否能迁移到强盛。项目内的竞品取舍已区分采用、后置和舍弃，并提醒竞品截图、二次整理和字段推演不能单独证明原文能力。后续域报告须回到本地原始操作页，明确现场多了哪一步、少了哪项事实、承担什么代价。

入库收货、上架、B2C波次、B2B装箱、退货识别、库存容器与盘点各由不同批次具体对照。产品的总体结论目前不将某家产品当成默认答案，也不因某项功能未纳入课程演示就认定未来无需建设。

### 4.2 课程演示的必要深度

演示要能从指令与资料开始，走到实物收发、库存数量变化和结果反馈；至少给六类出库和三类退货准备有区别的代表路径。容器、批次、效期、SN和多货主也需要在场景中显示其如何改变记录或资格。

本期不要求把四仓复制成大量数据，不要求生产级峰值测试、实体PDA、真实承运商或身份授权。示例数量须标注为课程沙盘，不能冒充真实仓库频次或损失。

### 4.3 当前明确的演示输入缺口

需求分析总览第6.3节已指出，OMS Mock的消息信封、标识和顺序已有设计，但完整正常输入、异常输入及结果样例还不齐；第6.2节的业务走查也标明管理端/PDA操作验收待执行。因此“接口模型已写”不能视为端到端演示通过。具体报文范围和页面分支由域审计与第6批再核。

### 4.4 当前不能定论的事项

本批以项目定位、范围、阶段验收、需求总览、竞品取舍和业务蓝图为依据。领域PRD、具体配置到源码动作的链路、B2B/FBA装箱流程以及详细页面动作由并行域任务复核；不把历史线索、菜单数或文件数提前转换为缺陷。

## 5. 本批结论与后续衔接

- 范围广，但大多数模块直接服务课程要求的“仓内执行、数量核对、异常与结果交接”。整体应保留业务覆盖，不要求每类能力都做成成熟仓库的完整自动化版本。
- 真实运营深度的缺口应标成后续上线输入，例如真实仓库布局、岗位权限、消息/物流接口、设备、峰值和作业样例；当前没有证据给出具体SLA或效率指标。
- “偏重、偏薄、实现缺口”需按步骤或数据事实拆开判断。当前较强的核验重点为收货/上架任务组织、容器库存贯通、B2B装箱，以及Mock输入/结果样例。
- 下一步接续2A–2C、3A–3C、4A–4C域报告；随后执行第5批文档/模板精简，定向完成第6批页面与实现验证，最后按第7批统一结论。
