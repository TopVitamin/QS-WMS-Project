# 入库业务需求调研

> 本文整理课程沙盘的目标业务场景与诉求。系统需求见[入库业务需求分析](入库业务需求分析.md)。

## 一、业务背景与参与方

强盛计划从第三方海外仓履约转向自行运营仓库，需要自行组织到货核对、实物清点、质量判断和存放，并向业务端交接入库结果。未来同仓可能同时收到多个货主、不同品类的货物，需要明确每批实物的归属和处理进度。

本模块研究正常入库、调拨入库的到货、收货、质检、上架及结果交接。业务端提供入库指令，仓库执行现场作业，货主对差异及无法匹配的到货提供信息或处理指示。各仓岗位分工和实际使用的单据尚无资料；客户退货入库不在本期研究范围。

## 二、主要业务场景与诉求

| 业务场景 | 约束或风险 | 业务诉求 |
| --- | --- | --- |
| 货物到仓，需要对应入库指令 | 同批到货可能涉及多张单据、多个货主 | 能通过随货信息识别业务指令，分别记录归属和到货情况 |
| 一张入库单分多次到货或分批清点 | 尚未到齐和最终短少是两种情况 | 分次记录实收，能区分仍待收货与收货完结后的差异 |
| 到货存在短少、超收、破损 | 实物与预报不一致，需要明确接收和处理责任 | 差异可查，实收数量可信，超收实物有明确处理依据 |
| 商品需要质检、SN、批次或效期管理 | 不同商品的检验与追溯要求不同 | 按商品要求采集信息，区分正常品和不良品，后续能够追溯 |
| 已收实物在上架前真实丢失 | 原实收与现场剩余不一致，不能把损失改成未收或补造实际落位 | 原实收、现场剩余与损失分别留痕，有异常处理依据及净库存结果 |
| 收货后安排存放 | 已收到货不等于已经放到可查的位置 | 记录上架位置和数量，支持分批上架；货主和品质归属不混记 |
| 没有匹配指令的货物到仓 | 可能已知货主但漏推单，也可能无法判断归属 | 已知货主能够补单；未知归属能够暂存和认领，认领不代替实物清点 |
| 已收货后上游要求取消或退回 | 原收货事实已经发生，不能抹去后直接恢复到未收货 | 保留原入库记录，退回有独立业务依据和执行结果 |
| 业务端与货主了解入库进度 | 需要区分收货、质检、上架及差异结果 | 业务端可取得仓内进度和最终结果，差异明细能与原指令核对 |

## 三、需要补充的资料

- 收货、质检和差异处理样例：清点记录、商品检验项目及原因明细、残损实物的登记方式，用于细化作业与记录方式。无真实材料时使用明确标注的沙盘样例。
- 入库指令与结果样例：上游提供哪些业务信息，业务端需要查看哪些进度和结果，用于后续表单及结果交接设计。
