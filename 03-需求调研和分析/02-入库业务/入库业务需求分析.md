# 入库业务需求分析

> 本稿说明一期范围与系统需求。
> 业务背景与场景见[入库业务需求调研](入库业务需求调研.md)。

## 一、分析结论与模块边界

WMS接收正常入库、调拨入库指令，完成到货登记、新品维护（量方称重）、按容器或按SKU收货（拒收数量与实收数量，实收内分良品与不良品）、按容器或按SKU上架和结果回传。一期不设质检任务与质检单。收货确认即按品质计入收货暂存库位库存，良品、不良品再分别上架到目标库位；管理端与PDA共用记录。调拨入库作为普通入库来源，不关联调出仓单据。

**职责范围**

- 本模块记录到仓识别、实收进度、品质分流、上架落位及入库异常（一期只有拒收）；库存影响见第二节。
- 入库指令与结果回传经[系统集成与对接需求分析](../06-系统集成与对接/系统集成与对接需求分析.md)；货主、商品、库位资格见[基础资料需求分析](../01-基础资料/基础资料需求分析.md)。
- 已收货物从仓库退回仓外由出库模块按采购退货出库指令执行；超收、未预报商品一期不在系统登记，由仓库线下暂存、联系货主补单或退还。

**不在本模块**

- 货从仓外退回本仓（派送失败退回、客户退货、平台仓退件）由[退货业务需求分析](../05-退货业务/退货业务需求分析.md)承接；FBA 移除退仓与换标换包装不在一期。仓外运输与收货预约（一期未纳入）。
- 无主货认领与 OMS 客户查看由后续真实 OMS 承接；入库取消一期由 OMS Mock 下发，真 OMS 上线后沿用同一受理规则。
- 商业计费与仓租。
- **LPN全仓跟踪**：不建立箱库存或托盘库存，不以作业容器为在库库存维度，不提供库内按容器移库、按容器查可用量或容器主数据全生命周期管理（容器编号仅服务本单收货—上架绑定与追溯）。

## 二、功能需求

| 编号 | 功能 | 需求结论 |
| --- | --- | --- |
| IN-FR-001 | 入库指令接收 | 接收正常入库和调拨入库指令，校验必要资料 |
| IN-FR-002 | 到货登记与签收 | 识别到货；已知货主补单，未知归属登记无主货 |
| IN-FR-003 | 收货 | 分次记录实收与拒收，校验追溯及效期；拒收自动记入库异常 |
| IN-FR-004 | 收货品质分流 | 实收内分良品/不良品并分别上架；拒收数量不计实收 |
| IN-FR-005 | 上架单 | 按容器×品质生成；分次保存，整张提交移库 |
| IN-FR-006 | 上架校验 | 上架不得超过已收货未上架数量 |
| IN-FR-007 | 入库完成与结果 | 收货完结且正常/不良均完成上架后结案，短少与拒收分项回传 |
| IN-FR-008 | 取消与变更 | 一期未实收可接收明细变更与上游取消；整单零实收（含全单拒收）受理后转已取消 |
| IN-FR-009 | 多货主归属与仓库权限 | 单据与库存按货主归属，访问范围引用公共能力 |
| IN-FR-010 | 库存影响 | 收货确认即按品质进入收货暂存库位库存；上架单提交时从暂存移到目标库位 |
| IN-FR-011 | 入库单来源 | 一期全部入库单由OMS Mock指令生成，不提供手工入口 |
| IN-FR-012 | 无主货登记 | 一期只登记和暂存；OMS上线后推送信息、在OMS认领并下发入库指令 |
| IN-FR-013 | PDA入库作业 | PDA执行同一入库任务，重复提交不重复增库存 |
| IN-FR-014 | 新品维护 | 首次到仓SKU量方称重并更新仓内规格；可按规则拍照留底 |
| IN-FR-015 | 作业容器收货与上架 | 可选按容器或按SKU收货；容器路径支持扫容器上架 |

#### IN-FR-001 入库指令接收

- 接收OMS Mock推送的正常入库或调拨入库通知，生成入库单（状态「待收货」），含业务类型、货主、仓库、商品与预计数量、到货方式等；货主或商品无法匹配时拒绝建档并记录异常。
- 页面联查新品维护记录：同一货主＋SKU无记录时，首次收货前必须维护；不在入库单上另设新品状态，也不以上游标记覆盖此判断。
- 调拨入库单不要求提供调出仓单号，也不与调出仓结果核对。

#### IN-FR-002 到货登记与签收

- 支持按入库单号、运单号或箱唛定位入库单并登记到货。
- 同一货主的一次送货可能对应多张入库单；一次到仓按识别信息分别登记到对应单据，不混记货主。
- 无预报到货：能判断货主的，联系货主补推入库单，到单后按正常入库执行；无法判断货主的，登记无主货并专门暂存，不生成入库单、实收或库存。
- 示例：同一货主到货1托3箱，其中2箱分别匹配到入库单，另1箱货主已知但缺少指令，暂存并联系补单。若另有一箱连货主也无法确定，才登记无主货。

#### IN-FR-003 收货

- 按商品记录每次实收，支持多次到货和部分收货。启用SN时采集SN；启用批次／效期时记录批次、生产日期和有效期，校验有效期不早于生产日期。
- 效期准入按[基础资料需求分析](../01-基础资料/基础资料需求分析.md)商品效期配置，按仓库当地业务日期计算剩余保质期，只与允许入库天数比较：小于时拒收、大于或等于时允许。临期、过期等级不追加收货限制；在库过期转不良见库存与库内需求分析。
- **拒收数量**：现场不予接收入库的件数（含效期不符、货主政策拒收残次、外包装严重不符等），须填**拒收原因**（原因代码或枚举，应用设计细化）。拒收记在收货明细行上，收货确认时系统自动生成一条拒收类**入库异常**，现场不重复登记；拒收不计入实收，不生成上架单、不增库存；入库单明细上的拒收数量为各次收货的拒收之和。实物交司机退回或拒收区，由仓库线下处理，不得改记为实收或不良品进仓。
- **实收数量**：同意接收入库的件数，各次实收之和为入库单明细的实收数量。效期准入仍按基础资料校验：不满足允许入库天数的部分应记入**拒收数量**，不能通过填不良品绕过。
- **良品数量／不良品数量**：在**实收数量**内拆分，须满足良品+不良品=本次实收。不良品为已接收入库但须管控的瑕疵件；良品、不良品在收货确认后分别进入本仓收货暂存库位的对应品质库存，上架单提交后再移到存储库位或不良隔离库位。库存品质维度记为正常／不良（良品对应正常，不良品对应不良）；暂存库位库存计入实际库存但不参与出库分配。
- 同一收货明细行按行录入拒收数量（及原因）与实收数量；**实收＋拒收不得超过预计**，不能超量收货。实收＋拒收＝预计时该行自动收货完结。
- 实收数量按入库商品明细累计；与作业容器的绑定、容器内分SKU数量及容器上架见[作业容器收货与上架](#in-fr-015-作业容器收货与上架)。
- 超出预计的实物（超收）以及本单没有的商品（未预报商品）不接收，一期不在系统登记：仓库线下暂存到异常处理区，联系货主补发新单后按新单校验收货；货主要求退还或处置的线下完成，不建出库单。
- **未收数量＝预计－实收－拒收**。收货未完结时，「预计10、实收8、拒收0」表示未收2、仍在等后续到货；授权确认收货完结后，未收数量即为**最终短少**（拒收单独统计，不与短少重复相加）。

#### IN-FR-004 收货品质分流

- 一期**不**生成质检任务、不设独立质检单；与富勒「质检后再剥不良」不同，**良品／不良品在收货界面于实收数量内一次性录入**（见[收货](#in-fr-003-收货)）。
- 接收入库的不良品与良品分别生成上架单，上架到适配库位；须保留操作者与时间。
- 一期不支持上架前品质转换。上架时才发现的残损（收货未录入部分），先按原品质上架，再按[库存与库内需求分析](../04-库存与库内业务/库存与库内业务需求分析.md)做库存品质转换；入库单的良品、不良品数量只取收货录入的数量。
- 不良原因枚举与界面字段结合商品样例在应用设计中细化。商品资料一期不设质检配置。

#### IN-FR-005 上架单

- 收货确认后按「作业容器×品质」自动生成上架单；单头固定容器与品质，单内分**应上架明细**与**实际上架明细**。实际上架可多次保存、不动库存；整单校验通过后提交，一次性把库存从收货暂存库位移到目标库位。良品推荐存储／拣货位置，不良品推荐不良隔离位置。
- 同一库位同一时点只能存放一个货主的实物；存在其他货主的实物、未提交上架单对目标库位的占用或未完结任务时阻断，具体见[基础资料的库位规则](../01-基础资料/基础资料需求分析.md#md-fr-004-库区与库位资料)。收货暂存库位允许多货主混放，不受目标库位一货主占用规则限制。
- 支持按 SKU 扫描库位确认与分次落位；容器路径支持扫描作业容器。上架单提交时，每条应上架行的各库位上架数量合计须等于应上架数量；应上架数量生成后不可修改。上架前发现的残损和暂存期间丢失的处理见[收货品质分流](#in-fr-004-收货品质分流)与[入库完成与结果](#in-fr-007-入库完成与结果)。

#### IN-FR-006 上架校验

上架数量不得超过已收货未上架数量；超出时阻断并提示可上架数量。按容器上架时，不得超过该容器当前可上架数量及对应商品行的已收未上架数量。

#### IN-FR-007 入库完成与结果

- **入库单状态**（系统推导）：待收货、收货中、上架中、已完成、已取消。收货中、上架中、已完成均要求整单累计实收大于 0。全单拒收等零实收不作已完成：仓库通知上游取消，Mock 受理后转已取消。明细行另有明细状态（含已取消），见[入库模块宏观系统架构](../../01-全局背景信息/04-入库模块宏观系统架构.md)。
- 累计实收大于 0，且所有明细行收货完结、已上架等于实收后，常规入库置为「已完成」。
- 收货未完结时表达未收数量；每行实收＋拒收＝预计时自动收货完结，或有行少收时由授权人员确认整单收货完结，未收数量即为**最终短少**（预计－实收－拒收）。**最终短少不含拒收数量**。
- 拒收数量（含效期类等原因）单独记入库异常，不计入实收；结案回传时与短少分别说明。
- 入库异常一期只记拒收：收货环节现场有实物、和入库单对不上的情况；短少、收货时录入的不良品不算入库异常，超收、未预报商品一期线下处理。存什么、不存什么见[入库模块宏观系统架构第 2.1.3 节](../../01-全局背景信息/04-入库模块宏观系统架构.md#213-入库异常存什么不存什么)。
- 整单完成回传时，短少取入库单未收数量、拒收取入库异常，分项说明；入库单头不设差异标记。执行结果在入库单已完成时按原指令回传 OMS Mock。
- 累计实收为 0 且确定不再接收（含全单拒收）时，保留到货与拒收事实；仓库通知上游，由 OMS Mock 下发取消并受理后原单转已取消。WMS 不能按零实收走入库完成或生成库存。
- 一期不支持已收未上架丢失收口。暂存期间真实丢失时，上架单仍按应上架数量提交，再由发现人员对该 SKU 发起盘点调整库存。回传给上游的上架数量不反映这部分丢失，由仓库线下告知货主。实收误记不适用此路径。
- 模拟例：预计并实收 10 件（良品 10）、暂存库位库存 10；上架时只找到 8 件。上架单仍按 10 件提交，目标库位账上 10、实物 8；再对该 SKU 发起盘点，盘亏 2。入库单实收 10、已上架 10，正常完成。完整案例见[入库业务设计第8.4节](../../04-业务分析和设计/02-入库业务设计.md#84-模拟补充分支实收正确未上架真实丢失先上架再盘点)。

#### IN-FR-008 取消与变更

- 尚未产生实收时可接受OMS Mock明细变更；产生实收后拒绝明细变更。

未实收明细变更须保留既有拒收事实：不能删除已有拒收的SKU，变更后该行预计不得小于累计拒收；不满足时拒绝，保留原单与原记录。
- 尚未产生实收时可接受上游取消；受理后原单转已取消，不交入库完成结果。身份字段不得在原单变更。
- 已收货物退回由OMS Mock下发采购退货出库指令；货还在收货暂存库位时也可接单预占，上架后才能分配拣货。未进入实收的实物线下处理，不建WMS采购退货出库。

#### IN-FR-009 多货主归属与仓库权限

入库单、收货与上架记录均带货主维度；用户只能访问授权仓库，具体操作还须具备相应动作权限，规则见[公共能力需求分析](../07-公共能力/公共能力需求分析.md)。

#### IN-FR-010 库存影响

- 入库单记录预计、实收、拒收、未收、良品/不良品、已上架等数量；待上架为实收－已上架，不单独记录；不另设待质检等库存类型。
- **收货确认**即按实收、按品质增加本仓**收货暂存库位**实际库存（良品为正常品，不良品整体不可用）；暂存库位允许多货主混放，仍按货主、SKU、品质、批次记账；良品计入可用、可被接单预占，但不参与出库分配。
- **上架单提交**时按实际上架明细，一次性把库存从暂存库位移到目标库位；保存实际上架明细不动库存。数量口径与流水见[库存与库内需求分析](../04-库存与库内业务/库存与库内业务需求分析.md)。上架前残损与暂存期间丢失一期不在入库内处理，上架后按库存品质转换与盘点执行。

#### IN-FR-011 入库单来源

- 一期全部入库单由OMS Mock指令生成，管理端不提供手工新建入口。
- 演示所需资料可预置，入库单仍由Mock指令生成。

#### IN-FR-012 无主货登记

- 记录无主货所在仓库、暂存位置、箱唛／运单等识别线索，实物使用专门位置，不与已识别货主实物混放。
- 登记只保留识别线索与暂存事实，不生成入库单、实收、库存或入库执行结果；WMS不提供认领入口。
- OMS上线后，WMS推送无主货信息供客户在OMS认领并下发入库指令；一期不以Mock代做认领。

#### IN-FR-013 PDA 入库作业

- PDA支持按单号、运单号或箱唛定位任务，完成新品维护（若需）、收货（拒收数量与原因、实收数量、实收内良品/不良品）、追溯采集、扫容器上架及库位校验。
- 与管理端共用业务记录，重复提交不重复增加库存。

#### IN-FR-014 新品维护

- **含义：**对首次进入本WMS仓网、尚无新品维护记录的SKU，在该SKU首次收货提交前完成量方称重（长宽高、毛重等），将结果写入该货主商品的**仓内规格**（见[基础资料需求分析](../01-基础资料/基础资料需求分析.md)维护与同步方式）。
- **维护范围：**同一货主 + 商品编码在WMS内首次维护成功后，四仓共用该仓内规格，后续入同一仓网不再重复量方；多仓并发首次维护以先确认提交为准。
- **作业节点：**可在到货登记后、该SKU首次收货提交前执行；需维护且未完成的明细，阻断该SKU在本单的后续收货与上架，直至维护确认完成。
- **与预报关系：**可展示OMS预报尺寸重量供对照；实测以仓库提交为准写入仓内规格，差异可留操作记录，是否回写上游不在一期验证范围。
- **影像留底：**按商品或入库规则，在签收验收前对外箱、标签、破损等拍摄并关联本次到货或收货记录；一期落实关键节点留痕与差异场景可关联原单，完整附件产品与在线沟通不纳入一期。
- 一期量方称重使用手工或模拟数据；DWS／电子秤对接留待后续集成。
- 业务展开与走查见[入库业务设计第3.7节与第8.6节](../../04-业务分析和设计/02-入库业务设计.md#37-新品维护首次到仓量方后再收该-sku)。

#### IN-FR-015 作业容器收货与上架

- **含义：**作业容器指现场一箱、一托或等价装载单元。在选用容器作业时，为容器绑定**作业容器编号**（可扫描货主箱唛／托唛，或由WMS生成），并登记容器类型（箱／托等）及容器内各商品的数量（含批次、效期、SN等按商品配置采集）。用于串联本入库单的清点、待上架与落位，便于现场跟踪。
- **作业方式（可选项）：**每次清点可选择以下一种方式，数量统一计入商品明细实收，不重复记账。
  - **按容器收货：**实收数量登记在作业容器及容器内分SKU明细上；后续可扫容器上架。
  - **按SKU收货（不绑容器）：**直接在商品明细上登记实收，不生成作业容器记录；后续仅支持按SKU（及库位）上架。
  - 一张入库单可混用（例如部分 SKU 按容器收、部分做无容器收货），以现场包装形态为准。各仓**默认收货方式**在[基础资料需求分析](../01-基础资料/基础资料需求分析.md)仓库资料中配置，PDA可按次改选。
- **收货绑定（容器路径）：**一容器可含多条商品，一条商品可拆到多容器。容器归属本入库单货主，同一容器不混记不同货主。收货确认后，容器内正常/不良数量分别进入对应上架进度。
- **容器上架：**支持扫描作业容器编号并确认目标库位，将容器内当前可上架数量落位；支持同一容器分次保存到同一或不同库位；各应上架行录满后整张提交，不支持单张上架单部分提交。与按SKU逐件扫库位上架共用同一套已收未上架数量口径，两种方式不重复增加库存。
- **库存与追溯：**上架完成后，实际库存仍按SKU、库位、品质及追溯维度记录；库内移库、盘点、出库预占不按作业容器编号执行。管理端与PDA可按入库单、作业容器编号查询收货与上架关联；结果回传以SKU汇总为主，是否附带容器明细由应用设计与集成约定。
- 容器号挂收货及上架行，不设独立容器对象；扫描和现场编号交互见应用设计。
- 业务展开与走查见[入库业务设计第3.8节与第8.6节](../../04-业务分析和设计/02-入库业务设计.md#38-作业容器按容器或按-sku数量仍记商品明细)。

## 三、调研诉求处理

依据[入库业务需求调研](入库业务需求调研.md)第四节，处理结论如下。具体规则见**第二节**。

| 诉求 | 处理结论 |
| --- | --- |
| 到货识别、分批收货、差异和分批上架 | 纳入一期，由入库业务记录执行过程与结果；入库异常一期只记拒收，超收与未预报商品线下处理 |
| 新品维护、收货品质与追溯 | 纳入一期，收货录入正常/不良；不设质检任务 |
| 容器与SKU两种作业方式 | 纳入一期，使用统一商品数量口径 |
| 已收未上架丢失、上架前发现残损 | 一期不在入库内处理：先按应上架数量和原品质上架，再由库存与库内盘点或品质转换 |
| 调拨入库 | 纳入一期，共用入库主流程 |
| 无主货、零实收与取消 | 无主货一期仅登记；零实收（含全单拒收）通知上游取消，一期 Mock 受理已取消；认领待真实 OMS |
| 指令变更与结果交接 | 未实收明细变更与整单完成结果回传纳入一期，与系统集成协作 |
