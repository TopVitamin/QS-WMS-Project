# 退货业务需求调研

> 文档状态：调研初稿（案头整理，课程沙盘）
> 调研范围：货从仓外退回本仓的三类来源——派送失败退回、客户退货、平台仓退件——的到件识别、清点收货、良品／不良品判定、上架及结果交接；FBA 移除退仓与换标不在本期
> 系统需求与已确认规则见[退货业务需求分析](退货业务需求分析.md)

## 一、调研范围与资料来源

自营 B2C 与多货主代发一旦开始发包裹，就会有货从末端退回海外仓：派送失败原路退回、买家签收后再寄回、非 FBA 平台仓移除退回。与「已收货物从本仓退回供应商」的采购退货出库方向相反，退回本仓需要单独认货主、对原发货或预报、再决定能否重新销售。

| 环节 | 本次关注内容 | 主要交接 |
| --- | --- | --- |
| 预报与建单 | 货主退货预报；派送失败扫原运单号关联原出库单 | OMS Mock 下预报；现场建单结果回传上游 |
| 到件识别 | 退货运单、原运单、移除单号、箱唛等线索 | 对到退货单；对不上则补预报或无主货登记 |
| 收货与差异 | 拒收与实收，实收内良品／不良品；SN 按来源核对 | 与入库相同的暂存库位记账规则 |
| 上架与库存 | 良品入存储、不良品入不良隔离；上架单与入库共用对象 | 形成可出库库存；结果回传 |
| 无主与 FBA | 认不出货主；识别为 FBA 移除特征 | 无主货只登记；FBA 一期线下协调 |
| 变更与取消 | 预报取消、零实收 | 与入库类似的取消受理边界 |
| 结果回传 | 结案时短少、拒收、实收分项 | WMS 交回 OMS Mock |

**不在本模块调研范围：**亚马逊 FBA 移除退仓的专属接收、FNSKU 换标、独立「退货库存」类型；退件认领公海、销毁倒计时与计费；退货全程视频；跨仓「A 仓出 B 仓入」就近退仓；报损／销毁；商业计费。

## 二、现有交接与目标作业分工

### 2.1 立项时的逆向交接

立项前 3PL 代发阶段，买家退货与派送失败退回多由服务商线下处理，强盛业务侧往往只看到库存或赔付汇总，缺少逐件 SN、退货运单与原订单的系统性对应。转向自营仓后，需要在本仓记录「谁退的、退了多少、品质如何、能否再卖」。

### 2.2 租仓自营后的作业分工

| 参与方 | 业务职责 | 需要补充的资料 |
| --- | --- | --- |
| 自营业务侧、外部货主 | 客户退货与平台仓退件提前下退货预报；对差异给出处理意见 | 预报字段、原订单号是否必填、演示样例 |
| 仓储物流 | 退件区到件、拆包或整包清点、良品／不良判定、上架 | 退件岗与收货岗是否分人、PDA 步骤 |
| 数字化／项目组 | 退货预报接入、派送失败建单、结果回传 | Mock 消息、与原出库单关联规则 |

一期由 OMS Mock 下发退货预报（客户退货、平台仓退件），仓库通过管理端和 PDA 执行退货收货与上架；派送失败退回允许现场扫原运单号生成退货单。WMS 将结案结果返回 Mock，不建设货主自助认领池。

## 三、三类来源与竞品对照（归纳）

竞品普遍把「谁退的」和「怎么建单」拆开处理，与强盛一期三类来源可对照理解，**不表示照搬其菜单或计费**。

| 来源 | 业务条件 | 竞品常见做法（摘要） | 强盛一期倾向 |
| --- | --- | --- | --- |
| 派送失败退回 | 原包裹未妥投，承运商退回；货主与 SKU 由原出库运单确定 | 领星「服务商退件」可按原跟踪号判定；极风支持扫退货运单在邻近仓直建退货入库，有的场景可不先建退货单 | 扫**原出库运单号**建退货单并关联原 B2C 出库；SN 与原出库复核一致才计实收 |
| 客户退货 | 买家用新运单寄回；须预报才知道内容与货主 | 两家均要求货主先建退货单；仓库可 PDA 扫面单／SKU 代建或加速（领星免认领配置、极风 PDA 带出货主） | 以 OMS Mock **退货预报**生成退货单；无预报则催补，不做公海认领产品 |
| 平台仓退件 | 带平台侧退货单号，整箱或混箱到仓 | 与退货预报类似，常单独字段记录平台侧退货单号 | 预报含平台侧退货单号；链路同客户退货 |
| 到仓无预报 | 面单磨损、错寄、空包 | 领星 D 级进认领公海；极风公有认领池＋货主 OMS 认领 | 已知货主催补预报；认不出货主走**无主货登记**（入库域） |
| FBA 移除 | FNSKU、换标、退货库存隔离 | 领星独立退货库存；极风 FBA 全流程换标 | **一期不做**，保留识别线索线下协调 |

领星常规退件支持「到仓暂存」与「到仓清点」分步，并 tied 到仓计费；极风强调退货验货录像与分级处置。强盛一期**不设**到仓暂存停单、**不**做退货后独立质检任务，良品／不良在退货收货一次录入；录像、阶梯质检与计费留后续评估。

## 四、核心场景与业务问题

| 场景 | 业务条件 | 需要解决的问题 | 当前确认情况 |
| --- | --- | --- | --- |
| 派送失败到件 | 外包装常未拆，件数应与原包裹一致 | 如何快速定位原出库单并防 SN 调包 | 扫原运单建单已纳入；SN 强核对已纳入分析稿 |
| 客户退货到件 | 可能已拆封、试用或损坏 | 预报与实物不一致如何记拒收／不良 | 拒收＋实收内良品／不良，方向已确认 |
| 平台仓退件 | 一箱多 SKU、可售与不可售混合 | 是否与 FBA 混淆、如何认移除单 | 一期按预报收货；FBA 特征不执行退货收货 |
| 无预报到件 | 只有退货运单或箱唛 | 不能凭空入账 | 补预报或无主货；不复制认领池 |
| 分批收货与上架 | 同一退货单可多次到件或分次清点 | 进度与库存分开 | 对齐入库分批规则 |
| SN 与 3C | 高价值件防调包 | 何时必须与原出库 SN 一致 | 派送失败强核对；预报能链原单且有原SN时强核对；不一致只能拒收、不计实收 |
| 良品再销售 | 货主是否要求先暂存待指令 | 影响周转与演示闭环 | 一期良品直接上架入可售库存 |
| 与入库、出库边界 | 采购退货出库、正常入库指令 | 避免混单 | 独立退货单，不入库类型枚举 |
| 结果交接 | 货主需知实收与品质 | 结案回传分项 | Mock 回传，字段待集成稿 |

## 五、业务诉求

| 场景 | 业务诉求 | 当前判断 |
| --- | --- | --- |
| 三类来源覆盖 | B2C 演示「发出—退回—再可售」闭环 | 一期核心（不含 FBA 退货） |
| 派送失败建单 | 现场可扫原运单开工，不必等预报 | 一期核心 |
| 客户／平台仓预报 | 货主提前下退货预报 | 一期核心 |
| 收货品质 | 实收内分良品／不良，拒收不计实收 | 一期核心 |
| 上架形成库存 | 与入库相同暂存→存储／隔离 | 一期核心 |
| SN 核对 | 能链原出库时防调包 | 一期核心 |
| 无主货 | 认不出货主不生成退货库存 | 一期登记，衔接入库无主货 |
| 变更取消 | 未实收可取消预报 | 一期纳入，细则见分析稿 |
| 认领公海、视频、计费 | 行业常见增强 | 后续评估 |
| FBA 退货与换标 | 平台移除专属流程 | 后续阶段 |

上表诉求对应的系统规则写在[退货业务需求分析](退货业务需求分析.md)。退货预报与结果见[系统集成与对接需求分析](../06-系统集成与对接/系统集成与对接需求分析.md)；权限与双端见[公共能力需求分析](../07-公共能力/公共能力需求分析.md)。
