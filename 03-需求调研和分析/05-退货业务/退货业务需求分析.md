# 退货业务需求分析

> 本稿说明一期范围与系统需求。
> 业务背景与场景见[退货业务需求调研](退货业务需求调研.md)。

## 一、分析结论与模块边界

WMS 接收退货预报或现场解析派送失败线索，生成退货单，完成到件识别、退货收货（拒收数量与实收数量，实收内分良品与不良品）、上架及结果回传。一期覆盖派送失败退回、客户退货、平台仓退件；亚马逊 FBA 移除退仓不在本期。退货收货后的上架单与正常入库共用对象与提交规则，单头标明来源为退货单。管理端与 PDA 共用记录。

**职责范围**

- 本模块记录退货来源、关联原出库单或退货预报、实收进度、品质分流、上架落位及退货异常（一期以拒收为主）；库存影响见第二节。
- 退货预报与结果回传经[系统集成与对接需求分析](../06-系统集成与对接/系统集成与对接需求分析.md)；货主、商品、库位资格见[基础资料需求分析](../01-基础资料/基础资料需求分析.md)。
- 认不出货主的到件登记[无主货](../02-入库业务/入库业务需求分析.md#in-fr-012-无主货登记)（入库模块），不生成退货单与库存；已知货主但长期无预报的，线下协调补预报，不用无主货登记替代。
- 已收货物从本仓退回仓外由出库模块执行（如采购退货出库），与本模块方向相反。

**不在本模块**

- FBA 退货接收、FNSKU 换标、独立退货库存类型、换标换包装。
- 退件认领公海、货主在 WMS 认领后转单（一期无真实 OMS 客户端；无主货待二期 OMS 认领）。
- 退货后独立质检任务、到仓仅暂存不计费、退货全程视频、商业计费。
- 将退货并入入库业务类型；一期入库仍只有正常入库与调拨入库。

## 二、功能需求

| 编号 | 功能 | 需求结论 |
| --- | --- | --- |
| RT-FR-001 | 退货预报接收 | 接收 OMS Mock 退货预报，生成退货单 |
| RT-FR-002 | 派送失败建单 | 扫原出库运单号定位原出库单并生成退货单 |
| RT-FR-003 | 到件识别与分流 | 对单收货；无单补预报、无主货或 FBA 线下 |
| RT-FR-004 | 退货收货 | 分次拒收与实收，追溯与效期校验 |
| RT-FR-005 | 收货品质与异常 | 实收内良品／不良；拒收自动记退货异常 |
| RT-FR-006 | 退货上架 | 按容器×品质生成上架单，规则同入库 |
| RT-FR-007 | 退货完成与结果 | 收货完结且实收全部上架后结案并回传 |
| RT-FR-008 | 取消与变更 | 未实收可取消预报；产生实收后规则同入库变更边界 |
| RT-FR-009 | 多货主与仓库权限 | 单据与库存按货主；访问范围引用公共能力 |
| RT-FR-010 | 库存影响 | 收货确认进暂存库位；上架提交进存储或不良隔离 |
| RT-FR-011 | SN 核对 | 按退货来源与原出库／预报关联强度校验 |
| RT-FR-012 | PDA 退货作业 | PDA 建单（派送失败）、收货、上架，双端一致 |

#### RT-FR-001 退货预报接收

- 接收 OMS Mock 推送的退货预报，校验仓库、货主、商品与预计数量；客户退货须含退货运单号等识别字段，平台仓退件须含平台移除单号（字段细节由应用设计承接）。
- 校验通过生成退货单（状态「待收货」），记录退货来源（客户退货或平台仓退件）、关联预报标识；同一预报重发不增加单据。
- 货主或商品无法匹配时拒绝建档并记录异常，与入库指令拒收口径一致。

#### RT-FR-002 派送失败建单

- 在授权仓库，PDA 或管理端扫描**原 B2C 出库运单号**（模拟运单号），系统定位已确认出库的 B2C 出库单，带出货主、仓库、SKU 及可退数量线索（通常与该行实发或包裹复核数量一致，应用设计细化行级预计）。
- 生成退货单，退货来源为「派送失败退回」，关联原出库单；若该运单已存在未完结的派送失败退货单，**阻断重复建单**（见《单据与状态流转》二之一节）。
- 建单与结案结果回传 OMS Mock，不伪造退货预报号。货主亦可先下退货预报，到仓时以预报单收货，并可与原运单交叉校验。

#### RT-FR-003 到件识别与分流

- 支持按退货单号、退货运单号、原运单号（派送失败）或移除单号（平台仓）定位退货单。
- 客户退货、平台仓退件到仓时无预报：能确定货主的，联系货主补推预报，有效预报到达后再收货；不能确定货主的，登记无主货，不生成退货单。
- 识别为 FBA 移除退仓特征（如 FNSKU 主导、货主明示为 FBA 退仓）的，一期不执行退货收货，保留识别线索由仓库线下协调，见项目定位第 4.1 节。
- 实物与退货单 SKU 对不上、超出预计等，按 RT-FR-004、RT-FR-005 拒收或线下暂存，不伪造明细行。

#### RT-FR-004 退货收货

- 规则对齐[入库收货 IN-FR-003](../02-入库业务/入库业务需求分析.md#in-fr-003-收货)：分次录入拒收数量（及原因）与实收数量；实收内分良品、不良品；效期准入、批次／SN 采集按商品配置。
- 每行实收＋拒收不得超过退货单预计；派送失败场景下预计来自原出库可退线索，不得超原包裹实发计实收。
- 未收数量＝预计－实收－拒收；授权确认收货完结后，未收为最终短少。
- 作业容器绑定与无容器收货规则同入库 IN-FR-015；容器路径用于生成上架单。

#### RT-FR-005 收货品质与异常

- 一期不设退货后独立质检任务；良品／不良品在退货收货界面于实收内一次性录入。
- 拒收不计实收，不生成上架单；收货确认时自动生成拒收类**退货异常**，指回退货收货明细行。
- 良品、不良品分别生成上架单，退货良品目标为存储库位，不良品目标为不良隔离库位；整单提交与货主占用校验同入库上架。

#### RT-FR-006 退货上架

- 收货确认后按「作业容器×品质」自动生成上架单，单头标记来源退货单与退货收货记录；应上架／实际上架、保存与提交规则见[入库模块宏观系统架构](../../01-全局背景信息/04-入库模块宏观系统架构.md)及 IN-FR-005、IN-FR-006。
- 上架数量不得超过已收未上架数量；提交后库存从收货暂存库位移到目标库位。
- 一期良品不因「等待货主指令」而停留在暂存库位；货主争议通过不良判定、备注与回传体现。

#### RT-FR-007 退货完成与结果

- 退货单状态：待收货、收货中、上架中、已完成、已取消。完成条件：累计实收＞0，所有明细收货完结，且已上架＝实收（良品、不良品各自上架完成）。
- 整单完成时向 OMS Mock 回传一次，分项列出最终短少、拒收（退货异常）、良品／不良品实收与上架结果；收货、上架过程不回传进度。
- 零实收且确定不再接收时，保留到件与拒收事实，受理上游取消预报后转已取消，不生成库存。
- 实收误记、货主认错一期无更正路径，与入库一致。

#### RT-FR-008 取消与变更

- 尚未产生实收时可接受 OMS Mock 对退货预报的明细变更或取消；产生实收后拒绝明细变更。
- 尚未产生实收时可受理取消；已收货物不可通过取消删除事实，须按实收继续上架或线下协调。

#### RT-FR-009 多货主与仓库权限

退货单、退货收货与上架记录均带货主维度；用户只能访问授权仓库，动作权限见[公共能力需求分析](../07-公共能力/公共能力需求分析.md)。

#### RT-FR-010 库存影响

- 收货确认按实收、按品质增加本仓**收货暂存库位**库存；上架单提交后移到存储或不良隔离库位。口径与[库存与库内需求分析](../04-库存与库内业务/库存与库内业务需求分析.md)一致。
- 退回形成的正常品库存参与后续出库预占，不单独设立「退货库存」类型。

#### RT-FR-011 SN 核对

- 商品配置要求 SN 时，退货实收须采集 SN。
- **派送失败退回：**实收 SN 须与原出库单复核记录（或实发 SN）一致才允许计入实收；不一致只能拒收，记录扫描SN、核对依据与拒收原因，不计实收、不生成上架单、不增库存，不能改记为不良品实收。
- **客户退货、平台仓退件：**若预报或关联原销售单能定位到原 B2C 出库且系统存有 SN，须扫描核对，不一致按上款处理；若无法关联原出库，仍须采集 SN 入账，系统提示「无可对核原单」，不阻断收货。

#### RT-FR-012 PDA 退货作业

- PDA 支持派送失败扫原运单建单、按单退货收货、追溯采集、扫容器上架及库位校验；与管理端共用记录，重复提交不重复增库存。

## 三、调研诉求处理

依据[退货业务需求调研](退货业务需求调研.md)第五节，处理结论如下。具体规则见**第二节**。

| 诉求 | 处理结论 |
| --- | --- |
| 三类来源（除 FBA 退货） | 纳入一期，由退货单贯穿识别、收货、上架与回传 |
| 派送失败现场建单 | 纳入一期，结果回传 OMS Mock |
| 预报驱动客户／平台仓退件 | 纳入一期；无预报不代货主虚构，催补或无主货 |
| 良品直接上架 | 纳入一期；不等货主二次指令 |
| SN 防调包 | 纳入一期，强度按 RT-FR-011 分来源 |
| 认领公海、视频、计费、FBA 全流程 | 不纳入一期 |
| 变更取消与结果交接 | 纳入一期，与系统集成协作 |

## 五、应用设计待输入

- 退货单、退货收货记录、退货异常字段与状态枚举；与入库收货记录的异同（单头来源、关联原出库／预报）。
- 退货预报与结案回传消息形态（见系统集成应用设计）。
- 派送失败「可退数量」与原出库行、包裹复核的映射规则。
- 重复运单、一单多包裹退回的演示样例。
- PDA 菜单：退货收货与上架是否独立入口或与入库合并展示。

**走查与示例（规则已确认，演示待执行）**

- **派送失败：**原出库实发 1 件 SN=S1，退回扫原运单建单，扫 SN=S1 计良品实收 1，上架后可再被 B2C 预占。
- **SN不一致：**原出库实发1件SN=S1，退回扫描S2，记拒收1、实收0、良品0、不良品0，不生成上架单与库存；保留拒收记录，零实收单按取消规则收口。可对核原出库的客户退货、平台仓退件同样处理。
- **客户退货：**预报退货运单 T-NEW、SKU 1 件无原单链，扫 SN 采集入账并提示无可对核；预报含原单且链到 S1 时，扫 SN 须为 S1。
- **无预报：**仅知货主催补预报；完全未知货主登记无主货，无退货单。
