# 出库业务需求调研

> 本文整理课程沙盘的目标业务场景与诉求。系统需求见[出库业务需求分析](出库业务需求分析.md)。

## 一、业务背景与参与方

未来自营四仓需要承接B2C包裹履约、平台仓备货转运、当地B2B批发和调拨出库。同一仓库的商品可能被多类业务同时需要，仓库既要按指令准确发货，也要保留库存占用、实物位置与交接结果。立项时第三方海外仓的具体作业方式未说明。

业务端提供发货、变更和取消指令，仓库执行拣货、复核及出仓交接，承运商、司机或自提客户接收货物。本模块研究仓内执行，也涵盖已收货物退回仓外和不良品其他出库；仓外运输、客户退货入库及渠道经营不在本模块范围。

## 二、主要业务场景与诉求

| 业务场景 | 约束或风险 | 业务诉求 |
| --- | --- | --- |
| B2C包裹按订单履约 | 需要核对商品、数量及包裹，防止错发 | 拣货和复核可执行、可记录，发出结果对应原指令 |
| 平台仓转运、B2B及调拨批量出仓 | 可能按件、箱或托组织交接，与包裹作业不同 | 记录容器内商品数量及交接结果，分别保留每张业务单据 |
| 多张单据同时需要同一SKU | 账面总量不能直接代表当前还可分配的数量 | 明确库存占用，避免重复安排同一批货；不跨仓借用可用量 |
| 建议位置无货或现场短拣 | 可能是局部位置差异，也可能整个仓库不足 | 能记录差异、重新找位，并按业务类型处理缺货，不能静默改量 |
| 多张B2C单据集中拣货 | 集中作业后仍需按单复核和交接 | 可按组组织拣货和查看进度，业务结果仍按单保留；B2B保持按单作业 |
| 已拣货后收到取消 | 商品可能仍在打包或暂存位置 | 核对实物回库后再恢复可用，原取消与回库记录可追溯 |
| 仓库确认出库与承运商揽收时间不同 | 两个事件混用会使仓库结果与库存口径不清 | 明确仓库完成点，另行记录已知交接信息 |
| 已收货物需要退回 | 入库事实已发生，退回需要新的业务依据 | 原入库记录保留，退回数量与出仓结果有独立记录 |
| 不良品按通知移出仓库 | 普通销售不可用不等于不能合法处置 | 上游通知与线下邮件依据均可追查，处置实物与数量可核对，品质与去向记录清楚 |
| 不同仓库和渠道有履约时限 | 仓库时区、起算事件和渠道时长可能不同 | 能查清起算事件、截止时间及超时原因；切换展示时区不改变履约判断 |

## 三、需要补充的资料

- 各出库类型的指令、拣货和交接样例，用于细化所需信息与作业差异；样例注明真实资料或课程模拟。
- 各渠道时效与超时原因样例，用于后续评估渠道差异；一期统一时长与起算规则见分析稿。
- 不良品其他出库的通知、核对及交接样例，用于落实处置依据与结果记录。
