# 出库业务需求调研

> 文档状态：调研初稿（案头整理，课程沙盘）
> 调研范围：B2C出库、FBA转运出库、批发出库、调拨出库、采购退货出库及其他出库的接单、占用、拣货、复核、确认出库与结果交接；货从仓外退回本仓见[退货业务需求调研](../05-退货业务/退货业务需求调研.md)
> 系统需求与已确认规则见[出库业务需求分析](出库业务需求分析.md)

## 一、调研范围与资料来源

本次调研要弄清楚：3PL 转自营后，出库指令如何对应实物、占用与实发如何分阶段留痕、异常如何交回上游，以及一期演示覆盖哪些类型。**六类出库范围**以[项目定位与范围](../../01-全局背景信息/01-项目定位与范围.md#22-仓内业务与上游协作)为准，调研重点如下。

| 环节 | 本次关注内容 | 主要交接 |
| --- | --- | --- |
| 指令与预占 | 出库单生成、资料校验；按类型区分能否部分预占 | 上游推送指令；仓库返回接收或拒收原因 |
| 拣货与分配 | 建议库位、批次／效期／SN 扫描；库位无货换位、整仓缺货 | 仓库记录；与库存占用、库位锁定衔接 |
| 作业组织 | B2C 可按单或基础波次汇总拣货；非B2C类型按单作业 | 波次进度可汇总查看，业务结果仍按单保留 |
| 复核与容器 | 包裹 SKU／数量复核；平台／B2B／调拨可记箱／托及内装 SKU 量 | 一期不建设箱库存或托盘库存 |
| 确认出库与交接 | 仓库确认出库为完成点；承运商 Mock、自提等交接信息另行登记 | 不以承运商揽收为前提扣库 |
| 缺货与恢复 | 接单不足、现场短拣、补货后人工恢复 | 不静默改需求量或实发量 |
| 取消与变更 | 未拣可变更或取消；已拣须返库上架核对后释放占用 | 已出库事实不可回写取消 |
| 退回与其他出库 | 已收正常品独立退回；不良品按通知或邮件依据处置 | 采购退货出库属本模块；买家退回本仓由退货模块承接；报损／销毁不在一期 |
| 结果回传 | 需求、实发、未发、短拣及交接结果 | 上游指令沿原来源回传，手工其他出库保留查询结果 |

**不在本模块调研范围：**货从仓外退回本仓的收货与上架（见退货业务调研）；仓外运输、运单跟踪与渠道订单经营；跨仓调拨主单、在途账与两端差异对账；人员派工、自动波次与产能调度；真实承运商面单、打印机与电子秤接入。

主要依据：

- [公司背景与业务概况](../../01-全局背景信息/00-公司背景与业务概况.md)、[项目定位与范围](../../01-全局背景信息/01-项目定位与范围.md)、[阶段规划与一期交付标准](../../01-全局背景信息/03-阶段规划与一期交付标准.md)
- [需求调研总览](../00-项目总览/01-需求调研总览.md)、[基础资料需求调研](../01-基础资料/基础资料需求调研.md)（货主、商品、物流渠道先于或并行出库作业）、[库存与库内业务需求调研](../04-库存与库内业务/库存与库内业务需求调研.md)（可用量、占用、盘点与流水）

## 二、现有交接与目标作业分工

### 2.1 立项时的出库交接

第三方海外仓负责其承接订单的拣货、打包及出仓交接，强盛业务侧提供履约要求并获取结果。现有材料尚未说明服务商返回的预占、拣货、实发与未发记录有多细，需通过出库样单和结果样表核实。

本次关注这些记录怎样对应原业务要求，以及缺货、短拣、取消等异常怎样交接。目标流程依据项目范围设计，不将尚未核实的记录缺口写成现状问题。

### 2.2 租仓自营后的作业分工

| 参与方 | 业务职责 | 需要补充的资料 |
| --- | --- | --- |
| 自营业务侧、外部货主业务侧 | 提供出库要求、合法变更与取消指令，接收实发及未发结果 | 指令、缺量及取消交接样例；外部货主一期使用模拟资料 |
| 仓储物流 | 组织拣货、复核、返库上架与确认出库，记录实际交接 | 各仓岗位分工、PDA操作步骤、包裹与箱托大货样例 |
| 承运商、司机或自提方 | 接收出仓实物，提供交接信息 | 承运商Mock、司机或自提凭证样例 |
| 数字化／项目组 | 建设WMS、OMS Mock及承运商Mock | 资料引用、指令接收和结果展示样例 |

一期OMS Mock提供五类普通出库指令及其他出库通知；其他出库也可由仓库依据线下邮件手工创建。WMS按类型校验和占用库存，管理端与PDA记录现场执行，上游指令的结果返回Mock，手工其他出库保留可查询结果。

基础资料提供货主、商品、位置与物流渠道，库存模块提供可用量、盘点限制和数量变化记录。平台仓（如FBA）是出库目的地，不属于强盛四仓。

## 三、核心场景与业务问题

以下场景依据目标业务整理，保留已确认方向与待补样例的区别；其中的风险不代表现场已发生的问题。

| 场景 | 业务条件 | 需要解决的问题 | 当前确认情况 |
| --- | --- | --- | --- |
| 多类型出库并存 | 四仓需同时支撑包裹、平台备货、B2B、调拨、退回及不良品处置 | 实物可按件、箱或托组织，各类型需要对应的复核和确认要求 | 类型范围见项目定位；各类型字段与交接样例待补 |
| 指令与资料匹配 | 出库指令带货主、仓库、SKU 与数量 | 资料缺失时返回拒收原因，并清除本次请求的占用 | 准入规则已确认，系统集成传递接收或拒收结果；推送样例待补 |
| 可用量与接单差异 | B2C 须按单足量；B2B／平台仓可先占现有；多笔出库可能争用同一 SKU | 须区分总量、占用与可分配量；不能跨仓借量；B2C 与批发／平台接单规则不同 | 方向已确认；分类型数字案例待沙盘 |
| 拣货与建议库位 | 系统推荐库位、批次，现场可能无货或扫错 | 区分换位继续拣货与整仓缺货，保留短拣及后续处理结果 | 已确认原则；PDA 操作样例待补 |
| B2C 汇总拣货 | 多单可集中拣货以提高效率 | 集中作业后仍须按单复核与确认，每张单的异常分别处理 | 基础波次已纳入一期；分拣页面细节见应用设计 |
| 复核与打包 | 包裹类需 SKU／批次／SN 与数量一致 | 复核差异应阻断确认出库；重量等一期可用模拟数据 | 已确认：六类出库都要复核，可随分拣或打包装箱完成；复核失败案例待演示包 |
| 确认出库与揽收 | 仓库交承运、司机或自提与承运商揽收往往不同步 | 完成点与库存扣减须以仓库确认为准，交接信息单独可查 | 已确认；交接字段样例待补 |
| 缺货、短拣与补货 | 接单后库存可能变化，现场可能少拣 | 需求、预占、实发、未发须分别保留；补货后须人工恢复而非自动占满 | 恢复操作走查待执行 |
| 已拣后取消 | 商品可能在打包区或暂存位 | 取消与返库上架记录可追溯，已拣实物不能凭账面直接恢复可用 | 已确认：受理即释放占用，已拣实物在出库暂存库位，退拣经返库上架单回到库位后才可再用；已拣后丢失按应返库数量提交再盘点调整 |
| 盘点与出库冲突 | 盘点与收发作业可能影响同一批库存 | 盘点中 SKU 的出库单可以接单预占，作业等盘点完成 | 盘点规则见库存需求分析；联合案例待补 |
| 调拨出库 | 本仓按调出指令出库，调入由另一仓入库指令处理 | 保留本仓足量执行结果，跨仓计划与对账由上游负责 | 已确认 |
| 采购退货出库 | 针对已收入库并形成库存的正常品 | 须独立指令引用原入库，不能冲销原收货事实；与消费者退货入仓不是同一条路 | 方向已确认；引用原单的样例待补 |
| 其他出库 | 销售不可用的实物仍可能合法移出 | 上游通知或线下邮件须可追溯，指定实物与数量可核对 | 一期纳入；邮件手工建单样例待补 |
| 进度与结果交接 | 业务端需知接收、拣货、出库及未发结果 | 回传须能对回原指令与明细；重复消息不能重复扣库 | 上游指令回传Mock，手工其他出库保留查询结果；字段待应用设计细化 |

## 四、业务诉求

| 场景 | 业务诉求 |
| --- | --- |
| 多类型出库与指令匹配 | 按业务类型接收要求，资料不全或暂不能执行时说明原因 |
| 可用量与接单差异 | 多单同时发货时，分清库存已被哪张单占用，以及还有多少可以安排 |
| 拣货、波次与复核 | 按位置找到正确商品，集中拣货后仍能核对每张单的数量和归属 |
| 确认出库与结果交接 | 查清实际发出、未发数量及交接对象，使业务侧能继续处理差异 |
| 缺货、短拣与恢复 | 保留原需求和现场差异，补货后能继续处理缺货单 |
| 取消与返库上架 | 实物返库上架和占用释放相互对应，其他订单的占用不受影响 |
| 盘点与出库 | 清楚提示哪些单据或动作需等待，避免盘点与发货同时改变同一批库存 |
| 调拨、退回与不良品处置 | 保留来源、指定实物和处理依据，分别追溯本次出库与原业务 |

各项诉求的范围取舍与功能规则见[出库业务需求分析](出库业务需求分析.md)。

## 五、待补资料与确认清单

| 资料主题 | 样例内容与待细化事项 | 用途 |
| --- | --- | --- |
| 现场作业 | 包裹PDA拣货、复核步骤及箱托大货核对样例 | 验证不同出库类型的现场操作与记录 |
| 指令与回传 | OMS Mock指令、拒收原因、取消结论和整单出库结果 | 核对原指令与实发、未发、差异能否对应 |
| 类型差异 | 六类出库的数字案例，包含足量、缺量与零实发 | 验证接单预占与确认出库采用各自的数量条件 |
| 波次与分单 | 汇总拣货、分单复核、一单异常的完整案例 | 核对集中作业后每张单的结果 |
| 缺货与恢复 | 已接单缺货、补货、人工重新分配；不按角色限制 | 验证缺口补足、占用及继续作业的结果 |
| 取消与返库上架 | 部分已拣、部分未拣的取消，以及已拣后少件、残损的退拣与返库上架记录 | 核对取消释放，保留实物位置和返库上架依据 |
| 退回与其他出库 | 原入库引用、不良品邮件依据及指定实物足量处置案例 | 区分正常品退回与不良品移出，并检查单据来源 |
| 交接与承运 | 承运商Mock、司机或自提方的交接字段和凭证 | 验证确认出库及交接信息的展示 |
| 渠道与时效 | 各渠道起算事件和超时原因样例 | 供后续评估渠道差异；一期仍使用公共能力统一参数 |

建议优先补齐**至少一条 B2C 完整链（指令→预占→拣货→复核→确认出库→回传）**、**一条 B2B 或平台仓含箱托记录的案例**，以及**一条已拣取消返库上架或已接单缺货恢复案例**。走查组织见[关键走查场景](../../04-业务分析和设计/06-海外仓典型业务场景与方案.md#84-关键走查场景)。竞品仅作参考，见[竞品原文入口](../../02-竞品调研和分析/00-双边能力对比矩阵.md#四资料入口与证据边界)；换标、自动分波、打印即发货等规则不自动纳入本项目。
