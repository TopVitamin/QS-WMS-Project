# 基础资料需求分析

> 本文维护基础资料模块的一期范围与功能规则。业务场景见[基础资料需求调研](基础资料需求调研.md)。

## 一、分析结论与模块边界

基础资料为香港、美西、美东、德国四仓提供货主、商品、仓库、库区、库位、物流承运商和物流渠道七类对象，供入库、出库和库存引用。物流资料分物流承运商与物流渠道两层维护，出库引用渠道、交接可展示所属物流承运商。商品按货主独立建档，自营与外部品牌使用同一套能力。

货主与商品身份由上游提供，仓内资料和作业配置由WMS维护，具体接收与更新规则见第二节。

本模块不维护供应商、客户档案、采购价、销售价及供货关系，也不建立箱库存或托盘库存资料。一期不做库位容量、体积、承重与占用率管理，不提供批量文件导入、不验证真实跨系统资料同步协议；货主自助维护由二期OMS承接。

## 二、功能需求

| 编号 | 功能 | 需求结论 |
| --- | --- | --- |
| MD-FR-001 | 货主资料 | 接收货主资料，预置自营货主并保留上游标识 |
| MD-FR-002 | 商品资料 | 按货主建档，配置形态、SN、批次和效期 |
| MD-FR-003 | 仓库资料 | 预置四仓及其时区，一期无业务侧新增入口 |
| MD-FR-004 | 库区与库位资料 | 维护库区库位及类型，存储、拣货、不良隔离等目标库位同一时点不混放不同货主实物，收货暂存与出库暂存库位允许多货主混放 |
| MD-FR-005 | 形态适配 | 按商品形态推荐适配位置，不做容量硬性阻断 |
| MD-FR-006 | 停用校验 | 有实物或未完结业务时拒绝停用，历史记录保留 |
| MD-FR-007 | 变更留痕 | 保留变更与历史快照，追溯开关受库存及作业限制 |
| MD-FR-008 | 数据权限 | 按仓库授权访问，维护须有动作权限 |
| MD-FR-009 | 维护与同步方式 | 上游推送身份资料，WMS维护自有资料及仓内属性 |
| MD-FR-010 | 物流承运商与物流渠道资料 | 物流承运商、物流渠道分层维护最小档案，供出库引用与模拟交接 |
| MD-FR-011 | 分节点准入 | 接收指令校验仓库、货主、商品，具体作业再验库位 |

#### MD-FR-001 货主资料

- 身份字段：货主编码、货主名称、货主类型（自营／外部）、使用状态（启用／停用）。
- 上游对接：保留上游货主标识，与货主编码并存，用于 OMS Mock 匹配与回传；可变更字段范围见[维护与同步方式](#md-fr-009-维护与同步方式)。
- 联系与地址：联系人姓名、电话、邮箱及结构化联系地址（国家或地区、省或州、城市、区或县、街道、补充行、邮编）；用于通知与演示，不作为出库收件地址。
- 自营货主系统预置，不可删除；外部货主由 OMS Mock 推送，WMS 接收并保留上游标识。
- 已停用货主不得作为新业务指令的货主引用；停用条件见[停用校验](#md-fr-006-停用校验)。
- 字段清单见应用设计[货主（初稿）](../../05-应用设计方案/20261002-MVP版本/字段清单合集/01-基础资料/货主/货主（初稿）.tsv)。

#### MD-FR-002 商品资料

- 每个货主独立建商品档案，包含商品编码、名称（含可选英文名称）、规格、计量单位、商品条码、使用状态，以及商品形态、是否带电、SN／批次／效期开关与效期阈值。同货主商品编码唯一，不同货主可使用相同编码，档案不共用。商品条码在系统内唯一，重复不能保存。
- **匹配键：**业务匹配使用「货主编码 + 商品编码」，与上游推送身份一致；更新与冲突处理见[维护与同步方式](#md-fr-009-维护与同步方式)。
- **效期配置：**效期商品维护保质期、允许入库天数、临期天数、过期天数；须满足允许入库天数≥临期天数≥过期天数（可相等），否则拒绝保存。剩余保质期按有效期与所属仓库当地业务日期计算（见公共能力时间规则）。具体阈值按商品样例，不默认过期天数为0。
- **效期执行：**收货是否准入、在库临期／过期等级及出库是否可用，分别由[入库业务](../02-入库业务/入库业务需求分析.md)和[库存与库内业务](../04-库存与库内业务/库存与库内业务需求分析.md)执行；本模块维护配置与保存校验。
- **追溯：**启用SN的商品按SN管理库存；启用批次／效期的商品在作业中采集批次、生产日期和有效期。一期不设质检配置，良品、不良品在收货时录入。
- **带电：**一期在资料中表达，不单独触发仓内校验规则。
- 尺重：毛重、净重及长宽高；上游可推送部分尺重，WMS 可经入库新品维护或管理端补充仓内规格，不得改写上游身份字段。
- 已停用商品不得作为新业务指令的SKU引用；停用条件见[停用校验](#md-fr-006-停用校验)。
- 不维护采购价、销售价、包装层次主数据及独立批次属性字典；批次／效期采集字段在作业单落实。
- 字段清单见应用设计[商品（初稿）](../../05-应用设计方案/20261002-MVP版本/字段清单合集/01-基础资料/商品/商品（初稿）.tsv)。

#### MD-FR-003 仓库资料

- 预置香港、美西、美东、德国四仓；含仓库编码、名称、简称、排序、使用状态及仓库备注。
- 结构化地址与联系人：国家或地区、省或州、城市、区或县、街道详细地址、地址补充行、邮编；联系人及备用联系人姓名、电话、邮箱；系统可拼接只读完整地址展示。
- 业务时区（IANA）用于所属仓库当地业务日期判断；建议预置后一期不可修改。
- 各仓可配置**默认入库收货方式**（按作业容器收货，或按SKU收货且不绑容器）；现场PDA收货可在该默认值基础上按次改选。规则与混用边界见[入库业务需求分析](../02-入库业务/入库业务需求分析.md)作业容器条；选项展示见应用设计。
- 时间存储、展示和导出口径见公共能力需求分析中的语言与时间规则。
- 每仓分别指定收货暂存、出库暂存库位，均属本仓启用的暂存类库区且不能相同。暂存正常品计入可用，可被接单预占，但不能参与库位分配；上架或返库上架后才能分配拣货。
- 一期不提供业务侧新增仓库。
- 字段清单见应用设计[仓库（初稿）](../../05-应用设计方案/20261002-MVP版本/字段清单合集/01-基础资料/仓库/仓库（初稿）.tsv)。

#### MD-FR-004 库区与库位资料

- 库区：所属仓库、库区编码、库区名称、库区类型、排序号、使用状态及备注。库区编码在同一仓库内唯一。
- 库位：所属库区（据此确定仓库）、库位编码、库位名称、使用状态、备注；可选维护上架拣货顺序号及排／层／列辅助编码、适配商品形态；展示当前货主占用（系统计算，只读）。库位编码在同一仓库内唯一；跨仓可出现相同库位编码文本，以仓库与库位共同定位。
- 一期不做库位容量、体积、承重与混放批次开关；存储、拣货、不良隔离等目标库位同一时点不混放不同货主实物，收货暂存与出库暂存库位允许多货主混放，同货主可多 SKU。
- 字段清单见应用设计[库区（初稿）](../../05-应用设计方案/20261002-MVP版本/字段清单合集/01-基础资料/库区/库区（初稿）.tsv)、[库位（初稿）](../../05-应用设计方案/20261002-MVP版本/字段清单合集/01-基础资料/货位/货位（初稿）.tsv)。
- 库区类型一期为存储、拣货、暂存、不良隔离、异常处理；无主货暂存、超收暂存等位置的使用场景见[入库业务需求分析](../02-入库业务/入库业务需求分析.md)。
- 存储、拣货、不良隔离等目标库位同一时点只存一个货主，可存该货主多个SKU；收货暂存、出库暂存库位允许多货主混放；已有该货主实物（含已确认出库待交接实物）、入库过程数量或未完结任务占用时，其他货主不得使用该库位。
- 库区停用不自动批量停用下属库位；申请库区停用时，若下属任一库位存在上述占用则拒绝。库区合法停用后不得新建下属库位，且不得把新的首次落位或推荐默认指向该库区下仍启用的库位。已有实物或任务的库位、库区不得通过改资料变更所属仓库或库区归属，须先移库或收口后停用旧位。业务展开见[基础资料业务设计](../../04-业务分析和设计/01-基础资料业务设计.md)第五节与第七节。

#### MD-FR-005 形态适配

大件、异形商品按形态限定推荐库区／库位类型，上架推荐避开不适配库位；人工可改位，不做容量类硬性阻断。

#### MD-FR-006 停用校验

- 商品、货主、库位停用前校验当前实际库存、已确认出库待交接实物、入库过程数量和未完结业务（订单占用、拣货分配、盘点等）；存在实物或未完结业务时拒绝停用，并提示对应数量或单据。
- 仅有历史流水且当前实物和任务均已清零时，可停用，历史记录保留。
- 不提供物理删除入口；已被业务引用的资料只能停用，历史单据与流水保持可追溯。

#### MD-FR-007 变更留痕

- 商品名称、形态、SN方式等关键字段变更保留记录；业务单据引用资料快照，资料变更不回溯改写历史单据。
- SN、批次、效期管理开关在该货主商品任一仓库有实际库存时禁止切换，包含收货暂存、出库暂存、正常品、不良品以及已拣未出库数量，须先清空库存。
- 实际库存为0但入库单已开始作业时也禁止切换（含已收货未上架）；禁止原因应能定位到数量或正在作业的单据。
- 仅有已推送、尚未开始作业且无库存的预报单，不因此阻断开关切换。
- 各仓库存清零且无正在作业的入库单后才可切换；历史单据、批次和SN轨迹保留。

#### MD-FR-008 数据权限

资料访问受仓库授权范围约束，维护操作还须具备相应动作权限。有某仓访问权限即可查看该仓全部货主数据，一期不设置货主级用户授权；资料仍按货主分别记录。具体规则见[公共能力需求分析](../07-公共能力/公共能力需求分析.md)。

#### MD-FR-009 维护与同步方式

- 一期由 OMS Mock 推送货主、商品；WMS 保留上游标识并用于单据匹配。仓库、库区、库位、物流承运商、物流渠道由管理端维护或系统预置。
- WMS可补充商品仓内执行属性（含经入库新品维护写入的仓内规格：长宽高、毛重等），不得静默改写上游身份（货主编码、货主内商品编码等）。
- 同一身份再次推送时按集成约定更新可变更字段；身份冲突或无法匹配时拒收并记录原因，不另建一套商品身份，消息处理见[系统集成与对接需求分析](../06-系统集成与对接/系统集成与对接需求分析.md)。

#### MD-FR-010 物流承运商与物流渠道资料

**物流承运商**

- 物流承运商编码、名称、简称、使用状态、备注；可选联系人及外部物流承运商代码（对接占位）。
- 物流承运商停用前须先处理其下仍启用的物流渠道，或校验不存在未完结出库／交接引用。停用成功后，其下渠道即使自身仍启用，也不得用于新出库接单或新增交接引用；不强制级联修改渠道状态，历史记录保留。恢复物流承运商后仍校验渠道自身启用状态。

**物流渠道**

- 所属物流承运商、渠道编码、名称、渠道类型、使用状态、备注；物流对接方式（系统 API 对接预留／线下交接）及外部服务产品代码（打单 API 占位）。渠道类型仅作分类筛选。
- 出库单引用渠道；交接登记在出库交接由作业选择交接方式，不在渠道上预置默认。四仓共用一套渠道档案，一期不建设物流产品层，渠道不按仓库或货主单独绑定。一期不接真实承运商生产打单服务。
- 渠道停用关闭后续引用；存在未完结出库或交接仍引用该渠道时拒绝停用，历史保留渠道快照。业务展开见[基础资料业务设计](../../04-业务分析和设计/01-基础资料业务设计.md)第七节。

字段清单见应用设计[物流承运商（初稿）](../../05-应用设计方案/20261002-MVP版本/字段清单合集/01-基础资料/物流承运商/物流承运商（初稿）.tsv)、[物流承运商（详细稿）](../../05-应用设计方案/20261002-MVP版本/字段清单合集/01-基础资料/物流承运商/物流承运商（详细稿）.tsv)、[物流渠道（初稿）](../../05-应用设计方案/20261002-MVP版本/字段清单合集/01-基础资料/物流渠道/物流渠道（初稿）.tsv)、[物流渠道（详细稿）](../../05-应用设计方案/20261002-MVP版本/字段清单合集/01-基础资料/物流渠道/物流渠道（详细稿）.tsv)。

#### MD-FR-011 分节点准入

- 业务指令进入WMS时校验仓库、货主、商品存在且为启用状态；入库上架时再校验目标库位及货主占用，出库拣货时再校验来源库位与货主。
- 资料缺失、已停用或库位已被其他货主占用时，按节点记录拒收或作业异常；不因入库预报尚未指定库位而拒绝接收有效指令。

## 三、调研诉求处理

调研诉求均纳入一期，具体规则见第二节，分工如下。

| 诉求 | 处理结论 |
| --- | --- |
| 多货主建档、位置管理、资料变更 | 由本模块处理归属、维护和变更校验 |
| 指令与资料匹配 | 本模块提供资料匹配与准入规则，系统集成负责消息拒收和原因反馈 |
| 商品属性与作业 | 本模块维护配置，入库、出库和库存业务按配置执行 |
| 物流承运商与物流渠道 | 本模块分层维护档案，出库业务负责引用渠道与交接登记 |
| 四仓共用框架 | 本模块提供各仓资料，演示覆盖按一期交付标准安排 |

## 五、应用设计待输入

业务样例见[调研稿第五节](基础资料需求调研.md#五待补资料)。各对象字段初稿已落在[字段清单合集／01-基础资料](../../05-应用设计方案/20261002-MVP版本/字段清单合集/01-基础资料/)；各对象已有详细稿和页面套件；本轮仓库暂存配置、单位及默认收货方式字段已同步，其他对象仍需对照实现验证；各仓默认收货方式预置值待补，并与系统集成对齐 OMS Mock 字段及更新、冲突案例。
