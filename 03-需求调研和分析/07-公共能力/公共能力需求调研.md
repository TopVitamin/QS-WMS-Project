## 一、调研范围与资料来源

本次调研要弄清楚：3PL 转自营后，**谁能在哪些仓库查看与操作、关键动作如何留痕、跨地区使用时语言与时间如何表达才不误导业务判断**，以及管理端与 PDA 如何共用同一批作业结果。香港、美西、美东、德国四仓共用同一套 WMS，**权限与时间规则不因仓别拆多套逻辑**。

| 环节 | 本次关注内容 | 主要衔接 |
| --- | --- | --- |
| 仓库数据范围 | 用户可进哪些仓、仓内可见哪些货主数据 | 与多货主同仓、单据货主字段一致 |
| 动作权限 | 菜单与具体操作能否执行 | RBAC 角色；关键确认与作业权限分开 |
| 语言 | 现场与管理端界面语言 | 中英文切换；标识符不本地化改写 |
| 时间三层 | 存储、业务判断、页面展示与导出 | 履约截止、效期与展示时区分开 |
| 操作记录 | 影响责任与库存的关键动作 | 可按模块、对象、人员查询 |
| 双端一致 | 管理端与 PDA 同一任务 | 同一记录；重复提交不重复动库存 |
| 演示边界 | 打印、称重与外部 Mock | PDA 为作业端；模拟范围明示 |

**不在本模块调研范围：**货主级数据权限与货主自助门户；复杂审批流与全量报表体系；中文、英文以外的语言；独立登录审计（登录时间、账号、来源端）；入出库、库存、集成消息等业务规则本身（见各业务模块调研）；承运商与 OMS 接口细节（见[系统集成与对接需求调研](../06-系统集成与对接/系统集成与对接需求调研.md)）。

## 二、当前角色与系统分工

### 2.1 立项时点的业务职责

| 角色 | 已知职责 | 仍需确认 |
| --- | --- | --- |
| 跨境与渠道业务 | 查看履约进度与出库结果 | 3PL 时期能否区分「谁操作的、何时截止」 |
| 第三方海外仓（3PL） | 代运营现场作业 | 强盛能否统一四仓人员权限与操作留痕口径 |
| 仓储物流（规划） | 租仓后组织四仓作业与现场管理 | 各仓岗位分工、PDA 使用习惯、关键确认谁签字 |
| 外部品牌货主（规划） | 关心自有货物执行结果 | 一期无货主登录 WMS；可见性待 OMS 二期 |
| 数字化／项目组 | 建设 WMS、账号与权限配置 | 演示账号、仓库授权与角色矩阵映射 |

自营阶段：**仓储人员**在授权仓库内按角色执行作业；**业务管理人员**通过 OMS Mock 等看结果，不直接经营 WMS 权限模型（一期）。**管理端与 PDA** 共用业务记录，不由两端各记一套库存。

### 2.2 当前系统与作业流转

立项前海外作业多在 3PL 系统内完成，强盛对「谁能改库存、关键差异谁确认」往往只有**汇总或口头交接**，难以在四仓统一追溯。

```mermaid
flowchart LR
    B[业务端] -->|要结果| P[3PL 海外仓]
    P -.->|汇总或部分明细| B
```

一期课程演示目标形态：

```mermaid
flowchart LR
    A[管理端] <-->|同一业务记录| W[强盛 WMS]
    D[PDA] <-->|同一业务记录| W
    W ---|按仓库授权| H[香港 / 美西 / 美东 / 德国]
```

| 载体 | 与本期公共能力的关系 | 已知问题或空白 |
| --- | --- | --- |
| 3PL | 立项前权限与留痕不透明 | 自营后需自建仓库范围与关键动作记录 |
| 管理端 | 查询、确认类动作入口 | 与 PDA 分工见各模块分析；双端一致规则待走查 |
| PDA | 现场扫描与确认 | 重复提交防护需与库存流水一致 |
| 用户与角色配置 | 仓库授权、RBAC | 演示账号与矩阵映射待补 |

## 三、核心场景与业务问题

| 场景 | 当前情况 | 主要问题 | 证据状态 |
| --- | --- | --- | --- |
| 多货主同仓 | 自营与外部品牌共四仓 | 须按仓授权查看，单据与库存仍分货主 | 方向已确认；不提供货主级数据权限 |
| 动作与数据可见分离 | 能看库存不等于能改库存 | 取消、差异确认、调整等须按角色控制 | 默认矩阵在应用设计；账号样例待补 |
| 关键确认集中 | 丢失、品质、盘点差异等影响责任 | 仓库主管持有关键确认，作业权限独立 | 岗位组合已确认；演示人员待配置 |
| 中英文界面 | 四地员工与管理端并用 | 一期须支持中英切换 | 方向已确认；界面走查样例待补 |
| 跨时区查看与导出 | 用户可能不在仓库当地 | 展示须可换算并标注；不改变履约与效期判断 | 三层时间方向已确认；导出样例待补 |
| 履约时间展示 | 出库有截止要求 | 起算、等待计入、超时后果须统一口径 | 48 小时为沙盘参数；见分析稿 |
| 管理端与 PDA 同一任务 | 现场与管理端都可能操作 | 不能形成两套结果或重复扣增库存 | 方向已确认；双端走查待执行 |
| 打印、称重演示 | 一期无真实硬件 | 易误以为已接入生产服务 | 模拟范围与集成模块分工见分析稿 |

## 四、原始业务诉求

与第三节场景对应，只保留业务侧说法；**不在此复述系统规则**（见分析稿第二节）。

| 场景（见第三节） | 业务诉求摘要 | 当前判断 |
| --- | --- | --- |
| 多货主同仓 | 授权仓内可见各货主数据，未授权仓不可见 | 一期核心 |
| 动作与数据可见分离 | 按职责执行，关键动作可追到人 | 一期核心 |
| 关键确认集中 | 重大确认与日常作业权限分开 | 一期核心；矩阵见应用设计 |
| 中英文界面 | 界面可切换语言 | 一期核心 |
| 跨时区与履约展示 | 时间看得懂，且不误导截止与效期 | 一期核心 |
| 双端一致 | 同一任务结果一致，重复提交不重复生效 | 一期核心 |
| 演示边界 | 模拟与真实作业端区分清楚 | 一期核心 |
| 货主自助、登录审计、多语言扩展 | 业务侧潜在诉求 | 不纳入一期 |

上表对应的系统规则写在[公共能力需求分析](公共能力需求分析.md)。履约与缺货处理衔接见[出库业务需求分析](../03-出库业务/出库业务需求分析.md)；效期与商品配置见[基础资料需求分析](../01-基础资料/基础资料需求分析.md)；外部 Mock 范围见[系统集成与对接需求分析](../06-系统集成与对接/系统集成与对接需求分析.md)。
