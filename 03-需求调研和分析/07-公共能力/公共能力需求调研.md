# 公共能力需求调研

> 本文整理课程沙盘的目标业务场景与诉求。系统需求见[公共能力需求分析](公共能力需求分析.md)。

## 一、业务背景与参与方

未来四仓共用WMS，仓库人员需要在职责范围内执行作业，业务和管理人员需要查看执行结果。不同地区使用语言与时区不同，管理端和PDA还需要共同记录同一批实物的作业结果。

本模块只研究跨模块必须统一的数据访问、操作授权、语言时间和操作记录。仓库物流团队、业务管理人员与数字化团队是背景中已列明的参与方；具体角色及动作权限清单需结合组织样例补充。

## 二、主要业务场景与诉求

| 业务场景 | 约束或风险 | 业务诉求 |
| --- | --- | --- |
| 一个仓库同时服务多个货主 | 仓库人员需要处理本仓业务，记录仍要区分实物归属 | 按授权仓库查看和操作，本仓各货主数据可见但分别记录，不能访问未授权仓库 |
| 不同人员执行取消、差异确认或库存调整 | 数据可见不等于拥有全部操作权限 | 操作按职责授权，影响库存和责任的动作能追到执行人员 |
| 不同地区使用同一系统 | 使用语言可能不同 | 一期范围包含中英文界面 |
| 跨时区查看作业记录和导出数据 | 无时区的时间容易误判先后或履约期限 | 时间表达清楚、可换算；展示方式不改变仓库业务的时限和效期判断 |
| 同一任务在管理端与PDA处理 | 两端重复提交可能形成两套结果或重复库存变化 | 共用同一业务记录，结果一致，重复提交不重复生效 |
| 演示使用打印、称重模拟数据 | 使用者可能误以为已接入真实硬件 | 明确模拟范围；PDA作为实际作业端与外部模拟区分 |

## 三、需要补充的资料

- 四仓演示账号与仓库授权样例（哪些角色可进哪些仓）。
- 默认 RBAC 角色矩阵是否与[应用权限配置第四节](../../05-应用设计方案/20261002-MVP版本/系统架构设计/05-全局机制与权限配置.md#四权限点与默认角色矩阵)一致，有无课程演示专用岗位命名。
- 中英文界面与导出样例（含时区标注）各一份，便于走查 COM-FR-002。
