# 公共能力需求分析

> 本稿说明一期范围与系统需求。
> 业务背景与场景见[公共能力需求调研](公共能力需求调研.md)。

## 一、分析结论与模块边界

公共能力统一维护演示仓库范围、动作可见性、关键操作记录，以及中文／英文与存储／业务／展示时间口径。管理端与 PDA 共用同一业务记录，不各自维护库存。一期 Demo 不做登录、角色或权限模型：所有满足业务状态条件的菜单和动作默认可见。

**职责范围**

- 顶栏当前仓库作为演示数据范围；不做用户仓库授权校验。
- 不按角色裁剪菜单与动作；动作是否可执行只由单据状态和业务规则决定。
- 中英文界面；业务时间 UTC 存储、仓库当地业务判断、用户所选展示时区及导出标注。
- 关键操作留痕的查询维度；管理端与 PDA 共用记录及重复提交不重复影响库存的原则。

**不在本模块**

- 入库、出库、库存、基础资料、系统集成各域的业务规则、状态与数量口径；本模块只提供演示仓库范围、时间展示与留痕等横切能力，业务动作是否允许由各域业务规则决定。
- 登录、账号、角色、权限、货主自助门户、复杂审批流、全量报表体系；中文、英文以外的语言版本。
- 独立登录审计（登录时间、账号、来源端）；登录与账号生命周期在账号体系／用户 PRD 设计时评估。
- OMS Mock、承运商 Mock、面单与物流轨迹的模拟边界表述以[系统集成与对接需求分析](../06-系统集成与对接/系统集成与对接需求分析.md)为准；本模块规定 PDA 为作业端、打印与称重使用模拟或手工数据且不误导为真实接入。

## 二、功能需求

| 编号 | 功能 | 需求结论 |
| --- | --- | --- |
| COM-FR-001 | 演示仓库范围与动作可见性 | 顶栏当前仓库作为演示范围；不做角色/权限裁剪，所有满足状态的动作默认可见 |
| COM-FR-002 | 语言、存储时间与业务时区 | 中英文可切换，时间统一存储，展示与业务判断分开 |
| COM-FR-003 | 操作记录 | 关键动作记录操作者、时间、原单及结果 |
| COM-FR-004 | 管理端与 PDA 一致 | 管理端与 PDA 共用记录，重复提交不重复影响库存 |

#### COM-FR-001 演示仓库范围与动作可见性

- 一期 Demo 不提供登录、账号、角色或权限配置，不校验用户仓库授权。
- 顶栏当前仓库作为演示数据范围；商品、库存和单据仍保留货主字段并按货主分别记录。
- 菜单和业务动作不按角色显隐或裁剪；只要单据状态、数量和业务规则允许，操作入口默认展示。
- 关键确认与常规作业不再区分岗位权限；操作者、时间与处理结果只进入操作记录，用于追溯。
- 发现账实不符的人员可直接对该 SKU 发起盘点，不等待审批；盘点差异确认与取消只受单据状态和业务规则约束。

#### COM-FR-002 语言、存储时间与业务时区

- 界面支持中文、英文切换，覆盖管理端与 PDA。
- 所有业务时间以 UTC+0 保存；用户通过页面右上角切换展示时区，列表、详情和操作记录按当前所选时区显示，导出文件也按发起导出时所选时区转换并标明时区。
- 履约截止时间自有效接收出库指令起算，按所属仓库当地业务时间加 48 小时计算；48 小时为课程一期设计参数，不是已核实的真实渠道承诺。接收后的缺货、盘点等待计入时长，拒收请求不开始计时。超时不自动取消、释放或强制缺量，由仓库组织者跟进、上游决定后续处理；缺货单补货后人工重新分配见[出库业务需求分析](../03-出库业务/出库业务需求分析.md#out-fr-009-缺货处理)。
- 商品剩余保质期按有效期与所属仓库当地业务日期计算；收货准入、临期及过期等级使用[基础资料需求分析](../01-基础资料/基础资料需求分析.md)商品效期配置，不使用 48 小时履约参数。
- 展示时区只转换页面和导出显示，不改变履约截止时间、收货效期准入或临期／过期判断。库位编码、SN 文本、批次号等标识符原样存储与展示，不做本地化改写。

#### COM-FR-003 操作记录

- 收货与拒收、无主货登记、出库取消、退拣与返库上架、缺货重新分配、其他出库手工创建与确认、盘点发起与差异确认、在库品质转换等关键动作保留操作者、时间、原单与处理结果。
- 关键动作记录可按业务模块、业务对象、操作者和时间查询。
- WMS 不记录调拨两端差异结案；业务动作的具体规则由对应模块维护。留痕范围与应用设计清单对齐，见[全局机制与操作留痕](../../05-应用设计方案/20261002-MVP版本/系统架构设计/05-全局机制与权限配置.md)。

#### COM-FR-004 管理端与 PDA 一致

- 同一任务在管理端和 PDA 的完成结果引用同一业务记录与库存流水；重复提交不得形成两次库存变化。
- PDA 是一期作业端，不作为外部模拟设备；打印机和电子秤使用模拟或手工数据。页面表达由应用设计细化。

## 三、调研诉求处理

依据[公共能力需求调研](公共能力需求调研.md)第三、四节，**调研所列纳入一期的场景由本模块落实**；规则见**第二节**。下列为跨模块或需单独指明的处理结论。

| 主题 | 处理结论 |
| --- | --- |
| 多货主同仓、仓库数据范围 | 本模块维护仓库访问范围；货主字段与单据归属由各业务模块维护 |
| 动作可见性与关键确认 | 不按角色裁剪；所有满足状态的动作默认可见，业务动作准入由各域规则决定 |
| 中英文界面 | 纳入一期，由本模块统一中英文切换要求 |
| 存储／业务／展示时间与履约展示 | 本模块统一时间口径；出库承接截止与超时后果，基础资料与库存承接效期判断 |
| 关键操作留痕 | 本模块维护留痕要求；具体动作清单与全局机制及权限配置对齐 |
| 管理端与 PDA 一致 | 本模块维护共用记录与重复提交原则；各业务域落实具体动作 |
| 打印、称重与外部 Mock 表述 | 模拟数据边界见系统集成分析；本模块区分 PDA 与外部模拟 |
| 货主门户、登录审计、扩展语言 | 不纳入一期 |

## 四、范围取舍与模块依赖

一期不包含项与[调研第一节「不在本模块调研范围」](公共能力需求调研.md#一调研范围与资料来源)及[项目定位「一期不做什么」](../../01-全局背景信息/01-项目定位与范围.md)一致，此处不重复罗列。

| 关联模块 | 衔接说明 |
| --- | --- |
| [基础资料](../01-基础资料/基础资料需求分析.md) | 资料维护按业务规则执行；效期配置按本模块规定的仓库当地业务日期判断 |
| [入库业务](../02-入库业务/入库业务需求分析.md) | 入库作业与 PDA 入库按单据状态和业务规则执行；关键确认见各模块规则 |
| [出库业务](../03-出库业务/出库业务需求分析.md) | 履约起算与超时展示采用本模块时间规则；出库确认与缺货重试按出库规则执行 |
| [库存与库内业务](../04-库存与库内业务/库存与库内业务需求分析.md) | 移库、盘点与品质确认按库存规则执行；库存模块维护流水，本模块维护双端一致原则 |
| [系统集成与对接](../06-系统集成与对接/系统集成与对接需求分析.md) | 外部服务模拟范围；WMS 内留痕与集成消息记录分工 |

操作记录的页面与字段由应用设计承接；一期不做用户与角色页面，当前边界见[全局机制与操作留痕](../../05-应用设计方案/20261002-MVP版本/系统架构设计/05-全局机制与权限配置.md)；未形成的PRD不作为现有依据。

## 五、应用设计待输入

以下在规则层仍依赖样例或界面设计细化，收集方向见[调研第五节](公共能力需求调研.md#五待补资料与确认清单)。

- 演示数据与顶栏仓库范围：覆盖四仓样例；不配置演示账号、角色或权限点映射。
- 操作记录查询条件、列表字段与详情：由应用设计补充，覆盖本稿规定的关键动作。
- 公共页面时区切换、Mock 标识、双端一致提示：由应用设计细化，不引用尚未形成的页面文档。
- 中英术语与字段清单对照：随字段清单合集与各模块 PRD 维护。
