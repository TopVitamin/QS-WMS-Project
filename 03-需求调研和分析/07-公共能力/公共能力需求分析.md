# 公共能力需求分析

> 本稿说明一期范围与系统需求。
> 业务背景与场景见[公共能力需求调研](公共能力需求调研.md)。

## 一、分析结论与模块边界

公共能力统一维护仓库数据范围、角色动作权限、关键操作记录，以及中文／英文与存储／业务／展示时间口径。管理端与 PDA 共用同一业务记录，不各自维护库存。数据访问按仓库授权，具体菜单与动作由 RBAC 角色控制。

**职责范围**

- 用户仓库授权范围；授权仓内可见全部货主资料、库存与单据（保留货主字段，不提供货主级数据权限）。
- 菜单、目录与业务动作的 RBAC；关键确认权限与常规作业权限的分工原则（默认矩阵在应用设计，不按岗位名称硬编码）。
- 中英文界面；业务时间 UTC 存储、仓库当地业务判断、用户所选展示时区及导出标注。
- 关键操作留痕的查询维度；管理端与 PDA 共用记录及重复提交不重复影响库存的原则。

**不在本模块**

- 入库、出库、库存、基础资料、系统集成各域的业务规则、状态与数量口径；本模块只提供授权、时间展示与留痕等横切能力，业务动作是否允许由各域规则与动作权限共同决定。
- 货主级用户数据授权、货主自助门户、复杂审批流、全量报表体系；中文、英文以外的语言版本。
- 独立登录审计（登录时间、账号、来源端）；登录与账号生命周期在账号体系／用户 PRD 设计时评估。
- OMS Mock、承运商 Mock、面单与物流轨迹的模拟边界表述以[系统集成与对接需求分析](../06-系统集成与对接/系统集成与对接需求分析.md)为准；本模块规定 PDA 为作业端、打印与称重使用模拟或手工数据且不误导为真实接入。

## 二、功能需求

| 编号 | 功能 | 需求结论 |
| --- | --- | --- |
| COM-FR-001 | 仓库数据范围与 RBAC 控制 | 授权仓库内可见全部货主，菜单和动作由角色权限控制 |
| COM-FR-002 | 语言、存储时间与业务时区 | 中英文可切换，时间统一存储，展示与业务判断分开 |
| COM-FR-003 | 操作记录 | 关键动作记录操作者、时间、原单及结果 |
| COM-FR-004 | 管理端与 PDA 一致 | 管理端与 PDA 共用记录，重复提交不重复影响库存 |

#### COM-FR-001 仓库数据范围与 RBAC 控制

- 一期给用户分配一个或多个仓库权限。
- 用户可以查看已授权仓库内全部货主的商品、库存和单据，不提供货主级数据权限；商品、库存和单据仍保留货主字段并按货主分别记录。
- 用户不能查看或操作未授权仓库。
- 无主货登记记录在 WMS 仅对所在仓库的授权用户可见；OMS 上线后面向所有 OMS 客户的信息展示属于外部协作，不改变 WMS 仓库授权。
- 已授权仓库内的菜单、目录和具体业务动作由 RBAC 角色权限控制：角色拥有相应权限时即可看见并执行，没有权限时不展示或不可执行；不按「管理员／仓库操作员」等名称硬编码动作范围。
- 已确认的岗位组合采用仓库主管集中持有关键确认权限，作业与常规收发确认独立配置；默认角色矩阵见[全局机制与权限配置第四节](../../05-应用设计方案/20261002-MVP版本/系统架构设计/05-全局机制与权限配置.md#四权限点与默认角色矩阵)。不增加审批层级。

#### COM-FR-002 语言、存储时间与业务时区

- 界面支持中文、英文切换，覆盖管理端与 PDA。
- 所有业务时间以 UTC+0 保存；用户通过页面右上角切换展示时区，列表、详情和操作记录按当前所选时区显示，导出文件也按发起导出时所选时区转换并标明时区。
- 履约截止时间自有效接收出库指令起算，按所属仓库当地业务时间加 48 小时计算；48 小时为课程一期设计参数，不是已核实的真实渠道承诺。接收后的缺货、盘点等待计入时长，拒收请求不开始计时。超时不自动取消、释放或强制缺量，由仓库组织者跟进、上游决定后续处理；缺货单补货后人工重试见[出库业务需求分析](../03-出库业务/出库业务需求分析.md#out-fr-009-缺货处理)。
- 商品剩余保质期按有效期与所属仓库当地业务日期计算；收货准入、临期及过期等级使用[基础资料需求分析](../01-基础资料/基础资料需求分析.md)商品效期配置，不使用 48 小时履约参数。
- 展示时区只转换页面和导出显示，不改变履约截止时间、收货效期准入或临期／过期判断。货位编码、SN 文本、批次号等标识符原样存储与展示，不做本地化改写。

#### COM-FR-003 操作记录

- 收货差异与损失处理、质检、无主货登记、出库取消、其他出库手工创建与确认、盘点调整、在库品质转换等关键动作保留操作者、时间、原单与处理结果。
- 关键动作记录可按业务模块、业务对象、操作者和时间查询。
- WMS 不记录调拨两端差异结案；权限控制与业务动作的具体规则由对应模块维护。留痕范围与应用设计清单对齐，见[全局机制与权限配置](../../05-应用设计方案/20261002-MVP版本/系统架构设计/05-全局机制与权限配置.md)。

#### COM-FR-004 管理端与 PDA 一致

- 同一任务在管理端和 PDA 的完成结果引用同一业务记录与库存流水；重复提交不得形成两次库存变化。
- PDA 是一期作业端，不作为外部模拟设备；打印机和电子秤使用模拟或手工数据。与[公共页面与交互约定](../../05-应用设计方案/20261002-MVP版本/需求文档PRD/02-公共页面与交互约定.md)一致。

## 三、调研诉求处理

依据[公共能力需求调研](公共能力需求调研.md)第三、四节，**调研所列纳入一期的场景由本模块落实**；规则见**第二节**。下列为跨模块或需单独指明的处理结论。

| 主题 | 处理结论 |
| --- | --- |
| 多货主同仓、仓库数据范围 | 本模块 COM-FR-001；货主字段与单据归属见各业务模块 |
| 动作权限与关键确认分工 | 本模块 COM-FR-001；默认矩阵在应用设计，业务动作准入见各域分析 |
| 中英文界面 | 本模块 COM-FR-002 |
| 存储／业务／展示时间与履约展示 | 本模块 COM-FR-002；出库截止与超时后果衔接出库分析；效期判断衔接基础资料与库存 |
| 关键操作留痕 | 本模块 COM-FR-003；具体动作清单与应用设计第五节对齐 |
| 管理端与 PDA 一致 | 本模块 COM-FR-004；各域 PDA 条目不重复双端规则 |
| 打印、称重与外部 Mock 表述 | 模拟数据边界见系统集成分析；本模块区分 PDA 与外部模拟 |
| 货主门户、登录审计、扩展语言 | 不纳入一期 |

## 四、范围取舍与模块依赖

一期不包含项与[调研第一节「不在本模块调研范围」](公共能力需求调研.md#一调研范围与资料来源)及[项目定位「一期不做什么」](../../01-全局背景信息/01-项目定位与范围.md)一致，此处不重复罗列。

| 关联模块 | 衔接说明 |
| --- | --- |
| [基础资料](../01-基础资料/基础资料需求分析.md) | 资料维护动作受仓库授权与 RBAC 约束；效期配置供 COM-FR-002 业务日期判断引用 |
| [入库业务](../02-入库业务/入库业务需求分析.md) | 入库作业与 PDA 入库受动作权限约束；关键确认（如已收未上架丢失）权限矩阵见应用设计 |
| [出库业务](../03-出库业务/出库业务需求分析.md) | 履约起算与超时展示引用 COM-FR-002；出库确认与缺货重试受 RBAC 约束 |
| [库存与库内业务](../04-库存与库内业务/库存与库内业务需求分析.md) | 移库、盘点与品质确认受权限约束；流水与双端一致引用 COM-FR-004 |
| [系统集成与对接](../06-系统集成与对接/系统集成与对接需求分析.md) | 外部服务模拟范围；WMS 内留痕与集成消息记录分工 |

用户、角色与操作记录的页面与字段由[公共能力 PRD](../../05-应用设计方案/20261002-MVP版本/需求文档PRD/06-公共能力/README.md)落实。
