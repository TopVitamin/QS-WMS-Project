# 退货管理

> 本目录把已在全局背景、需求分析和业务设计中确认的退货规则落到管理端与 PDA 的应用设计。退货模块处理“货从仓外退回本仓”，不把退货改写成入库业务类型，也不覆盖出库模块的采购退货出库。

## 一、范围与真源

一期覆盖三类来源：派送失败退回、客户退货、平台仓退件。FBA 移除退仓、FNSKU 换标、换包装、认领公海、退货后独立质检、销毁和计费不在一期。

## 三、页面入口（已确认）

退货收货页面名称沿用“退货收货”；Web 与 PDA 路由已按用户确认，并在 Demo 原型注册。结果重交从“系统集成 → 指令与结果”进入。

| 页面 | 确认路由 | 说明 |
| --- | --- | --- |
| 退货单列表 | `/wms/returns/orders` | 只提供查询、进入详情、满足条件时进入收货；预报建单通过 OMS Mock |
| 退货单详情 | `/wms/returns/orders/:returnNo` | 明细、收货记录、上架单、异常、操作日志 |
| Web 退货收货作业台 | `/wms/returns/orders/:returnNo/receive` | 与入库 Web 收货作业台同类，管理端和 PDA 共用提交动作 |
| PDA 退货收货 | `/pda/return-receive` | 可扫退货单、退货运单或原出库运单；派送失败可现场建单 |
| 系统集成：指令与结果 | `/wms/system/instructions-results` | 查看退货结果；失败时重交原结果序号与内容 |

## 四、阅读和交付边界

1. 先读[退货单主 PRD](退货单/退货单主PRD.md)，再读字段详细稿、页面骨架、Demo 分册和 PDA 分册。
2. “退货收货确认即进收货暂存库位”“SN 不一致只能拒收”“上架提交才移到目标库位”等数量和库存规则只在主 PRD 与上位真源维护，页面文档只引用。
3. 本次已按六项确认更新文档与 Demo 原型；静态检查不代表浏览器/PDA 作业验收或真实 OMS 接口验收。
4. 字段初稿与详细稿成对维护；详细稿使用 13 列，初稿为详细稿的五列投影，字段未确认项明确写“待确认”。

## 五、确认状态与剩余输入

> 2026-10-25 用户已确认派送失败包裹行、退货预报字段、FBA线索、拒收原因枚举及证据要求、收货页面名称与路由、回传字段和重交位置；这些规则已进入主 PRD、字段、Mock 和原型。

- 拒收原因固定为“外包装严重破损”（操作员选择）和“SN核对不一致”（系统固定记录）；照片、附件和破损等级均不强制。
