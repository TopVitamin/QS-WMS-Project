## 1. 业务背景与目标

退货单承接货从仓外退回本仓的事实。它既要能在客户退货、平台仓退件到仓前接收预报，也要支持派送失败现场扫原 B2C 出库运单建单；之后按退货单清点，录入良品、不良品和拒收，实收由两类品质数量合计，形成暂存库存并完成上架。

本 PRD 的目标是：

- 三类退货来源有唯一的归属和建单路径，不把无主货、FBA 退仓或采购退货出库混进来；
- 预计、拒收、实收、良品、不良品、未收和已上架能相互复算；
- 能沿“原出库单／退货预报 → 退货单 → 退货收货记录 → 上架单 → 库存流水”追溯；
- SN 商品在有原出库核对依据时防止调包；不一致件只能拒收，不进入实收、上架或库存；
- 退货已完成时向 OMS Mock 一次性回传分项结果，过程不回传进度。

## 2. 范围、使用方与对象

### 2.1 本期范围

| 功能 | 本期做法 |
| --- | --- |
| 退货预报 | OMS Mock 接收客户退货、平台仓退件预报；资料有效后生成待收货退货单 |
| 派送失败建单 | 管理端或 PDA 扫原 B2C 出库运单，定位已确认出库单并生成退货单；结果向 OMS Mock 登记 |
| 到件识别 | 按退货单号、退货运单号、原运单号、平台侧退货单号定位；无预报不代货主虚构 |
| 退货收货 | 可分次提交；拒收不计实收，实收内分良品／不良品，按商品配置采集批次、效期、SN |
| 上架与库存 | 收货确认进收货暂存库位；共用上架单按容器×品质拆分，提交后移到存储或不良隔离库位 |
| 完结与回传 | 收货完结且实收全部上架后完成；一次回传实收、拒收、最终短少、品质和落位 |
| 取消与变更 | 未产生实收时接受上游明细变更或取消；产生实收后拒绝 |

| 使用方 | 责任 | 需要交出的事实 |
| --- | --- | --- |
| 上游业务方／货主 | 提交客户退货、平台仓退件预报；处理差异 | 可匹配的预报、退货运单、SKU 和数量 |
| 退件／收货人员 | 识别来源、扫原运单建单、清点、录入良品、不良品和拒收、采集 SN | 退货收货记录、拒收原因、品质与追溯信息 |
| 上架人员 | 按退货收货生成的上架单落位 | 已提交的目标库位和上架数量 |
| 确认人 | 处理收货完结确认与跨岗位协调 | 收货完结确认或后续异常处理依据 |
| 系统集成与 WMS | 校验资料、生成单据、更新库存、回传结果 | 接收／拒绝、建单通知和结案回传 |

### 2.3 对象关系

| 对象 | 关系与边界 |
| --- | --- |
| 退货单 | 1 个货主、1 个仓库、1 种退货来源；预报类关联 1 条有效退货预报；派送失败关联 1 张原 B2C 出库单 |
| 退货单明细 | 1 张退货单 1～多行；预报类按来源明细，派送失败按原包裹保留预计行，同一 SKU 可因多个包裹重复出现；收货记录回指预计行 |
| 退货收货记录 | 1 张退货单 0～多条；每次确认生成 1 条记录，按容器、SKU、批次／效期拆行 |
| 退货异常记录 | 收货确认时按有拒收的收货明细行自动生成；不设手工新建，不计实收 |
| 上架单 | 与正常入库共用对象；来源业务=退货，来源单号=退货单，来源收货记录号=退货收货记录号 |
| 原出库单 | 只读引用；用于派送失败建单、可退数量和 SN 核对，不冲销原出库 |
| 无主货登记 | 认不出货主或长期无预报的到件走入库域无主货登记，不生成退货单与库存 |

## 3. 来源、建单与到件识别

### 3.1 客户退货与平台仓退件

OMS Mock 推送退货预报后，系统先校验仓库、货主、商品、预计数量及来源所需的识别字段。客户退货必填退货运单号、货主、SKU和数量；原销售单号、原出库单号、原运单号均选填。平台仓退件必填平台侧退货单号、货主、SKU和数量。OMS 消息标识用于接口幂等，不作为 Demo 表单中的额外业务必填项。通过后生成状态为“待收货”的退货单；同一来源、业务类型和上游消息标识重复接收时返回原单，不新增退货单。

- 客户退货必填退货运单号、货主、SKU和数量；原销售单号、原出库单号、原运单号均选填。
- 平台仓退件必填平台侧退货单号、货主、SKU和数量；平台仓不是 FBA 的同义词。
- 识别为 FBA 移除退仓的线索沿用现有平台／来源字段和备注记录；一期仅线下协调，不新增字段、作业流程或库存。
- 退货预报可携带原销售单号或原 B2C 出库关联。能关联且系统存在原出库 SN 时，收货按本 PRD §6.4 强核对；不能关联时仍按商品配置采集 SN，但提示“无可对核原单”。

### 3.2 派送失败退回

用户在管理端或 PDA 扫描**原 B2C 出库运单号**，系统只定位已确认出库的 B2C 出库单，并带出货主、仓库、SKU 和原出库追溯线索。建单结果如下：

1. 没有同一原运单的未完结派送失败退货单时，生成 1 张退货单，来源为“派送失败退回”，关联原出库单。
2. 按原包裹保留预计行，预计数量取原包裹复核量；每行保留原包裹号及原出库行关联，收货时按对应包裹行复核。
3. 同一退货单累计实收（良品＋不良品）与拒收数量按 SKU 汇总校验，不得超过原出库该 SKU 的实发总量；不得因多个包裹行重复放大可退上限。
4. 已存在同一原运单的未完结退货单时阻断重复建单，返回原退货单号。
5. 建单通知 OMS Mock，保留 WMS 生成的退货单号和原出库关联，不伪造退货预报号。

### 3.3 无预报、无主货与 FBA 分流

| 到件情况 | WMS 处理 |
| --- | --- |
| 客户退货／平台仓退件，无预报但货主可识别 | 催货主补预报；预报有效接收前不生成退货单、不收货、不增库存 |
| 到件无法确定货主 | 登记为无主货，记录识别线索和暂存位置；不生成退货单、不计入库存 |
| 识别为 FBA 移除退仓 | 沿用现有平台／来源字段和备注保留线索，线下协调；不新增字段或作业流程，不生成退货库存 |
| 已知货主的SKU与退货单不符、超过预计或没有有效预报 | 线下暂存，联系货主补报或安排退回；不生成退货收货、拒收或库存记录 |

## 4. 数量、状态与库存口径

### 4.1 数量公式

公式只在本节维护，页面和字段清单引用本节：

| 数量 | 口径 | 来源 |
| --- | --- | --- |
| 预计数量 E | 预报类取退货预报数量；派送失败按原包裹复核量形成包裹级预计行；同 SKU 实收＋拒收累计不超原出库该 SKU 实发总量 | 退货单明细 |
| 拒收数量 J | 本次收货拒收累计；带拒收原因，不计实收、不进库存 | 退货收货记录、退货异常 |
| 实收数量 R | 本次有效实收累计；超量或 SN 不一致件不进入 R | 退货收货记录 |
| 未收数量 U | `U = E − R − J`；收货完结前是当前未收，完结后是最终短少 | 退货单明细计算 |
| 良品 G／不良品 B | 按本次收货记录分别录入；`R = G + B` | 退货收货记录 |
| 已上架 PG／PB | 已提交上架单移到目标库位的良品／不良品数量 | 共用上架单 |
| 待上架 | `R − PG − PB`；只表达已收未落位，不是独立库存类型 | 退货单明细计算 |

必须满足：`E = R + J + U`、`R = G + B`、`PG ≤ G`、`PB ≤ B`。拒收、无主货、对不上单的超收和 SN 不一致件都不进入 R，不增加库存。

### 4.2 状态推导

退货单主状态闭集为：待收货、收货中、上架中、已完成、已取消。状态由业务事实推导，页面不提供手工改状态：

| 优先级 | 状态 | 判定 |
| --- | --- | --- |
| 1 | 已取消 | 已受理退货取消；仅允许整单累计实收为 0 |
| 2 | 已完成 | 累计实收大于 0，所有明细已收货完结，且已上架数量等于实收数量 |
| 3 | 上架中 | 存在实收，所有明细已收货完结，但仍有待上架数量 |
| 4 | 收货中 | 存在实收，仍有明细未收货完结 |
| 5 | 待收货 | 尚未产生有效实收，且未取消 |

收货完结是整单动作，不等于状态；操作人确认后关闭继续收货，未收数量定型为最终短少，已收部分仍可继续上架。零实收不允许通过收货完结结案，只能由上游取消消息受理后进入已取消。

### 4.3 库存生效点

| 动作 | 业务结果 | 库存结果 |
| --- | --- | --- |
| 退货收货确认 | 生成 RR；有拒收时生成 RX | 按 R、G、B 增加本仓收货暂存库位库存 |
| 上架单保存 | 记录落位进度，状态上架中 | 不动库存；目标库位取得未提交货主占用 |
| 上架单提交 | 整张单按行校验并完成 | 收货暂存库位 → 存储库位或不良隔离库位；写库存流水 |
| 拒收／SN 不一致 | 保留事实和原因 | 不计实收、不生成该件上架单、不增库存 |
| 退货完成 | 回传分项结果 | 不新增独立“退货库存”类型；良品进入正常可用库存口径 |

## 5. 状态—操作矩阵

| 当前状态 | 可执行操作 | 前置条件与校验 | 结果与联动 |
| --- | --- | --- | --- |
| 待收货 | 查看、退货收货、接收上游明细变更、接受退货取消；派送失败可定位原运单建单 | 变更／取消均无任何实收；退货收货须通过商品、批次、效期、SN与来源校验 | 首次有效实收后进入收货中；零实收取消受理后进入已取消 |
| 收货中 | 退货收货、保存／提交共用上架单、收货完结确认 | 累计实收＋拒收不超过预计；收货完结后不能继续收货；盘点中的 SKU 按库存规则阻断收货 | 收货确认增加暂存库存；拒收自动生成 RX；已实收后不得变更或取消 |
| 上架中 | 保存／提交共用上架单 | 每条应上架行各库位合计等于应上架；目标库位启用、品质适配、货主资格有效 | 提交后移出收货暂存库位；全部上架后完成 |
| 已完成 | 查看、追溯、结果重交（由系统集成入口执行） | 不允许收货、变更、取消和改写事实 | 已完成结果回传 OMS Mock；再次提交不重复改库存 |
| 已取消 | 查看、追溯 | 不允许收货、变更、上架和再次取消 | 保留预报、到件和拒收事实；不回传退货完成结果 |

## 6. 退货收货规则

### 6.1 收货提交

退货收货与入库收货共用“作业容器＋收货明细”的作业模型：一次提交生成一条退货收货记录，可包含一个或多个容器；PDA 可分批提交容器，管理端作业台可一次提交本次已录入容器。没有容器的收货必须显式选择“无容器收货”。

- 同一退货单已经确认使用过的容器不能再次使用；同一次提交内容器号不能重复。
- 本次实收＝良品＋不良品；页面只录良品、不良品和拒收，实收由系统计算且只读；仅拒收时可以不录品质。
- 拒收数量大于 0 必须选择原因。操作员可选“外包装严重破损”；SN 与原出库不一致时系统固定记录“SN核对不一致”，不向操作员提供原因选择，并保留扫描 SN 与核对依据。照片、附件和破损等级均不强制。已知货主的错 SKU、超量或无预报实物在线下处理，不录入本单拒收。
- 同一预计行的历史实收＋拒收＋本次提交各容器数量不得超过该行预计；派送失败单还须按 SKU 汇总校验不超过原出库实发总量。超出部分不得通过新增明细行入账。
- 商品启用批次管理时，批次号必填；启用效期管理时，现场手工录入生产日期或失效日期其中一项；生产日期加保质期天数等于失效日期，系统按此公式计算另一项，录入失效日期时反算生产日期；现场可手动修改计算值，且生产日期不得晚于失效日期。启用 SN 时按商品资料要求采集；字段来源和记录方式见退货收货字段详细稿。
- 收货确认后事实不可作废、不可更正。发现误记时保留原记录，按全局库存和盘点规则处理，不在退货模块提供反向冲销。

### 6.2 品质分流

良品和不良品都属于实收；良品进入正常库存口径，不良品进入不良品库存口径。退货一期不另建质检任务，不因等待货主意见而把良品长期留在收货暂存库位。

### 6.3 拒收异常

收货确认时，凡收货明细行有拒收数量，系统自动生成 1 条退货异常记录，指回退货单、退货收货记录和收货明细行。退货异常记录只读，不能手工补建，异常数量等于该行拒收数量。

### 6.4 SN 核对

| 场景 | 校验 | 不一致或无依据时的结果 |
| --- | --- | --- |
| 派送失败退回 | 按原包裹预计行收货；实收 SN 必须与原出库复核记录或实发 SN 一致 | 不一致只能拒收；系统固定记录“SN核对不一致”，不允许操作员改选原因；保留扫描 SN 与核对依据；不计实收、不生成上架、不增库存、不得改为不良品 |
| 客户退货／平台仓退件，能关联原 B2C 且系统有 SN | 实收 SN 必须与原出库 SN 一致 | 按派送失败的不一致规则拒收，由系统固定记录原因并保留扫描 SN 与核对依据 |
| 客户退货／平台仓退件，无法关联原出库 | 仍按商品配置采集 SN | 提示“无可对核原单”，但不因无原单阻断收货；SN 入账 |

SN 核对结果和扫描值属于收货事实；不一致件若进入拒收，异常记录必须能追到扫描 SN 与原出库核对依据。原因“SN核对不一致”由系统写入，不允许操作员选择或改写。没有原单可核时，不得把“无可对核”写成“核对一致”。

## 7. 上架、完成与结果

### 7.1 共用上架单

退货收货确认后，系统按“作业容器×品质”生成共用上架单：良品和不良品分开；无容器收货按本次收货记录×品质合并。上架单单头的来源业务为“退货”，来源单号为退货单号，来源收货记录号为 RR 号。

上架单的目标库位、保存占用、SN 落位、整单提交和重复提交规则均以[上架单主 PRD](../../2-入库管理/上架单/上架单主PRD.md)为准：保存不动库存，整张单提交才从收货暂存库位移到目标库位；退货良品目标为存储库位，不良品目标为不良隔离库位。

### 7.2 收货完结与整单完成

收货完结确认须同时满足：累计实收大于 0，操作人确认不再继续接收。确认后未收数量成为最终短少，不影响已经收货部分上架。整单完成还必须满足所有明细已收货完结且良品／不良品已全部提交上架。

完成时向 OMS Mock 回传一次，至少分项表达：退货来源、退货单号、来源关联单号、预计数量、良品数量、不良品数量、拒收数量、最终短少和上架结果。过程中的收货、保存上架不回传进度；回传失败后从系统集成“指令与结果”入口重交原结果，不重新收货或改库存。退货详情只提供跳转，不直接重交。

### 7.3 零实收与取消

全单仅拒收或尚未到货时，退货单仍保持待收货；仓库通知上游后，由 OMS Mock 发起退货取消。WMS 仅在累计实收为 0 时受理，保留退货单、到件和 RX，不生成库存，也不回传退货完成结果。产生任何实收后，取消和明细变更均拒绝。

## 9. 数据范围、异常与一致性

- 退货单按顶栏当前仓库过滤，显示该仓全部货主的数据；一期不提供登录、角色或用户仓库授权校验。
- 收货、收货完结和上架入口由单据状态控制；提交仍须通过数量、来源、品质、效期、SN和盘点冻结校验。
- 收货确认、拒收异常、SN核对、上架保存／提交、收货完结、建单通知和结果回传均留操作者、UTC 时间、原对象和结果；事实记录不可编辑。
- 管理端与 PDA 使用同一退货收货记录和库存流水；相同动作重复提交只返回原结果，不重复增库存。
- 盘点中的 SKU 按库存域规则阻断退货收货和相关上架，不在退货 PRD 另造一套冻结状态。
- 退货单已完成后不因结果回传失败回退状态；结果重交不重做业务。

## 10. 验收标准

| 编号 | 条件与操作 | 预期结果 |
| --- | --- | --- |
| AC01 | OMS Mock 推送合法客户退货或平台仓退件预报 | 客户退货必填退货运单号，原销售单号、原出库单号和原运单号选填；平台仓退件必填平台侧退货单号；两类均须有货主、SKU和数量，并生成待收货退货单 |
| AC02 | 同一预报重复推送 | 返回原退货单，不新增单据、不重复占用；冲突内容按消息规则拒绝 |
| AC03 | 扫已确认 B2C 原运单建派送失败退货 | 生成 1 张 RT，按原包裹复核量保留预计行，带出仓库、货主、SKU、原出库关联；向 Mock 留建单通知 |
| AC04 | 同一原运单已有未完结退货单再次建单 | 阻断并返回原退货单号，不生成第二张未完结单 |
| AC05 | 客户／平台退件无预报但货主可识别 | 不生成退货单、不收货、不增库存；页面给出补预报提示 |
| AC06 | 无法识别货主的退件 | 转无主货登记；不生成 RT、不生成 RR、不增加库存 |
| AC07 | 扫原运单或退货单进入收货作业 | 可按容器、SKU、批次／效期、SN录入，数量候选和单据上下文正确 |
| AC08 | 收货 2 件，其中良品 1、不良品 1 | RR 实收 2，良品 1、不良品 1；收货暂存库位正常品和不良品各增加对应数量 |
| AC09 | 录入拒收 1 件并选择“外包装严重破损” | J 增加 1，自动生成该枚举原因的 RX；拒收不计 R、不进库存、不生成该件上架 |
| AC10 | 拒收数量大于 0 但未选择固定原因 | 提交被阻断，保留录入内容，不生成 RR/RX |
| AC11 | 本次实收＋拒收超过预计行，或派送失败按 SKU 累计超过原出库实发 | 提交被阻断，不截断、不新增虚拟明细 |
| AC12 | 派送失败商品原出库 SN=S1，退回扫 S2 | 只能记拒收；系统固定记录“SN核对不一致”，不让操作员选原因；保留扫描 S2 和核对依据；R、良品、不良品均不增加，不生成上架和库存 |
| AC13 | 预报类退货能关联原单且 SN 不一致 | 与 AC12 相同；不允许改记不良品实收 |
| AC14 | 预报类退货无法关联原单但商品要求 SN | 扫 SN 后提示无可对核原单；允许按品质收货并保存 SN |
| AC15 | RR 确认后按容器×品质生成上架单 | 每种品质、每个容器各一张；来源业务为退货；无容器按规则合并 |
| AC16 | 保存上架落位但未提交 | 记录上架进度和库位占用，收货暂存库存不变；管理端和 PDA 看到同一进度 |
| AC17 | 上架单逐行填足并整单提交 | 收货暂存库位移到存储／不良隔离库位；库存流水、SN位置和退货已上架数量正确 |
| AC18 | 所有行收货完结且实收全部上架 | RT 转已完成，只生成一次退货完成结果 |
| AC19 | 全单零实收，OMS Mock 发起退货取消 | 转已取消；保留 RR/RX（如有）、到件和取消原因；不回传完成结果 |
| AC20 | 已产生实收后收到明细变更或取消 | 拒绝请求，原数量和事实不变 |
| AC21 | 管理端与 PDA 重复提交同一收货确认 | 只生成一条 RR、一次库存变化；第二次返回原结果 |
| AC22 | 当前仓库与退货单仓库不一致时进入详情或作业 | 不展示其他仓数据并返回列表；一期不按用户角色裁剪入口 |
| AC23 | FBA 特征退件到仓 | 记录识别线索并提示线下协调；一期不进入退货收货、不形成库存 |
| AC24 | 退货完成结果发送失败后重交 | 从系统集成“指令与结果”入口使用原结果序号和原内容重交；不重复上架、不重复库存变化 |
| AC25 | 拒收普通退货实物 | 可选原因只有“外包装严重破损”；照片、附件和破损等级不作为提交条件 |
