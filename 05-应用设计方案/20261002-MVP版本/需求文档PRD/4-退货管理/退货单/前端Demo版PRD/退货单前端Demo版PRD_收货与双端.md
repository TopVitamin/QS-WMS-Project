# 退货单前端Demo版PRD·收货与双端

> 2026-10-22：原型已补多容器、容器×品质上架、SN 与原出库核对和草稿恢复；Web 作业台为单页多容器，不拆弹窗向导。

> 定位：定义 Web 退货收货作业台与 PDA 退货收货共用的录入、校验、提交和反馈；业务规则以[退货单主 PRD](../退货单主PRD.md)为准，PDA 的屏幕步骤见[《PDA 退货收货前端 Demo 版 PRD》](../../../7-PDA作业端/退货收货作业/PDA退货收货前端Demo版PRD.md)。本文件只输出产品文档，不创建代码。

## 1. 能力概述

| 项目 | 约定 |
| --- | --- |
| Web 确认路由 | `/wms/returns/orders/:returnNo/receive` |
| PDA 确认路由 | `/pda/return-receive` |
| 提交动作 | Web 与 PDA 共用 `submitReturnReceipt`（建议名） |
| 一次提交 | 生成 1 条 RR，可包含 1～N 个容器；PDA 可分批提交容器 |
| 成功联动 | 自动生成 RX（有拒收时）、按容器×品质生成共用上架单、增加收货暂存库存、重算 RT 状态 |
| 不可进入 | 已完成、已取消、已确认收货完结或不属于当前仓的退货单 |

## 2. 两端共用录入规则

| 规则 | 说明 |
| --- | --- |
| 数量录入 | 只录良品、不良品和拒收；实收只读显示为良品＋不良品。数量公式与上限见主 PRD §4.1、§6.1 |
| 拒收 | 固定枚举：“外包装严重破损”由操作员选择；SN不一致时系统固定记录“SN核对不一致”。Web使用选择控件，PDA使用大按钮组选项；照片、附件和破损等级不强制 |
| 容器与追溯 | 容器、批次、效期和 SN 按商品资料及主 PRD 规则采集；页面只负责呈现和校验反馈 |
| 批次与效期日期 | 启用批次管理时显示并要求填写批次号；启用效期管理时显示“生产日期”和“失效日期”两个日期输入，现场至少手工录入其中一项，系统按商品保质期天数计算另一项；生产日期加保质期天数等于失效日期，录入失效日期时系统反算生产日期；两项均可手动修改，且生产日期不得晚于失效日期 |
| SN | 有原出库核对依据时必须比较；不一致只进入拒收分支。具体分支见主 PRD §6.4 |
| 超量 | 按主 PRD 数量上限阻断本次修改或提交，不截断、不新增虚拟行 |
| 草稿 | 只保存未提交内容；提交后的记录、库存和上架事实不因返回撤销 |

## 3. Web 作业台

### 3.1 入口与页面结构

入口：退货单列表行操作或详情页头“Web 端收货”，进入独立 Web 作业台。

```text
页头：退货收货作业 · RT号／状态 | 返回详情 | 返回列表
单头摘要：来源、货主、仓库、退货运单／原运单、预计、实收、拒收、未收
左侧：当前容器 → 扫商品／录入批次、生产日期、失效日期／扫SN → 录良品、不良品、拒收、原因
右侧：本次容器列表、容器件数、品质合计、拒收合计
底部：清空本次 | 提交退货收货（N个容器）
```

### 3.2 绑定容器与扫码

- 无当前容器时，扫码框识别作业容器号；也可选择无容器收货。
- 有当前容器时，扫码框识别该货主下 SKU 编码、商品条码或商品主条码；命中后定位本退货单对应行。
- Web 端可点选明细行录入；PDA 默认扫码逐件增加良品。
- 派送失败退货同一 SKU 可能对应多个原包裹预计行；操作员须选择对应包裹行后录入，收货记录回指该行。
- 扫到原运单号、退货单号或平台侧退货单号时，如果当前不是定位步骤，提示“当前步骤需要商品／容器码”，不能静默当成商品。
- 未命中本单 SKU 时提示具体码值和“不是本退货单明细”，不能创建新行。

### 3.3 SN 核对分支

1. 商品不启用 SN：按普通数量录入。
2. 商品启用 SN 且有原出库 SN：扫 SN 后显示原出库核对依据；一致才允许计入实收，重复 SN 或不一致进入拒收分支。
3. 商品启用 SN 但无原出库可核依据：扫 SN 后提示“无可对核原单”，允许选择良品／不良品并计入实收。
4. SN 不一致：系统带出拒收数量 1 和固定原因“SN核对不一致”；操作员不能选择或改写原因；记录扫描 SN 和核对依据，不能把该件改到不良品。

### 3.4 提交与反馈

提交前按主 PRD §6.1、§6.4 重新校验当前作业；界面需就近提示容器为空、拒收原因缺失、数量超限、SN 数量不一致等失败原因。

启用效期管理的商品缺少生产日期或失效日期，或生产日期晚于失效日期时，阻断提交并指出商品；保留当前录入，修正日期后重试。

成功后：

- 通过共用 `submitReturnReceipt` 动作生成 1 条 RR，并按主 PRD 生成 RX、上架关联和收货暂存库存；
- 清除未提交草稿，刷新列表、详情、状态和数量。

失败时保留当前录入，不部分写入。重复点击同一确认标识返回原结果。

## 4. 拒收原因与错误反馈

退货收货使用固定拒收原因枚举。操作员只能选择“外包装严重破损”；系统在SN不一致时固定记录“SN核对不一致”。普通拒收不要求照片、附件或破损等级。

| 场景 | 页面反馈 | 处理 |
| --- | --- | --- |
| 拒收大于 0 未选原因 | 就近红字 | 阻断提交 |
| SN 与原出库不一致 | 固定原因“SN核对不一致”，展示扫描 SN 和核对依据 | 只能拒收，不计实收；操作员不可改选原因 |
| 无原单可核 SN | 轻提示 | 允许按品质收货，记录“无可对核原单” |
| 超预计／超剩余 | 阻断提示 | 拒绝本次数量修改，不截断 |
| 商品不属于本退货单 | 扫码错误 | 不建新明细 |
| 已被另一端提交 | 并发阻断 | 刷新后按最新剩余量重录 |
| 退货单已取消／已完结 | 业务阻断弹窗 | 返回详情，不写 RR |

## 5. Web 与 PDA 的一致性检查

- [ ] 两端提交都生成一条 RR，不因端不同而产生两套收货事实。
- [ ] 两端均只录良品、不良品和拒收，实收显示为只读派生值。
- [ ] 数量、SN、库存和上架结果均引用主 PRD，不在两端各自维护一套规则。
- [ ] 重复提交不重复生成 RR、RX、上架单或库存流水。
- [ ] 中英文文案和仓库当地时区展示规则一致。
