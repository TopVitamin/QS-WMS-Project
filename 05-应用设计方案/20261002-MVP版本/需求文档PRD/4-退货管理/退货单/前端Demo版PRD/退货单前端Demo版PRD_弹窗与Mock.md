# 退货单前端Demo版PRD·弹窗与Mock

> 本文统一写退货管理的 Demo 输入、派送失败建单、收货完结和结果重交入口。它不定义真实 OMS 报文；消息身份、版本、送达与重交规则以[接口与 OMS Mock 消息设计](../../../系统架构设计/06-接口与OMS Mock消息设计.md)为准，业务条件以[退货单主 PRD](../退货单主PRD.md)为准。

## 1. 容器与共用交互

| 场景 | 建议容器 | 成功后 |
| --- | --- | --- |
| 退货预报 Mock | Dialog；允许多 SKU 明细 | 关闭并刷新列表；生成待收货 RT |
| 派送失败建单 | Dialog；只输入原 B2C 运单号 | 关闭并刷新列表；生成 RT 或返回重复单结论 |
| 确认收货完结 | 受控 Dialog；展示未收明细和最终短少 | 写入完结人／时间，刷新状态 |
| 结果重交 | 系统集成入口；退货详情只提供跳转 | 使用原结果序号，不重新执行业务 |

成功使用 toast；状态已变化或业务校验失败时使用明确错误文案，不静默关闭当前录入。

## 2. 退货预报 Mock

仅用于一期演示，不代表管理端提供货主自助建单。

| 字段 | 必填性 | 说明 |
| --- | --- | --- |
| 退货来源 | 是 | 客户退货／平台仓退件；不提供 FBA 退仓作为可选值 |
| 仓库 | 是 | 当前仓库或选择预置仓库 |
| 货主 | 是 | 只能选择启用货主 |
| 上游消息标识 | 是（消息信封） | 用于幂等；Demo 自动生成，不作为操作员填写的业务必填项 |
| 退货运单号 | 客户退货必填；平台仓退件选填 | 原样保存，不改写 |
| 平台侧退货单号 | 平台仓退件必填；客户退货不适用 | 原样保存，用作平台退件识别线索 |
| 原销售单号／原出库单号／原运单号 | 均选填 | 若带入且能定位原出库，收货时按 SN 强核对；派送失败建单按原出库关联生成 |
| 明细商品与预计数量 | 是 | 商品必须属于该货主，数量为正整数；同一 SKU 不重复行 |
| 备注 | 否 | 上游备注；FBA识别线索可记在现有平台／来源字段及备注中；不参与数量和状态 |

提交顺序：表单校验 → 消息标识和业务对象键判重 → 仓库、货主、商品和数量准入 → 生成 RT 待收货 → 写接收结论。客户退货的业务识别号为退货运单号；平台仓退件须有平台侧退货单号。失败不生成半张退货单。

## 3. 派送失败建单

| 步骤 | 交互 | 预期 |
| --- | --- | --- |
| 1 | 输入或扫描原 B2C 出库运单号 | 只查询已确认出库的 B2C 单；不接受任意退货运单代替原运单 |
| 2 | 展示原出库摘要 | 展示仓库、货主、原出库单号、SKU、原包裹和包裹复核量；每个原包裹形成一条预计行 |
| 3 | 确认建单 | 通过重复和状态校验后生成 RT，来源为派送失败退回 |
| 4 | 建单通知 | 写 WMS → OMS Mock 的仓内建单通知；不生成虚假的上游退货预报号 |

若原运单不存在、原单未确认出库、原单不是 B2C 或当前仓不匹配，提示具体原因并不建单。若已存在未完结 RT，返回原退货单号并不新增。后续实收和拒收按 SKU 累计不得超过原出库实发总量。

## 4. 确认收货完结

触发条件：RT 为收货中、累计实收大于 0。

Dialog 展示：

- 本次确认会停止继续收货；
- 仍未收的明细、商品和数量；
- 拒收已单独记录，不会被算进实收；
- 已收货物仍可继续完成共用上架。

提交时重新校验最新事实。成功写入收货完结确认人和 UTC 时间；如果实收部分已全部上架，状态立即进入已完成并形成结果回传，否则进入上架中。零实收不显示该按钮，改由退货取消消息处理。

## 5. Mock 走查资料

文档阶段只规定场景，不虚构仓库现有种子编号；实现时至少准备以下标明“演示数据”的场景：

| 场景 | 必须能观察到 |
| --- | --- |
| 客户退货预报 | 生成待收货 RT；收货运单和预报号可查询 |
| 平台仓退件 | 平台侧退货单号展示；同箱良品／不良品可拆分 |
| 派送失败 | 扫原 B2C 运单建单；原出库单可追溯；结果有建单通知 |
| SN 一致 | 实收良品、暂存库存、上架后可用库存 |
| SN 不一致 | 仅拒收；系统固定原因“SN核对不一致”，不提供操作员原因选择；RX保留扫描SN和核对依据；无上架和库存 |
| 无可对核原单 | 采集 SN并提示，不阻断收货 |
| 零实收取消 | 保留到件／拒收事实，取消后不回传完成结果 |
| 结果重交 | 从系统集成“指令与结果”进入，重交原结果序号和内容 |
| 重复提交 | 同预报、同原运单、同收货提交均不重复建单或增库存 |

## 6. 文案 key（建议）

| key | 中文 |
| --- | --- |
| `menu.returnOrders` | 退货单 |
| `return.source.failedDelivery` | 派送失败退回 |
| `return.source.customer` | 客户退货 |
| `return.source.platform` | 平台仓退件 |
| `return.mockPush` | 模拟推送退货预报（Demo） |
| `return.createFromTracking` | 派送失败建单 |
| `return.receive.action` | Web 端退货收货 |
| `return.openPdaReceive` | PDA 退货收货 |
| `return.receiptClose` | 确认退货收货完结 |
| `return.noReference` | 无可对核原单，仍需采集 SN |
| `return.snMismatch` | SN 与原出库不一致，只能拒收 |
| `return.overExpected` | 本次数量超过退货单剩余预计数量 |
| `return.stale` | 退货单状态已变化，请刷新后重试 |

最终 key 命名需与现有 i18n 词表合并，中文、英文均需补齐；本轮不修改语言包。
