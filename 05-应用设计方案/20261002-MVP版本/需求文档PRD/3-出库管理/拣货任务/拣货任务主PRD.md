## 一、生成与关联

| 任务来源 | 由谁触发 | 关联 |
| --- | --- | --- |
| 按单拣货 | 在出库单详情「生成拣货任务」 | 所属出库单 |
| 基础波次 | 在出库单列表组波 | 所属波次；各应拣行保留原单份额 |
| 补拣 | 在待拣货或待复核的出库单「重新分配」 | 所属出库单；已有未完成任务时返回原任务 |

生成即分配：应拣行记录库位、SKU、批次、品质与应拣数量，并计入对应库存明细的已分配；出库暂存库位在生成时确定。其他出库的应拣行直接取出库单指定的库存，不换位。拣货人员不能修改应拣行。

## 二、状态与操作

| 状态 | 允许操作 | 生效结果 |
| --- | --- | --- |
| 待拣货 | 查询、确认实拣（PDA 扫描或 Web 端录入）、上报缺货 | 首次确认或上报后进入拣货中；全部行有结果时可直接提交 |
| 拣货中 | 继续确认、上报缺货、提交 | 每次确认立即下架；提交只结束进度 |
| 已完成 | 查询与追溯 | 短拣定型，剩余分配已释放；不再确认 |
| 已关闭 | 查询与追溯 | 出库单取消导致；未拣分配释放，已确认实拣按原单退拣 |

确认实拣、上报缺货、提交有两个入口，规则相同、写同一条拣货任务，可交替使用：

| 入口 | 适用 | 做法 |
| --- | --- | --- |
| PDA 拣货 | 现场有 PDA | 按库位逐站扫描，见第三节第 1 条 |
| Web 端拣货 | 不用 PDA，按纸质拣货单拣完后补录 | 有拣货执行权限的人员在管理端逐行录入实拣数量、缺货数量与原因（SN 商品录序列号），保存即确认下架；全部行有结果后提交 |

管理端不提供关闭入口，也不能修改应拣行。波次任务的成员部分取消时只处理该单份额，全部成员取消才关闭任务。

## 三、扫描确认、缺货与提交

1. **按库位逐站确认**：任务内还有剩余的应拣行按来源库位分组，按库位编号顺序排成拣货路径（换位新增的库位并入路径）。作业员先扫当前库位确认到站，再逐件扫商品（SN 商品逐件扫 SN）计数；一行数满剩余应拣即自动确认，件数多时可扫一件后直接改数量再确认；一个库位拣完自动跳到路径上的下一个库位。扫到路径上另一个还有待拣的库位，就改去那个库位。批次随来源库位确定：同一库位同一商品有多个批次的应拣行时，扫批次号或点选区分。
   每次确认的数量为正整数，不超过该行剩余应拣（应拣－实拣－上报缺货）；SN 须属于来源库存，同一次确认中不得重复。确认成功即把本次数量从来源库位移到出库暂存库位：来源实际与已分配减少，暂存实际增加，原单已拣增加；SKU 实际总量与订单占用不变。同一确认标识重试返回原结果，不重复下架；还没确认的计数是本机草稿，不动库存。Web 端拣货逐行录入的实拣数量按同一规则确认。
2. **实拣归属**：按单与补拣任务直接归属所属出库单；波次任务按波次内序号把本次新增实拣归属给未取消的成员，归属确定后不重排，SN 记到对应原单。
3. **上报库位缺货**：填写缺货数量和原因（无货、残损）；本行已数未确认的件数先确认下架，再报缺货。释放该部分分配，按既有分配规则尝试一次换位（追加或合并应拣行，并保留原单份额），同时把本仓本货主该 SKU 标记待核对。此后不再继续分配或反复换位；其他出库与不良品行不换位。残损品质转换需另行确认，现场上报不直接改库存品质。
4. **提交**：各行须满足 实拣＋上报缺货＝应拣。通过后任务已完成，记录提交人与提交时间；未被换位补上的缺货即短拣，剩余分配释放；**不再次移库**。
5. **关闭**：由出库单取消触发（见出库单主PRD R13），不单独操作。

## 四、数量口径

| 层级 | 数量 | 关系 |
| --- | --- | --- |
| 应拣行 | 应拣、实拣、上报缺货、换位补上 | 实拣＋上报缺货 ≤ 应拣；换位补上 ≤ 上报缺货 |
| 应拣行 | 短拣（页面计算） | 上报缺货－换位补上 |
| 任务 | 应拣总数、实拣总数、短拣总数 | 各行之和 |
| 实拣归属 | 归属实拣、有效数量 | 有效＝归属实拣－已退拣；出库单已拣取有效之和 |

## 五、管理端页面

| 页面 | 内容 |
| --- | --- |
| 列表 | 状态页签（全部、待拣货、拣货中、已完成、已关闭）；筛选任务号、出库单号（命中所属、份额或归属）、任务来源、货主；列：任务号、状态、任务来源、所属出库单或波次、货主、应拣、实拣、短拣、创建时间、提交时间 |
| 详情 | 基本信息（任务来源、所属出库单或波次、货主、仓库、出库暂存库位、创建时间、提交人、提交时间、备注）；拣货进度卡；页签：应拣明细、实拣归属、原单份额（仅波次任务）、操作日志；未完成任务提供「Web 端拣货」「PDA拣货」两个入口 |
| Web 端拣货（录入页） | 基本信息；录入表单（应拣行按拣货路径排序，默认带出剩余应拣作实拣数量，另填缺货数量与原因、SN）；录入进度卡（已处理＝实拣＋上报缺货，提交按钮在卡片底部，条件不满足时写明还差多少）；页签：待拣明细（带剩余与「录入」）、实拣记录。保存一行后自动切到路径上下一条还有剩余的应拣行 |

## 六、验收

| 条件与操作（数字为模拟） | 预期结果 |
| --- | --- |
| B2C 需求 3，PDA 分次确认 1、2 后提交 | 每次确认来源减、暂存增；提交后状态已完成，库存流水无第三次移库；出库单已拣 3 |
| 同一确认标识重放 | 返回原结果，不重复下架 |
| 确认数量超过剩余应拣，或扫描他人 SN | 阻断，提示原因，不动库存 |
| L1 应拣 5，确认 3，上报缺货 2，换位到 L2 分到 2 | 新增或合并 L2 应拣行 2；SKU 待核对；确认 L2 的 2 后提交，短拣 0 |
| 同上但 L2 无货 | 提交后短拣 2；出库单已拣 3、待拣 2，预占仍 5 |
| 一行未拣足也未上报就提交 | 拒绝，提示还有未完成行 |
| 出库单在待拣货、待复核或待出库取消 | 任务已关闭；已确认实拣退拣，生成返库上架单 |
| 任务两个库位：L1 拣线材 3 件、L2 拣 SN 商品 1 件；PDA 扫 L1、扫商品 3 次 | 第 3 次扫描后自动确认 3 件，并跳到 L2 提示扫库位；扫 L2、扫 SN 后自动确认，进入提交 |
| 未扫库位就扫商品，或扫了不在路径上的库位 | 扫码错误，写明扫到的是什么、应去哪个库位；不计数 |
| 同一库位同一商品两个批次，只扫商品条码 | 提示点选批次或扫批次号；选定后继续计数 |
| 不用 PDA：Web 端拣货录入 L1 实拣 2、缺货 1（无货） | 与 PDA 结果相同：确认 2 件下架，缺货 1 件按规则换位或计短拣；录满后提交，提交人为录入人 |
| 管理端打开已完成任务 | 页头无「Web 端拣货」「PDA拣货」；应拣明细显示上报缺货、换位补上、短拣 |
