# 波次主PRD

> 2026-10-15，由原《出库管理主PRD》拆出。管理端菜单与列表标题统称**波次管理**；业务对象仍称**波次**（波次号、波次详情）。定义 B2C 基础波次的组波、查询与追溯；页面见[波次页面骨架](波次页面骨架.md)和[波次前端Demo版PRD](波次前端Demo版PRD.md)。依据为[出库宏观架构](../../../../01-全局背景信息/05-出库模块宏观系统架构.md)第2.1.1、3.4节；字段见[波次详细稿](../../../字段清单合集/03-出库管理/波次/波次（详细稿）.tsv)。拣货扫描与提交见[拣货任务主PRD](../拣货任务/拣货任务主PRD.md)；成员单的复核与出库见[出库单主PRD](../出库单/出库单主PRD.md)。不做自动波次、派工、边拣边分。

## 一、组波与关联

仓库组织者在出库单列表勾选 2 张及以上出库单生成波次。全部成员须同时满足：B2C出库、待处理、同一仓库、同一货主、尚未生成过拣货任务，且整单预占都能分配足；任一不满足整批保持原样并提示原因，不生成部分波次。SKU 待核对或盘点中时不组波。

组波完成硬分配并生成波次拣货任务（一期在同一操作内完成，头状态为**已下发任务**）。应拣按库位＋SKU＋批次汇总，每行保留各成员单的行号与份额（原单份额）；成员顺序即勾选后按单号排序的波次内序号，扫描确认时按此顺序把新增实拣归属给未取消的成员，归属确定后不重排。一张出库单至多进一个波次，波次不新增预占、不改需求。

远期：可先进入**已分配**（仅锁库），再【下发任务】拆成多张波次拣货任务后进入**已下发任务**。

## 二、状态与操作

波次头描述**计划与分配、任务下发、拣货段结案、整波作废**；**不**表达拣货任务是否拣货中（见拣货任务主PRD）。成员**补拣任务**不参与波次头。

| 状态 | 判断 | 允许操作 | 说明 |
| --- | --- | --- | --- |
| 已分配 | 硬分配已落库，尚未下发任何波次拣货任务 | 查询；【下发任务】（远期）、【取消】（远期整波作废） | 一期组波后不单独停留 |
| 已下发任务 | 至少一张波次拣货任务已对现场可见，且未全部终态 | 查询、进入未完成任务拣货 | 现场进度看拣货任务列表 |
| 已完成 | 全部波次拣货任务均为已完成或已关闭 | 查询与追溯 | 波次拣货段结案；不代表成员已出库 |
| 已取消 | 整波作废，或全部成员出库单已取消 | 查询与追溯 | 终态；与出库单「已取消」区分层级 |

一期不设人工【完成波次】；**已完成**由任务终态推导。成员单取消只扣该单份额；全部成员取消时相关任务关闭、波次为**已取消**。成员状态展示「在波次内」或「已取消」。

## 三、管理端页面

| 页面 | 内容 |
| --- | --- |
| 列表 | 状态页签（全部、已分配、已下发任务、已完成、已取消）；筛选波次号、出库单号、货主；列：波次号、状态、货主、波次拣货任务数、出库单数、应拣总数、实拣总数、创建时间 |
| 详情 | 基本信息（货主、仓库、出库单数、创建时间、备注）；拣货进度卡；页签：**出库单**、**商品明细**、操作日志（管理端文案；数据层仍称成员单、原单份额） |

管理端不提供新建（组波在出库单列表）、编辑、删除、移出成员入口。**已下发任务**时详情页头提供「去拣货」，跳未完成的波次拣货任务 PDA 拣货。

## 四、验收

| 条件与操作（数字为模拟） | 预期结果 |
| --- | --- |
| 勾选 B2C 单 A（需求 3）、B（需求 2）组波 | 生成波次与一张任务，应拣 5；波次已下发任务；A、B 状态待拣货；波次成员 2 |
| 勾选中混入一张 FBA 单或已有任务的单 | 整批拒绝，提示原因；无波次、无任务、无分配残留 |
| 勾选两张不同货主的 B2C 单 | 拒绝，提示货主不同 |
| 任务扫描确认 4 件后取消 A | 归属 A 3、B 1；A 的 3 件退拣返库，B 的 1 件保留；B 成员仍在波次内，A 显示已取消；波次仍已下发任务 |
| 波次任务提交 | 波次已完成；A、B 按已拣与复核进度进入待复核或待出库 |
| 波次内全部成员取消 | 任务已关闭，波次已取消 |
| 切换顶栏仓库 | 列表只显示该仓波次 |
