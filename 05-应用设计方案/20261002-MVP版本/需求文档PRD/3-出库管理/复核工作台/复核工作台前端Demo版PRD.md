# 复核工作台前端Demo版PRD

> 用途：在 `qs-wms-demo` 实现管理端复核工作台；说明路由、步骤、扫码规则、草稿、提交与走查。
> 规则真源：[《出库单主PRD》第7.5节](../出库单/出库单主PRD.md#75-复核)（按原单复核、复核方式与容器、序列号不重复计数、B2C 包裹信息、出库前删除重做），本文不重抄。布局真源：[《复核工作台页面骨架》](复核工作台页面骨架.md)。同一业务的 PDA 形态见[《PDA复核前端Demo版PRD》](../../7-PDA作业端/复核作业/PDA复核前端Demo版PRD.md)，两端读写同一份 `outboundVerifications`。共用约定见[出库单公共分册](../出库单/前端Demo版PRD/出库单前端Demo版PRD_公共与技术约定.md)。
> 版本：WMS-V0.1｜日期：2026-10-15。

**样式与组件**：**布局与占位须符合[需求文档 PRD / AGENTS.md](../../AGENTS.md)「布局硬规则」一节**；作业台字号、反馈分级、焦点与提示文案按原型[《作业台设计规范》](../../../../../09-产品原型/qs-wms-demo/docs/04-作业台设计规范.md)。样板 `pages/wms/inbound/inbound-order-receive-page.tsx`。

## 一、页面与路由

| 路由 | 组件 | 菜单 |
| --- | --- | --- |
| `/wms/outbound/verify-station` | `pages/wms/outbound/verify-station-page.tsx` | 出库管理 → `menu.verifyStation`「复核工作台」，排在拣货任务之后 |

- 当前单号写在查询参数 `?no=`；出库单详情「去复核」下拉的「复核工作台」带 `?no=` 进入。
- 顶栏仓库过滤：`no` 不属当前仓、已出库、已取消或没有待复核量时，不进入第二步，提示条写原因并清掉参数。
- 提交只受出库单状态、待复核量等业务规则约束，不按角色限制。

## 二、派生与动作

不新增单据、状态或动作，全部复用 `useDb().outboundAction`：

| 用途 | 来源 |
| --- | --- |
| 候选单 | `outboundOrders` 中本仓、非已出库／已取消、`Σ已拣 > Σ已复核` |
| 复核行 | `orderAssignments(db, no)`，每条有效实拣归属一行；待复核＝`verificationRemaining(db, a).qty`，可扫序列号＝`verificationRemaining(db, a).serialNos` |
| 本单进度 | 出库单各行 `pickedQty`、`verifiedQty`（`lineQty`） |
| 提交 | `VERIFY`：`{ no, method, containerType, containerNo, weightKg, lines: [{ assignmentId, qty, serialNos }] }`，成功返回复核记录号，Mock 运单号为 `MOCK-<复核记录号>` |
| 补包裹、删除重做 | 不在工作台；出库单详情复核记录页签的 `PACK_VERIFY`、`DELETE_VERIFY` |

## 三、扫码规则（一个扫码框）

| 当前步骤 | 扫到 | 结果 |
| --- | --- | --- |
| 未定位单 | 本仓可复核的出库单号（忽略大小写） | 写入 `?no=`，进入第二步；绿闪 |
| 未定位单 | 其他内容 | 红闪：「没找到可复核的出库单：X」＋原因（不在本仓／已出库／已取消／没有待复核） |
| 已定位单 | 本单某行尚未复核、本次也没扫过的序列号 | 该行本次 +1 并记下序列号；该行设为当前行 |
| 已定位单 | 已复核过或本次已扫的序列号 | 红闪：「序列号 X 已经复核过」或「本次已扫」 |
| 已定位单 | 商品编码或条码（主条码、本货主条码） | 序列号商品：红闪「要逐件扫序列号」；普通商品：当前行是该商品且有余量则记当前行，否则记第一条有余量的同商品行，本次 +1 |
| 已定位单 | 本单商品但各行都已扫满 | 红闪：「X 已经扫满」＋本单该商品待复核数 |
| 已定位单 | 其他可复核出库单号 | 本次没有录入时切换到该单；有录入时红闪「本次还有 N 件没提交」 |
| 已定位单 | 其他内容 | 红闪：「没找到这个商品：X」＋「它不是本单待复核的商品」 |

- 普通商品可在「本次」列直接改数，回车回到扫码框；超过待复核量拒绝并保留原值。序列号商品「本次」只读，行尾「×」清空本行。
- 同一商品多批次：点行设为当前行，扫商品记到当前行，批次核对由作业员看行内批次完成；不另设扫批次步骤。

## 四、装箱与提交

| 控件 | 默认 | 规则 |
| --- | --- | --- |
| 复核方式 | B2C 随打包装箱；其他随分拣（本单已有有效随分拣记录时改为随打包装箱） | 单选按钮组 |
| 容器类型 | B2C 包裹；其他无（随打包装箱时为箱） | 无／包裹／箱／托 |
| 容器号 | B2C 预填 `PKG-<出库单号>` | 容器类型非无时必填 |
| 模拟重量（kg） | 空 | 随打包装箱时显示；B2C 随打包装箱必填正数 |

提交按钮「提交复核（N 件）」，本次为 0 时不可点。前端先查：本次有数量、容器号、B2C 包裹与重量；不通过时提示条写缺什么并聚焦对应输入。动作被拒时用「知道了」弹窗写 `t(errorKey)`，本次录入保留。成功后清空本次，提示条写「已提交复核 VR-…：N 件，包裹 PKG-…，运单 MOCK-…」；本单已全部复核时回到第一步，否则停留本单。

## 五、本次草稿

`stores/web-verify-session.ts`（zustand persist，名 `qs-wms-demo-web-verify`）按「仓库＋出库单号」保存：各行本次数量与序列号、当前行、复核方式、容器类型、容器号、重量。刷新、切页签不丢；提交成功、清空本次、换一单（二次确认）后移除。草稿不是业务记录，不计入有效复核量。

## 六、出库单详情入口

页头「去复核」改为下拉：「复核工作台」（`/wms/outbound/verify-station?no=`）与「PDA 复核」（`/pda/verify?no=`）。显示条件不变。复核记录页签与 PDA 提交一样即时出现新记录。

## 七、i18n

页面文案放 `outbound.ui.station*`（`[中文, English]` 成对），菜单名 `menu.verifyStation`。提示条结果在发生时翻译，切换语言时清掉结果，回到当前语言的默认提示。

## 八、走查

| 步骤 | 操作 | 预期 |
| --- | --- | --- |
| 1 | 0001 生成拣货任务，PDA 拣货 3 件并提交 | 出库单待复核，已拣 3 |
| 2 | 出库单详情「去复核 → 复核工作台」 | 直接进入 0001，待复核 3；B2C 默认随打包装箱＋包裹 |
| 3 | 扫错条码；扫 CABLE-01 三次；再扫一次 | 红闪写原因；本次 3；第四次提示已扫满 |
| 4 | 不填重量提交 | 提示条写缺重量，重量框获焦 |
| 5 | 填 0.45 提交 | 绿色提示带 VR 号与 MOCK 运单；回到第一步 |
| 6 | 回出库单详情 | 复核记录页签 +1，已复核 3，包裹信息齐全，可确认出库 |
| 7 | 刷新中途页面 | 本次录入与装箱信息保留 |
| 8 | 切 English、DE-FRA-01 各走一遍 | 文案、仓库过滤随之变化 |
