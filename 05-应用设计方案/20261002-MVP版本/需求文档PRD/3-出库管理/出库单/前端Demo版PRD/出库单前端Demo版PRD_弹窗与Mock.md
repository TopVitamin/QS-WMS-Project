# 出库单前端Demo版PRD·弹窗与Mock

> **版本**：WMS-V0.2  
> **更新时间**：2026-10-15  
> **定位**：统一定义出库单的**确认出库、登记交接、退拣、包裹信息、OMS Mock、创建其他出库、指令处理记录**七个弹窗，以及 Mock 种子。正式验收不以 Demo Mock 为准。  
> **业务规则**：[《出库单主PRD》](../出库单主PRD.md)（§6.5、R01～R04、R09～R15；F04、F06～F11）。

## 1. 共用约定

| 项 | 约定 |
| --- | --- |
| 容器 | `Dialog`，宽度 `sm:max-w-*`；内容超高时内部滚动，底部按钮固定 |
| 布局 | `FormGrid columns={2}` + `FormField`；长文本 `className="col-span-2"` |
| 必填 | `FormField required`；提交时前端先校验必填与正整数，再调动作 |
| 反馈 | 失败 `toast.error` 写具体原因，弹窗不关、输入保留；成功 `toast.success` 写对象与数量后关闭 |
| 占位 | 可编辑 Input 用 `common.inputPlaceholder` 或模块 key；Select 用 `common.selectPlaceholder`；只读字段不设 |
| 枚举 | 两到三项的单选用 `RadioGroup` 横排，多项用 `OptionSelect`；渠道、货主选项显示「编码 名称」 |

## 2. 确认出库（F08）

| 项 | 内容 |
| --- | --- |
| 入口 | 详情页头「确认出库」（待出库、主管） |
| 宽度 | `sm:max-w-2xl` |
| 标题 | 「确认出库 · 单号」；描述「确认后按实发扣减出库暂存库存，不能撤销」 |

**逐行检查区**：调用 `shipCheck(order, db)`，每行一条：商品、需求、已拣、已复核、实发、未发；有问题的行红字（`text-destructive`）写 `outbound.ui.problem*`；整单问题（未完成任务、B2C 包裹未齐）写在检查区底部；FBA、批发有未发时写「可缺量结案」。

**同时登记交接**：`Checkbox`「同时登记交接」，默认不勾；勾选后展开 §3 的交接字段（同一组件 `HandoverFields`）。

**提交**：按钮文案「确认出库（实发 N 件）」，`shipCheck.ok=false` 时 `disabled` 并在按钮左侧写第一条问题；勾选交接时先校验交接必填。调用 `run({type:'SHIP', no, handover?})`，成功 toast「OB-… 已出库，实发 N 件」，详情刷新为已出库。

## 3. 登记交接（补登，F08）

| 字段 | 控件 | 必填 | 规则 |
| --- | --- | --- | --- |
| 交接方式 | `RadioGroup`：承运商／司机交接／客户自提 | 是 | 默认承运商 |
| 交接对象 | `Input` | 是 | 承运商名、司机或自提人 |
| 物流渠道 | `OptionSelect`（启用渠道，编码 名称） | 否 | 默认带出库单渠道 |
| 运单号或面单号 | `Input` | 否 | — |
| 包裹或箱托数 | `Input type=number` | 是 | 正整数；默认取有效复核记录的容器数，无容器为 1 |
| 交接时间 | `DateTimeField` | 是 | 按顶栏展示时区录入，默认当前时间，提交转 UTC |
| 交接备注 | `Textarea`，`col-span-2` | 否 | — |
| 交接凭证附件 | `MockPhotoField`，`col-span-2` | 否 | 模拟上传，只存文件名 |

入口：详情页头「补登交接」（已出库）。提交 `run({type:'HANDOVER', ...})`，成功 toast「已登记交接 HO-…」，交接记录页签 +1，库存不变。字段组件 `HandoverFields` 与确认出库共用，校验一致。

## 4. 退拣（F07）

| 字段 | 控件 | 必填 | 规则 |
| --- | --- | --- | --- |
| 实拣归属 | `OptionSelect`，选项「商品 · 批次 · 来源库位 · 有效 n」 | 是 | 只列本单有效实拣 > 0 的归属；只有一条时默认选中 |
| 退拣原因 | `RadioGroup`：少件／残损 | 是 | 默认少件；少件下方提示「将标记该 SKU 待核对」，残损提示「须先由主管转不良」 |
| 退拣数量 | `Input type=number` | 是 | 1～有效数量；超出时字段下红字，不提交 |
| 序列号 | `Textarea`，每行一个 | SN 商品必填 | 条数等于数量，须属于该归属 |

提交 `run({type:'UNPICK', ...})`，成功 toast「已退拣 N 件，生成返库上架单 PB-…」，返库上架单页签 +1，汇总卡已拣、已复核同步减少。

## 5. 包裹信息（F06）

| 字段 | 控件 | 必填 | 规则 |
| --- | --- | --- | --- |
| 包裹号 | `Input` | 是 | 默认原记录容器号，空时为 `PKG-复核记录号` |
| 模拟重量（kg） | `Input type=number`，步长 0.01 | 是 | 大于 0 |

入口：复核记录页签行内「补包裹信息」（B2C、未出库、未删除）。提交 `PACK_VERIFY`，成功 toast「已生成 Mock 运单 …」，复核记录行出现模拟运单号；复核数量不变。

## 6. OMS Mock、创建其他出库、指令处理记录（F10、F11）

### 6.1 OMS Mock

文件 `mock-dialog.tsx`，`mode: 'CREATE' | 'CHANGE' | 'CANCEL'`，宽度 `sm:max-w-3xl`。

| 字段 | 新建 | 变更 | 取消 |
| --- | --- | --- | --- |
| 消息标识 | 自动生成，可改 | 同左 | 同左 |
| 预期对象版本 | 0 | 原单当前版本 | 原单当前版本 |
| 业务类型、仓库、货主、上游指令号 | 可填（仓库默认顶栏） | 只读带出 | 只读带出 |
| 物流渠道、收货人、联系电话、收货地址、备注 | 可填；收货人、地址必填 | 不显示 | 不显示 |
| 引用原入库单号 | 采购退货出库必填 | 不显示 | 不显示 |
| 明细行（商品、需求数量） | 1～N 行，同 SKU 不重复 | 可改数量、增删行 | 不显示 |
| 取消原因 | — | — | 可填 |

- 从列表进入为新建；从详情「更多」进入锁定变更或取消。
- 提交分别调 `CREATE`／`CHANGE`／`CANCEL`；成功 toast「已接收，生成 OB-…」或「已受理变更／取消」；拒收 toast 写具体原因，并写入处理记录。
- 业务类型选「其他出库」时，明细行改为选择不良品库存（同 §6.2）。

### 6.2 创建其他出库（主管）

同一文件 `mode='MANUAL'`。字段：仓库（默认顶栏）、货主、线下依据摘要（必填，`Textarea col-span-2`）、明细行。每行：商品、库存明细（`OptionSelect`，只列本仓本货主该商品已上架的不良品，选项「库位 · 批次 · 可指定 n」）、指定数量（不超过可指定）、序列号（SN 商品必填）。提交 `CREATE`（`source:'MANUAL'`），成功跳新单详情。

### 6.3 指令处理记录

文件 `messages-dialog.tsx`，宽度 `sm:max-w-5xl`。`DataTable`（`createDataColumns<OutboundMessage>()`，时间倒序）：消息标识、上游指令号、动作、预期版本、结论（`StatusBadge`）、出库单号（`DocNo` 跳详情并关闭弹窗）、拒收原因、时间、操作「重发」。重发按原消息内容重放，返回原结论时 toast「消息已处理，返回原结论」。
