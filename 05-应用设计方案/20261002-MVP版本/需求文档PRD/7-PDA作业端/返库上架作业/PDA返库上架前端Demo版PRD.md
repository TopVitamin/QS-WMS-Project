# PDA返库上架前端Demo版PRD

> **版本**：WMS-V0.2｜2026-10-18。V0.2：改为按建议库位逐站放回（扫目标库位到站 → 扫商品计数 → 数满自动保存 → 本库位放完自动跳下一个 → 全部保存后提交），取代 V0.1「先选行再扫目标再填数」。  
> **业务真源**：[返库上架单主PRD第三节](../../3-出库管理/返库上架单/返库上架单主PRD.md#三保存与提交校验)；布局见[页面骨架](PDA返库上架页面骨架.md)。管理端不用 PDA 时走[返库上架单 Web 端返库](../../3-出库管理/返库上架单/返库上架单前端Demo版PRD.md#五web-端返库录入页)，两端调用同一组动作。  
> **样式与交互服从[《PDA作业端设计规范》](../PDA作业端设计规范.md)**，与 PDA 拣货同一套按库位作业版式。

## 1. 能力概述

| 项目 | 内容 |
| --- | --- |
| 作业对象 | 返库上架单（取消或复核退拣自动生成） |
| 路由 | `/pda/return-putaway`；步骤用路由参数 `step`；`no` 为返库单号，`at` 为当前站（建议库位），`to` 为实际扫到的目标库位 |
| 返库路径 | 还没保存满的应返库行按建议库位（原拣货库位）分组，按库位编号顺序排（`putbackStops`）；一站一个建议库位 |
| 计数 | 扫目标库位后，每扫一件商品本行＋1；SN商品也可按数量录入，不强制逐件SN落位；数满本行剩余自动保存落位；件数多时扫一件后改数量再点保存 |
| 数据动作 | `outboundAction`：`SAVE_PUTBACK`（仅本次全部逐件核实且SN数与数量一致时带SN；否则按数量保存，不补造SN）、`RESET_PUTBACK_LINE`、`SUBMIT_PUTBACK`；与 Web 端返库相同 |
| 草稿 | 还没保存的计数存 `stores/pda-outbound-session.ts`（按「仓库:返库单号」）；已保存的落位在返库单里，不进草稿 |

## 2. 步骤与返回

| step | 屏幕 | 进入方式 | 安卓返回键 / 标题栏返回 |
| --- | --- | --- | --- |
| `list` | 选返库单 | 首页「返库上架」；默认 | 回首页 |
| `work` | 按库位返库 | 扫到或点选返库单；管理端「PDA返库上架」带 `step=work&no=` | 回选返库单 |
| `done` | 全部已保存 | 最后一行保存后自动进入 | 回选返库单 |

- 到站（`at` + `to`）随路由保存；刷新后丢了目标时，未保存的计数先不显示，重扫目标库位后接着数，保证计数落到扫过的库位。
- 返库单已完成时回到选返库单并提示。

## 3. 每步可识别的码

| 步骤 | 可识别 | 命中 | 不命中（扫码错误：红闪、低音、红字） |
| --- | --- | --- | --- |
| 选返库单 | 返库上架单号；原出库单号 | 进入按库位返库 | 「没有找到待返库的单据：xxx」 |
| 按库位返库·未到站 | 库位码（本仓存储、拣货、不良隔离库位） | 是某站的建议库位 → 到该站；是其他合法库位 → 改放到该库位（卡片写「改放库位（建议 L）」） | 收货暂存、出库暂存、异常处理等库位：「不能放返库货」；扫到商品／SN：「请先扫描目标库位 L」；其他：「没认出 xxx」 |
| 按库位返库·已到站 | SN（本站某行还没落位的 SN）；商品（SKU 编码、本货主启用条码、主条码）；库位码 | 本行 +1，数满自动保存；库位码＝换站或改放 | SN 本次已扫；同商品多批次未选行（提示点选）；本站另一行有未保存计数；商品属于别的站：「X 建议放回 L」；都不是：「不是本单要返库的商品」 |

- 品质、货主、混放在保存时由动作校验；不通过弹「知道了」阻断，计数保留，可改扫别的库位。
- 模拟扫码候选：选返库单＝前 3 个待返库单号；未到站＝本站建议库位（标「建议」）、下一站库位；已到站＝本站各行主条码；SN可手动扫描识别商品或逐件核实。

## 4. 屏幕内容

**按库位返库**（`work`）：上下文条（返库单号 · 退拣原因 · 已保存/应返库）；当前站卡片（「建议放回库位」→「已到达库位」或「改放库位（建议 L）」，右侧下一站）；扫码框；「本库位待放（n）」行卡（SKU、品质标签、名称、批次、实际逐件核实的SN依据，右侧「待放 n」或「已数 a/n」，下方「应返库 · 已保存」）；「已保存落位（n）」分组列出各行落位，行右侧红字「重录」（需确认，清掉本行全部落位，不动库存）。底部：未到站提示扫目标库位；计数中显示数量步进器（SN商品也支持数量录入）与主按钮「保存落位（n 件）」。

**全部已保存**（`done`）：完成卡（应返库、已保存、落位处数）；少件原因时提示「少件仍按应返库量提交，再盘点扣差异」；已保存落位列表（可重录）；说明「提交后才把库存从出库暂存移到各目标库位」；主按钮「提交返库上架」→ 确认弹窗 → `SUBMIT_PUTBACK` → toast 并回到选返库单。

## 5. i18n

文案在 `outbound.ts` 的 `pdaReturn` 组（中英成对），计数类提示复用 `pdaPick` 的 `okBump`、`errSnUsed`、`errNeedSn`、`infoPickBatch`、`counted`、`clearCount`。

## 6. 走查

种子 0020 生成的 PB-…-0002：CABLE-01 × 1 建议 A-01-01，SN-DEMO-01 × 1 建议 A-01-02。

| 步骤 | 操作 | 预期 |
| --- | --- | --- |
| 1 | 首页 → 返库上架 | 列表 2 张；PB-…-0002 显示「2 个库位 · 2 行」 |
| 2 | 打开 PB-…-0002，先扫商品条码 | 红闪：「扫到的是商品 CABLE-01：请先扫描目标库位 A-01-01」 |
| 3 | 扫 A-01-01，扫线材条码 | 自动保存 1 件到 A-01-01，提示本库位放完、前往 A-01-02；下方「已保存落位」出现一行 |
| 4 | 扫 B-01-02（他货主占用），扫 SN | 卡片显示改放 B-01-02；保存被阻断：「目标库位或返库数量不符合规则…」 |
| 5 | 扫 A-01-02，扫 SN | 自动保存，进入「全部已保存落位」：应返库 2 · 已保存 2 · 落位 2 |
| 6 | 提交返库上架 | 确认后 toast「库存已返库」，回到列表；管理端详情已完成、实际返库明细 2 行 |
