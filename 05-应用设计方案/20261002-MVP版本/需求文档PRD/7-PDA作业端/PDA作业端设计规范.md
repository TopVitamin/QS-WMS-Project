| 项 | 约定 |

## 2. 设备基线

参考机型（一期验收不绑定机型）：

| 机型 | 屏幕 | 分辨率 | CSS 视口 | 说明 |
| --- | --- | --- | --- | --- |
| 新大陆 MT90 | 5 英寸 | 720×1280 | 360×640 | 16:9 全触屏 |
| 成为 C66 | 5.5 英寸 | 720×1440 | 360×720 | 18:9 全面屏，当前主流 |
| 优博讯 DT50 | 5.7 英寸 | 720×1440 | 360×720 | 18:9 全面屏，当前主流 |
| 东集 AUTOID Q9 | 4 英寸 | 800×480 | 约 320×533 | 24 键键盘机，支持厚手套触控 |

CSS 视口按 2 倍（5 英寸以上）、1.5 倍（4 英寸）像素密度换算。一期全屏运行（装成应用或用企业浏览器打开，没有地址栏），只扣状态栏（24）；带虚拟导航栏的机型再少 48。由此定三档：

| 档位 | 可用区域 | 要求 |
| --- | --- | --- |
| **验收基线** | 360×616 | 5 英寸机全屏运行时的可用区域。每一屏的主按钮、当前对象和关键数量不滚动就能看到 |
| 宽松档 | 360×696 | 5.5～5.7 英寸 18:9 机（当前主流）全屏运行时的可用区域；用来检查留白是否过大 |
| 兼容档 | 320×509 | 4 英寸键盘机。允许主区滚动，但底部主按钮始终可见；文字不得截断到看不出含义 |

任何档位都不允许横向滚动。模拟机框按整块屏幕画（状态栏 24 + 可用区），比例与真机一致；默认显示当前主流的 18:9 机型（720×1440，可用区即宽松档 360×696），机框上方可切换 5 英寸机（验收基线 360×616）和 4 英寸键盘机（兼容档 320×509）。窗口不够高时整台等比缩小，不压扁比例。验收按 360×616 检查。

## 3. 页面骨架

所有作业页面统一分四段：

```text
+------------------------------------+
| <  作业名                 US-LA-01 |  标题栏：返回、作业名、当前仓库编码
+------------------------------------+
| IB-…0001 · 容器 BOX-01 · 已录 2 行  |  上下文条：本次作业的单据与进度（有才显示）
+------------------------------------+
| 请扫描商品条码                      |  主区（可滚动）：提示语、扫码框、
| [扫] 等待扫描…               [键盘] |  当前对象卡片或列表
| …                                  |
+------------------------------------+
| [次按钮]          [   主按钮   ]    |  底部操作区（固定）
+------------------------------------+
```

- **一屏一件事**：每屏只有一个主按钮，放在底部操作区右侧或通栏。
- **提示语代替步骤条**：扫码框上方的提示语说明「现在该扫什么」，进度放在上下文条。超过 3 步的作业不用步骤条，360 宽放不下 4 个以上带文字的步骤。
- **底部操作区固定**：内容超出时只滚主区，主按钮始终可见。主按钮不可用时，原因写在按钮上方一行，不藏在主区底部。
- **上下文条常驻**：已绑定的单据、容器、库位等，在后续每一屏都能看到；单号完整显示、末几位加粗。
- **核心交互不用下拉和浮层**：6 个以内的枚举用大按钮组（每项不小于 48px），更多选项用整屏选择页；下拉、浮层只用于低频设置。
- **弹窗只做两件事**：业务阻断提示、二次确认。

## 4. 扫码与数量录入

### 4.1 扫描接入

一期按「键盘模拟」接入：扫描头把条码当键盘字符输出，以回车结尾。现场设备须在扫描设置里把输出方式设为键盘（或文本框）、结束符设为回车。这是「扫了没反应」「扫了不跳下一步」最常见的原因（[极风：PDA扫码异常解决方案](../../../../02-竞品调研和分析/极风WMS/01-原始页面/JF-PDA-013-PDA扫码异常解决方案.md)）。一期不对接厂商广播或 SDK。

### 4.2 扫码优先

扣下扫描键时，作业员眼睛在货上。页面必须保证扫到的码一定按扫码处理：

| 当时焦点在哪 | 处理 |
| --- | --- |
| 扫码框 | 扫码框接收，回车后按本步规则识别 |
| 没有聚焦任何输入框 | 页面级监听接收整串字符，回车后按本步规则识别 |
| 数量输入框 | 数量框**不得**接收扫码内容。内容含非数字字符或超过 6 位时视为扫码：数量恢复原值，内容按本步扫码规则处理 |

进入每一步自动聚焦扫码框；弹窗关闭后焦点回到扫码框。

### 4.3 识别规则

- 每个作业 PRD 必须列出「每一步能识别哪些码、命中后去哪、不命中怎么提示」。
- 统一去首尾空格；单号、编码类比较不区分大小写；条码原样比较。
- 商品识别与管理端一致：SKU 编码、货主条码、主条码，按单据货主匹配。
- 扫到不该在这一步出现的码（如绑容器时扫到商品条码），要说出扫到的是什么码，不能只报「无效」。

### 4.4 手动输入兜底

- 扫码框默认不弹软键盘，避免遮住半个屏幕。
- 扫码框右侧放「键盘」按钮，点按后弹出软键盘手输，回车提交；用于条码褶皱、反光扫不出时。
- Demo 中每一个扫码步骤都要有「模拟扫码」候选值（包括容器、库位），否则没有扫描枪就走不下去。

### 4.5 数量录入

- 默认值由作业 PRD 规定（如按待收、按剩余应上架带出）。
- 步进器 −/+ 之外，点数字可直接改，回车或离开输入框时生效。
- **超出上限不截断**：拒绝本次修改，提示上限，保留原值。不能把输入静默改成上限。
- 支持逐件计数的作业：再扫一次同一商品，数量 +1。
- 联动规则（如「改不良品时良品自动扣减」）必须与管理端同一动作一致，并写进作业 PRD。

### 4.6 按库位作业（拣货、返库上架、上架）

要去多个库位的作业按「一个库位一站」推进，作业员不用自己挑行、也不用回列表：

| 规则 | 说明 |
| --- | --- |
| 路径 | 还没做完的行按库位分组、按库位编号自然顺序排（A-01-02 在 A-01-10 前）；拣货按来源库位，返库按建议库位，上架按推荐库位（没有推荐库位的行排最后一站，扫任一可用库位） |
| 当前站卡片 | 扫码框上方固定一张当前站卡片：未到站为主色「前往库位」+ 24px 库位号，到站后变绿「已到达库位」；右侧写下一站。下面列出本站要做的商品（编码、名称两行、批次、待做数量 24px） |
| 先到站 | 先扫库位确认到站，扫到商品时提示「请先扫描库位 X」，说出扫到的是什么；扫到路径上另一个还有活的库位就改去那里（返库、上架可改放到其他合法库位，卡片写明「改放库位（建议／推荐 X）」） |
| 扫码计数 | 到站后每扫一件 +1（SN 商品每扫一个 SN）；数满本行剩余自动确认或保存，不用点按钮；件数多时扫一件后在底部数量框改数，再点主按钮 |
| 自动跳站 | 本站做完自动换成下一站并提示去哪，主区回到顶部；全部做完自动进入汇总提交屏 |
| 未确认计数 | 本机草稿；本站有未确认计数时不能换站、不能数另一行，提示先确认 |
| 多批次 | 同一库位同一商品多个批次时，扫批次号或点选行区分，选定后接着计数 |
| 低频操作 | 缺货、重录等放在行卡或分组里，缩小、红字，远离底部主按钮 |

### 4.7 处理连续扫码

扫码处理一律读最新数据：动作写入后、路由切换后组件可能还没重渲染，紧跟的下一枪不能拿旧状态判断（例如刚扫完库位就扫商品，不能被当成「未到站」；连扫两件不能只记一件）。

## 5. 反馈分级

| 级别 | 场景举例 | 声音与震动 | 界面 | 消失 |
| --- | --- | --- | --- | --- |
| 成功 | 扫码命中、加入、提交成功 | 短高音 | 扫码框绿闪；扫码计数类作业在扫码框下一行写绿字结果（对象 + 数字，如「CABLE-01 +1，已数 2/3」），离开本屏的结果用轻提示 | 绿字到下一次扫码时换掉；轻提示 1.5 秒自动 |
| 扫码错误 | 码不存在、不属于本单、库位不可用 | 长低音 + 震动 | 扫码框标红，框下一行红字写原因 | 下一次扫码时清除 |
| 业务阻断 | 容器已用、超收、单据状态已变、提交校验失败 | 长低音 + 震动 | 阻断弹窗，写清原因和下一步 | 必须点「知道了」 |
| 需确认 | 放弃草稿、提交整箱或整单、撤销已录明细 | 无 | 确认弹窗，列出影响 | 手动 |

- 提示音要在嘈杂仓库里听得见；成功音和错误音在音高、时长上明显区分。
- 轻提示不得遮挡标题栏的返回键。
- 语音播报一期不做。

## 6. 返回、离开与草稿

- **安卓返回键 = 标题栏返回 = 回到上一步**，不是退出整个作业。每一步对应一条浏览历史（路由参数 `step`），第一步再返回才回首页。
- **草稿保留**：还没提交成业务记录的录入（如收货作业中已暂存的容器与明细）保存在本机，每次录入即时保存。离开作业、刷新页面、换电池重启后再进入，先问「继续上次作业」还是「放弃」。
- **放弃要确认**：放弃草稿、换单据、换容器时，如有未提交内容，二次确认并列出会丢掉的内容。
- 已提交的业务记录不受返回影响；已保存的进度（如上架单的实际上架明细）以业务记录为准，不进草稿。

## 7. 触控与文字

| 项 | 要求 |
| --- | --- |
| 可点元素 | 不小于 48×48px，标题栏返回键同样适用 |
| 主按钮 | 高不小于 48px，通栏或占底部操作区大半；戴手套岗位（冷库、搬运）建议 56px |
| 列表行 | 整行可点，行高不小于 56px |
| 间距 | 相邻可点元素不小于 8px |
| 危险或低频操作 | 放弃、撤销、标记缺货、强制完成等：缩小、远离主按钮、不与主按钮同色（[极风：缩小「标记缺货」按钮](../../../../02-竞品调研和分析/极风WMS/01-原始页面/JF-PDA-026-为防止仓库频繁点错，PDA上面的操作按钮-标记缺货按钮比例缩小，减低误操出错率.md)） |

| 文字 | 字号 |
| --- | --- |
| 关键信息：库位、数量、单号尾号、SKU 编码 | 18～24px 粗体 |
| 正文、按钮 | 15～16px |
| 辅助说明、标签 | 13～14px |
| 下限 | 12px；关键信息不得用 12px |

- 编码类（单号、库位、SKU、容器号）用等宽字体，便于对照实物标签逐位核对。
- 商品名称最多两行，不截成一行省略号；作业员要靠名称核对实物。
- 颜色只用语义色；状态颜色统一走状态映射，页面里不自行配色。

## 8. 多语言、时间与仓库

- 中文、英文两套文案全部走语言包。英文更长：按钮控制在两个词内，标签不截断。
- PDA 不提供时区切换，时间一律按当前仓库时区显示。
- 当前作业仓在首页选择，标题栏右侧常驻显示仓库编码；业务数据按当前仓过滤。
- 一期无登录，操作人取全局设置中的当前用户，写入业务记录。

## 11. 与竞品的取舍

| 竞品做法 | 本项目 |
| --- | --- |
| 原生 APK，适配优博讯、东集等扫描引擎 | 一期浏览器页面 + 键盘模拟扫码；二期再评估 |
| 按单收货时扫完多箱再一次提交（[领星：使用PDA实现收货](../../../../02-竞品调研和分析/领星WMS/01-原始页面/LX-WMS-022_使用PDA实现收货.md)） | 采用：一次作业可新增多个容器，统一或分批提交，一次提交生成一条收货记录（《入库单主PRD》R16、R17） |
| 扫一次记一件（领星收货、[极风收货上架](../../../../02-竞品调研和分析/极风WMS/01-原始页面/JF-PDA-018-PDA收货、上架.md)） | 采用：收货录入支持逐件计数 |
| 返回后保留扫描记录（领星收货） | 采用：草稿保留 |
| 扫错震动加告警音、禁止提交（[领星：移动端PDA作业](../../../../02-竞品调研和分析/领星WMS/02-竞品知识库/10-移动端PDA作业与报表.md)） | 采用：第 5 节反馈分级 |
| 先扫库位、再扫商品、填数量（[领星：通过PDA实现上架](../../../../02-竞品调研和分析/领星WMS/01-原始页面/LX-WMS-020_通过PDA实现上架.md)） | 采用先扫库位再扫商品；数量改为逐件扫码计数，件数多时扫一件后改数（§4.6） |
| 离线缓存、断网续传 | 一期不做（本机运行） |
| 语音播报 | 一期不做 |
