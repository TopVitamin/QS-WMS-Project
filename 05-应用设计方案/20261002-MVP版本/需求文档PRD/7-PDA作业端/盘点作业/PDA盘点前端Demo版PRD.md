# PDA盘点前端Demo版PRD

版本：WMS-V0.3｜2026-10-21（按 Demo 实现回写）。规则见[盘点单主PRD](../../4-库存管理/盘点单/盘点单主PRD.md)，布局见[PDA盘点页面骨架](PDA盘点页面骨架.md)。差异确认与取消只在管理端提供。

路由：`/pda/stocktake`列本仓盘点中单据，并列出本仓待核对、还没在盘点中的商品作为发起入口；`/pda/stocktake?step=location&no=ST-…`执行实盘，`step`允许`list`、`location`、`item`、`count`、`review`；`/pda/stocktake/start`发起盘点，参数带货主、SKU、发现环节、原单号、库位。

## 一、实盘步骤

| 步骤 | 可识别的码 | 成功结果 | 校验与候选 |
| --- | --- | --- | --- |
| 选择盘点单 | ST单号 | 打开本仓盘点中单据 | 候选为当前仓盘点中；已完成／取消阻断 |
| 扫库位 | 存储、拣货、不良隔离库位 | 列出该位在盘范围 | 暂存库位阻断；候选来自盘点快照，另列一个快照外的空库位 |
| 扫商品 | SKU、商品条码；SN商品扫SN | 定位快照行或创建待确认新增行 | 商品须在本盘SKU范围；SN须是本仓这个商品的序列号，账面在别的库位时照实记在本库位；同一SN只能盘在一行 |
| 录入实盘 | 普通SKU再扫同一商品+1，件数多时改数；SN逐件扫描 | 只显示已数，不显示账面（盲盘） | 数量≥0；SN数即实盘量；重复SN阻断；新增批次行先填批次号和有效期 |
| 保存 | 不接收扫码 | 这时才显示账面、实盘、差异和SN差异，填差异原因说明后保存，回库位继续 | 只写实盘，不改库存；重复保存更新同一行并留录入人时间 |

快照外新发现的归属明确实物按账面0新增一行（品质跟库位用途：不良隔离库位记不良品）；认不出归属的提示去无主货登记。保存后管理端立即看到同一盘点单数据。安卓返回逐步回退；当前未保存行进本机草稿，已保存实盘属于业务记录。刷新可恢复未保存草稿，选择放弃时二次确认；去盘另一行时，有未保存计数先确认放弃。

## 二、发现账实不符发起

入口：盘点首页的“待核对商品”（拣货缺货、复核少件、移库时上报的待核对，带最近一次发现的环节、原单号或库位），以及PDA移库确认账实不符后。用户确认账实不符时，原作业已用共用的库内动作`REPORT_DISCREPANCY`（或出库缺货、退拣动作）立即按本仓库＋货主＋SKU标记“待核对”。

当该SKU还有进行中的上架、返库上架或拣货任务时，页面逐条列出并提示先收尾当前任务，不创建盘点单；等待期间仍保持“待核对”。收尾后用户补充少了多少与说明，调用`CREATE_STOCKTAKE_FROM_DISCREPANCY`创建盘点单。创建成功返回ST号并直接进入实盘，不重复设置“待核对”。

发现依据使用原业务记录，不另建差异单。该SKU已在盘点中时，同一动作不新建盘点单：把本次发现环节、原单号、库位、差异数量和说明追加到该单发现依据，返回原ST号并提示已加入，不重复冻结。

## 三、动作与文案key

实盘保存走`SAVE_COUNTS`（快照行）和`ADD_COUNT_LINE`（新增行），与管理端实盘录入共用。文案放在`pdaStocktake`分组（`pda.count`已是首页宫格名）。

| 业务动作／文案 | key | 中文 | 英文 |
| --- | --- | --- | --- |
| 保存本行实盘 | `pdaStocktake.saveCount` | 保存实盘 | Save Count |
| 发起盘点 | `pdaStocktake.createStocktake` | 发起盘点 | Start Count |
| 已在盘点中时追加 | `pdaStocktake.appendSubmit` | 加入现有盘点 | Add to Count |
| 等待任务收尾 | `pdaStocktake.pendingTaskClose` | 已标记待核对，请先提交当前任务 | Marked for review. Finish the current task first. |
| 已有盘点 | `pdaStocktake.existingStocktake` | 已加入现有盘点 {{no}} | Added to existing count {{no}} |

## 四、反馈、权限与走查

PDA用户须有当前仓授权和相应盘点发起／实盘权限。扫描错误就近提示，状态变化、范围不符和任务未结束用业务阻断弹窗或页面提示。每一步提供来自当前单据的模拟候选。

走查：计划盘点、多SKU多库位、分人分次、普通数量、SN、账面0新增行、无法识别归属、发现差异后立即待核对、任务未提交时暂不建盘点、已有盘点时追加发现依据、管理端确认前重录、单据状态变化、重复保存。验证实盘保存不动库存，只有管理端差异确认才调账。
