# PDA盘点前端Demo版PRD

版本：WMS-V0.1｜2026-10-15。规则见[盘点单主PRD](../../4-库存管理/盘点单/盘点单主PRD.md)，布局见[PDA盘点页面骨架](PDA盘点页面骨架.md)。主管差异确认与取消只在管理端提供。

路由：`/pda/stocktake`列本仓盘点中单据；`/pda/stocktake?no=ST-…`执行实盘，`step`允许`location`、`item`、`count`、`review`；`/pda/stocktake/start`从拣货、复核、上架或返库上架的差异入口发起。

## 一、实盘步骤

| 步骤 | 可识别的码 | 成功结果 | 校验与候选 |
| --- | --- | --- | --- |
| 选择盘点单 | ST单号 | 打开本仓盘点中单据 | 候选为当前仓盘点中；已完成／取消阻断 |
| 扫库位 | 存储、拣货、不良隔离库位 | 列出该位在盘范围 | 暂存库位阻断；候选来自盘点快照和可新增的合法库位 |
| 扫商品 | SKU、商品条码；SN商品扫SN | 定位快照行或创建待确认新增行 | 商品须在本盘SKU范围；SN身份与库位匹配 |
| 录入实盘 | 普通SKU输入数量；SN逐件扫描 | 显示账面、实盘、差异 | 数量≥0；SN数即实盘量；重复SN阻断 |
| 保存 | 不接收扫码 | 保存本行实盘，回库位继续 | 只写实盘，不改库存；重复保存更新同一行并留录入人时间 |

保存后管理端立即看到同一盘点单数据。安卓返回逐步回退；当前未保存行进本机草稿，已保存实盘属于业务记录。刷新可恢复未保存草稿，选择放弃时二次确认。

## 二、发现账实不符发起

从原作业带入仓库、货主、SKU、发现环节、原单号和库位；用户确认账实不符时，共用原作业的差异上报动作`reportInventoryDiscrepancy`立即按本仓库＋货主＋SKU标记“待核对”，并在原业务记录保留发现依据。

当前手上任务未提交时，页面提示先收尾当前任务，不创建盘点单；等待期间仍保持“待核对”。当该SKU已无进行中的上架、返库上架或拣货任务时，用户补充差异数量与说明，调用`createStocktakeFromDiscrepancy`创建盘点单。创建成功返回ST号并进入实盘入口，不重复设置“待核对”。

发现依据使用原业务记录，不另建差异单。已存在盘点中单据时返回原盘点单并提示加入既有盘点，不重复冻结。

## 三、动作与文案key

| 业务动作／文案 | key | 中文 | 英文 |
| --- | --- | --- | --- |
| 保存本行实盘 | `pda.stocktake.action.saveCount` | 保存实盘 | Save Count |
| 发现差异 | `pda.stocktake.action.reportDiscrepancy` | 上报差异 | Report Issue |
| 发起盘点 | `pda.stocktake.action.createStocktake` | 发起盘点 | Start Count |
| 等待任务收尾 | `pda.stocktake.message.pendingTaskClose` | 已标记待核对，请先提交当前任务 | Marked for review. Finish the current task first. |
| 已有盘点 | `pda.stocktake.message.existingStocktake` | 已加入现有盘点 | Added to Existing Count |

## 四、反馈、权限与走查

PDA用户须有当前仓授权和相应盘点发起／实盘权限。扫描错误就近提示，状态变化、范围不符和任务未结束用业务阻断弹窗。每一步提供来自当前单据的模拟候选。

走查：计划盘点、多SKU多库位、分人分次、普通数量、SN、账面0新增行、无法识别归属、发现差异后立即待核对、任务未提交时暂不建盘点、已有盘点、管理端确认前重录、单据状态变化、重复保存。验证实盘保存不动库存，只有管理端主管确认才调账。
