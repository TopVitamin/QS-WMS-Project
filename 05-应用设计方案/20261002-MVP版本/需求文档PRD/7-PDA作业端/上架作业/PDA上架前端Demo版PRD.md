# PDA上架前端Demo版PRD

> **版本**：WMS-V0.2  
> **更新时间**：2026-10-19（V0.2：改为按推荐库位逐站上架：扫库位到站 → 扫商品计数 → 数满自动保存落位 → 本库位放完自动跳下一个 → 全部落完汇总提交；取代 V0.1「扫库位 → 选商品填数量」与「剩余全部放此」）  
> **定位**：供 AI / 研发实现 PDA 上架作业（`/pda/putaway`）：按上架单定位、按推荐库位逐站落位、保存进度、提交上架单。  
> **业务真源**：[《上架单主PRD》](../../2-入库管理/上架单/上架单主PRD.md)第三节（保存与提交校验）；[《入库单主PRD》](../../2-入库管理/入库单/入库单主PRD.md) R09、R10、§7.6；[《入库业务设计》](../../../../../04-业务分析和设计/02-入库业务设计.md)第 6.3 节（推荐位置、品质适配、提交时合计须等于应上架）；[《系统与模块地图》](../../../系统架构设计/00-系统与模块地图.md)附录（一库位一货主）。  
> **边界**：残损与缺件按既定库存路径处理；盘点阻断、库位启用与SN落位必须执行。管理端提供上架单查询，并可在 Web 端上架页补录；PDA 与 Web 共用同一保存、撤销、提交动作，可交替录同一张单。

**样式与交互服从[《PDA作业端设计规范》](../PDA作业端设计规范.md)**（按库位作业见 §4.6、§4.7），与 PDA 拣货、返库上架同一套按库位作业版式；布局见[《PDA上架页面骨架》](PDA上架页面骨架.md)。

## 1. 能力概述

| 项目 | 内容 |
| --- | --- |
| 作业对象 | 上架单（按「容器 × 品质」生成；无容器收货按「收货记录 × 品质」）。M0 的上架任务已退役，上架单是唯一上架对象 |
| 路由 | `/pda/putaway`；步骤用路由参数 `step`（§2）；`po` 为上架单号，`at` 为当前站（推荐库位），`to` 为实际扫到的目标库位 |
| 上架路径 | 还没落满的应上架行按推荐库位分组，按库位编号自然顺序排（A-01-02 在 A-01-10 前），一站一个推荐库位；没有推荐库位的行排在最后一站，扫任一可用库位 |
| 计数 | 到站后每扫一件商品本行 +1（SN 商品每扫一个 SN）；数满本行剩余自动保存落位；件数多时扫一件后在底部数量框改数，再点「保存落位」 |
| 保存 | 每次保存写入上架单的实际上架明细（未提交）：只记进度，不动库存、不增加已上架；上架单变为上架中 |
| 提交 | 全部落完自动进入汇总屏；每个应上架行已录＝应上架时提交：库存从收货暂存库位移到目标库位，实际明细标为已提交，上架单已完成，来源入库／退货单已上架增加并重算状态，SN同步移到目标库位 |
| 数据动作 | `savePutawayLine`、`removePutawayLine`、`submitPutawayOrder`（`mock/db.ts`），与 Web 端上架相同 |
| 草稿 | 还没保存的计数存 `stores/pda-putaway-session.ts`（按「仓库:上架单号」）；已保存的落位在上架单里，不进草稿 |

## 2. 步骤与返回

| step | 屏幕 | 进入方式 | 安卓返回键 / 标题栏返回 |
| --- | --- | --- | --- |
| `list` | 选上架单 | 首页「上架」；默认 | 回首页 |
| `work` | 按库位上架 | 扫到或点选上架单；管理端上架单列表、详情「PDA上架」直达该单 | 回选上架单 |
| `done` | 全部已录落位 | 最后一行保存后自动进入 | 回选上架单 |

- 到站（`at` + `to`）随路由保存，刷新后仍在原站。重新进入本单时没有目标库位：未保存的计数先不显示，当前站停在计数所在那一站，重扫目标库位后接着数，保证计数落到扫过的库位。
- 汇总屏撤销某条落位后剩余又大于 0，自动回到按库位上架。
- 上架单已被提交或不存在时，`work`、`done` 回到选上架单并提示。

## 3. 每步可识别的码

| 步骤 | 可识别 | 命中 | 不命中（扫码错误：红闪、低音，扫码框下一行红字） |
| --- | --- | --- | --- |
| 选上架单 | 上架单号；容器号；SKU 编码、货主条码、主条码 | 命中 1 张未提交的上架单 → 按库位上架；命中多张 → 列表只留命中项，框下蓝字提示点选 | 「没有找到待上架的上架单：xxx」 |
| 按库位上架·未到站 | 库位码 | 是某站的推荐库位 → 到该站；是其他合法库位 → 改放到该库位（卡片写「改放库位（推荐 L）」）；「无推荐库位」一站扫任一合法库位即为目标 | 库位校验不通过：「L 不能放：原因」（§4）；扫到本单商品或 SN：「扫到的是商品 X：请先扫描库位 L」；已全部落位的商品：「X 已全部落位，不用再扫」；其他：「没认出 xxx：请扫描库位 L」 |
| 按库位上架·已到站 | 商品（SKU 编码、货主条码、主条码）；SN；批次号；库位码 | 本行 +1，数满自动保存；批次号选中同商品的那一批；库位码＝换站或改放 | SN 商品扫商品码：「X 要逐件扫序列号」；SN 本次已扫或本单已落位；同商品多批次未选行（蓝字提示点选或扫批次号）；本站另一行有未保存计数：「X 还有 n 件没保存…」；本行已数满；商品属于别的站：「X 推荐放到 L，不在这一站」；已全部落位；都不是：「没找到这个码…」 |

- 数量框获得焦点时收到扫码内容，不写入数量，按本步规则处理（规范 §4.2）。
- 扫码处理一律读最新数据（规范 §4.7）：扫完库位紧跟一枪扫商品、连扫两件，都按最新的到站与计数处理。
- 模拟扫码候选：选上架单＝前 2 个待上架单号与 1 个容器号；未到站＝本站推荐库位（标「推荐」）、下一站库位、一个不在路径上的可用库位（演示改放）；已到站＝本站各行主条码，同一站同一商品多批次时加批次号，SN 行取还没落位的前 2 个实收 SN。

## 4. 目标库位校验与推荐

| 校验 | 规则 | 提示 |
| --- | --- | --- |
| 存在与启用 | 本仓库位及所属库区均启用 | 库位不存在或库位／库区已停用 |
| 盘点 | 单内SKU不在盘点中 | SKU盘点中，不能开始上架 |
| 非暂存 | 不能是收货暂存或出库暂存库位 | 不能上架到收货暂存或出库暂存库位 |
| 品质适配 | 入库来源良品放存储或拣货库位；退货来源良品只放存储库位；不良品只放不良隔离库位；异常处理库位不能作为上架目标 | 良品不能放不良隔离库位 / 不良品只能放不良隔离库位 / 不能上架到异常处理库位 |
| 一库位一货主 | 库位上已有其他货主库存，或有其他货主未提交的落位 → 不可用 | 库位已被其他货主占用 |

到站扫库位时先按上表校验，不通过就不到站；保存、提交时动作再校验一次。

推荐库位（决定上架路径，可不采用）：

- 良品：先找同货主、同商品已有良品库存的存储或拣货库位；没有则取第一个空闲存储库位。
- 不良品：先找同货主已有不良品的不良隔离库位；没有则取第一个空闲不良隔离库位。
- 都没有时，这些行归到最后一站「无推荐库位」，扫任一可用库位作为目标。实际库位与推荐不同时，卡片与结果行写明「改放（推荐 L）」，不阻断。
- 保存不动库存，作业中推荐库位不变，路径不会因为保存而重排。

Demo 的库位取运营数据 `locations`（编码如 `A-01-01`，A 区为拣货、B/C 区为存储，`DEFECT-01` 为不良隔离，`STAGE-IN-01` 为收货暂存，`EX-01-*` 为异常处理）。基础资料的库位档案使用另一套仓库编码，尚未与运营数据打通，必须统一引用基础资料的库位及库区启用状态；两套编码未打通属于原型待修项，不能省略一期校验。

### 4.1 批次与SN落位

商品扫码命中同一站多个应上架行（同SKU多批次）时，点选行或扫批次号区分，选定后接着计数；落位保存按应上架行号定位，撤销按实际明细行号定位，都不按SKU合并。

启用SN的行逐件扫 SN 计数（扫商品码会提示要扫 SN）：有实收 SN 时只认本行来源暂存库存上还没落位的 SN；Demo 收货尚未采集 SN，这时按商品资料的 SN 规则认（没配规则照收，与 Web 端上架手录一致）。条数等于数量，同一 SN 不可跨行重复（本次已扫与本单已保存都拦）。保存不改SN当前库位，整张提交才更新。库位及库区停用、盘点、SN缺失与货主占用均提示具体阻断原因，计数保留。

## 5. 计数、保存与提交

| 动作 | 规则 |
| --- | --- |
| 到站 | 扫推荐库位或其他合法库位；本站有未保存计数时不能换库位，提示先保存 |
| 计数 | 扫一件 +1，SN 行每个 SN +1；超过本行剩余（应上架 − 已录）拒绝 |
| 自动保存 | 数满本行剩余即 `savePutawayLine` 保存到扫过的目标库位；同一库位、同一应上架行再次保存可累加 |
| 改数保存 | 计数中底部出现数量框（默认已数，上限本行剩余，超出拒绝不截断）与通栏主按钮「保存落位（n 件）」；SN 行不出数量框，行卡上可「清空已扫」 |
| 自动跳站 | 本站各行落满后自动换到路径上的第一站并提示去哪，主区回到顶部；全部落完自动进入汇总屏 |
| 保存失败 | 业务阻断弹窗「落位没有保存成功」写原因；计数保留，可改扫别的库位 |
| 撤销 | 「已录落位」每条可撤销（需确认），只删进度不动库存；该行剩余回到路径上；删光落位后上架单回到待上架 |
| 提交上架单 | 汇总屏（应上架、已录、落位处数，已录落位列表）唯一主按钮；二次确认后 `submitPutawayOrder` |
| 提交校验 | 上架单未提交；每行合计＝应上架（`pdaPutaway.error.planMismatch`）；所有落位库位及所属库区启用、品质、货主占用、SKU盘点状态重新校验（§4）；SN须完整匹配应上架行 |

V0.1 的「剩余全部放此」（整箱落位）不再提供：同一推荐库位的行本来就在一站，扫一件后改数量即可保存。

## 6. 反馈与文案

| 场景 | 级别（规范 §5） | key |
| --- | --- | --- |
| 没有找到上架单；命中多张 | 扫码错误；提示 | `pdaPutaway.orderNotFound`；`pdaPutaway.multiMatch` |
| 库位校验不通过 | 扫码错误 | `pdaPutaway.errLocation`（原因取 `pdaPutaway.error.*`，§4） |
| 未到站先扫商品 | 扫码错误 | `pdaPutaway.errLocationFirst`；无推荐站 `pdaPutaway.errAnyFirst` |
| 到站；改放；无推荐站选定目标 | 成功；提示；成功 | `pdaPutaway.okArrived`；`pdaPutaway.okOther`；`pdaPutaway.okTarget` |
| 计数 +1；选中批次 | 成功；提示 | `pdaPutaway.okBump`；`pdaPutaway.okBatch`、`pdaPutaway.infoPickBatch` |
| 数满自动保存；本站放完跳站；全部落完 | 成功 | `pdaPutaway.saved`；`pdaPutaway.okStopDone`（剩下的无推荐 `okStopDoneAny`）；进入汇总屏时轻提示 |
| 有未保存计数时换库位或换行 | 扫码错误 | `pdaPutaway.errPending` |
| 商品属于别的站；已全部落位；不在本单 | 扫码错误 | `pdaPutaway.errOtherStop`；`pdaPutaway.errSkuDone`；`pdaPutaway.errNotInOrder` |
| SN 商品扫商品码；SN 已扫 | 扫码错误 | `pdaPutaway.errNeedSn`；`pdaPutaway.errSnUsed` |
| 保存失败 | 业务阻断 | `pdaPutaway.saveFailed` + 动作返回的 `errorKey` |
| 提交前确认、撤销确认 | 需确认 | `pdaPutaway.submitTitle`、`pdaPutaway.undoTitle` |
| 提交失败；提交成功 | 业务阻断；成功（轻提示） | 动作返回的 `errorKey`；`pdaPutaway.submitSuccess` |

| key | 中文 |
| --- | --- |
| `pdaPutaway.goTo` / `arrivedAt` | 前往库位 / 已到达库位 |
| `pdaPutaway.placeOther` | 改放库位（推荐 {{suggested}}） |
| `pdaPutaway.promptLocation` | 扫描库位 {{location}}，或其他可放的库位 |
| `pdaPutaway.promptItem` | 扫描商品条码或序列号，每扫一件 +1 |
| `pdaPutaway.errLocationFirst` | 扫到的是商品 {{sku}}：请先扫描库位 {{location}} |
| `pdaPutaway.okStopDone` | {{sku}} 已保存 {{count}} 件到 {{location}}。本库位放完，前往 {{next}} |
| `pdaPutaway.saveCount` | 保存落位（{{count}} 件） |
| `pdaPutaway.submit` | 提交上架单 |

完整文案以语言包 `pdaPutaway.*` 为准，中英文同时维护。

## 7. Mock 动作

| Action | 入参 | 结果 |
| --- | --- | --- |
| `savePutawayLine` | `putawayNo`、`locationCode`、`planLineNo`、`qty`、`serialNos`（启用时）、`operator` | 追加或累加一条未提交的实际上架明细；上架单状态上架中；不动库存 |
| `removePutawayLine` | `putawayNo`、`actualLineNo`（实际明细行号）、`operator` | 按实际明细行号删除一条未提交明细（SN 商品同库位同一应上架行可有多条，不能按库位与应上架行找）；删光明细后上架单回到待上架 |
| `submitPutawayOrder` | `putawayNo`、`operator` | 校验后逐条把暂存库位库存移到目标库位（不良品一并移动）；写库存流水；上架单已完成并记提交人、提交时间；入库单各行已上架＝已提交上架单合计，重算状态 |

重复提交同一张上架单返回「上架单已提交」，不重复移库存。

| 步骤 | 操作 | 预期 |
| --- | --- | --- |
