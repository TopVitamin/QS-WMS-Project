# PDA上架前端Demo版PRD

> **版本**：WMS-V0.1  
> **更新时间**：2026-10-12  
> **定位**：供 AI / 研发实现 PDA 上架作业（`/pda/putaway`）：按上架单定位、扫货位落位、保存进度、提交上架单。  
> **业务真源**：[《入库单主PRD》](../../2-入库管理/入库单/入库单主PRD.md) R09、R10、§7.6；[《入库业务设计》](../../../../../04-业务分析和设计/02-入库业务设计.md)第 6.3 节（推荐位置、品质适配、提交时合计须等于应上架）；[《系统与模块地图》](../../../系统架构设计/00-系统与模块地图.md)附录（一货位一货主）。  
> **不写**：上架前发现残损或缺件的处理（交库存域，一期按应上架数量提交后再调整）；盘点冻结拦截（盘点上线后补）；新品维护阻断；管理端上架入口（一期管理端只读）。

**样式与交互服从[《PDA作业端设计规范》](../PDA作业端设计规范.md)**；布局见[《PDA上架页面骨架》](PDA上架页面骨架.md)。

## 1. 能力概述

| 项目 | 内容 |
| --- | --- |
| 作业对象 | 上架单（按「容器 × 品质」生成；无容器收货按「收货记录 × 品质」）。M0 的上架任务已退役，上架单是唯一上架对象 |
| 路由 | `/pda/putaway`；步骤用路由参数 `step`（§2） |
| 保存 | 每次「保存落位」写入上架单的实际上架明细（未提交）：只记进度，不动库存、不增加已上架；上架单变为上架中 |
| 提交 | 每个应上架行的落位合计＝应上架数量时可提交：库存从收货暂存库位移到目标货位，实际明细标为已提交，上架单已完成，入库单已上架增加并重算状态 |
| 数据动作 | `savePutawayLine`、`removePutawayLine`、`submitPutawayOrder`（`mock/db.ts`） |

## 2. 步骤与返回

| step | 屏幕 | 进入方式 | 安卓返回键 / 标题栏返回 |
| --- | --- | --- | --- |
| `list` | 选上架单 | 首页「上架」；默认 | 回首页 |
| `work` | 上架单作业 | 扫到或点选上架单 | 回选上架单 |
| `place` | 落位录入 | 在上架单作业扫到目标货位 | 回上架单作业；未保存的数量不保留 |

- 已保存的落位在上架单里（业务记录），不需要本机草稿；刷新后按路由参数回到原屏。
- 上架单已被提交或不存在时，`work`、`place` 回到选上架单并提示。

## 3. 每步可识别的码

| 步骤 | 可识别 | 命中 | 不命中 |
| --- | --- | --- | --- |
| 选上架单 | 上架单号；容器号；SKU 编码、货主条码、主条码 | 命中 1 张未提交的上架单 → 上架单作业；命中多张 → 列表只留命中项，提示点选 | 扫码错误：没有找到待上架的上架单 |
| 上架单作业 | 货位码 | 校验通过 → 落位录入 | 货位校验不通过：扫码错误并写明原因（§4）。扫到商品条码：扫码错误「请先扫描目标货位」 |
| 落位录入 | 商品条码；货位码 | 商品在本单且有剩余 → 选中该行，数量默认剩余；货位码 → 校验后切换目标货位 | 商品不在本单或已落完：扫码错误 |

- 数量框获得焦点时收到扫码内容，不写入数量，按本步规则处理（规范 §4.2）。
- 模拟扫码候选：选上架单 = 待上架单号与容器号；上架单作业 = 推荐货位 + 一个其他可用货位；落位录入 = 本单还有剩余的商品主条码。

## 4. 目标货位校验与推荐

| 校验 | 规则 | 提示 |
| --- | --- | --- |
| 存在 | 当前仓库的货位 | 货位不存在 |
| 非暂存 | 不能是收货暂存库位 | 不能上架到收货暂存库位 |
| 品质适配 | 良品放存储或拣货货位；不良品只放不良隔离货位 | 良品不能放不良隔离货位 / 不良品只能放不良隔离货位 |
| 一货位一货主 | 货位上已有其他货主库存，或有其他货主未提交的落位 → 不可用 | 货位已被其他货主占用 |

推荐货位（显示在上架单作业页，可不采用）：

- 良品：先找同货主、同商品已有良品库存的存储或拣货货位；没有则取第一个空闲存储货位。
- 不良品：先找同货主已有不良品的不良隔离货位；没有则取第一个空闲不良隔离货位。
- 都没有时显示「无推荐货位，请扫描可用货位」。实际货位与推荐不同只做轻提示，不阻断。

Demo 的货位取运营数据 `locations`（编码如 `A-01-01`，A 区为拣货、B/C 区为存储，`DEFECT-01` 为不良隔离，`STAGE-IN-01` 为收货暂存）。基础资料的库位档案使用另一套仓库编码，尚未与运营数据打通，本期不按其启用状态校验。

## 5. 录入、保存与提交

| 动作 | 规则 |
| --- | --- |
| 选商品 | 落位录入页扫码或点选；只剩一个商品有剩余时自动选中 |
| 数量 | 默认该行剩余（应上架 − 已录）；上限为剩余，超出拒绝不截断 |
| 保存落位 | `savePutawayLine`：同一货位同一商品再次保存则数量累加；成功后回上架单作业 |
| 剩余全部放此 | 把本单所有剩余数量逐行保存到当前货位（整箱落位）；任一行货位校验不通过则整体不保存 |
| 撤销 | 已录落位可撤销（需确认）；撤销后该行剩余增加；无落位时上架单回到待上架 |
| 提交上架单 | 每个应上架行已录＝应上架时可点；二次确认后 `submitPutawayOrder`。不可点时，底部写「还有 N 件未落位」 |
| 提交校验 | 上架单未提交；每行合计＝应上架（`pdaPutaway.error.planMismatch`）；所有落位货位重新校验（§4） |

## 6. 反馈与文案

| 场景 | 级别（规范 §5） | key |
| --- | --- | --- |
| 没有找到上架单 | 扫码错误 | `pdaPutaway.orderNotFound` |
| 货位校验不通过 | 扫码错误 | `pdaPutaway.error.*`（§4 各条） |
| 未扫货位先扫商品 | 扫码错误 | `pdaPutaway.scanLocationFirst` |
| 商品不在本单或已落完 | 扫码错误 | `pdaPutaway.notInOrder`、`pdaPutaway.lineDone` |
| 与推荐货位不同 | 轻提示 | `pdaPutaway.locationDiffers` |
| 保存成功 | 成功 | `pdaPutaway.saved` |
| 提交前确认、撤销确认 | 需确认 | `pdaPutaway.submitTitle`、`pdaPutaway.undoTitle` |
| 提交失败 | 业务阻断 | 动作返回的 `errorKey` |
| 提交成功 | 成功 | `pdaPutaway.submitSuccess` |

| key | 中文 |
| --- | --- |
| `pdaPutaway.promptOrder` | 请扫描上架单号、容器号或商品条码 |
| `pdaPutaway.promptLocation` | 请扫描目标货位 |
| `pdaPutaway.suggested` | 推荐货位 |
| `pdaPutaway.remainToPlace` | 还有 {{count}} 件未落位 |
| `pdaPutaway.placeAll` / `save` | 剩余全部放此 / 保存落位 |
| `pdaPutaway.submit` | 提交上架单 |
| `pdaPutaway.error.otherOwner` | 货位已被其他货主占用 |

完整文案以语言包 `pdaPutaway.*` 为准，中英文同时维护。

## 7. Mock 动作

| Action | 入参 | 结果 |
| --- | --- | --- |
| `savePutawayLine` | `putawayNo`、`locationCode`、`skuCode`、`qty`、`operator` | 追加或累加一条未提交的实际上架明细；上架单状态上架中；不动库存 |
| `removePutawayLine` | `putawayNo`、`locationCode`、`skuCode` | 删除一条未提交明细；无明细时回到待上架 |
| `submitPutawayOrder` | `putawayNo`、`operator` | 校验后逐条把暂存库位库存移到目标货位（不良品一并移动）；写库存流水；上架单已完成并记提交人、提交时间；入库单各行已上架＝已提交上架单合计，重算状态 |

重复提交同一张上架单返回「上架单已提交」，不重复移库存。
