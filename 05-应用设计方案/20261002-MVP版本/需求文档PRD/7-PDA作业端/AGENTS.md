# PDA 作业端文档约定（Agent）

本目录放 PDA 作业端的全局规范和各作业的 PDA 页面骨架、PDA 前端 Demo 版 PRD。上层约定见[需求文档 PRD / AGENTS.md](../AGENTS.md)；涉及 PDA 时以本文件为准，上层的「布局硬规则」只适用于管理端。

## 文件组织

| 文件 | 写什么 |
| --- | --- |
| [PDA作业端设计规范](PDA作业端设计规范.md) | 全局：设备基线、页面骨架、扫码与数量、反馈分级、返回与草稿、触控与文字、首页菜单 |
| `<作业>作业/PDA<作业>页面骨架.md` | 按 360 宽画的 ASCII 线框：每一步一屏，含弹层 |
| `<作业>作业/PDA<作业>前端Demo版PRD.md` | 路由与步骤、每步可识别的码、录入与校验、反馈、返回与草稿、Mock 动作、走查 |

按**作业**拆，不按单据拆：一次 PDA 收货同时会动到入库单、收货记录、上架单、入库异常，按单据拆会把一个作业切成四份。

## 与三件制的关系

- **业务规则不在本目录重写**：以各单据《主PRD》为真源（收货、上架见[《入库单主PRD》](../2-入库管理/入库单/入库单主PRD.md)），PDA 文档只引用规则编号。
- 页面骨架只画布局与按钮位置；校验、文案、Mock 写在 Demo 版 PRD。
- 单据 Demo 版 PRD 的「双端」小节只写两端共用的动作与规则，PDA 交互链接到本目录，不在单据 PRD 里重复写 PDA 步骤。

## PDA 硬规则（写 PRD 和骨架时逐条自检）

1. 线框按 360 宽画，按 360×560 可用区域检查：主按钮、当前对象、关键数量不滚动可见。
2. 每一步写清：提示语、可识别的码、命中后去哪、不命中时是扫码错误还是业务阻断。
3. 每个扫码步骤写明 Demo 模拟候选值从哪来。
4. 写清安卓返回键在每一步回到哪里，哪些内容进草稿、哪些已是业务记录。
5. 数量的默认值、上限、联动规则与管理端同一动作一致；超上限拒绝，不截断。
6. 枚举选择用大按钮组，不用下拉。
7. 两端共用的 Mock 动作写同一个 action，不为 PDA 另起一套。
8. 新增文案中英文都要有 key。
