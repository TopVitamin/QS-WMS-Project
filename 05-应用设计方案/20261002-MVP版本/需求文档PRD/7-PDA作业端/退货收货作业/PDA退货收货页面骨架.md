# PDA退货收货页面骨架

> 文档版本：WMS-V0.1｜日期：2026-10-15｜状态：初稿，待评审。  
> 线框按 360 宽、360×616 可用区域绘制，遵循[《PDA作业端设计规范》](../PDA作业端设计规范.md)第 2、3 节。业务规则以[《退货单主PRD》](../../4-退货管理/退货单/退货单主PRD.md)为准；共享上架不在本作业重复设计。

## 页面与弹层清单

| 页面/弹层 | 路由参数 | 入口 | 用途 |
| --- | --- | --- | --- |
| 选退货单 | `step=order`（默认） | PDA 首页「退货收货」；管理端「PDA 退货收货」带单号进入 | 扫退货单号、退货运单号或原出库运单号，建立本次退货收货上下文 |
| 派送失败建单 | `step=create` | 扫描原出库运单号且没有可收货退货单时 | 确认以原出库运单创建派送失败退货单；重复活跃退货单时阻断 |
| 扫容器 | `step=container` | 选退货单成功；容器作业「新增容器」 | 扫描或录入收货容器；列出本次作业已有容器 |
| 容器作业 | `step=box&box=<容器号>` | 绑定新容器或打开已有容器 | 扫商品、录入良品、不良品、拒收和追溯信息 |
| 本行录入 | `step=line&box=<容器号>&line=<退货行号>` | 扫到或点选退货明细 | 录入本退货明细的良品、不良品、拒收及 SN |
| 提交收货 | `step=submit` | 容器作业页「提交收货」 | 选择本次提交的容器，一次生成退货收货记录 |
| 业务阻断 | 弹窗 | 单据状态、货主/仓库、数量或 SN 校验不通过 | 说明阻断原因与下一步；只保留「知道了」 |
| 二次确认 | 弹窗 | 放弃草稿、移出明细、提交收货 | 展示将被删除或落账的范围，明确主动作 |

无容器收货可作为本次作业中的一组，容器参数使用 `BULK`；若现场容器管理是必需的，需由业务确认后再收紧。

## 绘制约定

- 每屏四段：标题栏（返回、退货收货、当前仓库编码）→ 上下文条 → 主区（可滚动）→ 底部操作区（固定）。
- 上下文条常驻显示退货单号尾号、当前容器、本次作业的容器数与行数；完整单号进入详情或阻断提示查看。
- `[扫]` 为扫码框，`[键盘]` 为手输切换；「模拟扫码」只在 Demo 版出现。
- 关键数量始终分开显示：预计、实收（只读）、拒收、未收、良品、不良品；不能用“已处理”一个数字替代。
- SN 校验结果必须直接出现在当前行；具体状态和反馈引用主 PRD 与 PDA Demo，不在骨架中重复业务规则。

## 1. 选退货单（step=order）

- **用途**：确定本次退货收货的退货单；允许直接扫描退货运单或原出库运单。
- **关键要素**：未提交作业卡片（有才显示）、扫码框、模拟扫码、可收货退货单列表。

```text
+--------------------------------------+
| <  退货收货                 US-LA-01 |
+--------------------------------------+
| 未提交的退货收货作业                 |
| RT-20261015-0001                     |
| 1 个容器 · 2 行 · 10:32 暂存         |
| [放弃作业]               [继续作业]  |
+--------------------------------------+
| 请扫描退货单号、退货运单或原出库运单 |
| [扫] 等待扫描…               [键盘]  |
| 模拟扫码 [RT-…0001] [YT-…0001]       |
|                                      |
| 可收货退货单 (2)                     |
| RT-20261015-0001            收货中   |
| ANKR · 2 种商品 · 未收 8             |
| RT-20261015-0002            待收货   |
+--------------------------------------+
```

**补充说明**：

- 扫退货单号或退货运单号：命中待收货/收货中的退货单后进入扫容器。
- 扫原出库运单号：若已有对应派送失败退货单，进入该单；若没有，进入派送失败建单确认页。
- 扫到不存在的运单号、已完成/已取消退货单或属于其他仓库/货主的数据，按扫码错误或业务阻断分别提示。
- 有其他退货收货草稿时，不能直接切换退货单，须提交或放弃当前草稿。

## 2. 派送失败建单（step=create）

- **用途**：现场只有原出库运单且确认是派送失败退回时，创建一张退货单。
- **关键要素**：原出库单/运单摘要、仓库、货主、待退回商品提示、建单原因；主按钮为「创建并开始收货」。

```text
+--------------------------------------+
| <  创建派送失败退货         US-LA-01 |
+--------------------------------------+
| 原出库运单                           |
| YT-20261015-0001                     |
| 原出库单 SO-20261015-0042            |
| 货主 ANKR · 预计退回 3 件             |
+--------------------------------------+
| 建单原因                             |
| [派送失败退回]（固定）                |
| 说明：退回商品收货后按实际品质入账    |
+--------------------------------------+
| [返回]             [创建并开始收货]  |
+--------------------------------------+
```

**补充说明**：

- 只允许从原出库运单识别派送失败退回；不能从任意未知商品直接创建退货单。
- 已有活跃的派送失败退货单时不创建第二张，直接阻断并引导进入原退货单。
- 原出库单不能唯一匹配、属于其他仓库/货主或已不允许关联时，阻断并保留扫描值。

## 3. 扫容器（step=container）

- **用途**：绑定下一个收货容器，或继续打开本次作业已有容器。
- **关键要素**：上下文条、扫码框、模拟扫码、已有容器列表、提交收货。

```text
+--------------------------------------+
| <  退货收货                 US-LA-01 |
+--------------------------------------+
| RT-…0001 · 本次 1 个容器 · 1 行      |
+--------------------------------------+
| 请扫描收货容器                       |
| [扫] 等待扫描…               [键盘]  |
| 模拟扫码 [BOX-RT-01] [BOX-RT-02]     |
|                                      |
| 本次作业的容器 (1)                   |
| BOX-RT-01          已暂存 · 1 行  >  |
|   良品 2 · 不良 1 · 拒收 0            |
+--------------------------------------+
| [无容器收货]          [提交收货 (1)] |
+--------------------------------------+
```

**补充说明**：

- 扫到本次作业已有容器，打开该容器继续录入；扫到本退货单已提交使用的容器，业务阻断。
- 扫到退货单号、商品条码、库位码或原出库运单号时，明确提示“扫到的是退货单/商品/库位/运单，请扫描收货容器”。
- 本次作业没有任何明细时，不显示「提交收货」。

## 4. 容器作业（step=box）

- **用途**：在当前容器中逐个扫描退回商品，进入明细录入。
- **关键要素**：退货单上下文、商品扫码框、已录明细、待收明细、提交收货。

```text
+--------------------------------------+
| <  退货收货                 US-LA-01 |
+--------------------------------------+
| RT-…0001 · 容器 BOX-RT-01 · 1 行     |
+--------------------------------------+
| 请扫描退回商品条码                   |
| [扫] 等待扫描…               [键盘]  |
| 模拟扫码 [690000000001 CABLE-01]     |
|                                      |
| 本容器已录 (1)                       |
| CABLE-01  USB 数据线             >   |
|   实收 3（良 2 · 不良 1）· 拒收 0    |
| 退货明细                             |
| CABLE-01  预计 3 · 已收 3 · 未收 0    |
+--------------------------------------+
| [新增容器]               [提交收货]  |
+--------------------------------------+
```

**补充说明**：

- 扫到本退货单明细中的 SKU，命中新行；同一商品再次扫描，按本行当前规则进入数量/明细录入。
- 不在本退货单的商品按扫码错误处理，不自动新增退货明细。
- 商品启用 SN、批次或效期时，在本行录入页展开对应追溯区。

## 5. 本行录入（step=line）

- **用途**：录入良品、不良品、拒收和 SN；实收由系统计算。
- **关键要素**：商品卡片（预计/已收/本次可收）、实收（只读）、拒收数量、良品/不良品、拒收原因、SN 核验结果。

```text
+--------------------------------------+
| <  退货收货                 US-LA-01 |
+--------------------------------------+
| RT-…0001 · 容器 BOX-RT-01            |
+--------------------------------------+
| CABLE-01                             |
| USB 数据线                           |
| 预计 3 · 已收 0 · 本次可收 3         |
|                                      |
| 实收（只读）            2             |
| 良品        [ - ]     2    [ + ]     |
| 不良品      [ - ]     0    [ + ]     |
| 拒收        [ - ]     1    [ + ]     |
| 拒收原因：                            |
| [外包装严重破损]                      |
| 合计：实收 2 + 拒收 1 / 预计 3       |
+--------------------------------------+
| SN核验：待核对                       |
| [扫序列号]  [无可对核原单]           |
+--------------------------------------+
| [返回]                 [加入本容器]  |
+--------------------------------------+
```

**补充说明**：

- 本屏只展示数量控件和本次汇总；实收为系统计算的只读值，录入项为良品、不良品和拒收。
- 拒收原因使用大按钮组，操作员可选“外包装严重破损”；SN核对不一致时显示系统固定原因，不提供其他选择。照片、附件和破损等级不强制。
- 数量、拒收原因、SN 结果和草稿行为见[退货单主 PRD](../../4-退货管理/退货单/退货单主PRD.md)及[PDA 退货收货前端 Demo 版 PRD](PDA退货收货前端Demo版PRD.md)。

## 6. 提交收货（step=submit）

- **用途**：确认本次提交的容器，生成一条退货收货记录。
- **关键要素**：容器勾选、实收（只读）/拒收/良品/不良品汇总、主按钮「确认提交」。

```text
+--------------------------------------+
| <  提交退货收货             US-LA-01 |
+--------------------------------------+
| RT-20261015-0001                     |
+--------------------------------------+
| [x] BOX-RT-01        1 行            |
|     实收 2（良 2 · 不良 0）· 拒收 1  |
| [ ] 无容器收货       1 行            |
|     实收 0 · 拒收 2                  |
|                                      |
| 已选 1 个容器：实收 2，拒收 1        |
| 提交结果：显示 RR、拒收和待上架摘要  |
+--------------------------------------+
| [返回]             [确认提交 (1)]    |
+--------------------------------------+
```

**补充说明**：

- 提交按钮位置固定；校验、提交结果和共享上架跳转见[PDA 退货收货前端 Demo 版 PRD](PDA退货收货前端Demo版PRD.md)。

## 7. 弹层

```text
+----------------------------------+   +----------------------------------+
| SN不一致                         |   | 放弃本次退货收货作业？            |
| 扫描 SN SN-002，与原出库实发     |   | 将删除 1 个容器、2 行未提交录入  |
| SN-001 不一致，只能拒收。        |   | 已提交的收货不受影响              |
|                          [知道了]|   | [取消]             [放弃作业]    |
+----------------------------------+   +----------------------------------+
             业务阻断                         二次确认
```

## 骨架检查

- [ ] 每屏在 360×616 下主按钮、当前对象、关键数量可见；无横向滚动
- [ ] 退货单、退货运单、原出库运单、容器、商品、SN 各扫码步骤均有提示与模拟候选
- [ ] 数量区把实收作为只读汇总，良品、不良品和拒收作为录入项
- [ ] SN 核验结果在当前行附近展示，具体业务处理引用主 PRD
- [ ] 提交后展示 RR、RX 和共享上架关联，不在退货收货页重复设计上架步骤
- [ ] 刷新、退出后草稿可恢复；放弃需确认
