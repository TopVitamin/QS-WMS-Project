> **版本**：WMS-V0.1
> **更新时间**：2026-10-15

> **业务真源**：[《退货单主PRD》](../../4-退货管理/退货单/退货单主PRD.md)第 4～10 节；PDA 共性约束见[《PDA作业端设计规范》](../PDA作业端设计规范.md)。
>
> **2026-10-22 实现说明**：原型按单页多容器实现，用查询参数 `no` 定位退货单，未拆 `step` 路由；多容器、SN 拒收、派送失败建单、草稿恢复规则按本文执行。

**布局以[《PDA退货收货页面骨架》](PDA退货收货页面骨架.md)为准。** 本文只定义 PDA 端动作与演示数据，不新增退货业务规则；共享上架单使用已有[《PDA上架前端Demo版PRD》](../上架作业/PDA上架前端Demo版PRD.md)，不在此重复。

## 1. 能力概述

| 项目 | 内容 |
| --- | --- |
| 功能 | 退货收货（PDA 端） |
| 确认路由 | `/pda/return-receive`；当前原型以查询参数 `no` 定位退货单 |
| 作业单位 | 一次退货收货作业 = 一张退货单 + 1～N 个容器；无容器收货至多一组 |
| 数据动作 | 提交生成一条退货收货记录；拒收生成退货异常记录；实收由良品/不良品计算并生成共享上架来源记录；收货暂存库存由提交动作产生 |
| 前置 | 退货单为待收货或收货中，仓库与货主在当前操作范围内，尚有未收数量；派送失败现场可用原出库运单建单 |
| 不负责 | 共享上架的扫描、落位与提交；退货结果回传；退货单的管理端改名/取消 |

## 2. 步骤、返回与草稿

| step | 屏幕 | 进入方式 | 返回行为 |
| --- | --- | --- | --- |
| `order` | 选退货单 | 首页「退货收货」；默认 | 回首页 |
| `create` | 派送失败建单 | 扫原出库运单且无对应活跃退货单 | 回选退货单 |
| `container` | 扫容器 | 选单成功；容器作业点「新增容器」 | 回选单，保留本次作业 |
| `box` | 容器作业 | 绑定或点选容器 | 回扫容器，保留当前容器 |
| `line` | 本行录入 | 扫到或点选退货明细 | 回容器作业；未点「加入本容器」的改动不落入容器草稿 |
| `submit` | 提交收货 | 容器作业点「提交收货」 | 回容器作业 |

- 每个步骤对应一条浏览历史；安卓返回键、标题栏返回按规范逐步回退。
- 本机草稿只保存未提交内容，不改退货单状态、库存或上架记录；每次加入明细、保存容器、切换单据前即时保存。
- 一台设备同时只保留一份退货收货草稿；进入其他退货单时先阻断并要求提交或放弃当前草稿。
- 退货单在草稿期间变为已完成、已取消或没有未收时，恢复作业被阻断，只能放弃。

## 3. 每步可识别的码

| 步骤 | 可识别 | 命中后的路径 | 不命中或冲突 |
| --- | --- | --- | --- |
| 选退货单 | 退货单号、退货运单号、原出库运单号 | 退货单号/退货运单号命中 → 扫容器；原出库运单命中活跃派送失败退货单 → 扫容器；无退货单 → 派送失败建单页 | 不存在、其他仓/货主、已完成/已取消 → 扫码错误或业务阻断；重复活跃退货单 → 指向原单 |
| 派送失败建单 | 原出库运单号 | 显示原出库摘要，确认后生成退货单并进入扫容器 | 不能唯一匹配、非可退回状态或重复活跃单 → 业务阻断 |
| 扫容器 | 箱唛、托唛、容器号 | 新容器 → 容器作业；本次已有容器 → 打开继续录入 | 扫到商品、库位、单号或运单 → 提示扫到的码种类；本单已提交过的容器 → 业务阻断 |
| 容器作业 | 本退货单明细的 SKU 编码、货主条码、主条码 | 命中未收明细 → 本行录入；已在当前容器的行 → 打开当前行或按规则增加待录数量 | 不在本退货单、已收满、商品配置与单据不一致 → 扫码错误 |
| 本行录入 | SKU 条码；启用 SN 时为序列号 | SKU 进入数量与品质；SN 进入核验区并按核验结果落到实收或拒收 | 扫到其他 SKU、SN 重复、SN 与原出库不一致 → 错误或业务阻断；不一致只能拒收 |

- 扫码识别统一去首尾空格；单号与编码不区分大小写，条码和 SN 按原值比较。
- 商品识别按仓库、货主和当前退货单明细解析；不能用固定伪 SKU/SN 绕过校验。
- 每个扫码步骤都提供「模拟扫码」候选值；候选必须来自当前 Mock 退货单、明细、容器或原出库 SN。

## 4. 数量、品质与 SN 录入

### 4.1 数量关系

| 项 | 规则 |
| --- | --- |
| 本次可收 | 退货行预计数量 − 历史实收 − 历史拒收 − 本次作业其他容器已录数量 |
| 实收 | 系统计算为良品 + 不良品，只读展示，不提供独立录入控件 |
| 允许范围 | 实收 + 拒收 ≤ 本次可收；三项合计大于 0 才能加入容器 |
| 默认值 | 扫 SKU 新行默认良品 1；已有行进入时显示当前草稿值 |
| 超限 | 拒绝本次修改、保留原值并提示上限；不静默截断 |
| 拒收原因 | 拒收大于 0 时必须选择“外包装严重破损”；SN不一致时系统固定写入“SN核对不一致”，不提供原因选择。PDA用大按钮组；照片、附件和破损等级不强制 |
| 批次与效期日期 | 启用批次管理时显示并要求填写批次号；启用效期管理时显示“生产日期”和“失效日期”两个日期输入，现场至少手工录入其中一项，系统按商品保质期天数计算另一项；两项均可手动修改，且生产日期不得晚于失效日期 |

良品、不良品和拒收是三个独立录入项；实收只由良品与不良品计算。日期缺失或顺序不符时，不允许加入容器或提交；提交前再次校验日期和当前退货单累计数量。

### 4.2 SN 分支

1. 商品未启用 SN：不出现 SN 区。
2. 商品启用 SN 且存在原出库 SN：每个实收件扫描/输入 SN，并与原出库复核结果或实际发出 SN 比对。
3. 比对一致：记为实收，可按操作员选择良品或不良品；SN 记录品质与核验依据。
4. 比对不一致：显示阻断提示，当前 SN 只允许计入拒收；系统固定原因“SN核对不一致”，并记录扫描 SN、原出库 SN 和核验依据；不生成实收、不生成上架、不增加库存，不能转成不良品。
5. 没有原出库可核对依据：采集 SN 并明确显示“无可对核原单”；允许继续按现场品质收货，记录该事实，不把“无依据”误报为“一致”。
6. SN 重复、同一退货行 SN 数与实收数量不一致、良品/不良品 SN 数不一致：提交时业务阻断。

PDA 不能提供“跳过 SN 核验后按不良品收货”的快捷路径。无可对核原单与不一致是两种不同结果，页面文案和记录字段必须区分。

## 5. 容器与提交

### 5.1 新增容器

- 当前容器无明细：不保留空容器，直接回扫容器。
- 有明细：逐行校验数量、拒收原因、品质与 SN；通过后标为「已暂存」，进入扫容器。
- 已提交过的容器不能重新绑定；同一次作业已有容器直接打开原草稿。

### 5.2 提交收货

1. 先校验并暂存当前容器。
2. 列出所有有明细的容器，默认全选；每个容器显示实收、拒收、良品、不良品。
3. 允许取消部分容器，支持分批提交；未勾选容器继续留在本机草稿。
4. 点击「确认提交 (N)」后，按退货单最新状态、累计数量、当前仓库与货主归属、品质和 SN 重新校验；任一不通过则整次不提交。
5. 成功：生成 1 条 RR 退货收货记录；拒收生成 RX 退货异常；实收进入收货暂存库存；按容器×品质生成/关联共享上架单。
6. 退货单仍有未收时回到扫容器；所有明细关闭但仍有实收未上架时，退货单保持上架中；只有收货、上架和结果回传条件满足后才完成。

## 6. 反馈与文案

| 场景 | 反馈级别 | 建议文案 key | 处理 |
| --- | --- | --- | --- |
| 退货单不存在或不能收货 | 扫码错误 | `pdaReturn.orderInvalid` | 留在选单，说明单号/状态原因 |
| 原出库运单无法唯一匹配 | 业务阻断 | `pdaReturn.outboundNotUnique` | 不建单，保留扫描值 |
| 已有活跃派送失败退货单 | 业务阻断 | `pdaReturn.activeReturnExists` | 展示原退货单号，可进入原单 |
| 扫到的不是收货容器 | 扫码错误 | `pdaReturn.notContainer` | 说明扫到的码种类 |
| 商品不在退货单 | 扫码错误 | `pdaReturn.skuNotInOrder` | 不新增明细 |
| 本行超过预计或本次可收 | 扫码错误 | `pdaReturn.overExpected` | 拒绝修改，保留原值 |
| SN 与原出库不一致 | 业务阻断 | `pdaReturn.snMismatchRejectOnly` | 只能拒收，禁止实收/不良品路径 |
| 无可对核原单 | 成功提示 | `pdaReturn.snNoReference` | 允许继续，记录核验依据 |
| SN 重复或数量不一致 | 业务阻断 | `pdaReturn.snCountInvalid` | 停在当前行，指出差异 |
| 拒收未选原因 | 输入提示 | `pdaReturn.rejectReasonRequired` | 不允许加入容器 |
| 提交服务端校验失败 | 业务阻断 | `pdaReturn.submitInvalid` | 不清空草稿，按返回原因修正 |
| 放弃作业 | 二次确认 | `pdaReturn.discardTitle` | 展示容器、行数和未提交数量 |
| 提交成功 | 成功 | `pdaReturn.submitSuccess` | 显示 RR、实收、拒收和待上架摘要 |

建议主要文案：

| 场景 | 中文 |
| --- | --- |
| 选单 | 请扫描退货单号、退货运单或原出库运单 |
| 建单 | 已识别原出库运单，确认创建派送失败退货单 |
| 容器 | 请扫描收货容器 |
| 商品 | 请扫描退回商品条码 |
| SN | 请扫描序列号；无原单可对核时请选择“无可对核原单” |
| 不一致 | SN 与原出库不一致，本件只能拒收，不计入实收 |
| 提交 | 提交后生成退货收货记录；拒收生成异常，实收进入收货暂存 |

中英文文案需同步维护；最终 key 和英文表达随前端语言包统一确认。

| 原出库单/运单 | `SO-20261015-0042` / `YT-20261015-0001` | 有可核对 SN |
| 退货明细 | `CABLE-01`，预计 3 | 良品、不良品、拒收分支 |

### 7.2 走查场景

| 步骤 | 操作 | 预期 |
| --- | --- | --- |
| 1 | 首页 → 退货收货 → 模拟扫 `RT-20261015-0001` → 扫 `BOX-RT-01` | 进入容器作业 |
| 2 | 扫 `CABLE-01`，录 1 件良品，进入 SN 核验 | 当前行等待 1 个良品 SN，不直接写入业务记录 |
| 3 | 扫 `SN-CABLE-001` | 记录与原出库一致，形成 1 件良品，可加入容器 |
| 4 | 再扫 `CABLE-01`，录 1 件拒收并选原因；扫 `SN-CABLE-999` | 只能拒收；本容器实收 1、拒收 1，不出现“转不良品”操作 |
| 5 | 扫 `YT-20261015-0003`，确认建单 | 生成 RT 退货单后进入扫容器 |
| 6 | 再扫同一派送失败运单 | 不生成第二张，指向已有活跃退货单 |
| 7 | 录两个容器，提交页取消勾选一个 | 只生成一条 RR，未勾选容器仍在草稿 |
| 8 | 刷新页面 | 出现未提交作业卡片；继续后数量与 SN 原样 |
| 9 | 提交全部 | 管理端可见 RR/RX、暂存库存和共享上架来源；退货单按累计结果更新 |

## 8. 与管理端及共享上架的边界

- PDA 与管理端共用退货单、退货收货记录、退货异常和库存结果；PDA 草稿不属于业务记录。
- PDA 提交后不直接把实收放入目标货位；实收先进入收货暂存，良品/不良品分别等待共享上架。
- 共享上架单的来源为退货、来源收货记录为 RR；上架页负责扫码容器、选择目标库位和提交落位。
- 退货收货页面不提供“强制完成”“修改已确认收货”“把拒收转不良品”等越权动作。
