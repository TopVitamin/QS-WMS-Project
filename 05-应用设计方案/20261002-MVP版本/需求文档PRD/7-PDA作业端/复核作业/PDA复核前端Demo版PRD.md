# PDA复核前端Demo版PRD

> **版本**：WMS-V0.4｜2026-10-25。V0.2 改为逐件扫描计数（不用先选行），扫齐自动进入装箱；V0.3 补充 FBA 箱托和父托；V0.4 明确 FBA 仅使用已建档容器，候选只列当前仓、货主、类型与状态匹配的档案，缺档先去容器管理建立，不在复核时自动建档。
> **业务真源**：[出库单主PRD第7.5节](../../3-出库管理/出库单/出库单主PRD.md#75-复核)；布局见[页面骨架](PDA复核页面骨架.md)。打包台电脑上的同一作业见[复核工作台](../../3-出库管理/复核工作台/复核工作台前端Demo版PRD.md)，两者共用复核记录与 `VERIFY` 动作。  
> **样式与交互服从[《PDA作业端设计规范》](../PDA作业端设计规范.md)**。

## 1. 能力概述

| 项目 | 内容 |
| --- | --- |
| 作业对象 | 出库单（始终按原单，不直接复核汇总波次） |
| 路由 | `/pda/verify`；步骤 `list`、`scan`、`pack`；`no` 为出库单号 |
| 行 | 本单有效实拣归属，扣除已复核量（`verifyRows`） |
| 计数 | 扫商品条码本行 +1；SN 商品逐件扫 SN；同一商品多批次时优先记到点选的行；件数多可扫一件后改数量 |
| 装箱默认 | B2C：随打包装箱 + 包裹，包裹号 `PKG-单号`（已有包裹记录时加序号）；FBA：随打包装箱 + 箱，必须绑定同仓同货主容器档案；其他：随分拣 + 无容器（已有随分拣记录时改随打包装箱 + 箱） |
| 数据动作 | `VERIFY`（与复核工作台相同） |
| 草稿 | 本次复核（行数量、SN、当前行、复核方式、容器、父托、重量、备注）存 `stores/pda-outbound-session.ts`（按「仓库:出库单号」），与复核工作台各存各的；提交成功后清除，未提交不计入有效复核量 |

## 2. 步骤与返回

| step | 屏幕 | 进入方式 | 安卓返回键 / 标题栏返回 |
| --- | --- | --- | --- |
| `list` | 选出库单 | 首页「复核」 | 回首页 |
| `scan` | 逐件复核 | 扫到或点选出库单；管理端「PDA 复核」带 `step=scan&no=` | 回选出库单（本次录入留在草稿） |
| `pack` | 装箱提交 | 扫齐自动进入，或点「装箱提交（n 件）」 | 回逐件复核 |

## 3. 每步可识别的码

| 步骤 | 可识别 | 命中 | 不命中（扫码错误） |
| --- | --- | --- | --- |
| 选出库单 | 出库单号 | 本仓、未出库未取消、有待复核量 → 逐件复核 | 「不能复核 xxx：原因」（不在本仓、已出库、已取消、没有待复核） |
| 逐件复核 | SN；商品（SKU 编码、本货主启用条码、主条码）；另一张出库单号 | SN／商品：对应行 +1；本单扫齐 → 装箱；另一张单：本次没录入时换单 | SN 本次已扫或已复核过；SN 商品扫商品码；商品已扫满；不是本单商品；本次有录入时扫别的单：「先装箱提交，或清空本次再换单」 |
| 装箱提交 | 容器号（B2C 包裹、FBA 箱/托、其他已选箱/托时）；FBA 箱的可选父托号 | 写入容器号和父托号 | 不属于当前仓的容器、货主不符或跨货主拼托按业务阻断，不作为扫码格式错误 |

- 模拟扫码候选：选出库单＝前 3 张待复核单；逐件复核＝各行商品编码与还没扫的 SN（最多 4 个）；B2C 装箱＝默认包裹号；FBA 箱/托＝当前仓、本单货主、类型匹配且空闲或已被本单占用的容器档案。缺档须先进入容器管理建档。
- 逐件复核与提交都读最新草稿，连续快扫不丢计数。

## 4. 屏幕内容

**逐件复核**：上下文条（单号 · 业务类型 · 待复核 n · 本次 n）；扫码框（结果写在下一行）；「待复核商品（n）」行卡（SKU、SN 标签、名称、批次、已扫 SN；右侧「待复核 n」或「本次 a/n」，扫满变绿；点选设为当前行）；分组右上角红字「清空本次」（需确认）。底部：未录入时提示「逐件扫描本单商品；扫齐自动进入装箱」；当前行为普通商品且有数量时显示数量步进器；主按钮「装箱提交（n 件）」。

**装箱提交**：复核方式大按钮组（随分拣、随打包装箱）；容器类型按业务类型显示：B2C 仅包裹，FBA 仅箱/托且必选，B2B 可选无/箱/托，其他类型按主PRD；有容器时显示容器号与扫码框。FBA 选箱时可选同仓、同货主父托；父托最多一层，须使用已建档档案。FBA 每条复核记录仅写一个箱/托内的 SKU、批次/SN（按商品配置）与数量；各容器同 SKU 数量合计等于本单实发量，父托只汇总子箱。提交有效复核后容器档案进入「出库中」，确认出库后为「已出库」。模拟重量只对 B2C 随打包显示并必填；FBA 不采集箱重/体积，不增加预约、标签打印或标签集成。校验与复核工作台一致（`verifyPackProblem`）：FBA 容器号必须匹配当前仓已建档的同货主箱/托，缺档须先去容器管理建档，不在复核时自动建档；箱托关系与状态须可用。失败弹「知道了」写原因并保留本次录入。提交成功 toast 写复核记录号与容器号：本单还有待复核时退回逐件复核继续下一个容器，复核完回到选出库单。

## 5. i18n

`outbound.ts` 的 `pdaVerify` 组（中英成对）；扫码结果复用复核工作台 `outbound.ui.station*` 文案。

## 6. 走查

| 步骤 | 操作 | 预期 |
| --- | --- | --- |
| 1 | 首页 → 复核 | 本仓待复核出库单列表（单号、类型、状态、已拣、待复核） |
| 2 | 扫 0019（已拣线材 3 + SN 1），连扫线材条码 4 次 | 前 3 次计数；第 4 次「已经扫满」 |
| 3 | 扫 SN | 本单扫齐，自动进入装箱：随打包装箱 + 包裹 + `PKG-OB-…-0019` |
| 4 | 不填重量提交 | 阻断「包裹重量还没填」 |
| 5 | 填 0.6 提交 | toast 写复核记录号与件数；回到列表，0019 不再出现；管理端复核记录有 Mock 运单 |
| 6 | 分批：只扫 1 件就装箱提交 | 提交后退回逐件复核，待复核数减少，可继续装下一个容器 |
| 7 | FBA 需求10、实拣8；分别记录箱C1的X5、箱C2的X3，并关联同仓同货主父托P1 | 禁止无容器；C1/C2/P1 进入「出库中」；P1 汇总 X8；确认实发8后容器为「已出库」，未发2不计入箱托内容 |
| 8 | FBA 扫到其他仓/货主容器，或把不同货主的箱关联到同一托 | 拒绝提交，提示需使用本仓、本单货主的档案；本次草稿保留，无错误复核记录 |
| 9 | B2B 按件复核并选无容器 | 允许提交；不要求箱重、体积、预约或标签信息 |
