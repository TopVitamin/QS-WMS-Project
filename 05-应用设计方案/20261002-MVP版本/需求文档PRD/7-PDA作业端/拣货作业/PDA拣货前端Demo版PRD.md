# PDA拣货前端Demo版PRD

> **版本**：WMS-V0.2｜2026-10-18。V0.2：改为按库位逐站拣货（扫库位到站 → 扫商品计数 → 数满自动确认 → 本库位拣完自动跳下一个库位 → 全部拣完提交），取代 V0.1「先选行再逐步扫描」。  
> **业务真源**：[拣货任务主PRD第三节](../../3-出库管理/拣货任务/拣货任务主PRD.md#三扫描确认缺货与提交)；布局见[页面骨架](PDA拣货页面骨架.md)。管理端不用 PDA 时走[拣货任务 Web 端拣货](../../3-出库管理/拣货任务/拣货任务前端Demo版PRD.md#五web-端拣货录入页)，两端调用同一组动作。  
> **样式与交互服从[《PDA作业端设计规范》](../PDA作业端设计规范.md)**，版式与上架作业一致（`PdaHeader`、`PdaContextBar`、`PdaCard`/`PdaListItem`、`ScanInput`、`PdaFooter` 通栏主按钮）。

## 1. 能力概述

| 项目 | 内容 |
| --- | --- |
| 作业对象 | 拣货任务（按单、波次、补拣） |
| 路由 | `/pda/pick`；步骤用路由参数 `step`（§2）；`no` 为任务号，`at` 为已到达的库位，`line` 为缺货行 |
| 拣货路径 | 剩余大于 0 的应拣行按来源库位分组，按库位编号自然顺序排（`lib/outbound-pick-route.ts` 的 `pickStops`）；一站一个库位 |
| 计数 | 到站后每扫一件商品（SN 商品每扫一个 SN）本行 +1；数满本行剩余自动确认下架；件数多时扫一件后在底部数量框直接改数再点确认 |
| 数据动作 | `outboundAction`：`PICK`（每次新的 `confirmationId`）、`SHORTAGE`、`FINISH_PICK`；与 Web 端拣货相同 |
| 草稿 | 还没确认的计数存 `stores/pda-outbound-session.ts`（按「仓库:任务号」）；确认后清除。已确认下架的数量在任务里，不进草稿 |

## 2. 步骤与返回

| step | 屏幕 | 进入方式 | 安卓返回键 / 标题栏返回 |
| --- | --- | --- | --- |
| `list` | 选任务 | 首页「拣货」；默认 | 回首页 |
| `work` | 按库位拣货 | 扫到或点选任务；管理端「PDA拣货」直接带 `step=work&no=` | 回选任务（未确认的计数留在草稿，再进来回到原库位接着数） |
| `short` | 上报缺货 | 本站某行的「上报缺货」 | 回按库位拣货（同一库位） |
| `done` | 全部拣完 | 最后一行确认后自动进入 | 回选任务 |

- 到站（`at`）随路由保存，刷新后仍是「已到达」；本库位拣完时清掉 `at`，页面换成下一站并提示扫库位。
- 任务已结束（他人提交或出库单取消）时，`work`、`done` 回到选任务并提示「任务已结束」。
- 扫码处理读最新数据（库位到站用 ref 立即生效、计数读 store），扫库位后紧跟的一枪不会因路由切换还没渲染而被当成「未到站」。

## 3. 每步可识别的码

| 步骤 | 可识别 | 命中 | 不命中（均为扫码错误：红闪、低音、扫码框下一行红字，下一次扫码时清除） |
| --- | --- | --- | --- |
| 选任务 | 任务号；波次号；出库单号（任务的所属单、份额或归属单） | 进入该任务按库位拣货 | 「没有找到待拣任务：xxx」 |
| 按库位拣货·未到站 | 库位码 | 当前库位或路径上另一个还有待拣的库位 → 到站，提示扫商品；本站有未确认计数时不能换站 | 扫到商品／SN：「扫到的是商品 X：请先扫描库位 L」；已拣完的库位：「L 已拣完，请前往 M」；不在路径上的库位：「不是本任务的拣货库位，请前往 L」；其他：「没认出 xxx：请扫描库位 L」 |
| 按库位拣货·已到站 | SN（属于本站某行来源库存）；批次号（本站某行）；商品（SKU 编码、本货主启用条码、主条码）；库位码 | SN／商品：本行 +1，数满自动确认；批次号：选中该行；库位码：换站（同上） | SN 本次已扫：「序列号已扫过」；SN 商品扫商品码：「要逐件扫序列号」；同一商品多批次且没选行：提示点选或扫批次号（不计数）；本站另一行有未确认计数：「X 还有 n 件没确认」；商品在路径别的库位：「X 不在这个库位，它在 L」；都不是：「没找到这个码，不是本任务要拣的商品」 |
| 上报缺货 | 不接收扫码 | — | — |

- 数量框获得焦点时收到扫码内容，不写入数量，按本屏扫码规则处理（规范 §4.2）。
- 模拟扫码候选：选任务＝前 3 个待拣任务号；未到站＝当前库位、下一库位；已到站＝本站各行主条码（无主条码用 SKU 编码），SN 行取来源库存里本次没扫过的前 2 个 SN，同商品多批次时加批次号；最多 4 个。

## 4. 屏幕内容

**按库位拣货**（`work`）：

- 上下文条：任务号（末 4 位加粗）· 库位 当前/总数 · 已拣/应拣。
- 当前站卡片（`PdaStopCard`）：未到站为主色「前往库位」+ 24px 库位号；到站后变绿「已到达库位」；右侧「下一个」库位。
- 扫码框标签随状态换：「扫描库位 L」→「扫描商品条码或序列号，每扫一件 +1」。
- 「本库位待拣（n）」：每行一张卡——SKU 编码（等宽粗体）、名称最多两行、批次·效期、不良品时品质标签、SN 标签；右侧大号「待拣 n」，计数中换成「已数 a/n」并描边；底栏「应拣 · 已拣（· 缺货）」与右侧缩小的红字「上报缺货」（到站后才出现）。
- 底部操作区：未到站提示「先扫描库位 L 确认到站」；到站未计数提示「扫一件 +1，数满自动下架」；计数中左侧数量步进器（不显示标签，SN 行改为「清空」按钮），右侧主按钮「确认拣货（n 件）」，未计数时置灰。
- 换站后主区回到顶部，新库位卡总在第一屏。

**上报缺货**（`short`）：库位·商品卡（右侧待拣）；本行有已数未确认的件数时提示「已数的 n 件会先确认下架，再报缺货」；缺货数量步进器（默认 待拣 − 已数，上限同）；缺货原因大按钮组（无货、残损）；说明换位与待核对；主按钮「确认缺货（n 件）」。成功后 toast 写明换位到哪些库位（或没有可换位库存、提交后按短拣），退回同一库位：换位到本库位的新行接着拣，本库位拣完则自动跳站。

**全部拣完**（`done`）：完成卡（应拣、实拣、上报缺货、短拣）；「把货送到出库暂存库位」+ 24px 暂存库位号；说明「确认时已经下架到出库暂存；提交只结束任务，不再移库」；主按钮「提交拣货任务」→ 确认弹窗 → `FINISH_PICK` → toast 并回到选任务。

## 5. 反馈

| 场景 | 级别 | 表现 |
| --- | --- | --- |
| 到站、计数 +1、自动确认、换站 | 成功 | 扫码框绿闪、短高音；扫码框下一行绿字写对象与数字（如「CABLE-01 已拣 3 件。A-01-01 已拣完，前往 A-01-02」） |
| 扫错码 | 扫码错误 | 见第 3 节，红闪、低音、红字 |
| 确认下架、上报缺货、提交被动作拒绝（库存变化、盘点冻结、数量超限等） | 业务阻断 | 「知道了」弹窗写原因；计数保留 |
| 提交任务 | 需确认 | 确认弹窗写已拣件数与短拣件数 |
| 离开本屏的结果（全部拣完、缺货结果、提交） | 轻提示 | toast |

## 7. 走查

种子 0019 的任务（PK-…-0010）：A-01-01 线材 3 件、A-01-02 SN 商品 1 件。

| 步骤 | 操作 | 预期 |
| --- | --- | --- |
| 1 | 首页 → 拣货 | 待拣任务列表；0019 的任务显示「2 个库位 · 2 个商品」 |
| 2 | 打开该任务，先扫商品条码 | 红闪：「扫到的是商品 CABLE-01：请先扫描库位 A-01-01」 |
| 3 | 扫 A-01-01，再连扫 3 次线材条码 | 到站变绿；第 1、2 次「+1，已数 n/3」；第 3 次自动确认，提示 A-01-01 已拣完、前往 A-01-02，页面换成 A-01-02 |
| 4 | 刷新页面 | 仍在 A-01-02；已拣 3/4 |
| 5 | 扫 A-01-02，扫候选 SN | 自动确认，进入「本任务已全部拣完」，显示暂存库位 |
| 6 | 提交拣货任务 | 确认后回到选任务；管理端任务已完成，库存流水没有第二次移库 |
| 7 | 另一任务：数 1 件后点「上报缺货」报 3 件无货 | 先确认 1 件，再报缺货；toast 写换位结果；回到同一库位或自动跳站 |
| 8 | 切 English、DE-FRA-01 | 列表与作业页文案、仓库正确；320×509 无横向滚动，主按钮与库位卡可见 |
