# PDA移库前端Demo版PRD

版本：WMS-V0.1｜2026-10-15。规则见[移库作业主PRD](../../4-库存管理/移库作业/移库作业主PRD.md)，布局见[PDA移库页面骨架](PDA移库页面骨架.md)。

路由`/pda/move`，`step`允许`source`、`item`、`target`、`lines`、`confirm`。一次提交可含一行或多行，成功后形成一条移库作业；管理端只查询，不下发任务。

| 步骤 | 可识别的码 | 成功结果 | 校验与候选 |
| --- | --- | --- | --- |
| source | 本仓库位码 | 绑定源位，进入商品 | 启用、非暂存；候选为本仓有可移库存的库位 |
| item | SKU、商品条码；SN商品可直接扫SN | 显示货主、批次、品质、实际、已分配、可移 | 必须存在源位；多批次时整屏选择；候选来自源位库存 |
| target | 本仓库位码 | 显示目标位，确认搬到位后加入待提交清单 | 非源位、非暂存、启用、同货主或空位、品质适配；候选为合法目标位 |
| lines | 不接收扫码 | 查看、删除未提交行；继续添加或进入确认 | 至少1行；全部行须同仓库、同货主；同一源明细累计数量不超可移上限；同一SN不得重复 |
| confirm | 不接收扫码 | 整次提交后返回一个MV号 | 再校验全部行的数量、SN、盘点状态和目标占用；任一行失败时整次不生效 |

普通SKU默认数量1，可调到可移上限；SN商品逐件扫描，重复SN报错。盘点中阻断；待核对不自动增加移库冻结，但页面提示核对实物。扫描发现源位实物与账不符时，用户确认后调用共用的`reportInventoryDiscrepancy`动作立即标记“待核对”。若待提交清单已有其他行，页面要求先提交这些行，或确认实物已全部放回源位后放弃草稿；完成收尾后再进入盘点发起页，不直接发起无依据调整。

安卓返回逐步回退；当前行和待提交清单均进入本机草稿，刷新可继续或放弃。从清单继续添加时只清空当前行，保留已加行；后续行扫到其他货主库存时阻断。提交失败保留全部草稿并标出失败行；放弃含已搬实物的草稿前，须二次确认实物已全部放回源位。提交成功后草稿清除，重复提交返回原MV号。每个扫码步骤提供模拟候选；数量框接收到扫码字符时转给当前扫码步骤，不改数量。

## 动作与文案key

| 业务动作／文案 | key | 中文 | 英文 |
| --- | --- | --- | --- |
| 加入待提交清单 | `pda.move.action.addLine` | 加入清单 | Add Line |
| 继续添加 | `pda.move.action.addAnother` | 继续添加 | Add Another |
| 删除未提交行 | `pda.move.action.removeLine` | 删除本行 | Remove Line |
| 整次提交`submitMove` | `pda.move.action.submit` | 提交移库 | Submit Move |
| 上报账实不符并转盘点 | `pda.move.action.reportAndOpenStocktake` | 退出并去盘点 | Start Count |
| 整次失败 | `pda.move.message.atomicFailed` | 存在失败行，本次移库未生效 | Move failed. No lines were applied. |
| 放弃草稿确认 | `pda.move.message.confirmPhysicalRestored` | 请确认实物已全部放回源位 | Confirm all items were returned to source locations. |

走查：单行和多行移库、不同源／目标库位、批次、SN、后续行命中其他货主、暂存位、已分配上限、盘点中、待核对提示、重复提交、保存草稿后刷新、一行失败时整次不生效。验证每行源减目标增成对、SKU三量不变，管理端能立即查询同一MV记录。
