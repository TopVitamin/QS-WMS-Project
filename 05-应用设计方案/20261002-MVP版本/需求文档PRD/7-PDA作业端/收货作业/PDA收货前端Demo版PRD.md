## 1. 能力概述

| 项目 | 内容 |
| --- | --- |
| 功能 | F07 收货确认（PDA 端） |
| 路由 | `/pda/receive`；步骤用路由参数 `step`（§2） |
| 作业单位 | 一次**收货作业** = 一张入库单 + 1～N 个容器（无容器收货至多一组）。录入随时暂存在本机；「提交收货」把勾选的容器一次提交 |
| 数据动作 | `submitReceipt`（与 Web 共用）：一次提交生成**一条**收货记录，明细按「容器 × SKU」成行；拒收行生成入库异常；按「容器 × 品质」生成上架单（无容器收货按「收货记录 × 品质」） |
| 前置 | 入库单可收货（`canReceiveInbound`）：待收货或收货中、未收货完结、未取消、仍有未收 |

## 2. 步骤与返回

| step | 屏幕 | 进入方式 | 安卓返回键 / 标题栏返回 |
| --- | --- | --- | --- |
| `order` | 选单 | 首页「收货」；默认 | 回首页 |
| `container` | 扫容器 | 选单成功；容器作业「新增容器」 | 回选单，作业保留 |
| `box` | 容器作业 | 绑定新容器；点选或扫到已有容器 | 回扫容器，当前容器保留 |
| `line` | 本行录入 | 扫到或点选商品 | 回容器作业；本次修改未点「加入本容器」则不保存 |
| `submit` | 提交收货 | 容器作业或扫容器页「提交收货」 | 回上一屏 |

- 每一步对应一条浏览历史；页面内的「回到上一屏」（如加入本容器后）优先用历史后退，避免同一步重复入栈。
- 返回不丢数据：作业内容都在暂存里，只有「放弃作业」「移出本容器」会删除，且需二次确认。
- 管理端「PDA 收货」带单号进入：没有未提交作业，或作业正是这张单 → 直接进入扫容器；有其他单的未提交作业 → 停在选单并阻断提示。
- 路由参数与暂存不一致（如刷新后容器已提交）→ 回到能继续的最近一步。

## 3. 每步可识别的码

| 步骤 | 可识别 | 命中 | 不命中或冲突 |
| --- | --- | --- | --- |
| 选单 | 入库单号、柜号（不区分大小写） | 选中该单 → 扫容器 | 扫码错误：入库单不存在或当前状态不能收货。已有其他单的未提交作业：业务阻断 |
| 扫容器 | 箱唛、托唛等容器号（非空编码） | 新容器 → 容器作业；本次作业已有的容器 → 打开它继续录入 | 扫到入库单号、柜号、商品条码、货位码：扫码错误，提示扫到的是什么码。本单已提交过的容器：业务阻断 |
| 容器作业 | SKU 编码、货主条码、主条码（按本单货主，与 Web 同一解析） | 本单该 SKU 仍有本次可收 → 本行录入：新行良品计 1；已在本容器的行良品 +1 | 不在本单：扫码错误。本次可收为 0：扫码错误「本次已收满」 |
| 本行录入 | 同上 | 同一商品：良品 +1；超过本次可收则扫码错误 | 其他商品：扫码错误「请先加入本容器，再扫下一个商品」 |

- 本行录入页没有扫码框，由页面级监听接收扫码；数量框获得焦点时收到扫码内容，不写入数量，按本步规则处理（规范 §4.2）。
- 模拟扫码候选：选单 = 可收货入库单号；扫容器 = `BOX-<单号后 4 位>-01` 起本单与本次作业都没用过的 3 个；容器作业 = 本单仍有本次可收的商品主条码。

## 4. 录入与联动（本行录入）

| 项 | 规则 |
| --- | --- |
| 本次可收 | 该行未收 − 本次作业中其他容器已录的同 SKU 合计（良品＋不良＋拒收） |
| 默认值 | 点选待收行进入：良品 = 本次可收；扫码进入新行：良品 = 1；已在本容器的行：显示已录数量（扫码进入再 +1） |
| 三个数量 | 良品、不良品、拒收；实收 = 良品＋不良品（R03、R15） |
| 联动 | 与收货分册 §2 一致：调整不良品或拒收时，数量在良品与该项之间转移（增加先从良品扣，良品不够才加合计；减少退回良品）；直接改良品只改合计 |
| 上限 | 三者合计 ≤ 本次可收；超出时拒绝本次修改并提示上限，保留原值，不截断 |
| 拒收原因 | 拒收大于 0 时出现 4 个大按钮（破损、标签不符、效期不符、其他），单选必填；拒收归 0 时清空 |
| 加入本容器 | 合计大于 0、有拒收时已选原因 → 写入暂存并回容器作业；不可用时主按钮上方一行写原因 |
| 移出本容器 | 已加入的行可移出，需二次确认 |

## 5. 新增容器与提交收货

### 5.1 新增容器（容器作业页次按钮）

1. 当前容器没有明细：直接回扫容器，空容器不保留。
2. 有明细：按最新数量逐行校验（§4 上限、拒收原因）；不通过 → 业务阻断，停在当前容器并指出商品。
3. 通过 → 当前容器标为「已暂存」→ 扫容器。

### 5.2 提交收货（容器作业页主按钮；扫容器页有明细时也显示）

1. 先按 5.1 校验并暂存当前容器。
2. 进入提交收货页：列出本次作业里有明细的全部容器，默认全选；每个容器显示行数和良品、不良、拒收合计；底部显示已选汇总。
3. 可取消勾选部分容器，只提交其余容器（分批提交，R17）。
4. 「确认提交 (N)」→ `submitReceipt`：勾选的容器整体按最新数量校验（R04、R16），任一不通过则整次不提交，业务阻断并指出容器与商品。
5. 成功：提示「已提交收货：N 个容器，实收 X，拒收 Y」；已提交的容器从作业中移除。
   - 入库单仍有未收 → 回扫容器（未勾选的容器仍在作业中）；
   - 入库单已全部收完 → 提示「该入库单已全部收货」，清空作业，回选单。

### 5.3 无容器收货

- 扫容器页次按钮「无容器收货」：作为本次作业中的一组，录入方式与容器相同；一次作业至多一组，再点即打开已有的那组。
- 上架单按「收货记录 × 品质」生成，容器号为空。

## 6. 暂存与恢复（R17）

| 项 | 规则 |
| --- | --- |
| 暂存内容 | 入库单号；容器列表（容器号或无容器、状态「录入中/已暂存」、各行良品、不良、拒收、拒收原因）；最后修改时间 |
| 保存时机 | 每次「加入本容器」「保存本行」「移出本容器」「新增容器」、选择无容器收货、提交成功后即写入。本行录入页未点主按钮的修改不保存 |
| 恢复 | 再次进入收货：选单页顶部显示「未提交的收货作业」卡片（单号、容器数、行数、暂存时间）。「继续作业」回到最后操作的容器；「放弃作业」二次确认后清空 |
| 失效 | 作业所属入库单已收货完结、已取消或已收完：继续作业被阻断，提示原因，只能放弃 |
| 性质 | 暂存不是收货记录：不改库存，不生成上架单与入库异常，管理端看不到 |
| 存放 | Demo 存浏览器 `localStorage`（键 `qs-wms-demo-pda-receive`）；一台设备同时只有一份作业（主 PRD Q12） |

## 7. 反馈与文案

| 场景 | 级别（规范 §5） | key |
| --- | --- | --- |
| 入库单不存在或不能收货 | 扫码错误 | `pda.inboundInvalid` |
| 扫到的不是容器号 | 扫码错误 | `pdaReceive.notContainer`（`{{kind}}`） |
| 商品不在本单 | 扫码错误 | `pda.notInOrder` |
| 本次已收满 | 扫码错误 | `pdaReceive.fullThisTime` |
| 录入页扫到其他商品 | 扫码错误 | `pdaReceive.scanNextFirst` |
| 超出本次可收 | 扫码错误（数量框为输入提示） | `pda.overMax` |
| 已有其他单的未提交作业 | 业务阻断 | `pdaReceive.sessionConflict` |
| 作业所属入库单已不能收货 | 业务阻断 | `pdaReceive.sessionInvalid` |
| 容器在本单已提交过 | 业务阻断 | `inbound.receive.containerAlreadyUsed` |
| 新增容器或提交时校验不通过 | 业务阻断 | `pdaReceive.lineInvalid` + 原因 key |
| 提交服务端校验失败 | 业务阻断 | 动作返回的 `errorKey`（见收货分册 §6） |
| 放弃作业、移出本容器 | 需确认 | `pdaReceive.discardTitle`、`pdaReceive.removeLineTitle` |
| 提交成功 | 成功 | `pdaReceive.submitSuccess` |

主要界面文案：

| key | 中文 |
| --- | --- |
| `pdaReceive.promptOrder` / `promptContainer` / `promptSku` | 请扫描入库单号或柜号 / 请扫描箱唛或托唛 / 请扫描商品条码 |
| `pdaReceive.pendingTitle` | 未提交的收货作业 |
| `pdaReceive.resume` / `discard` | 继续作业 / 放弃作业 |
| `pdaReceive.addContainer` / `submitReceipt` | 新增容器 / 提交收货 |
| `pdaReceive.addToBox` / `saveLine` / `removeLine` | 加入本容器 / 保存本行 / 移出本容器 |
| `pdaReceive.thisRemain` | 本次可收 {{count}} |
| `pdaReceive.scanToCount` | 再扫同一商品，良品 +1 |
| `pdaReceive.submitHint` | 提交后生成 1 条收货记录，未勾选的容器继续留在作业中 |
| `pdaReceive.confirmSubmit` | 确认提交 ({{count}}) |
| `inbound.bulkPiece` | 无容器收货 |

完整文案以语言包 `pdaReceive.*` 为准，中英文同时维护。
