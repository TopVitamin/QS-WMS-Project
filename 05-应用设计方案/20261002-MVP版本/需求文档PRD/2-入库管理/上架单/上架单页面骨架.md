# 上架单页面骨架

> 文档版本：WMS-V0.5｜日期：2026-10-21｜状态：演示已走查（2026-10-21）。V0.2：列表与详情只展示应上架与已上架，不展示「已录」。V0.3：详情改为与入库单相同的「概览卡 + 多页签」，新增 Web 端上架录入页。V0.4：Web 端上架改为一张录入表、一次确认。V0.5：Web 端上架改为作业台（扫商品条码选行、扫库位条码填库位），商品列与收货作业台一致。
> 线框画法遵循[《页面骨架模板-WMS-V1》](../../../../../06-常用模板和方法论/页面骨架模板-WMS-V1.md)；动作条件以[《上架单主PRD》](上架单主PRD.md)为准；字段以[《上架单（详细稿）》](../../../字段清单合集/02-入库管理/上架单/上架单（详细稿）.tsv)为准；交互见[《上架单前端Demo版PRD》](上架单前端Demo版PRD.md)。PDA保存与提交的线框见[PDA上架页面骨架](../../7-PDA作业端/上架作业/PDA上架页面骨架.md)，本文只画管理端（含 Web 端上架录入页）。

## 页面与弹窗清单

| 页面/容器 | 路由 | 入口 | 用途 |
| --- | --- | --- | --- |
| 上架单列表 | `/wms/inbound/putaway` | 入库管理 → 上架单 | 状态页签、查询、进入详情、进入 Web 端上架或跳转PDA上架 |
| 上架单详情 | `/wms/inbound/putaway/:putawayNo` | 列表点击上架单号；入库单详情上架单页签点单号 | 基本信息、上架进度、应上架与实际上架明细、操作日志 |
| Web 端上架 | `/wms/inbound/putaway/:putawayNo/entry` | 详情页头、列表行操作（未完成单） | 作业台：扫商品条码选行、扫库位条码填库位，撤销PDA已保存行，一次确认整单上架 |
| 序列号 Sheet | 详情实际上架页签行内「序列号」 | 只读查看该落位行关联的SN |  — |

**本期不提供**：管理端新建、编辑、删除上架单；更正、作废、重新打开已完成单；行勾选与批量操作；批量导入落位。保存与提交在 PDA 或 Web 端上架页完成，规则相同。

容器选型：上架单有单头、两张子表和日志，且要从入库单详情跳入 → **独立路由详情页**（概览卡 + 多页签）；补录需要边看明细边录 → **独立路由录入页**；SN明细字段少 → **Sheet**。入库单详情内原有的上架单 Sheet 保持只读快览，单号可跳本详情页。

## 绘制约定

- 列表查询区：`FilterBar` 6 列栅格（常显最多 5 项 + 第 6 列查询/重置；筛选项 >5 时其余进 `advanced`），见[需求文档 PRD / AGENTS.md](../../AGENTS.md)。
- 详情：与入库单相同的业务单据详情版式——上方 `DetailOverview`（左「基本信息」`Descriptions columns={3}`，右 320px 汇总卡），下方 `DetailTabs`（带条数，写入 URL）；货主、仓库展示为 `{编码} {名称}`；示例值为虚构。
- 列表与详情只展示「应上架」与「已上架」：「已上架」只在整单提交后等于应上架；保存进度（已录／剩余）只在作业页（PDA、Web 端上架页）。

## 列表页

- **用途**：按当前仓库查看上架进度，查找某容器、某来源单的上架单，进入详情或转到PDA作业。

## 详情页（独立路由）

- **用途**：核对一张上架单应上架了什么、录到了哪些库位、是否已提交、谁在什么时候做了什么，以及追到来源收货行。
- **关键要素**：版式同入库单详情。页头标题 + 状态；右侧 `返回列表`、`Web 端上架`、`PDA上架`（后两个仅未完成时）。上方左「基本信息」卡、右「上架进度」汇总卡；下方页签：应上架明细、实际上架明细、操作日志。

## Web 端上架（作业台）

- **用途**：现场已按纸单或口头完成搬运、没用 PDA 时，在管理端扫码（或手输）把每个商品放到哪、放几件录进上架单，一次确认整单上架；规则与 PDA 相同。
- **关键要素**：作业台版式，与收货作业台一致——当前对象（作业容器）、步骤提示条、一个扫码框、录入表；右侧「本次上架」汇总卡按库位列出这次放了什么，底部主按钮写明件数。商品列条码大字、SKU 小字一列，名称单独一列；表内全部左对齐。

```text
+--------------------------------------------------------------------------------------------------------+
| Web 端上架 · PA-20261011-0001  [待上架]                                          [返回详情] [PDA上架]  |
| +-- 作业区 ---------------------------------------------------------+ +-- 本次上架（320px）----------+ |
| | ┃ 作业容器                         ANKR Shenzhen Anker Trading    | | 已填 2 / 3 个商品    8 / 9 件 | |

| | | (i) 扫描库位条码                                              | | | A-01-01                       | |
```

**补充说明**：

- 一个应上架行一组：商品、名称、待上架纵向跨整组；同 SKU 多批次时条码列下面写批次号。库位默认留空、显示推荐库位，扫库位条码或点「用推荐」才算录入；和推荐一致打勾，改放别处框变橙并写出推荐库位。
- 扫商品条码选中一行（左侧蓝条），再扫库位条码填进这一行；不选行直接扫库位，填给推荐到该库位、还没填的第一行。不能放的库位当场提示原因，不填入。
- 「拆分」把同一行拆到多个库位，每组合计须等于待上架；SN 商品每条落位下面多一行序列号。
- PDA 已保存未提交的落位不进表：待上架列下面小字写「PDA 已存 n」，右侧清单对应库位下标「PDA 已存」，可撤销（二次确认）。
- 汇总卡底部写第一处没填好的地方，主按钮此时不可点；确认时任何一条不过整单不生效，弹窗写明哪个商品、哪个库位、为什么，出错的库位框标红，已填内容保留；确认成功后回到详情（已完成）。
- 宽度变化：内容区够宽时两栏（汇总卡 320／280px），窄了上下堆叠；名称最多两行，编码和数量不截断。
- 与 PDA 交替录同一张单时，两边看到的是同一份已保存明细。
