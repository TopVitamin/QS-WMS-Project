## 一、生成与关联

收货确认后自动按“本次收货记录＋容器＋品质”拆单：同一容器良品、不良品分别一张，某品质为0不生成；无容器收货按本次收货记录、品质合并。来源可以是入库或退货，分别引用原单及收货记录；仓库、货主、来源暂存库位和品质均固定，不允许手工建单。

一张单含1～多条应上架行，一条应上架行对应原收货明细行及其中一种品质；同SKU不同批次保留不同应上架行。实际明细引用应上架行号，一行可拆到多个目标库位；不另建上架结果对象。

## 二、状态与操作

| 状态 | 允许操作 | 生效结果 |
| --- | --- | --- |
| 待上架 | 查询、扫描定位、保存，或录满直接提交 | 首次保存进入上架中；直接提交进入已完成 |
| 上架中 | 查询、继续保存、修改或删除未提交行、整单提交 | 保存不动库存；删光实际明细仍保持上架中，删除的目标位占用释放 |
| 已完成 | 查询与追溯 | 不更正、不作废、不重复提交移库 |

上架单列表与详情只展示「应上架」与「已上架」两个数量：「已上架」只在整单提交后等于应上架；录入过程中的保存进度（已录／剩余）只在作业页（PDA 上架、管理端 Web 端上架页）出现，列表与详情不展示「已录」。入库分批上架指不同上架单先后提交，同一张上架单只能录满后整体提交。

## 三、保存与提交校验

1. 用户须有本仓权限及上架／移库执行权限（[《全局机制与权限配置》](../../系统架构设计/05-全局机制与权限配置.md)权限矩阵）；来源有效，单据尚未完成。含盘点中SKU的上架单不能开始作业，提交时也重新检查盘点状态。
2. 目标库位及所属库区启用，属于本仓，不能为收货暂存、出库暂存或异常处理库位。入库来源良品到存储／拣货库位，退货来源良品到存储库位；不良品到不良隔离库位。形态用于推荐，可在符合来源与品质要求的库位中人工改位，不做容量硬阻断。
3. 目标库位已有库存、未提交上架或返库上架占用及其他未完结任务归属须为空或同货主。先保存者取得货主占用；删除行或改位释放原占用，提交后转为库存占用。收发暂存库位允许混放，但不是上架目标。
4. 保存数量为正整数，各应上架行已录（未提交实际明细合计）不得超过应上架数量；提交时每条应上架行合计必须等于应上架数量，不能只校验整单总量。
5. 启用SN的应上架行，实际行须关联本次落位的实收SN，来自对应来源行、批次和品质，SN条数等于该行数量；同SN不能重复关联。可扫描或选择已有SN，不凭SKU总量猜单件去向。

保存只更新实际明细和目标位货主占用，不移动库存、不改变SN当前位置。提交时按原收货记录的暂存库位及实际上架行一次移库，更新SN库位，写一减一加流水、提交人与UTC时间；SKU实际总量、品质与订单占用不变。提交失败整张不生效，保留已录内容；重复提交返回原结果。

## 四、异常与展示

管理端提供上架单独立列表查询，筛选单号、来源单号、容器、货主、品质与状态；当前仓库和权限限定范围。详情显示来源、应上架数量、实际上架明细、提交留痕与操作日志（不展示「已录」）；入库单详情内只读查看相同数据（单号跳本单详情，行内「查看」开 Sheet 快览）。管理端不提供新建、编辑或作废入口；未完成单给出「Web 端上架」和「PDA上架」两个入口。

**Web 端上架**：用于现场已按纸单或口头完成搬运、没有使用 PDA 的情况，由有上架执行权限的人员在管理端把结果补录进同一张上架单。

| 项 | 规则 |
| --- | --- |
| 录入内容 | 逐条选择应上架行，录目标库位、数量；SN商品逐件录SN。系统给出推荐库位，可改 |
| 校验 | 与第三节完全相同：库位用途与品质、货主占用、行内不超应上架、SN条数与去重；提交时每行已录等于应上架 |
| 保存与撤销 | 每保存一条即写入实际明细（不动库存），可撤销未提交行；PDA 与 Web 可交替录同一张单，以已保存明细为准 |
| 提交 | 整单提交一次移库，提交人记实际点提交的账号；成功后回到详情，单据已完成 |
| 不做 | 不批量导入、不另设「补录」状态或单据；Web 不做扫码作业台 |

上架前才发现残损：按原品质提交后，交库存模块品质转换；暂存丢失：仍按应上架数量提交，再由发现人员对SKU发起盘点。该已确认路径可能造成提交至盘点之间账面多于实物，入库回传不反映丢失；不新增上架损失确认或改写原实收。实收误记、货主认错没有更正路径，受影响数量保持未完成，不能套用丢失路径。

## 五、验收

| 条件与操作（数字为模拟） | 预期结果 |
| --- | --- |
| 同一容器实收良品8、不良品2 | 自动生成两张上架单，应上架分别8、2 |
| 良品单先保存5件到L1，再保存3件到L2 | 保存后已上架仍为0，暂存库存仍8；提交后L1为5、L2为3、暂存减8 |
| 同SKU两个批次，各应上架4；误录第一批5、第二批3 | 即使总量8也阻断，逐应上架行校验 |
| A货主先保存到空位，B货主再保存同位 | B被阻断；A删除该行后，其他占用均为空时B可用 |
| SN商品两件分到两个库位 | 两条实际行各关联一个来源SN；提交后SN分别在对应库位，合计数量2 |
| SKU盘点中、库位停用或重复提交 | 分别阻断作业、阻断目标位、返回原提交结果；不重复移库 |
| 现场按纸单把良品8件放到L1，未用PDA；文员在Web 端上架录L1×8并提交 | 与PDA提交结果相同：L1为8、暂存减8；提交人为文员账号 |
| PDA已保存L1×5后，文员在Web 端上架打开同一单 | 看到已录5、剩余3，可继续录剩余或撤销L1×5 |

以上为文档验收要求；管理端查询、Web 端上架与 PDA 落位、提交已按本文实现并演示通过（2026-10-15）。库存流水是 Mock 域结果，未接真实库存服务。
