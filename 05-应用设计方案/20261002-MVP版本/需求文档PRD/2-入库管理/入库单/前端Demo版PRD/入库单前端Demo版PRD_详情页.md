## 1. 页面概述

| 项目 | 内容 |
| --- | --- |
| 页面名称 | 入库单详情页 |
| 路由 | `/wms/inbound/orders/:inboundNo` |
| 入口 | 列表点击入库单号 |
| 目标 | 只读查看头、到货、数量、明细；追溯收货记录/上架单/异常；**收货（F07）**与确认收货完结 |
| 骨架顺序 | 页头 → 基本信息 → 到货 → 数量汇总 → 时间与完结 → 入库明细 → 三类 Tabs → 操作信息 |

| 模式 | 说明 |
| --- | --- |
| 容器 | **独立路由页**（多 Panel + 子表，不用 880px 主详情 Sheet） |
| 返回 | `返回列表`，保留列表 query |

> **本期边界**  
> - 无编辑、删除；上架保存/提交不在本页（AC15）。  
> - 收货走**独立收货作业台路由**（页头「Web 端收货」入口），规则与 PDA 一致（R15）。  
> - 子对象页签无新建/提交入口。  
> - 上架单列表「已上架」仅计**已提交**量（AC09）。

## 2. 页头

### 2.1 标题与状态

| 元素 | 规格 |
| --- | --- |
| 标题 | `t('inbound.detailTitle', { no })` |
| 状态 | 标题旁 1 枚 `<StatusBadge>`（单据状态） |
| 布局 | 左：标题 + 状态；右：`PageContainer` `actions` |

### 2.2 页头按钮矩阵

`返回列表` **始终第一**（outline）。

| 按钮 | 待收货 | 收货中 | 上架中 | 已完成 |
| --- | :---: | :---: | :---: | :---: |
| 返回列表 | ✅ | ✅ | ✅ | ✅ |
| Web 端收货（F07） | ✅* | ✅* | ❌ | ❌ |
| PDA 收货 | ✅* | ✅* | ❌ | ❌ |
| 确认收货完结 | ❌ | R07 ✅ | ❌ | ❌ |

\* 须 `receiptCloseFlag=未确认` 且存在未收>0 的行（与 §6.4 一致）。全部拒收等零实收单走上游取消，受理后整单与明细为已取消，页头不渲染收货/完结按钮。

「收货」→ [收货与双端 §3](入库单前端Demo版PRD_收货与双端.md)，outline 或 secondary；成功刷新详情（AC21）。

「确认收货完结」→ [弹窗 PRD §3](入库单前端Demo版PRD_弹窗与Mock.md)，primary。

### 2.3 二次确认与刷新

与采购详情「操作→弹窗→反馈」一致：

1. 点击「确认收货完结」→ 打开弹窗分册 §3（不在此重复弹窗正文）。  
2. 确认成功 → `toast.success(inbound.receiptCloseSuccess)` → **刷新当前详情**（或 `revalidate` 从 `db` 重读）。  
3. 失败 → `toast.error`；列表进入详情时若单已变状态，页头按钮应已随 `recompute` 消失。

## 3. 主档分区

每组 `Panel` + `Descriptions columns={4}`（字段分组对齐字段详细稿「字段所属分组」）。

| Panel | 字段要点 |
| --- | --- |
| 基本信息 | 单号、状态、业务类型、仓库、货主、上游单号、SKU 种类数 |
| 到货信息 | 到货方式、柜号、运单号（multiline）、预计到仓、首次到货 |
| 数量汇总 | 预计/实收/拒收/已上架合计 + 收货/上架进度（R13：`Progress` + `done/total`，无 `%`） |
| 时间与完结 | 创建、完成、收货完结标记/确认人/确认时间、备注 |

货主/仓库：`{编码} {名称}`。

---

## 4. 入库明细 DataTable

列：行号、商品编码、**条码**、名称、明细状态、预计、实收、拒收、未收、**实收良品数量**、**实收不良品数量**、**已上架数量**（只读展示，不计入编辑；口径为已提交上架单累计）。**不展示**待上架数量列（可由实收与已上架自行心算）。

- 数字列 `<Num>`，`meta.align: 'right'`。  
- 单状态已完成且未收>0：`TagLabel` `inbound.shortage`（AC10）。  
- 已取消单的明细状态为**已取消**（随单收口，不设已完成；见主 PRD §7.4）。  
- 宽表横向滚动。

## 5. 子对象页签（F03）

`Tabs` 在明细表**下方**；角标为条数。无数据时各 Tab 内 **空态**「暂无收货记录」等（i18n `inbound.tabs.empty.*`）。

### 5.1 收货记录 Tab（简表）

| 列 | 展示 | 说明 |
| --- | --- | --- |
| 收货记录号 | `<DocNo>` 可点 | 不跳路由，开 §5.4 Sheet；不另设「查看」列 |
| 收货时间 | `<DateTime>` | 可默认倒序 |
| 收货人 | 文本 | — |
| 作业容器 | 由明细汇总：只有一个容器显示容器号；多个显示「首个容器号 等 N 个」；只有无容器收货显示「无容器收货」 | 一次提交可含多个容器（主 PRD R16）；`receiptContainerLabel()` |
| 暂存库位 | 库位编码 | — |
| 实收合计 / 拒收合计 | `<Num>` | 本记录明细汇总 |

### 5.2 上架单 Tab（简表）

| 列 | 展示 | 说明 |
| --- | --- | --- |
| 上架单号 | `<DocNo>` 可点 | → §5.5 Sheet |
| 作业容器 | 文本；空显示「无容器收货」 | AC19 |
| 品质 | 良品/不良品 | `TagLabel` |
| 单据状态 | `<StatusBadge>` | 上架单三态 |
| 应上架总数量 | `<Num>` | — |
| 已上架数量 | `<Num>` | **仅已提交**上架单累计（AC09） |

### 5.3 入库异常 Tab（简表）

| 列 | 展示 |
| --- | --- |
| 异常记录号 | 文本 |
| 异常类型 | 拒收 |
| 商品编码 / 名称 | 编码 + 名称 |
| 异常数量 | `<Num>` |
| 异常原因 | 枚举文案 |
| 收货记录号 | 文本 |
| 登记时间 | `<DateTime>` |

### 5.4 收货记录 Sheet

宽 `880px`（《02-设计规范》§4.2）。单头「作业容器」列出本次提交的全部容器（含无容器收货），与 §5.1 同一汇总规则。只读明细：行号、商品编码、名称、作业容器、实收、拒收、拒收原因、良品、不良品、批次、生产日期、失效日期（按 SKU 配置）；明细按容器分组排列；批次/效期样例见 AC18。

### 5.5 上架单 Sheet

只读；内层 Tabs：**应上架明细** / **实际上架明细**。作业容器为空 → `t('inbound.bulkPiece')`＝「无容器收货」（AC19）。

应上架列：行号、商品、批次/效期（按 SKU）、应上架数量。实际上架列：应上架行号、目标库位、上架数量；SN商品下钻查看每行关联的SN。
