## 1. 能力概述

| 项目 | 内容 |
| --- | --- |
| 功能编号 | F07 收货确认 |
| 端 | **管理端收货作业台**（独立路由）+ **PDA**（`/pda/receive`，交互见 PDA 收货 PRD） |
| 数据动作 | 两端共用 `submitReceipt`：**一次提交 = 一条收货记录**，可含 1～N 个容器（R16）。成功后生成收货记录、拒收类入库异常（如有）、上架单（按「容器 × 品质」；无容器收货按「本次收货记录 × 品质」）并重算状态 |
| 与 F04 关系 | 收货完结后 **禁止**再收货；与主 PRD §11.1 并发规则一致 |

**设计原则（Web）**：管理端收货是**桌面作业台**，不是弹窗向导。单头上下文固定，先绑定作业容器（或无容器收货），再在**本次收货录入表**内按行录入良品/不良/拒收；一个容器录完扫下一个，右侧「本次收货」列出已录容器与合计，最后一起提交成一条收货记录。支持扫码枪定位 SKU 与连续收货。

## 2. 录入规则（两端共用：R03 / R04 / R15 / R16）

| 规则 | 说明 |
| --- | --- |
| 本次实收 | 良品 + 不良品；在实收内拆分，良品＋不良品＝本次实收 |
| 本次拒收 | 拒收>0 须选原因；拒收不计实收、不进库存，提交后自动生成拒收类入库异常 |
| 上限 | 同一 SKU：历史实收＋拒收，加上本次提交内**各容器**的实收＋拒收，不得超过预计（R04）；整单收货完结后不得再提交 |
| 仅拒收 | 本次实收为 0 时可不做品质拆分，直接提交 |
| 提交单位 | 一次提交生成**一条**收货记录，明细按容器、SKU、批次／效期拆行（R16）。两端都可一次收多个容器后统一提交；PDA 还可勾选部分容器分批提交（R17），Web 一次提交本次全部容器 |
| 容器复用 | 已在本单提交过的容器不得再用于本单（绑定与提交两处校验）；同一次提交内容器号不得重复 |
| 默认值 | 点选行进入录入时，按本次可收预填良品（相当于「全部记为良品」）；扫码进入时良品从 1 开始逐件计数，再扫同一商品 +1 |
| 联动 | 调整不良品或拒收时，数量在良品与该项之间转移：增加时先从良品扣减，良品不够才增加合计；减少时退回良品。直接改良品只改合计。三者合计不超过本次可收；超出时拒绝本次修改，不截断 |

「本次可收”＝该SKU未收减去本次作业其他行已录的同SKU数量（包含同容器其他批次行及其他容器）。Web 录入表显示为「本容器可收」，有其他容器已录时在下方提示数量。

## 3. 管理端（Web）收货作业台

### 3.1 路由与入口

| 项 | 规格 |
| --- | --- |
| 路由 | `/wms/inbound/orders/:inboundNo/receive` |
| 页签 | `inbound.tabReceive`（收货作业） |
| 入口 | 列表操作列「Web 端收货」；详情页头「Web 端收货」 |
| 文案 | Web：`inbound.receive.action`（Web 端收货）；PDA：`inbound.openPdaReceive`（PDA 收货） |
| 显示条件 | `canReceiveInbound`（主 PRD §6.4） |
| 不可收货 | 重定向至详情（如已上架中/已完成/已收货完结/已取消） |

### 3.2 页面结构

```
PageContainer fill
├─ 页头：收货作业 · 单号 + 状态 | 返回详情 | 返回列表
├─ Panel：单头摘要（只读一行）：货主、柜号、运单号、SKU 种类、计划总数量、剩余待收
└─ 双栏
   ├─ Panel：当前容器 + [新增容器] → 扫码框（无当前容器时扫箱号，有当前容器时扫商品）→ 本次收货录入表
   └─ 右侧 320px「本次收货」：容器列表（容器号、SKU 数、件数、拒收；点击切回修改，× 移除）
        → 容器数 / 良品 / 不良 / 拒收合计 → [提交收货（N 个容器）] [清空本次]
```

### 3.3 绑定作业容器

- 没有当前容器时，扫码框用于扫描或输入箱号/托唛「绑定」；或点「**无容器收货**」（`inbound.bulkPiece`，本次至多一组）。
- 已在本单确认过收货的容器不可复用：绑定与提交两处校验，命中提示更换容器；扫到本次已有的容器则切回该容器。
- 「新增容器」：当前容器留在本次收货里，扫码框回到扫箱号；没录任何数量的容器切走时自动丢弃。
- 右侧列表点击容器可切回修改；「×」移除容器（有录入时二次确认）。
- 未绑定容器前，录入表禁用，提示先绑定。
- 本次收货保存在本机（按入库单），切页签、刷新后仍在；不是收货记录，不改库存。提交成功或「清空本次」后移除。

### 3.4 扫码定位

- 有当前容器时，扫码框回车匹配 **SKU 编码或货主条码**（货主条码表 / 主条码）；
- 命中：定位该行并「良品 +1」（连续扫码累计），刷新选中行；
- 未命中：`inbound.receive.scanMiss`；未绑容器：提示先绑定。

### 3.5 本次收货录入表

列：SKU（编码；下方名称 · 条码）、已收 / 预计、**本容器可收**、批次／生产日期／失效日期（按配置）、SN明细入口（按配置）、本次收货数量（**良品**、**不良品**、**拒收**）、拒收原因（拒收>0 时出现选择）、重置图标（本行有录入时出现）。录入列须在 1440 宽屏内不横向滚动即可见。

- 仅**选中行**可录入；点击行或扫码定位选中。
- 本次良品/不良/拒收按 §2 联动；合计不得超过本容器可收。
- 行「重置」恢复该行空值；重新点选后再按本次可收预填良品。

### 3.6 提交与反馈

| 动作 | 行为 |
| --- | --- |
| 「提交收货（N 个容器）」 | 校验本次全部容器的录入行（拒收须原因；各容器同 SKU 合计≤未收）→ `submitReceipt`（多容器，生成一条收货记录）→ `toast.success`；清空本次收货；收满的行从待收列表移除 |
| 全部收完 | 提示 `inbound.receive.doneAll` 并返回列表 |
| 「清空本次」 | 二次确认后清空本次全部容器与录入 |
| 失败 | `toast.error(errorKey)`；不改变录入内容 |

## 4. PDA

PDA 收货的步骤、每步可识别的码、「新增容器」与「提交收货」、暂存与恢复、分批提交，统一见[《PDA收货前端Demo版PRD》](../../../7-PDA作业端/收货作业/PDA收货前端Demo版PRD.md)与[《PDA收货页面骨架》](../../../7-PDA作业端/收货作业/PDA收货页面骨架.md)。本分册只约束两端共用部分：

- 录入、上限、默认值、联动按本分册 §2；拒收原因枚举按 §5；
- 提交动作与 Web 共用 `submitReceipt`，一次提交生成一条收货记录；
- 收货完结、已取消或非可收货状态不可进入；提交时按最新数量整体重新校验（主 PRD §11.1）。

## 6. 错误与 i18n

| key | 场景 |
| --- | --- |
| `inbound.receive.containerRequired` | 未绑定容器且未选无容器收货 |
| `inbound.receive.containerAlreadyUsed` / `containerAlreadyUsedNo` | 容器在本单已确认收货 |
| `inbound.receive.containerDuplicated` | 同一次提交内容器号重复，或无容器收货超过一组 |
| `inbound.receive.emptySubmit` | 提交内容为空：没有容器，或容器内没有明细 |
| `inbound.receive.scanMiss` | 扫码未命中待收行 |
| `inbound.receive.overRemain` | 超未收（含本次各容器合计） |
| `inbound.receive.qualitySumInvalid` | 良品+不良≠本次实收 |
| `inbound.receive.rejectReasonRequired` | 有拒收未选原因 |
| `inbound.receiptCloseStale` | 已收货完结仍提交 |
| `inbound.receive.cancelled` | 已取消单据提交收货 |
