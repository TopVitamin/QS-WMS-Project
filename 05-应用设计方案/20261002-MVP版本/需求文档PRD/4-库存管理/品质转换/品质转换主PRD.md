# 品质转换主PRD

> 定义在库正常品转为不良品的系统动作。品质转换不建单据、不编号，结果写入库存明细、SN库存和库存流水。规则依据见[库存模块宏观系统架构](../../../../../01-全局背景信息/07-库存模块宏观系统架构.md)第3.1.3节；管理端布局和交互分别见[库存查询页面骨架](../库存查询/库存查询页面骨架.md)和[库存查询前端Demo版PRD](../库存查询/库存查询前端Demo版PRD.md)。

## 一、范围

一期只有“正常品→不良品”，不提供不良品转回正常品。转换在原库位、原批次上发生，不搬实物、不改变实际总量；需要移至不良隔离库位时，转换完成后另做移库。

| 来源 | 触发 | 适用范围 |
| --- | --- | --- |
| 在库受损 | 仓库主管在管理端或PDA确认 | 存储、拣货库位上未被分配的正常品；复核发现已拣残损时可在出库暂存库位转换后退拣 |
| 过期 | 系统按仓库当地日期自动触发 | 存储、拣货库位上进入过期且未被分配的正常品 |

收货暂存库位发现残损时先按原品质上架，再在目标库位转换；出库暂存库位的已拣货不做过期自动转换。盘点中的SKU暂停人工和自动转换，盘点完成后补做过期转换。

## 二、人工转换输入与校验

人工入口依赖当前终端的库存明细：管理端从库存明细详情发起，PDA从受损实物核对入口发起。仓库、货主、SKU、库位、批次、当前品质和可转换数量由库存明细带入，原因代码固定为在库受损；作业人员输入转换数量、原因说明、依据说明和货主通知结果，SN商品还须逐件选择或扫描。人工转换的原因说明、依据说明和货主通知结果均必填。

- 所选明细必须为正常品；转换数量大于0且不超过实际－已分配。
- 盘点中的SKU不能转换。待核对不是第三种品质，也不自动增加新的品质转换状态；若现场实际是账实不符，须按盘点处理，不能借品质转换调数量。已核实且仍在库的受损实物，继续按本PRD的数量与权限条件转换。
- SN商品须逐件选择或扫描，SN数等于转换数量，且每件仍在所选明细。
- 人工转换须具备本仓授权和“在库受损品质确认”权限；普通移库、拣货或库存查询权限不自动包含。
- 重复确认返回原结果，不生成第二组转换流水。

一期Demo仅实现管理端入口；PDA入口的实现延后，不改变上述业务能力与权限范围。

## 三、结果

同一库位、批次上正常品实际减少，不良品实际增加；SKU实际总量不变，预占因不良品增加而增加，可用相应减少。系统写两行品质转换流水，保留原因、依据、通知结果、操作者和时间；SN商品同步更新品质并保留轨迹。

转换可能使可用为负，表示订单占着的正常品不足。系统不得为了维持可用非负而阻断已经核实的真实品质变化；相关出库在分配或补拣时按缺货规则处理。

## 四、自动过期转换

- 效期等级按商品阈值和所属仓库当地日期计算，过期优先于临期。
- 每次处理只转换当时未被分配的数量；已分配未拣的过期品先不转，拣货时上报库位缺货并释放分配后再转。
- 自动动作同样生成成对流水，原因标为“效期过期”，操作者显示系统。
- 因仍有已分配、盘点暂停或执行失败而未转换时，保留对应待补做原因；分配释放、盘点完成或系统重试后补做，不重复转换。

## 五、验收

| 条件与操作（数字为模拟） | 预期结果 |
| --- | --- |
| 正常10、订单占用3，转换2件受损 | 实际仍10；正常8、不良2；预占5、可用5；生成两行转换流水 |
| 正常明细10、已分配3，输入8 | 阻断并提示最大可转换7，不截断输入 |
| 选择2个SN但数量填3 | 阻断，提示SN数与数量不一致 |
| 盘点中的SKU触发人工或自动转换 | 均不生效；自动过期进入待补做提示 |
| 重复确认同一人工转换 | 库存只转换一次，返回原流水结果 |
