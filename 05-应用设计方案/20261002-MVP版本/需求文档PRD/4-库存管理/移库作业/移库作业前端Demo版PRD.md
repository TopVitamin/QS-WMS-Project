## 1. 页面概述

| 项目 | 内容 |
| --- | --- |
| 页面名称 | 移库作业列表页、移库作业详情页 |
| 路由 | 列表 `/wms/inventory/moves`；详情 `/wms/inventory/moves/:moveNo` |
| 入口 | 左侧菜单「移库作业」；列表点移库作业号；库存流水详情的来源单据跳转 |
| 页面目标 | 查询 PDA 已提交的移库记录，核对一次提交的明细、源／目标库位、批次／SN、品质、数量及两组流水 |
| 适用状态 | 移库作业没有状态；提交成功即生效，管理端只读 |
| 版式 | 列表：`PageContainer fill` + 筛选 `Panel` + 表格 `Panel`；详情：`DetailTitle` + `DetailOverview` + `DetailTabs` |
| 页面边界 | 不提供新建、下达任务、编辑、删除、撤销、重做、再次执行、行勾选、批量操作、状态页签、正式文件导出 |

**URL 状态**：

| 页面 | 参数 | 含义 |
| --- | --- | --- |
| 列表 | `no` | 移库作业号前缀 |
| 列表 | `sku` | SKU 编码／名称分词 |
| 列表 | `customerId` | 货主 id |
| 列表 | `source` | 源库位编码包含 |
| 列表 | `target` | 目标库位编码包含 |
| 列表 | `submittedFrom`、`submittedTo` | 提交日期起止 |
| 列表 | `operator` | 操作者 |
| 详情 | `tab` | `lines`（默认）／`logs`／`audit` |

- 列表筛选写入 URL；排序、分页不写入。详情页签写入 URL，刷新和返回仍停在原页签。
- 从详情返回列表时恢复原筛选条件，分页回第一页；从列表进入详情时保留列表查询串。页码恢复（导航 state 或缓存）列为待实现，不在本版验收。
- 顶栏切换仓库后，列表按新仓库取数；详情中若当前 `MV` 号不属于新仓库，显示未找到态。

## 2. 查询区

`FilterBar columns={6}`。常显 5 项占第 1～5 列，第 6 列放查询、重置、展开；提交时间、操作者放 `advanced`。筛选项总数 7，必须出现「展开」。

| # | 筛选项 | 区域 | 控件 type | 匹配方式 | placeholder key | 选项／空值 |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | 移库作业号 | 常显 | `input` | 前缀匹配，不区分大小写 | `inventory.move.moveNoPlaceholder` | 空串；输入去首尾空格 |
| 2 | SKU | 常显 | `input` | 空格分词，任一分词命中明细行的 SKU 编码或名称即匹配该 `MV` 号 | `inventory.stock.skuKeywordPlaceholder` | 空串 |
| 3 | 货主 | 常显 | `select` | 精确匹配货主 id | `common.selectPlaceholder` | 全部 + 货主资料；默认 `FILTER_ALL` |
| 4 | 源库位 | 常显 | `input` | 包含匹配任一行源库位编码 | `inventory.stock.locationPlaceholder` | 空串 |
| 5 | 目标库位 | 常显 | `input` | 包含匹配任一行目标库位编码 | `inventory.stock.locationPlaceholder` | 空串 |
| 6 | 提交时间 | advanced | `date-range` | 闭区间，按提交时间比较 | `inventory.move.submittedRangePlaceholder` | 起止都为空表示不限 |
| 7 | 操作者 | advanced | `select` | 精确匹配操作者 | `common.selectPlaceholder` | 全部 + 当前仓已出现过的操作者；默认 `FILTER_ALL` |

**交互行为**：

| 行为 | 规则 |
| --- | --- |
| 查询 | 草稿条件写入生效条件并写 URL；回到第 1 页；展开区收起后条件仍生效 |
| 重置 | 清空 7 项（含展开区），回到第 1 页；保留顶栏仓库 |
| 展开／收起 | 只切换可见性，不触发查询，不清空条件 |
| 空条件 | 返回当前仓全部移库记录，按提交时间倒序 |
| SKU 筛选 | 按明细行匹配；命中任一行即返回整张 `MV`，列表不展开成多行 |
| 源／目标库位筛选 | 按明细行的库位集合匹配；不要求同一行同时满足源和目标条件 |
| 筛选无结果 | 显示表格空态，不弹 Toast |

## 4. 状态页签

**无。** 移库作业没有待执行、执行中、已完成、已取消等状态，提交成功即形成记录并生效。因此：

- 列表不渲染 `StatusTabs`，不提供状态筛选或状态列。
- 详情标题不带状态徽标，基本信息中没有「状态」字段。

## 5. 列表表格

### 5.1 视角说明

**单头视角**：每行一个移库作业号（一次 PDA 提交），明细行只在详情「移库明细」页签展开。商品、源库位、目标库位筛选均按明细集合匹配，但列表始终一行一个 `MV` 号。

### 5.3 本页列表约定

| 项目 | 规则 |
| --- | --- |
| 默认排序 | 提交时间降序；同一时间按移库作业号降序 |

## 7. 详情页

### 7.1 页头与概览

| 区域 | 规格 |
| --- | --- |
| 标题 | `DetailTitle`「移库作业 · {MV号}」，不带状态徽标 |
| 页头操作 | 仅「返回列表」 |
| 基本信息 | `Section` + `Descriptions columns={3}`：所属仓库、货主、操作者、提交时间、操作终端 |
| 汇总卡 | 右侧 320px `SummaryCard`「移库汇总」：明细行数、移库总数；底部说明「移库总数是各行数量合计，不代表单一 SKU 数量」 |

### 7.5 异常与边界

| 场景 | 展示 |
| --- | --- |
| `MV` 号不存在 | 整页「未找到移库作业」+「返回列表」 |

## 10. 派生与计算

| 项 | 公式／口径 | 说明 |
| --- | --- | --- |
| 明细行数 | `lines.length` | 本次提交的明细行数 |
| 移库总数 | `Σ line.qty` | 各行数量直接相加；不同 SKU 相加只表示件数 |
| 源库位摘要 | 对 `lines.sourceLocation` 去重 | 1 个显示编码；多个显示「首个 等 n 个」，悬浮给完整列表 |
| 目标库位摘要 | 对 `lines.targetLocation` 去重 | 规则同源库位 |
| 库存流水条数 | 明细行数 ×2 | 每行一减一加；页面按实际流水展示，不补造 |
| 稀疏流水号显示 | 流水号找不到时 `-` | 不生成临时编号 |

不派生：移库作业没有状态、进度、差异、库存余额；这些不在本页计算。

| 单行普通 SKU | 1 | 1 行，源、目标各 1 个库位；移库总数 = 行数量 |
| 不良品移库 | 1 | 品质为不良品，目标为不良隔离库位 |
| 多行移库 | 1 | 至少 2 行，含批次商品与 SN 商品；明细行数 ≥2，移库总数为各行合计 |
| 批次商品行 | 1 | 批次号有值，SN 清单为空 |
| SN 商品行 | 1 | SN 清单有值，条数等于本行数量 |
| 多源库位摘要 | 1 | 一个 `MV` 内明细行源库位 ≥2，列表显示「首个 等 n 个」 |
| 多目标库位摘要 | 1 | 一个 `MV` 内明细行目标库位 ≥2；**现有种子只有多源，需补一条多目标** |
| 两组流水 | 每行 2 条 | 源减、目标增各 1 条；同一业务动作标识 |
| 操作日志 | 每 `MV` 1 条 | 操作「提交移库」，操作者与单头一致 |
| 跨仓记录 | 1 | 任一其他仓记录，用于验证详情未找到 |

**边界**：

- 每仓 3 个 `MV` 号足够覆盖单行、多行、不良品；若增加分页演示，可扩到每仓 12 条（不足两页时至少补到 21 条单仓）。
- 明细行数和移库总数必须与明细行一致，不允许列表汇总与详情各行相加不一致。
- SN 清单必须是本行实际采集的 SN，不得用数量补造。
- 所有库位必须属于当前仓库，且不为暂存位。
