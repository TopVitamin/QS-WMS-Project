## 一、系统分工

强盛 WMS 是仓内执行系统：维护仓内位置与存放资格，承接上游推送的基础资料和入库、出库业务指令，用管理端和 PDA 记录现场作业，形成可回传、可追溯的库存与执行结果。业务决策在 OMS 与 ERP、仓外运输在物流系统、核算在财务 ERP，都不在这套系统内。一期为可演示、可操作的课程沙盘，上游与承运商由 Mock 模拟；形态与演示边界见本目录《系统边界与上下游链路总览》。

```mermaid

    M[OMS Mock：资料、指令与结果]

    subgraph WMS[强盛 WMS]

        P[PDA 作业端：收货 · 退货收货 · 上架 · 拣货 · 复核 · 返库上架 · 移库 · 盘点]

    end
```

四仓是一期目标仓网／课程规划，不代表立项前已有自营实体仓；立项前由第三方海外仓履约，经营目标是先租仓自营、再拓展外部货主。演示按顶栏当前仓库过滤数据，同仓可见全部货主，一期不做登录与货主级账号隔离。外部系统的输入输出与阶段边界见本目录《系统边界与上下游链路总览》。

### 使用端与系统动作分工

一期就两个使用端；按「哪一步在哪个端发生」把动作收口，双端对同一业务动作共用一条记录、不重复记账，详细机制见本目录《全局机制与操作留痕》：

| 类别 | 覆盖动作 | 说明 |
| --- | --- | --- |
| PDA 作业端（现场） | 收货（到货识别并入收货，不设独立到货登记；含拒收与实收内良品/不良）、退货收货（含派送失败扫原运单建单）、上架、拣货、复核（随分拣或打包装箱）、大货核对、退拣返库上架、移库、发起盘点与实盘录入 | 现场作业默认在 PDA；与下行「双端共用」不重复计账 |
| 管理端（后台） | 基础资料维护（仓库、库区库位、承运商与渠道、商品作业属性）、无主货登记、手工其他出库创建与确认、盘点创建、差异确认与取消、波次创建、查询与追溯 | 组织、配置与确认端 |
| 系统自动（不依赖端） | 指令接收校验与建档、出库预占与释放、库位分配推荐、库存三量与流水、盘点快照生成、结果回传、送达状态 | 由合法指令或满足业务状态的操作触发；补货后缺货单须人工重新分配，不随库存增加自动恢复 |
| 双端共用（同一动作同一记录） | 入库收货、上架落位录入与提交、新品维护、无主货登记、收货完结确认、确认出库、盘点实盘录入、在库受损品质转换 | 入库管理端收货作业台、Web 端上架页与PDA按同一业务规则和数量规则执行；同一动作只生成一份记录与库存结果；在库受损品质转换一期 Demo 只放管理端入口 |

入库和出库各自把作业事实交给库存，不另设中间汇总层；系统集成是与 OMS Mock 交换资料、指令、结果与异常的唯一通道，本身不产生业务事实。各模块功能真源见对应模块《需求分析》第二节；下文只列地图级摘要。

| 模块 | 解决什么问题 | 功能范围（摘要） | 本目录展开位置 |
| --- | --- | --- | --- |
| 基础资料 | 识别货主、商品与位置，提供作业资格 | 上游资料接收；商品作业配置；仓库、库区库位、容器档案、承运商与物流渠道；变更留痕与停用校验 | 《系统流程与单据交互》资料准备；《实体对象关系》主数据对象 |
| 入库管理 | 记录实收、品质、落位与拒收异常 | 正常／调拨入库；新品维护；容器或按件收货与上架；分批实收；收货实收内录入良品/不良（不设质检任务）；按容器×品质生成上架单；入库异常（一期仅拒收）；零实收上游取消；无主货登记（认领待 OMS 上线）；收货完结 | 《系统流程与单据交互》入库链路；《单据与状态流转》入库与任务；对象与数量摘要见[入库模块宏观系统架构](../../../01-全局背景信息/04-入库模块宏观系统架构.md) |
| 退货管理 | 退回本仓的识别、收货与上架 | 派送失败扫原运单建单；客户退货与平台仓退件退货预报；退货收货与退货异常；共用上架单对象；结案回传；FBA 移除不在一期 | 《系统流程与单据交互》三之一；[退货宏观架构](../../../01-全局背景信息/06-退货模块宏观系统架构.md) |
| 出库管理 | 组织预占、拣核、交接及剩余收口 | 六类出库；按类型准入预占；B2C 基础波次；拣货（提交后进出库暂存库位）与退拣返库上架；缺货人工重新分配；复核与容器核对；确认出库；变更与取消；为派送失败退货提供原 B2C 运单与 SN | 《系统流程与单据交互》出库链路；《单据与状态流转》出库与任务 |
| 库存与库内 | 对应库存数量、品质和现场位置 | 多维库存与流水；订单预占、已分配与可分配；移库；盘点；批次、效期与 SN 追溯；PDA 与管理端共用记录 | 《实体对象关系》数量公式；《系统流程与单据交互》库内链路 |
| 系统集成与对接 | 接收上游输入，交回结论与结果 | OMS Mock 资料与指令、退货预报、明细变更、入库/退货取消（零实收）与出库取消；拒收可查；消息去重与顺序；入出库与退货结果送达与重交；承运商 Mock | 《接口与 OMS Mock 消息设计》 |
| 公共能力 | 各模块共用机制 | 演示仓库范围与动作可见性；中英文；时间存储与展示；关键操作留痕；双端共用记录 | 《全局机制与操作留痕》 |

按模块归并的一级、二级菜单和期次见文末附录《管理端菜单基线》。功能划分与菜单导航不是同一套层级：前者划业务范围，后者是管理端展示。

## 三、模块依赖

| 模块 | 依赖谁 | 依赖什么 |
| --- | --- | --- |
| 基础资料 | 外部（OMS Mock） | 货主、商品身份及其更新 |
| 入库管理 | 基础资料、系统集成、库存与库内 | 有效的仓、货主、商品、库位资料；上游指令与结果回传；库存口径、流水与库存形成节点 |
| 退货管理 | 基础资料、出库（只读）、系统集成、库存与库内 | 退货预报或原 B2C 出库运单；上架单共用规则；结案回传 |
| 出库管理 | 基础资料、库存与库内、系统集成 | 同入库，另加物流渠道与承运商 Mock 交接信息；缺量资格按类型的出库结果 |
| 库存与库内 | 基础资料 | 商品配置（品质、效期、SN、形态）、位置资料与货主占用 |
| 系统集成 | 基础资料、入库、退货、出库、库存与库内 | 资料匹配资格、各段业务结果与操作记录 |
| 公共能力 | （被全部模块引用） | 演示仓库范围与动作可见性配置 |

表中列的是业务依赖，不是技术调用顺序。执行与库存模块不反向改写上游资料身份；库存数量口径以库存与库内需求及《实体对象关系》为准，入库、出库引用不重定义；调拨两端分别落在入库、出库模块内，互不依赖。

## 四、资料流：谁提供、谁维护、谁使用

| 资料 | 提供或维护 | 更新约束 | 使用 |
| --- | --- | --- | --- |
| 货主 | OMS Mock 推送，自营预置 | 身份标识不得静默改写；停用前校验实物与未完结业务 | 全部仓内业务与记录 |
| 商品 | OMS Mock 提供身份；WMS 补充仓内执行属性 | 关键变更留痕；业务单据引用快照；追溯开关切换与停用须校验在库与未完结作业 | 入库、出库、库存 |
| 仓库 | 系统预置四仓 | 一期不提供业务侧新增 | 全部 |
| 库区与库位 | 管理端维护，可系统预置 | 存储、拣货、不良隔离库位一库位一货主；收货与出库暂存库位允许多货主混放；有实物、入库过程量或未完结任务时不得停用 | 到货暂存、上架、拣货、移库、盘点 |
| 承运商 | 管理端维护 | 最小档案；停用前校验是否被渠道或交接引用 | 物流渠道归属、出库交接模拟 |
| 物流渠道 | 管理端维护，归属承运商 | 最小资料；一期不接真实生产服务 | 出库交接 |
| 库存与占用 | 只能由已确认业务事实和盘点调整产生 | 不提供直接改数；重复提交幂等 | 全部查询与后续作业 |
| 上游业务对象（指令） | OMS Mock 推送 | 仓库、货主、业务类型身份不得原单改，出库允许节点内取消后重下发；入库与退货仅零实收时可受理上游取消；派送失败退货单由 WMS 建单并回传 | 入库、退货、出库执行 |
| 无主货登记记录 | 仓内登记到货与暂存线索 | 一期不确认认领、不建入库单或库存；OMS 上线后推送信息供客户认领并下发指令 | 到货查询与后续 OMS 协作 |

## 五、本期范围

本期覆盖四仓同框架的收存发主链、三类退货来源（不含 FBA 移除）、六类出库、基础波次、无主货登记和库内处置；管理端与 PDA 共用记录，通过 OMS Mock 与承运商 Mock 演示协作。模块功能见第二节，菜单期次见附录。

一期不做项、后置项及跨系统约定见《项目定位与范围》（全局背景）与本目录《系统边界与上下游链路总览》。本目录范围内另约定：不设质检任务；上架单使用待上架／上架中／已完成，已收未上架数量是进度，库存记在收货暂存库位；字段清单对象名不一定对应一级菜单，部分在出库单、库存查询等下钻展示。

菜单差异说明：

- 菜单顺序跟随原型动线：业务菜单在前（入库→退货→库存→出库→集成），基础资料与系统设置在后；PDA 端导航见[《PDA作业端设计规范》](../需求文档PRD/7-PDA作业端/PDA作业端设计规范.md)第 9 节。
- 原型的「计费结算」为占位：一期不建设。退货管理一期建设「退货单」，与原型「退件单」命名对齐时以本表为准。
- 原型入库类型中的「FBA 退货」不是一期范围；入库类型收敛为正常入库、调拨入库；无主货登记不作为入库类型。
- 原型曾按 B2C 单独建「出库包裹」页；本表以「出库单」覆盖六类类型，包裹复核是 B2C 内的动作。复核记录、出库交接在出库单详情页签展示，不强制独立一级菜单；一期不设出库异常记录。
- 收货记录、上架单（上架任务）、拣货任务与 PDA 作业共用同一业务记录；管理端菜单是查询与组织入口，不形成第二套账。一期不设入库质检任务菜单。
- 菜单增删先改本表，再同步产品原型导航；模块范围变化回到正文「WMS 模块与功能清单」及对应需求分析。


## 出库页面与现场作业承接

管理端保留出库单、波次、拣货任务、返库上架单四个入口；复核和交接在原单详情查看。管理端分配或组波，PDA从任务进入拣货；原单进入PDA复核，返库单进入PDA返库上架。路由、组件与页面清单统一见[出库Demo PRD](../需求文档PRD/3-出库管理/出库单/前端Demo版PRD/出库单前端Demo版PRD_公共与技术约定.md)。
