# 容器档案与容器库存

> 本文承接[项目定位与范围](../../../01-全局背景信息/01-项目定位与范围.md)、[入库宏观架构](../../../01-全局背景信息/04-入库模块宏观系统架构.md)和[库存宏观架构](../../../01-全局背景信息/07-库存模块宏观系统架构.md)，定义容器作为基础资料和可选库存追溯引用后的对象及跨模块规则。订单按 SKU 预占；在库移库允许部分转散件；同一托盘只允许一个货主。散件移库不依赖容器档案状态，也不自动修改档案的状态、当前位置或复用资格。

## 一、定位与边界

| 项目 | 结论 |
| --- | --- |
| 容器是什么 | 箱、托、袋、笼车、包裹等装载单元的档案；有编号、类型、所属货主、容量、状态、当前库位和内容明细 |
| 与库存的关系 | 容器号是可选的批次库存追溯引用；同一 SKU、库位、批次、品质的库存可有关联容器，也可作为散件不绑定容器；容器内容由在库明细汇总，不另建一套商品库存 |
| 与 SKU 库存的关系 | SKU库存按仓库＋货主＋SKU＋品质分行汇总，良品实际＝订单预占＋可用，不良品单独记数；按容器查询是批次库存的下钻，不改变三量公式 |
| 与作业的关系 | 收货可绑定容器、上架按容器落位、出库装箱/复核关联容器、盘点可按容器发起；库存移库可部分转为散件。订单按仓库＋货主＋SKU预占，不绑定容器；分配候选可额外筛选容器 |
| 不做什么 | 容器容量自动测算、三维装载优化、容器循环调拨结算、跨仓容器调拨；一期可维护容量字段并做超容提示 |

## 二、对象

### 2.1 容器档案

| 字段 | 说明 |
| --- | --- |
| 容器号 | 同仓唯一；外部箱唛/托唛原样保存，内部容器按 `CT-{仓库}-{YYYYMMDD}-{序号}` 生成 |
| 容器类型 | 箱、托、袋、笼车、包裹；基础资料字典维护 |
| 来源 | 货主箱唛、仓库内部、出库打包生成 |
| 所属货主 | 必填；单个箱或托按单一货主管理；同一托盘禁止装载不同货主的箱 |
| 当前仓库 | 必填；跨仓移动按调拨出/入处理，不直接改仓 |
| 状态 | 空闲、收货中、上架中、在库、出库中、已出库、已释放、停用 |
| 容量 | 最大件数、最大重量、最大体积；可空，空表示不限制；超容提示或阻断按仓库配置 |
| 当前库位 | 有容器整箱落位时记录；拆散后清空或保留“最近库位” |
| 父容器 | 可选；托承载箱时指向父容器，最多一层；库存仍按最内层容器记账 |
| 内容摘要 | SKU 数、件数、批次/SN 数，由批次库存汇总，不手工改 |
| 最近扫描人/时间 | 现场最后一次绑定、落位或交接 |
| 创建人/时间、停用人/时间 | 留痕 |

### 2.2 容器内容

容器内容不是独立库存表，按以下顺序取数：

1. 在库：批次库存按 `containerId` 汇总，显示 SKU、批次、品质、数量、SN。
2. 收货中/上架中：收货记录、上架单的容器明细；未提交的 PDA/Web 草稿不进入容器档案内容。
3. 出库中/已出库：复核记录、交接记录中的容器明细。
4. 容器拆散、释放后，历史内容仍可按容器轨迹查询，但不再计入当前内容。

### 2.3 容器类型

容器类型是基础资料字典，字段为：类型编码、名称、是否可循环、默认容量、是否允许混装 SKU、备注。类型停用不影响历史容器。

## 三、状态与动作

| 状态 | 进入条件 | 可做什么 | 离开 |
| --- | --- | --- | --- |
| 空闲 | 新建容器；容器循环复用由容器管理作业另行处理，不作为库存移库条件 | 绑定收货、出库装箱 | 绑定业务 |
| 收货中 | 收货首次扫容器 | 录容器内 SKU、批次、SN；暂存 | 收货提交 |
| 上架中 | 收货确认生成上架单 | 按上架单落位 | 整箱落位或拆散 |
| 在库 | 容器关联的库存落在库位 | 查询、整容器移库、部分移库转散件、按容器盘点；分配候选可限定容器 | 出库；部分移出不要求绑定新容器 |
| 出库中 | 拣货/复核/装箱绑定容器 | 复核、交接 | 确认出库 |
| 已出库 | 确认出库 | 查询轨迹 | 本轮不自动回收或复用；后续如需容器循环管理，再定义对应作业规则 |
| 已释放 | 一次性箱完成、拆散或报废 | 查询轨迹 | 终态 |
| 停用 | 容器损坏、丢失或不再使用 | 查询轨迹 | 终态 |

关键规则：

- 容器号同仓唯一；同一容器同一时点只能绑定一个未完结业务。
- 单个箱或容器不混记不同货主；FBA 父托和其中的箱必须同仓、同货主，禁止跨货主拼托。
- 容器容量只做提示/阻断，不改变库存数量；容量为空不校验。
- 移库可以只移动容器内部分库存；移出的数量在目标库位生成不带 `containerId` 的散件明细，未移部分继续保留原容器引用。无需为散件移库指定新容器。
- 订单接单与补占只按仓库＋货主＋SKU 计算；订单不绑定指定容器。容器只用于库存追溯、容器查询和可选的分配候选筛选。
- 按容器盘点时，盘点范围是该容器内批次库存；确认差异仍按批次库存和 SKU 库存调账。

## 四、页面

| 页面 | 路由建议 | 内容 |
| --- | --- | --- |
| 容器管理列表 | `/wms/master/containers` | 容器号、类型、货主、仓库、状态、当前库位、内容摘要、最近扫描时间；筛选和导出 |
| 容器详情 | `/wms/master/containers/:containerNo` | 基本信息、容量、当前绑定、内容明细、关联单据、容器轨迹 |
| 容器类型 | 基础资料字典 | 类型编码、名称、可循环、默认容量、混装规则 |
| 收货/上架/复核/盘点 | 复用现有作业页 | 入库/退货首次绑定按现有流程建档；FBA复核只接受已建档容器，箱可关联父托，最多一层；盘点限定容器当前快照 |

容器管理放在基础资料下；对象性质是“可作业的容器档案”，不是普通商品主数据。列表默认按状态和仓库筛选，不提供物理删除。

当前原型已实现容器管理列表/详情、新增/编辑、停用/启用、容量与当前库位展示、内容与关联单据页签；收货首次扫容器自动建档，上架提交回写状态和当前库位。FBA复核关联既有箱/托档案，复核后标记出库中、确认出库后标记已出库；父托内容由箱明细汇总。

## 五、与现有模块的接口

| 模块 | 变化 |
| --- | --- |
| 入库 | 收货行增加 `containerId`；上架单按容器×品质生成；容器档案在首次绑定或预登记时建立 |
| 退货 | 退货收货同样绑定容器；容器归属退货单货主 |
| 出库 | 拣货周转箱、复核包裹/箱/托关联容器档案；确认出库更新容器状态 |
| 库存 | 批次库存和流水可含 `containerId`；按容器查询、盘点；移库可部分转散件并清除目标明细的容器引用；SKU 汇总不变。订单预占不绑定容器 |
| 基础资料 | 新增容器档案和容器类型；容器号唯一性、容量、状态 |
| 系统集成 | 回传上游仍以 SKU 汇总为主；容器明细留在仓内，是否回传按接口约定 |

## 六、当前实现与待确认

- **库存维度：**批次库存、库存余额和流水可按 `containerId` 区分；未装载在容器中的散件可不带该引用。收货、退货、上架、移库、品质转换、容器查询与按容器盘点已接通。旧数据迁移仅在业务记录能唯一确定容器时回填。
- **分配：**SKU 汇总库存口径不变；订单接收不按容器占用。分配候选可按容器筛选，但不改变订单预占来源。
- **FBA：**箱与父托使用既有容器档案；同仓同货主、最多一层父子关系，托盘不能混装货主；父托内容从箱内容汇总，复核/出库状态联动。
- **移库和生命周期：**可全量转移容器，也可只移一部分并将移出数量转为散件。库存中的容器号只作追溯引用；散件移库不依赖容器档案状态，不自动修改档案状态、当前位置或复用资格。容器循环管理仍按容器作业规则处理。
- **字段：**容器档案与库存字段清单已存在。本轮只修改派生的波次字段初稿，没有修改受保护的容器或库存详细字段清单。

静态类型、lint 和差异格式检查通过；尚未执行容器与 FBA 的浏览器作业验收。业务待决项统一见[整改进度与待确认事项](../../../参考归档/20261024-全面走查接力资料/续做结果/整改进度与待确认事项.md)。
