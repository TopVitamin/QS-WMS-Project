| 消息类别 | 方向 | 内容 | 识别键 | 结论回执 |
| --- | --- | --- | --- | --- |
| 基础资料推送 | Mock → WMS | 货主（自营预置除外）、商品及更新 | 来源＋消息标识；货主/商品业务身份＋预期版本 | 建立/更新；冲突或缺失拒收并回原因 |
| 新建业务指令 | Mock → WMS | 入库（正常/调拨）、出库（六类）、退货预报（客户退货/平台仓退件）完整表单 | 业务对象键＋新消息标识＋预期版本 0 | 准入则建档/预占；否则整单拒收、不建档、不留部分占用 |
| 仓内建单通知 | WMS → Mock | 派送失败退回：扫原 B2C 运单生成退货单及关联原出库 | 退货单号＋原出库业务对象键＋新消息标识 | Mock 回执已记录；不伪造退货预报号 |
| 明细变更 | Mock → WMS | 新明细与变更原因 | 业务对象键＋新消息标识＋预期版本 | 接受或拒绝；失败保持原需求与原占用 |
| 入库取消 | Mock → WMS | 取消原因 | 业务对象键（入库）＋新消息标识＋预期版本 | 接受/拒绝；仅当整单累计实收为 0（含全单拒收、未到货零收）；原单转已取消，不交入库完成结果 |
| 退货取消 | Mock → WMS | 取消原因 | 业务对象键（退货预报）＋新消息标识＋预期版本 | 接受/拒绝；仅当退货单累计实收为 0；原单转已取消，不交退货完成结果 |
| 出库取消 | Mock → WMS | 取消原因 | 业务对象键＋新消息标识＋预期版本 | 接受/拒绝；接受即已取消、本单占用一次释放，受理结论即最终结论；已拣实物退拣返库是仓内作业，不另交结果 |
| 重复消息 | Mock → WMS | 同标识同内容 | 相同消息标识 | 返回原结论；不重复建档、预占或扣库 |
| 同标识不同内容 | Mock → WMS | 同标识不同 payload | 相同消息标识 | 记冲突，不覆盖；上游用新可区分请求重提 |
| 结果回传（入库） | WMS → Mock | 整单执行结果与差异分项（实收内良品/不良、拒收、最终短少、落位）；不在收货或上架过程中回传进度 | 原指令＋结果序号 | 入库单已完成时形成；Mock 回执；失败待重试 |
| 结果回传（退货） | WMS → Mock | 退货来源、关联原出库或预报、实收内良品/不良、拒收（退货异常）、短少、上架落位；不在收货或上架过程中回传进度 | 退货预报或仓内建单关联键＋结果序号 | 退货单已完成时形成；派送失败建单与预报类共用结果形态 |
| 结果回传（出库） | WMS → Mock | 需求、实发、未发（缺货与短拣分项）、确认与交接；不在拣货或复核过程中回传进度 | 原指令＋结果序号 | 出库单已出库时形成；Mock回执，失败只重交原结果 |
| 请求结论回传 | WMS → Mock | 变更/取消的接受或拒绝及原因 | 关联消息标识 | 同上 |
| 拒收反馈 | WMS → Mock | 拒收原因与输入摘要 | 对应消息标识 | Mock 可查；修正后用新消息重提 |
| 交接信息 | WMS → Mock（可查询） | 承运商 Mock/司机/自提、凭证、模拟运单 | 关联出库单 | 随出库结果或查询提供 |

**一期 Mock 与消息相关边界**（系统分工与完整一期表见《系统边界与上下游链路总览》）：

- 无主货认领：Mock **不**代做认领链路。入库取消：Mock 可下发取消消息，WMS 受理后转已取消，**无**入库完成类结果回传（拒收等事实仓内可查）。
- 手工其他出库：无上游业务对象键，保留邮件依据，结果仓内可查，不伪造上游关联。
- 调拨出/入：各自指令类型交换，WMS 不衔接两端指令号。
- 退货：客户退货、平台仓退件须先有退货预报消息；派送失败可由 WMS 扫原运单建单并向 Mock 登记与回传结案，不伪造预报号。
- 库存结果：一期仅随入库、退货与出库结果交回已有的关联差异处理记录，不新增独立库存回传消息；独立盘点、品质转换等库存变化回传留待后续。
- 打印、称重：模拟或手工；PDA 扫码为 WMS 内部能力，非外部接口。

## 二、消息身份、版本与处理顺序

以下为**一期 Mock 应用约定**，不绑定未来真实接口协议。

| 标识 | 定义 | 作用 |
| --- | --- | --- |
| 业务对象键 | 来源＋业务类型＋上游指令号 | 定位一笔业务；有效新建对应一张执行单据 |
| 消息标识 | 来源内唯一；新建/变更/取消各用新标识 | 同标识同内容返回原结论；同标识不同内容记冲突 |
| 预期对象版本 | 请求基于的已接受版本；首次为 0 | 与 WMS 当前版本一致才进入节点校验 |
| 当前对象版本 | 接受合法新建后为 1；接受变更/取消后递增 | 拒绝、重发、仓内作业、结果重交不推进 |
| 结果序号 | 固定标识一份已发生结果 | 重交沿用原序号与内容，不生成新事实 |

处理顺序：先按来源＋消息标识判重；再定位业务对象、校验预期版本；最后按《单据与状态流转》当前节点与业务条件判断。记录原输入、结论、版本变化；版本匹配**不能**绕过盘点、库存、已实收或已拣等校验。

| 输入情况 | 处理结果 |
| --- | --- |
| 变更/取消先于有效新建 | 拒绝「对象尚未建立」；不缓存待受理 |
| 预期版本低于当前 | 拒绝「版本已变化」，交当前版本 |
| 预期版本高于当前 | 拒绝「前序请求尚未接受」 |
| 同旧版本并发不同请求 | 至多一条接受并推进版本 |
| 已有对象再次新建 | 内容一致返回原结论；不一致应走变更 |
| 原新建已拒收后修正 | 新消息标识、预期 0 重提；重发旧消息仍返回旧拒收 |
| 已取消/结案后再变更 | 按终态拒绝；新业务用新上游指令号 |

模拟例：新建预期 0 接受→版本 1；变更预期 1 接受→版本 2；晚到变更预期 1 被拒。业务单据状态与消息版本分开：开始拣货不增消息版本，但会阻断后续明细变更。

## 三、拒收与拒绝原因

资料/格式错误、接单失败、执行节点不允许分三类表达。下列为**原因类别**；字段级编码在字段清单命名。

| 原因类别 | 条件及结果 | 上游处置 |
| --- | --- | --- |
| 资料不存在、停用或归属不符 | 无法匹配货主/商品 | 补推资料后新消息重提 |
| 身份或编码冲突 | 不能匹配为同一对象 | 按资料规则处理，不静默改身份 |
| 仓库或数量非法 | 非四仓、数量非正等 | 修正输入 |
| 必填缺失 | 按当前表单必填项 | 补齐后重提 |
| B2C 任一 SKU 不足 | 整单拒收，不留部分占用 | 补库存或调整需求 |
| 退回来源或指定实物不合法 | 退回无合格库存来源；其他出库实物不在库或已被处置 | 按出库业务规则处理 |
| 重复冲突、版本不符、对象不存在 | 按第二节返回，不推进 | 核对版本后重提 |
| 变更/取消节点不允许 | 按状态篇操作表拒绝 | 依据当前事实处理 |

除B2C外的四类普通出库可部分预占接单；其他出库必须指定足量不良品；已接单后短拣/缺货为执行异常，不回写为新建拒收。变更重算失败保持原需求与原占用。

## 四、典型时序

节点内业务动作与状态见《系统流程与单据交互》《单据与状态流转》；下图只表达**消息层**。

**正常入库**

```mermaid
sequenceDiagram
    participant M as OMS Mock
    participant W as WMS
    M->>W: 新建入库（业务对象键，预期版本0）
    W-->>M: 已接收：入库单待收货
    W->>W: 到货、收货（拒收与实收内良品/不良）、上架单保存与提交
    Note over W: 收货与上架过程不回传进度
    alt 零实收不再执行（含全单拒收）
        W->>W: 仓库通知上游
        M->>W: 入库取消
        W-->>M: 接受/拒绝（请求结论回传）
    else 有实收且结案
        W->>M: 整单完成回传（入库单已完成时一次，含短少与拒收分项）
    end
    alt 送达失败
        W->>M: 重交同一结果序号
    end
```

已收未上架真实丢失一期不在入库回传中体现：上架数量按应上架数量提交，丢失由仓库线下告知货主，损失由库存域盘点调整。

**退货（预报类与派送失败）**

```mermaid
sequenceDiagram
    participant M as OMS Mock
    participant W as WMS
    alt 客户退货或平台仓退件
        M->>W: 新建退货预报（业务对象键，预期0）
        W-->>M: 已接收：退货单待收货
    else 派送失败退回
        W->>W: 扫原B2C运单定位出库单
        W->>M: 仓内建单通知（关联原出库）
        M-->>W: 已记录
    end
    W->>W: 退货收货、上架单提交
    Note over W: 过程不回传进度
    alt 零实收
        M->>W: 退货取消
        W-->>M: 接受/拒绝
    else 有实收且结案
        W->>M: 整单退货完成回传
    end
```

**B2C 出库：准入、变更与取消**

```mermaid
sequenceDiagram
    participant M as OMS Mock
    participant W as WMS
    M->>W: 新建 B2C（新消息标识，预期0）
    alt 资料或足量预占失败
        W-->>M: 整单拒收
    else 通过
        W-->>M: 已接收，版本1
        M->>W: 明细变更（新标识，预期1）
        W-->>M: 接受或拒绝
        W->>W: 拣货、复核
        alt 确认前有效取消
            M->>W: 取消
            W-->>M: 接受：已取消，本单占用已释放
            W->>W: 已拣实物退拣返库（仓内作业，不另交结果）
        else 先确认出库
            W->>M: 确认出库结果
            M->>W: 取消请求
            W-->>M: 拒绝：已出库
        end
    end
```

## 五、结果重交与送达状态

请求结论、执行结果、送达状态三者分开。出库取消受理即为最终结论；已拣实物的退拣返库是仓内作业，不再另交结果。

| 送达状态 | 说明 |
| --- | --- |
| 待发送 | 结果已形成，尚未首次发送 |
| 待重试 | 发送失败，保留原结果与尝试记录 |
| 已送达 | Mock 已确认；重复接收返回原回执 |

重交必须使用**原结果序号与原内容**，不重新触发收货、上架、盘亏、扣库或释放。业务状态不因送达失败回退。

## 七、一期 Mock 演示形态

采用管理端内置 **Mock 收发台**（菜单「系统集成－指令与结果」），与仓内业务共用可追溯记录，不另建独立 OMS 进程。

- 支持按完整表单推送资料、新建指令、退货预报、变更、入库/退货取消与出库取消；可注入重复、冲突、版本错序、送达失败；可查看派送失败仓内建单通知与退货结案回传。
- 不支持无主货认领链路。
- 可查看输入、结论、版本、执行结果与送达状态；支持人工重交已有结果。
- 承运商 Mock 提供模拟运单与交接，标注为演示数据。

一期不做真实协议、鉴权联调；库表与 API 由技术设计落实。演示与验收边界见《系统边界与上下游链路总览》第六节。

## 出库一期样例与前端承接

出库B2C足量、FBA缺量、上游其他出库、已拣后取消与结果样例见[OMS Mock样例目录](../字段清单合集/05-系统集成与对接/OMS-Mock/样例/)。消息信封沿用本篇约定：首次预期版本0，后续变更／取消携带当前对象版本，接受后推进，拒收不推进。同消息改内容拒收；业务键仍是来源＋业务类型＋上游指令号。
