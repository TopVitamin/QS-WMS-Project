# 文档写作与结构偏好

- 依据参考项目文档改写/迁移到当前项目时（如 ERP 结构 → WMS 内容）：保留参考文档的章节骨架，内容按当前项目上游已确认口径完全重写，同时把文内所有相对路径引用修正为当前工作区的实际文件，不留死链。Confidence: 0.85
- 覆盖式改写时选择「直接原地覆盖、不做备份留档」（在"先拷贝留档 vs 直接覆盖"的选择中明确选了直接覆盖）。Confidence: 0.7
- 应用设计类文档格式惯例：文档头部为「用途」blockquote + 版本变化表（版本/本次变化/状态）；流程、ER、状态机用 mermaid 图；正文设「权威声明」并按相对路径链到上游阶段目录；功能点与上游需求编号（如 MD/IN/OUT/INV/INT/COM 各组的 FR 编码）逐项对齐；文档间互链形成索引。Confidence: 0.75
- 上游未决事项在正文显式标注「待补/待决策」，不默认取值、不自行新增上游未确认的机制；影响数量或责任的待决策不能留给实现阶段默认处理。Confidence: 0.85
- WMS 应用设计的单据分层采用「三层概念、两层单据」：上游业务对象（指令）→ 执行单据（入库/出库/盘点/处置/待认领）→ 任务与事实记录挂靠单据、不另成单；波次是 B2C 的组织层不是单据层；不设提交-审核-驳回审批状态机，产生人工后果的动作统一以「确认」类命名（收货完结确认、差异确认、处置确认、确认出库、归属确认）。Confidence: 0.9
- 模块地图类文档末尾写「管理端菜单基线」附录：按一期范围拟定一/二级菜单，期次用「一期/后置（未排期）/不做」三档（不用原型自身里程碑号），与产品原型现有菜单对照并标注范围外占位项；菜单变更先改文档表、再同步原型。Confidence: 0.8
- 数量/公式类口径在应用设计文档群中单处收口（如《单据与状态流转》的公式表），其他文档只引用不重复定义，避免出现第二套口径。Confidence: 0.75
- PM/产品设计类工作文档默认加载 vitamin-pm-writing skill 约束文风；交付前运行其 AI 味扫描脚本，命中逐条人工判断，项目既有风格（如序数标题、「口径」术语）保留不改。Confidence: 0.7
- 评估某目录文档集是否齐全时（用户会主动问"只有这几个文件够不够、要不要再补"），以 AGENTS.md 为该目录划定的职责范围逐项对账，优先指出「上游明确交代到本目录、但尚无文档承接」的缺口，按「必补 / 可选」分类给出补充建议；属其他目录职责的内容（如模块 PRD、字段清单，以及页面级作业端交互设计——PDA 界面、操作次序、扫码交互这层内容应按端出 PRD 或留到原型阶段）不并入当前目录，另立推进计划处理。Confidence: 0.7
- 系统流程/架构类文档必须把「端」写成显式维度：PDA 与管理端并列为一期的两个使用端，PDA 是系统的一端而非周边设备；链路表的行动主体不能只按角色（收货人员、上架人员）写，需标注每一步的执行端（管理端 / PDA / 系统自动动作），并写明两端如何共用同一记录（双端一致约束）；缺少该维度会让用户觉得流程文档「跟 PDA 没关系」。Confidence: 0.75
