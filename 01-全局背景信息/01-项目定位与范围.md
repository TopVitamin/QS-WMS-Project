# 强盛WMS项目定位与范围

> 本文维护项目定位、一期范围与系统职责边界。模块规则见[需求分析总览](../03-需求调研和分析/00-项目总览/02-需求分析总览.md)，业务执行与交接见[业务蓝图](../04-业务分析和设计/00-业务蓝图.md)。

## 一、项目定位

强盛WMS是面向强盛自行运营仓网的仓内作业与实物库存管理系统。它接收上游业务指令，支持仓库完成收货、上架、库内管理、拣货、出库和退货处理，并记录实际数量、存放位置、货主归属及执行结果。

| 项目要素 | 定位 |
| --- | --- |
| 建设方式 | 从零自研，支撑强盛租仓后的仓内业务 |
| 服务对象 | 强盛自营业务，以及未来接入的外部品牌货主。自营作为一个普通货主使用共同能力 |
| 使用端 | WMS管理端和PDA仓内作业端 |
| 本次交付 | 可运行、可操作的演示系统，用课程沙盘数据展示仓内执行、库存变化和结果交接 |

系统用于强盛自己的仓储经营。外部品牌购买的是仓配服务，本项目不向其他仓储运营商销售WMS软件。

## 二、一期范围

### 2.1 仓库、货主与商品

| 对象 | 一期覆盖范围 |
| --- | --- |
| 仓库 | 香港、美西洛杉矶、美东新泽西、德国法兰克福四仓，共用同一功能框架，纳入一期演示范围 |
| 货主 | 强盛自营与外部品牌货主的资料、库存和单据。外部货主在一期是多货主能力的演示对象 |
| 商品 | 3C及类似轻小件、大件、异形货，以及需要批次、生产日期、有效期或保质期管理的商品。带电、SN、批次和效期要求按商品配置 |

仓网现状与经营顺序见[公司背景](00-公司背景与业务概况.md)，演示覆盖要求见[一期交付标准](03-阶段规划与一期交付标准.md#三一期完成的判断标准)。

### 2.2 仓内业务与上游协作

| 业务 | 一期范围 |
| --- | --- |
| 基础资料 | 接收货主、商品等上游资料；维护仓库、库区、货位和物流渠道等仓内资料；配置商品的仓内作业要求 |
| 入库 | 正常入库和调拨入库：到货识别、收货清点（实收内分良品、不良品）、上架及结果记录，含收货差异和拒收等异常。无主货只登记、暂存 |
| 库存与库内作业 | 实际、预占、可用库存查询；存放位置及正常品／不良品管理；库存占用与释放、移库、盘点、库存流水；批次、效期、SN追溯 |
| 出库 | 下表各类出库：库存占用、拣货、核对、确认出库及结果记录，含缺货、短拣和取消退拣返库上架等异常 |
| 退货 | 货从仓外退回本仓：到件识别、清点收货、良品／不良品判定、上架及结果反馈，覆盖下文三类来源；FBA退货不在一期 |
| 上游协作 | 接收上游基础资料和业务单据（含退货预报）的新建、明细变更；入库取消与退货取消（零实收）、出库取消；保留接收或拒绝结果；反馈入库、退货、出库执行及关联差异结果，独立库存回传留待后续 |

一期出库覆盖以下业务类型：

| 出库类型 | 仓库执行范围 |
| --- | --- |
| B2C包裹履约 | 按订单拣货、复核、打包，记录确认出库与交接信息 |
| 平台仓转运 | 按指令备货，记录装箱或组托及实发数量，发往电商平台仓库（如FBA） |
| 当地B2B批发 | 按批发出库指令备货、核对数量，记录承运商或自提方等交接信息 |
| 调拨出库 | 按调出指令在本仓出库；调入仓另按调拨入库指令处理 |
| 退回出库 | 已收货物按上游新指令从仓库退回仓外 |
| 不良品其他出库 | 对不良品执行出库处置并保留来源记录；来源可以是上游通知，也可以是仓库收到的线下邮件，后者在管理端手工创建 |

调拨出库、调拨入库分别作为出库、入库业务执行。WMS不建设跨仓调拨主单，不建立两仓调拨号关联、在途账或差异对账。

一期退货覆盖以下来源：

| 退货来源 | 是什么 | 怎么认出归属 |
| --- | --- | --- |
| 派送失败退回 | 本仓发出的货没有送达（地址错误、拒收、无人签收等），由承运商原路退回 | 扫原运单号找到原出库单，带出货主、商品和数量 |
| 客户退货 | 买家签收后退货，寄回本仓 | 依据货主的退货预报（退货运单号、商品和数量） |
| 平台仓退件 | FBA以外的电商平台仓（如沃尔玛WFS）把库存移除或退回本仓 | 依据货主的退货预报和平台移除单号 |

客户退货和平台仓退件到仓时没有预报的，已知货主的请其补预报，认不出货主的按无主货登记。FBA退货（亚马逊移除退仓）单独作为一类：商品贴FNSKU，常要换标后再销售或发回FBA，一期不做，见第4.1节。

货从仓外退回本仓（退货）与已收货物从本仓退回仓外（退回出库）方向相反，分属退货和出库两个模块。

箱、托等作业容器服务于清点、搬运和交接，库存按商品记录，不另建箱库存或托盘库存。

### 2.3 使用端与公共能力

管理人员通过管理端维护仓内资料、查询库存、处理业务与异常；现场人员通过PDA执行收货、上架、拣货、复核、移库、盘点和退货收货。具体动作由权限控制，不因岗位名称自动授予。

| 能力 | 一期范围 |
| --- | --- |
| 仓库授权与货主归属 | 用户只能访问已授权仓库，有某仓权限即可查看该仓全部货主数据；商品、库存和单据按货主分别记录，一期不做货主级用户授权 |
| 角色与动作权限 | 菜单、目录和业务动作通过RBAC角色授权 |
| 语言与时间 | 中文／英文界面；业务时间统一以UTC+0存储，页面展示和导出可切换时区；履约与效期判断按仓库当地时区 |
| 关键操作记录 | 影响库存、差异或责任的关键动作保留操作者、时间、原单和处理结果 |
| 两端一致 | 管理端与PDA使用同一份业务记录与库存流水 |

## 三、系统职责边界

下表说明目标系统分工；一期模拟接入方式见[能力蓝图第二节](02-能力蓝图与系统协作.md#二一期演示系统协作)。

| 系统或参与方 | 承担的工作 | 与WMS的交接 |
| --- | --- | --- |
| 强盛业务ERP | 采购、销售及供应链业务管理，全局库存协同 | 自营业务的目标上游。专用接口直连WMS或作为普通货主经OMS接入，具体路径待定 |
| 外部货主业务侧 | 提供自己的商品资料、入出库要求及处理决定 | 经OMS接入并获取执行结果 |
| OMS客户端 | 服务外部货主：接收货主业务，向WMS推送基础资料和业务单据，接收执行结果 | 二期建设真实客户端；一期由OMS Mock模拟 |
| 强盛WMS | 仓内位置、收发存、实物作业和库存记录 | 可在到货前接收指令，通过管理端和PDA记录从到仓接收到出仓交接的全过程 |
| 承运商及物流系统 | 运单服务、仓外运输与配送 | 提供出库所需的物流及交接信息；一期由承运商Mock模拟 |
| 财务ERP（金蝶云·星空） | 存货成本、总账、税务及正式财务核算，与强盛业务ERP是两套系统 | 不与WMS直接对接，不因WMS结果自动触发核算；一期不接入 |


## 四、一期不做什么

### 4.1 后续建设或评估

| 内容 | 后续安排 |
| --- | --- |
| 真实OMS客户端与货主自助端 | 二期建设，对客功能和接入深度在二期明确 |
| FBA退货与增值服务 | FBA退货（亚马逊移除退仓）的接收与处理，以及换标、换包装等，留到后续阶段 |
| 商业计费与结算 | 是否建设及系统归属后续评估 |
| 深圳宝安国内自营主仓 | 接入WMS的阶段后续确定 |

### 4.2 由其他系统承担

渠道经营、采购与销售业务管理、集团全局库存协同决策、调拨计划与在途运输、跨仓差异跟进、仓外配送和正式财务核算，不属于WMS的仓内执行职责。

### 4.3 一期暂不覆盖

- 报损／销毁，以及报损后的非库存暂存跟踪。
- 人员派工和大促产能方案。
- WMS自行导入上游业务指令。
- 打印机、电子秤的真实集成。打印和称重使用模拟或手工数据。

## 五、术语

- 货主：仓内货物的业务归属，包括强盛自营和外部品牌客户。
- OMS：订单管理系统，在本项目中是外部货主向WMS下发指令、接收结果的入口。
- PDA：仓内手持终端，现场人员用它执行收货、上架、拣货等操作。
- RBAC：基于角色的权限控制。
- 调拨对手方：调入或调出的另一方仓库，可以是自营四仓中的其他仓，也可以是第三方海外仓。
- SKU：区分商品规格的库存管理单位。
- SN：单品序列号，按商品启用，用于收发采集和单品库存追溯。
- FNSKU：亚马逊FBA用来识别卖家商品的标签条码，与卖家SKU对应。
