## 一、范围与取舍

出库模块按发给谁、怎么交付分三大类：B2C 出库、FBA 转运出库、B2B 出库。B2B 出库再按出库原因细分为批发出库、调拨出库、采购退货出库和其他出库，一期共六种业务类型。各类共用一条链路：接单预占 → 拣货 → 复核 → 确认出库 → 结果回传，区别只在接单怎么占库存、怎么拣和复核、确认时能不能缺量。完成与扣库以仓库确认出库为准，承运商是否揽收不影响；四仓共用这套规则。

| 大类 | 业务类型 | 是什么 |
| --- | --- | --- |
| B2C 出库 | B2C 出库 | 按消费者订单发包裹（一件代发），交承运商派送 |
| FBA 转运出库 | FBA 转运出库 | 从本仓库存拣货、按箱／托装货，发往亚马逊 FBA 等平台仓补货；平台仓不是强盛四仓 |
| B2B 出库 | 批发出库 | 向当地批发客户、经销商交付大货，交司机或客户自提 |
| B2B 出库 | 调拨出库 | 按调出指令发往另一仓（自营仓或第三方海外仓），不关联调入仓单据 |
| B2B 出库 | 采购退货出库 | 已收入库的正常品按上游指令退回供应商；引用原入库单，不冲销原入库 |
| B2B 出库 | 其他出库 | 以上类型之外的出库；一期只处理不良品，按上游通知或线下邮件移出指定的在库不良品 |

FBA 转运出库不并入 B2B 出库，是因为平台按箱核收：每箱装了哪些 SKU、各几件要逐箱记准，箱数和组托方式还关系到货主在平台申请的箱唛与预约，装箱变化影响这些资料时要先交货主确认。B2B 出库的四种业务类型都按单拣货、按件或箱／托核对，差别在单据来源、占用哪部分库存、确认时能不能缺量。除其他出库外的五种业务类型统称普通出库，只发正常品。

六种业务类型的差异：

| 业务类型 | 接单怎么占库存 | 怎么拣、怎么复核 | 确认出库条件 |
| --- | --- | --- | --- |
| B2C 出库 | 所有 SKU 都能足量预占才接单，否则整单拒收，不留部分占用 | 整单能分配足才生成拣货任务，按单或基础波次拣货；复核随分拣或打包，按包裹记模拟运单号与重量 | 每行足量 |
| FBA 转运出库 | 按需求与可用的较小值预占，差额记缺货 | 按单拣货；按箱／托复核，逐箱记各 SKU 件数 | 可缺量：至少一行实发大于 0，一次确认整单结案 |
| 批发出库 | 同 FBA 转运出库 | 按单拣货；按件或箱／托核对，登记司机或自提信息 | 同 FBA 转运出库 |
| 调拨出库 | 同 FBA 转运出库 | 按单拣货；按件或箱／托核对 | 每行足量 |
| 采购退货出库 | 同 FBA 转运出库 | 按单拣货；按件或箱／托核对 | 每行足量 |
| 其他出库 | 指定创建时选定的在库不良品，计入这些库存的已分配，不加订单占用；指定实物不足不建单 | 按单、按指定实物拣，不换位 | 指定数量足量 |

接单时允许部分预占，不代表确认时允许缺量：调拨出库、采购退货出库带缺货接单后，要补齐才能确认出库。

本版已确认的取舍：

| 主题 | 一期做法 |
| --- | --- |
| 出库单来源 | 普通出库全部由上游指令生成，一期由 OMS Mock 模拟，管理端不提供手工新建。其他出库可由 OMS Mock 下发，也可凭线下邮件在管理端手工创建；手工来源保留邮件依据，不伪造上游指令号 |
| 接单预占 | 按本仓本货主 SKU 的可用预占，接单时不锁库位、不跨仓借量。可用＝正常品实际－订单占用，收货暂存、出库暂存库位上的正常品也算；不良品不算 |
| 库位分配 | 生成拣货任务时才分配库位与批次，计入库存明细的已分配。只分存储、拣货库位上没被分配的正常品，货还在暂存的等上架或返库上架后再分；效期商品先到期先出，过期品不出，临期正品可出 |
| 拣货组织 | B2C 出库可按单拣，也可手工组基础波次（同仓同货主，先拣后分），整单能分配足才生成拣货任务；FBA 转运出库和 B2B 出库一律按单拣货，可以先拣分到的部分。不做自动波次和派工 |
| 拣货任务 | 每次扫描并确认数量成功，即把新增实拣数量从来源库位移到出库暂存库位；全部应拣行有结果后提交，只结束任务进度，不再移库 |
| 出库暂存库位 | 每仓配置，与收货暂存库位分开；允许多货主混放；已拣未发的库存在这里仍计实际库存和本单预占，不参与出库分配 |
| 货位缺货 | 在拣货任务上上报，系统尝试本次换位，换不到的记短拣；本次换位与本仓本货主 SKU 的「待核对」标记同时生效，随后暂停新分配，已有任务收尾或取消后盘点。盘点完成才解除，不改需求、不释放预占 |
| 复核 | 各类出库都要复核，可以和分拣放在一起，也可以和打包装箱放在一起，结果记为复核记录。容器只是记录，不形成箱库存或托盘库存 |
| 确认出库 | 实发取已复核数量，已拣的须全部复核；缺量只因库存不足（接单缺货或短拣），FBA 转运出库、批发出库可缺量一次结案，其余业务类型必须足量。交接信息可随确认登记，也可之后补登 |
| 缺货恢复 | 补货或上架后人工「重新分配」，只补预占缺口；补拣只分剩余待拣量，B2C 须把剩余量分足；已有未完成补拣任务时不重复生成。SKU 待核对或盘点中时等待 |
| 取消与变更 | 生成拣货任务前可受理明细变更与取消；之后只受理取消；确认出库后都不受理 |
| 退拣与返库上架 | 取消时已拣实物自动退拣，复核发现残损或少件时人工退拣。退拣生成返库上架单，结构与提交规则同入库上架单 |
| 已拣后残损、丢失 | 一期不在出库单上单独收口。残损件先由仓库主管在出库暂存库位转不良，再退拣回不良隔离库位；找不到的退拣后仍按应返库数量提交，再对这个 SKU 发起盘点调整库存 |
| 出库异常 | 一期不设出库异常单据。货位缺货和短拣记在拣货任务上，复核发现的残损、少件记为退拣原因，随返库上架单留痕；库位账实差异和残损品质由库存与库内通过盘点、品质转换处理 |
| 结果回传 | 出库单已出库时整单回传一次；取消受理即为已取消并回传结论；手工创建的其他出库不回传，在仓内可查 |

## 二、实体对象

### 2.1 出库模块自有对象

| 对象 | 是什么 | 关系与基数 |
| --- | --- | --- |
| 出库单 | 由一条有效上游指令生成（其他出库也可凭邮件手工创建），记录业务类型、货主、仓库、物流渠道、收货或交接信息及整单进度 | 1 个仓库、1 个货主、1 种业务类型；同一指令重发不增加单据；采购退货出库引用 1 张原入库单 |
| 出库单明细 | 每个 SKU 的需求、预占、已拣、已复核、实发 | 1 张出库单有 1～多行；同一 SKU 只占一行；其他出库在行下挂指定的库位、批次／SN |
| 波次 | 把多张 B2C 单合起来拣货的组织对象 | 只收同仓、同货主、待处理且整单能分配足的 B2C 单；1 张单至多进 1 个波次；不改需求、不加预占。一期组波即生成 1 张波次拣货任务；远期可一波多张波次拣货任务（如分区、分批释放），头状态仍按下列聚合规则推导 |
| 拣货任务 | 现场拣货工作单，分应拣明细（系统分配的库位、批次、数量）与实拣明细；货位缺货和短拣记在应拣行上 | 按单或按波次生成；1 张出库单可有多张（首次拣货＋补拣）；提交后的拣货任务就是拣货结果，不另建拣货记录 |
| 复核记录 | 一次复核提交的结果：本单核对过的 SKU、批次／SN 和数量，装进包裹或箱／托时带上容器号 | 1 张出库单有 0～多条；随分拣复核时按单一条，随打包装箱复核时一个包裹或箱／托一条；B2C 包裹另记模拟运单号与重量 |
| 出库交接记录 | 实物交给了谁：交接方式（承运商、司机、客户自提）、物流渠道、运单号、件数与凭证 | 1 张出库单有 0～多条；确认出库时登记或之后补登，补登不再扣库 |
| 返库上架单 | 把退拣实物从出库暂存库位送回存储、拣货库位或不良隔离库位的现场工作单，分应返库明细与实际返库明细；单头记退拣原因（取消、残损、少件） | 每次退拣生成 1 张，指回原出库单；结构与提交规则同入库上架单 |

以上是业务对象，不等于每种都要单独做菜单。追溯关系：出库单明细 → 应拣行 → 实拣行 → 复核记录；退拣生成的返库上架单指回原出库单。

复核记录和交接记录在出库单详情里用页签展示，一期不设独立菜单；出库单、波次、拣货任务、返库上架单可列表查询，PDA 以拣货、复核、返库上架为作业入口。作业容器不建独立对象：拣货周转箱号记在实拣明细上，包裹号、箱号、托号记在复核记录上。

#### 2.1.1 拣货任务怎么生成

出库单接单后只有 SKU 级预占。仓库组织者生成拣货任务时，系统才在预占范围内分配具体库位和批次：

| 组织方式 | 规则 |
| --- | --- |
| 按单拣货 | 一张出库单生成一张拣货任务；FBA 转运出库和 B2B 出库的四种业务类型一律按单 |
| 基础波次 | 从同仓、同货主、待处理且整单能分配足的 B2C 单中手工组波；一期组波生成一张波次拣货任务，远期可多张，各任务应拣按库位＋SKU＋批次汇总并保留各单份额。扫描确认时按波次内顺序归属未取消的原单，已确认归属不重排；提交只确定剩余短拣 |
| 补拣 | 重新分配后，只为剩余待拣量生成一张按单任务；已有未完成补拣任务时返回原任务，不重复生成 |

分配规则：

- 只在本仓本货主的存储、拣货库位上分配没被分配的正常品，合计不超过本单预占；效期商品先到期先出，过期品不分配，临期正品可出。收货暂存、出库暂存库位上的货分不到，要等上架或返库上架。
- 分配计入库存明细的已分配：其他任务不能再分配，也不能移库或做品质转换。B2C 首次须整单预占量分配足，补拣只须剩余待拣量分配足；其他普通出库可先拣分到的部分。SKU 待核对时不新增分配、组波或补拣，已有分配收尾或取消后盘点。
- 其他出库不另分配，应拣明细直接取创建时指定的库位、批次／SN，这些数量建单时已计入已分配。
- 生成拣货任务即视为出库单「开始拣货」：之后不再受理明细变更，波次成员也不能移出，只能取消。

#### 2.1.2 拣货任务里的两类明细

界面上可用「应拣」「实拣」两个页签（或上下两个子表），数据都在同一张拣货任务上。

| 明细 | 一行代表什么 | 来源与可否修改 | 行数关系 |
| --- | --- | --- | --- |
| 应拣明细 | 到哪个库位拣哪个 SKU、批次、多少 | 生成任务时系统分配；拣货人员不能改，只能上报货位缺货 | 一条出库单明细可对应多条应拣行（多库位、多批次）；波次任务一行可汇总多张单 |
| 实拣明细 | 实际从该库位拣了多少；SN 按商品配置逐件扫描 | 可分次扫描确认；每次确认立即下架，只累计新增量，已生效数量不回写 | 一条应拣行对应一条累计实拣行；波次另保留各原单的实拣归属 |

扫描确认与任务提交规则：

- **扫描确认：**核对库位、SKU、批次／SN 和数量，错扫或超出尚未拣出的应拣量即阻断。确认成功即把本次新增数量移到出库暂存库位、减少来源库位已分配并增加原单已拣，实际总量和订单占用不变；SN 同步更新位置。同一次确认重试返回原结果，不重复下架；仅扫描识别或尚未确认的输入不动库存。
- **货位缺货：**上报缺货数量和原因（无货、残损），系统释放该行缺货部分的分配，尝试在其他合法库位换位并追加应拣行。本次换位与 SKU 待核对标记同时生效；此后不新增分配或再次换位，已有任务按已分配量收尾，拣不到的记短拣。原位账实差异交盘点，残损交品质转换；其他出库不换位。
- **提交：**每条应拣行须拣足或已上报缺货。通过后任务变为「已完成」，确定短拣并释放剩余未拣分配，不再移动已扫描确认的库存。
- **短拣：**不改需求、不释放预占。补货后重新分配补拣；FBA 转运出库、批发出库也可按已复核数量缺量结案；其余业务类型等补齐或上游取消。

模拟例：L1 应拣 X 商品 5 件，现场只有 3 件。扫描确认 3 件后，这 3 件立即移到出库暂存库位；上报缺货 2 件，本次换位在 L2 分到 2 件，同时 X 标记待核对。扫描确认 L2 的 2 件后提交任务，已拣为 5，提交不再移库。若 L2 也无实物，提交时短拣 2、已拣 3、待拣 2，预占仍为 5；盘点完成解除待核对后再补拣 2 件。

#### 2.1.3 复核、确认出库与退拣

**复核**是各类出库的必经环节，但不单设一道工序：可以和分拣放在一起，也可以和打包装箱放在一起。不论哪种做法，都按原单逐件扫描核对 SKU、批次／SN 和数量，结果记为复核记录；波次汇总数量对不能代替逐单核对。

| 做法 | 常见场景 | 复核记录怎么形成 |
| --- | --- | --- |
| 和分拣一起 | B2C 波次集中拣出后按原单分拣，分的时候逐件扫描 | 每单一条；打包时补记包裹号、重量（模拟）和模拟运单号 |
| 和打包装箱一起 | 按单拣货的单；FBA 转运出库按箱／托装货 | 边扫边装，一个包裹或一个箱／托一条，记容器号和内含各 SKU 件数；B2C 另记重量与模拟运单号 |

不用容器的（如批发散件自提、其他出库）按单核对一条，容器为空。复核不动库存，确认出库前复核记录可删除重做。

**确认出库**时，实发取各行已复核数量，已拣的须全部复核，按第一节各业务类型的确认条件校验；缺量只因库存不足，装车放不下等交接安排不算缺量。普通出库只能发正常品，复核发现残损的要先退拣；已拣出的货不再做过期转换，照常发出。通过后出库单变为「已出库」，按实发扣减出库暂存库位实际库存；普通出库同时扣本单预占并释放剩余预占，其他出库不扣订单占用。确认后实物即使还在仓里等揽收，也不再计入库存。

**退拣**是把已拣实物从本单退出，生成返库上架单送回存储、拣货库位（不良品回不良隔离库位），单头记退拣原因：

| 退拣情况 | 怎么触发 | 本单预占 |
| --- | --- | --- |
| 复核时发现残损或少件 | 复核人员人工退拣；残损件先由仓库主管转不良 | 保留，可重新分配补拣 |
| 取消时已有已拣 | 受理取消时自动退拣 | 随取消释放 |

返库上架单的结构与提交规则同入库上架单：应返库明细不能改；实际返库可多次保存，不动库存；全部填完后提交，一次性把库存从出库暂存库位移到目标库位，并校验目标库位启用、品质适配与货主占用。残损件退拣前已转不良，返库到不良隔离库位，不回到存储、拣货库位；找不到的仍按应返库数量提交，再通过盘点调整。

### 2.2 引用其他模块的对象

| 对象 | 所属模块 | 出库怎么用 |
| --- | --- | --- |
| 出库指令、明细变更与取消消息、结果回传消息 | 系统集成与对接 | 去重后交出库模块判断受理；接收或拒绝结论、整单结果按原指令回传，失败只重试回传 |
| 承运商 Mock 运单与交接信息 | 系统集成与对接 | B2C 打包时取模拟运单号；交接登记引用 |
| 仓库、货主、商品、库位 | 基础资料 | 接单校验；每仓配置出库暂存库位（暂存类库区，允许多货主混放）；拣货与返库校验库位启用、品质适配与货主占用 |
| 物流渠道、物流承运商 | 基础资料 | 指令引用的渠道及其所属承运商须启用，任一停用整单拒收；交接登记引用渠道 |

### 2.3 数量骨架

| 层级 | 字段 | 含义 | 关系 |
| --- | --- | --- | --- |
| 接单 | 需求数量 | 上游要求发出的件数 | 待处理时可随明细变更调整，生成拣货任务后不变 |
| 接单 | 预占数量 | 普通出库在 SKU 库存上的订单占用 | 预占≤需求；普通出库缺货＝需求－预占。其他出库不加订单占用，以指定数量控制 |
| 拣货 | 已拣数量 | 已扫描确认下架、仍在本单名下的件数 | 扫描确认时增加，退拣时减少。普通出库已拣≤预占，待拣＝预占－已拣；其他出库已拣≤指定数量，待拣＝指定数量－已拣 |
| 复核 | 已复核数量 | 有效复核记录里的件数 | 已复核≤已拣；退拣时对应复核量同步失效，取消后有效复核量归零，原记录保留留痕 |
| 结果 | 实发数量 | 确认出库时认定的发出件数 | 实发＝确认时的已复核数量；确认时已拣须全部复核，已拣等于实发 |
| 结果 | 未发数量 | 最终没发出的件数 | 未发＝需求－实发；出库单已出库后定型 |

缺货、待拣是执行中的数量；出库单已出库后只看实发与未发，已取消后预占、已拣都归零。

接单预占看本仓本货主该 SKU 的**可用**，即正常品实际减订单占用，收货暂存、出库暂存库位上的正常品也算。分配看库存明细的**可分配**，即实际减已分配，只取存储、拣货库位上的正常品。所以货还在暂存时，单子能接、能占，但要等上架或返库上架后才能分配、拣货；B2C 要等整单都能分配到才生成拣货任务。

普通出库接单只加订单预占；其他出库只指定不良品并计入已分配。扫描确认下架把新增实拣量从来源库位移到出库暂存库位，来源的已分配同步减少，实际总量和订单占用不变；任务提交只结束进度，复核不动库存。确认出库扣减实发库存：普通出库同时清掉本单预占，其他出库不扣订单占用。取消释放预占与未拣分配，已扫描确认的实物退拣，经返库上架提交后才回到可分配库位；SKU 待核对时仍不能新分配。

模拟例：美西仓货主 A 的 X 商品在存储库位实际 8、无其他占用。FBA 转运出库单需求 10，预占 8、缺货 2。拣货扫描确认后 8 件进入出库暂存库位，实际仍为 8、预占仍为 8。复核装两箱（C1 装 5、C2 装 3）后确认出库：实发 8、未发 2，实际与预占都变为 0；回传需求 10、实发 8、未发 2。两个箱号只记在复核记录上，不形成箱库存。

取消例：X 商品在存储库位实际 10，B2C 单需求 3 并全部预占，可用剩 7。拣货扫描确认后 3 件在出库暂存库位。上游取消：出库单已取消，预占 3 释放，3 件自动退拣并生成返库上架单。返库上架单提交前，实际 10、预占 0、可用 10，新单可以占这 10 件，但存储库位上能分配的只有 7 件；提交后 3 件回到存储库位，能分配的恢复为 10。

## 三、状态与状态机

已扫描确认的实拣、已提交的返库上架单与交接记录，以及已出库单的复核记录，都是已发生事实，一期不作废、不更正；取消通过退拣承接已确认实拣，确认出库前复核记录可删除重做。出库单状态由任务和确认出库自动推导。

### 3.1 状态怎样推导

一张出库单可以拣多次（首次拣货、补拣）、复核多次（多个包裹或箱托），多人协作。缺货和短拣不单设状态：带着缺货或待拣停在待拣货，等补货后人工重新分配；已拣未复核停在待复核；满足本类型确认条件且已拣等于已复核时进入待出库。明细行不单设状态，进度看需求、预占、已拣、已复核、实发。

头状态由拣货任务、数量与本类型确认条件**自上而下**推导（先命中先返回；已出库、已取消为动作写入的终态，不再重算）：

| 顺序 | 状态 | 判断条件 |
| --- | --- | --- |
| 1 | 已取消 | 已受理取消 |
| 2 | 已出库 | 已确认出库 |
| 3 | 待处理 | 历史上尚未生成拣货任务 |
| 4 | 待拣货 | 存在未提交、未关闭的本单相关拣货任务；或任务都已结束，但本类型不能按当前已拣／已复核结案（含足量类型仍有待拣、已拣全复核但未达需求） |
| 5 | 待复核 | 本单相关任务均已提交或关闭，且存在已拣大于已复核；允许缺量结案的类型在仍有待拣时也可处于待复核 |
| 6 | 待出库 | 任务均已结束，各行已拣等于已复核，且满足本类型确认出库数量条件 |
| 7 | 待拣货 | 其余（兜底） |

待处理表示已接单、尚未生成拣货任务（尚未产生应拣明细）；库位与批次在生成任务时分配，与库存明细「已分配」口径不同。

### 3.2 出库单状态

| 状态 | 含义 | 说明 |
| --- | --- | --- |
| 待处理 | 尚未生成拣货任务 | 可受理明细变更、重新分配补占；可生成拣货任务或（B2C）组波；B2C 须整单能分配足；非 B2C 可能带缺货 |
| 待拣货 | 拣货或补拣未收尾 | 有未提交任务，或任务已结束但仍不能按类型确认（须补齐或重新分配补拣） |
| 待复核 | 已拣未全部复核 | 复核、退拣；FBA 转运出库、批发出库可在仍有待拣时先复核已拣部分 |
| 待出库 | 可确认出库 | 已拣等于已复核且满足本类型数量条件；确认出库、可同时登记交接 |
| 已出库 | 已确认出库 | 实发、未发定型并回传；可补登交接，不能取消 |
| 已取消 | 已受理取消 | 预占全部释放，已拣实物退拣返库；返库上架单另行完成；不回传出库结果 |

```mermaid
stateDiagram-v2
    [*] --> 待处理: 有效指令接单 或手工创建
    待处理 --> 待处理: 明细变更 重新分配补占
    待处理 --> 待拣货: 生成拣货任务 按单或组波
    待拣货 --> 待复核: 任务全部提交 已拣大于已复核
    待拣货 --> 待出库: 任务全部提交 已拣等于已复核 且满足确认条件
    待拣货 --> 待拣货: 任务全部提交 仍须补拣或补齐
    待复核 --> 待复核: 复核 退拣
    待复核 --> 待出库: 已拣等于已复核 且满足确认条件
    待复核 --> 待拣货: 重新分配 生成补拣任务
    待出库 --> 已出库: 确认出库
    待处理 --> 已取消: 受理取消 释放预占
    待拣货 --> 已取消: 受理取消 关闭未提交任务
    待复核 --> 已取消: 受理取消 已拣自动退拣

```

出库单头不再使用「拣货中」；拣货任务的「拣货中」仅表示该任务已有扫描确认、尚未提交。

### 3.3 变更与取消按状态受理

| 出库单状态 | 明细变更 | 取消 |
| --- | --- | --- |
| 待处理 | 受理：需求与预占一起重算，B2C 仍须足量；重算失败保留原单原预占 | 受理：释放预占，转已取消 |
| 待拣货、待复核、待出库 | 拒绝 | 受理：释放本单预占与未拣分配；关闭未完成任务（波次只处理本单份额）。拿了但未扫描确认的人工放回原位；已扫描确认的全部自动退拣，生成返库上架单；转已取消 |
| 已出库 | 拒绝 | 拒绝；后续撤销走上游其他业务，不回写已出库事实 |
| 已取消 | 拒绝 | 重复取消返回原结论 |

仓库、货主、业务类型不能在原单变更，只能在允许取消时取消原单、重新下发。手工创建的其他出库，由有权限的仓库用户在管理端按同样规则取消。

### 3.4 拣货任务、返库上架单与波次状态

| 对象 | 状态 | 说明 |
| --- | --- | --- |
| 拣货任务 | 待拣货、拣货中、已完成、已关闭 | 待拣货：已分配，尚无扫描确认。拣货中：已有确认，尚未提交。已完成：所有应拣行有结果，提交结束进度。已关闭：取消后释放未拣分配，已确认的实拣保留并退拣；波次成员全部取消才关闭任务，否则只处理该单份额 |
| 返库上架单 | 待上架、上架中、已完成 | 与入库上架单相同；已完成表示库存已从出库暂存库位移回目标库位 |
| 波次 | 已分配、已下发任务、已完成、已取消 | 描述**计划与硬分配、任务下发、拣货段结案、整波作废**；不表达工人是否扫描、任务是否拣货中（见拣货任务）。成员补拣任务不参与波次头 |

**波次拣货任务**：任务来源为波次、归属该波次号的拣货任务。一期组波即生成 1 张；远期可在**已分配**后拆成多张，再**下发任务**；扫描归属规则不变（见第 2.1.1 节）。

波次头与接单**预占**区分：预占在 SKU 订单占用；波次**已分配**表示本波次应拣已写入库存明细**已分配**（通常伴随应拣行生成）。现场拣货进度只看拣货任务，不在波次重复「拣货中」。

| 状态 | 触发时点 | 波次职责 | 一期 |
| --- | --- | --- | --- |
| 已分配 | 成波且硬分配成功，尚未对现场下发任务 | 订单批次 + 货位锁定事实 | 远期可与下发拆开；一期组波后瞬时跳过 |
| 已下发任务 | 波次拣货任务已生成并对现场可见 | 计划侧转交任务域 | 组波同一事务内进入此态 |
| 已完成 | 该波次下全部波次拣货任务均为已完成或已关闭 | 波次拣货段结案（非成员已出库） | 由任务终态推导或回写 |
| 已取消 | 整波作废或成员全部取消 | 解除波次绑定；未拣分配释放；已确认实拣按取消规则退拣 | 成员单取消只扣份额；全取消时任务关闭、波次已取消 |

成员单取消不自动把波次标为已取消；仅当波次内**全部**成员出库单已取消时，波次进入**已取消**。复核、确认出库仍在各成员出库单上推进。

结果只在出库单变为「已出库」时回传一次：需求、实发、未发分项列出，附交接信息；拣货、复核过程中不回传进度。明细变更与取消先回受理或拒绝结论，取消受理后出库单即为已取消。手工创建的其他出库不回传，结果和邮件依据在仓内可查。同一指令重发不重复建单；管理端与 PDA 共用同一份记录，重复提交不重复移库、扣库。

```mermaid
    E -.->|货位缺货| E1["自动换位 换不到记短拣"]
    E --> F["提交拣货 结束进度 不重复移库"]
    F --> G["复核 随分拣或打包装箱一起做"]
    G -.->|残损或少件| G1["退拣 生成返库上架单"]
    G --> H{"满足本类型确认条件"}
    H -->|否 有缺货或待拣| J["补货或上架后人工重新分配 差异须先盘点 只补剩余待拣量"]
    J --> E
    H -->|是| K["确认出库 按实发扣库 登记交接"]
    K --> L["出库单已出库 回传结果"]
```

上游可以在确认出库前的任何时点取消，按第 3.3 节受理。缺货、短拣的单不会自动循环：FBA 转运出库、批发出库可以按已复核数量缺量结案，其余业务类型等补货后重新分配，或由上游取消。

| 环节 | 谁做 | 交出什么 |
| --- | --- | --- |
| 接单预占 | 上游下发，系统校验；邮件来源由有权限的仓库用户手工创建 | 待处理的出库单（预占与缺货），或拒绝原因 |
| 组织拣货 | 仓库组织者 | 按单拣货任务或 B2C 基础波次，库位与批次已分配 |
| 拣货 | 拣货人员 | 每次扫描确认即下架；任务提交只结束进度；缺货上报与短拣留痕 |
| 复核 | 分拣或打包装箱的人员一并完成 | 复核记录；B2C 包裹号、重量与模拟运单号；不能发的实物退拣 |
| 确认出库与交接 | 有确认出库权限的仓库人员；邮件来源的其他出库由仓库主管确认 | 实发、未发与库存扣减；交接记录 |
| 返库上架 | 上架人员 | 退拣实物回到存储、拣货库位，不良品回不良隔离库位 |
| 缺货恢复 | 有权限的仓库人员 | 补上的预占与补拣任务；补货、上架本身不触发 |

同一辆车或同一次自提可能带走多张出库单的货，包括不同货主的货：每张单仍各自复核、确认出库和登记交接，不合并单据或库存；细节见[出库业务设计](../04-业务分析和设计/03-出库业务设计.md)第 3.2 节。

## 六、一期已知限制

- 已拣后的残损、丢失仍用退拣和库存处理，不另建损失单。丢失件按应返库数量提交后盘点调整，账面会暂时多于实物；发现差异即暂停该 SKU 新分配，盘点完成后再补拣，补不上时按类型缺量结案或等上游取消。
- 货位缺货上报触发本次换位并暂停后续新分配；已有任务收尾或取消后，由库存与库内盘点修正原位差异。
- 缺货、短拣的单补货后不自动恢复，要人工重新分配；超过 48 小时履约截止只提示，不自动取消或缺量结案。
- 接单可以占收货暂存、出库暂存库位上的货，但要等上架或返库上架后才能分配、拣货；B2C 要等整单都能分配到，非 B2C 先拣了一部分的，剩下的要人工重新分配补拣。
- 生成拣货任务后不再受理明细变更，上游只能取消后重新下发；确认出库后不能取消或撤销。
- 波次只支持同仓同货主 B2C 手工组波、先拣后分；不做自动波次、边拣边分、派工和产能调度。
- 承运商运单、打印和称重都是模拟，不跟踪揽收与运输。FBA 等平台仓的箱唛、预约、BOL／POD 在线下协作，装箱变化要线下通知货主。
- 其他出库按指定实物执行，指定实物找不到时不能换位，只能取消后重新指定。
- 容器细节仍待应用设计细化：可优先采用 B2C 一单一包、FBA 按箱计量且托号仅分组的简单方案；该建议尚未作为一期限制。
