# 04 强盛WMS阶段规划与交付边界

> 本文说明系统建设阶段、一期交付方式和完成条件，以及尚未确定的后续扩展。业务范围见[项目定位与范围](02-项目定位与范围.md)，能力与系统协作见[能力蓝图与系统架构](03-能力蓝图与系统架构.md)。

## 阶段规划

经营顺序是先租仓，再自研WMS，先服务强盛自营业务，之后拓展外部客户。对外仓配服务从开始就纳入计划，因此一期建设多货主能力，并以模拟的外部货主参与演示；这不表示立项时已经有外部客户在强盛自营海外仓经营。

已确定的系统建设阶段如下：

| 阶段 | 建设目标 | 交付边界 |
| --- | --- | --- |
| 一期：WMS仓内业务 | 交付覆盖四仓、多货主和多品类的可运行演示系统，完成入库、库存、出库及相应异常处理，并能通过管理端与PDA操作和查看结果。 | 一期范围以项目定位文稿为准。OMS和承运商通过Mock参与演示，打印与称重使用模拟或手工数据；真实OMS客户端、客户退货入库、增值服务、商业计费及深圳宝安仓接入均不计入一期。 |
| 二期：OMS客户端 | 建设面向货主的业务接入与协作能力，衔接业务资料、仓内指令和WMS执行结果。 | 已确定建设方向；具体对客功能、真实接口范围与接入深度在二期设计中明确。一期完成不以二期建设为前提。 |

客户退货与增值服务、深圳宝安仓接入和商业计费的期号与实施安排尚未确定，单独列入本文“后续待明确事项”。

系统建设阶段、经营推进和开发批次分别安排：先自用再拓客描述经营顺序，不把一期缩减为单货主；一期分批开发不改变完整一期范围；四仓共同纳入演示不规定真实租赁、开仓或上线的先后次序。

## 一期交付方式

一期交付可运行的演示系统，使用明确标注的课程沙盘数据；管理端与PDA应能操作已纳入一期的业务，并观察库存变化、异常处理和上下游交接结果。演示通过不表示真实仓库已部署上线，也不表示真实接口、设备或峰值性能已经验证（样例与验证范围见下文「演示资料与验证范围」）。

允许分批开发、交付和验证。每批可以完成部分模块或场景，但完成全部一期范围才算一期完成。当前已有页面或某一条出库样板，只能代表对应部分的实现进度。

香港、美西、美东、德国四仓使用共同功能框架。演示时应能分别进入每个仓，跑通入库、库存和出库主链。已确认的一期业务类型均需有演示路径；商品差异、特殊出库和异常案例按验收覆盖安排分配到相应仓库，不要求每个仓重复全部案例。

OMS Mock需要能推送基础资料和业务指令，并展示WMS接收或拒绝、执行和回传结果；承运商Mock需要支持相关出库协作。Mock模拟尚未接入的外部系统，WMS本身的业务仍须实际执行。PDA作业属于一期WMS功能。

人员派工、大促产能方案及WMS自行导入上游业务指令等一期排除项，继续按[项目定位与范围](02-项目定位与范围.md)执行。

## 一期完成的宏观判断

以下条件共同构成一期完成的判断标准。

| 判断维度 | 应能验证的结果 |
| --- | --- |
| 仓库与业务覆盖 | 四仓分别跑通入库、库存和出库主链；正常入库、调拨入库及一期各类出库、库内作业均有可运行路径。 |
| 多货主与商品差异 | 自营与外部货主的资料、库存和单据分别归属；轻小件、大件、异形货及按商品启用的质检、带电、批次、效期和SN要求有相应演示覆盖。 |
| 库存与异常结果 | 实际、预占、可用库存与业务记录能够对应；收货差异、质检不合格、缺货／短拣、已拣取消回库以及盘点、报损／销毁等处理结果能追溯到原业务与库存流水。 |
| 管理端与PDA一致 | 两端使用同一业务记录和库存，操作结果一致，重复提交不造成重复库存变化。 |
| 上游与物流协作 | OMS Mock下发资料及新建、变更、取消消息后，可查看接收或拒绝与执行结果；重复消息不重复建单或影响库存，回传失败后可重试已有结果。承运商模拟信息能参与相应出库流程。 |
| 公共能力 | 仓库与角色权限按规则生效，中文／英文及时间处理可验证，关键动作保留操作者、时间和结果。 |

各开发批次的结果合起来应覆盖完整一期范围。具体案例、输入数据和预期结果由需求分析与业务设计维护，覆盖安排见[关键走查场景](../04-业务分析和设计/06-海外仓典型业务场景与方案.md#84-关键走查场景)。本节只定义项目级完成条件，不替代模块验收规则。

## 演示资料与验证范围

演示需要与业务路径配套的仓库、库区、货位、货主和商品资料，以及入出库指令、异常案例和预期库存结果。样例应能体现四仓、多货主及不同商品作业要求，不能只准备一套普通商品和正常出库数据。

一期范围内的PDA、承运商模拟、作业容器、商品追溯、语言与时间处理均已纳入建设目标。具体字段、动作和规则由相应设计文稿承接；样例不足或实现尚未完成，应作为交付工作继续补齐，不再列为是否进入一期的待确认事项。

真实现场资料可以用于校验方案，但课程演示不以取得真实企业生产记录为完成前提。模拟数据和真实资料应注明性质，检查记录也应说明实际验证了哪些业务与集成范围。

## 后续待明确事项

| 后续事项 | 已知安排 | 仍需明确 |
| --- | --- | --- |
| 客户退货入库与增值服务 | 后续规划客户退货接收、质检、重新入库，以及换标、换包装等服务；不计入一期，也不影响一期退回出库。 | 归入二期还是三期，以及具体业务范围和交付条件。 |
| 深圳宝安国内自营主仓接入 | 宝安仓已服务国内业务，后续考虑接入WMS。 | 接入阶段、业务适配范围及具体实施安排。 |
| 商业计费与结算 | 后续评估，不计入一期。 | 是否建设、系统归属及与仓储业务记录的交接。 |
| 二期OMS接入深度 | 二期建设OMS客户端，承接自营和外部货主业务协作。 | 对客功能、真实ERP／货主侧接口范围、接入方式及验证要求。 |

集团全局库存协同由业务ERP承担，仓外运输与配送由物流系统承担，正式财务核算由集团财务ERP承担。这些职责不因分期调整而转入WMS；后续需要明确的是系统之间如何交换相应业务结果。
