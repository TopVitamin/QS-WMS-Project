# 02 强盛WMS项目定位与范围

> 本文说明强盛WMS的建设目标、一期范围和系统分工。公司与仓网为课程沙盘，背景见[公司背景与业务概况](01-公司背景与业务概况.md)；能力分区见[能力蓝图与系统架构](03-能力蓝图与系统架构.md)，阶段安排见[阶段规划与交付边界](04-阶段规划与交付边界.md)。

## 一、为什么建设强盛WMS

从第三方海外仓转向租仓自营后，需要自研 WMS 支撑收货、存放、拣货、出仓交接，并把上游指令与现场实物、库存执行结果对应起来。经营顺序（先自用、再拓客、一期即建多货主能力）与立项背景见[公司背景与业务概况](01-公司背景与业务概况.md)第三节。

## 二、项目定位

强盛WMS是面向强盛自行运营仓网的仓内作业与实物库存管理系统。它接收上游业务指令，支持仓库完成收货、质检、上架、库内管理、拣货和出库，并记录实际数量、存放位置、货主归属及执行结果。

| 项目要素 | 定位 |
| --- | --- |
| 项目名称 | 强盛WMS |
| 建设方式 | 从零自研，支撑强盛租仓后的仓内业务；立项时尚无自行运营的海外实体仓，也没有自研WMS。 |
| 服务对象 | 强盛自营业务及未来接入的外部品牌货主。自营作为普通货主使用共同能力。 |
| 使用端 | WMS管理端和PDA仓内作业端，共用同一份业务记录和库存。 |
| 本次交付 | 可运行、可操作、可供学习的演示系统，用课程沙盘数据展示仓内执行过程、库存变化和结果交接。 |

系统用于强盛自己的仓储经营。外部品牌购买的是仓配服务，本项目不向其他仓储运营商销售WMS软件。

## 三、一期范围

### 3.1 覆盖的仓库、货主与商品

| 对象 | 一期覆盖范围 |
| --- | --- |
| 仓库 | 香港、美西洛杉矶、美东新泽西、德国法兰克福四仓，共用同一功能框架。每个仓都要能切换进入，并运行入库、库存和出库主链。深圳宝安国内自营主仓后续接入。 |
| 货主 | 强盛自营与外部品牌货主的资料、库存和单据。外部货主在一期作为多货主能力的演示对象，经营上仍按先自用、再拓客的顺序推进。 |
| 商品 | 3C及类似轻小件、大件、异形货，以及需要批次、生产日期、有效期或保质期管理的商品。带电、SN、批次、效期和质检要求按商品配置。 |

四仓属于目标仓网，一期共同覆盖四仓的演示范围；实际租赁和开仓顺序另行安排。

### 3.2 仓内业务与上游协作

| 业务 | 一期要完成什么 |
| --- | --- |
| 基础资料 | 接收货主、商品等上游资料，维护仓库、库区、货位和物流渠道等仓内资料，配置商品的仓内作业要求。货主与商品等上游资料由OMS Mock模拟推送，WMS自有资料由管理端维护或系统预置。 |
| 入库 | 接收正常入库、调拨入库指令，完成到货识别、收货清点、按商品要求质检、上架及结果记录。收货差异和质检不合格等异常有对应处理记录。 |
| 库存与库内作业 | 查询实际、预占和可用库存，管理存放位置及正常品／不良品，支持库存占用与释放、移库、盘点、库存流水和报损／销毁处置。启用批次、效期或SN的商品保留相应追溯记录。 |
| 出库 | 按下表覆盖各类出库，完成库存占用、拣货、核对、确认出库及结果记录。B2C可选择基础波次，B2B按单摘果拣货。缺货、短拣和已拣取消回库等异常按对应业务规则处理。 |
| 上游协作 | 接收上游基础资料，以及业务单据的新建、变更、取消消息，保留接收或拒绝结果，并反馈仓内执行结果。重复消息不能重复建单或影响库存，结果回传失败后重试已有结果。 |

一期出库覆盖以下业务类型：

| 出库类型 | 仓库执行范围 |
| --- | --- |
| B2C包裹履约 | 按订单拣货、复核、打包并记录确认出库与交接信息。 |
| 平台仓转运 | 按指令备货，记录装箱或组托及实发数量，发往电商平台仓库。 |
| 当地B2B批发 | 按批发出库指令备货、核对数量并记录承运商或自提方等交接信息。 |
| 调拨出库 | 按调出指令在本仓执行出库；调入仓另按调拨入库指令处理。 |
| 退回出库（业务蓝图亦称「正常品已收退回」） | 已收货物先完成入库，再按上游另行下发的退回指令从本仓发出，保留原入库与本次出库记录。 |
| 不良品其他出库 | 根据上游通知，或仓库收到的线下邮件，在WMS执行不良品出库并保留来源和处置记录。线下邮件来源支持在管理端手工创建。 |

调拨出库、调拨入库分别作为出库、入库业务执行。WMS不建设跨仓调拨主单，也不建立两仓记录的调拨号关联、在途账或差异对账。

### 3.3 使用端与公共能力

管理人员通过管理端维护仓内资料、查询库存、处理业务与异常；现场人员通过PDA执行收货、质检、上架、拣货、复核、移库和盘点。具体动作由权限控制，不因岗位名称自动授予操作权限。

| 能力 | 一期范围 |
| --- | --- |
| 仓库权限与货主归属 | 用户只能访问已授权仓库；拥有某仓权限即可查看该仓全部货主数据。商品、库存和单据按货主分别记录，一期不做货主级用户授权。 |
| 角色与动作权限 | 菜单、目录和业务动作通过RBAC角色授权。 |
| 语言与时间 | 支持中文／英文界面，业务时间统一以UTC+0存储，页面展示和导出可切换时区。履约与效期判断按所属仓库当地时区计算。 |
| 关键操作记录 | 会影响库存、差异或责任的关键动作保留操作者、时间、原单和处理结果。 |
| 两端一致 | 管理端与PDA使用同一份业务记录与库存流水，重复提交不产生重复库存变化。 |

模块详细规则见[需求分析总览](../03-需求调研和分析/00-项目总览/02-需求分析总览.md)及其模块索引，目标业务的执行与交接见[业务蓝图](../04-业务分析和设计/00-业务蓝图.md)。本节只维护项目级范围。

## 四、系统职责边界

上游提供货物归属、收发要求、仓库和目的地等业务信息；WMS负责记录仓库实际接收、存放和发出的货物，并反馈执行结果。采购销售经营、跨仓计划、仓外运输和正式财务核算，由相应业务系统承担。

| 系统或参与方 | 承担的工作 | 与WMS的交接 |
| --- | --- | --- |
| 强盛自研ERP | 采购、销售及供应链业务管理，ERP层面的全局库存协同。 | 目标链路中，自营业务先进入OMS，再由OMS向WMS推送，执行结果经OMS返回。 |
| 外部货主业务侧 | 提供自己的商品资料、入出库要求及必要的处理决定。 | 后续通过OMS接入业务并获取执行结果；一期用模拟货主资料与指令演示。 |
| OMS客户端 | 接收ERP或货主侧资料与业务，再向WMS推送基础资料和业务单据，并接收执行结果。 | 二期建设真实客户端；一期由OMS Mock模拟其与WMS的交接。 |
| 强盛WMS | 仓内位置、收发存、实物作业和库存记录。 | 可在到货前接收指令，通过管理端和PDA记录到仓接收到出仓交接的执行过程。 |
| 承运商及物流系统 | 运单服务、仓外运输与配送。 | 提供出库所需的物流及交接信息；一期由承运商Mock参与演示。 |
| 集团财务ERP | 存货成本、总账、税务及正式财务核算，与强盛自研业务ERP是两套系统。 | 使用相关业务结果进行核算，WMS负责提供其产生的仓储业务记录。具体接入路径后续设计。 |

目标协作关系为“ERP或货主业务侧→OMS→WMS”，执行结果沿对应链路返回。一期由OMS Mock推送货主、商品等基础资料，以及入库单、出库单、变更和取消消息，并接收WMS结果；一期不依赖真实ERP或OMS接入。

不良品其他出库还支持线下邮件通知后在WMS管理端手工创建。这个入口保留邮件来源和处理依据，不扩展为WMS自行导入上游业务指令。

## 五、一期不做什么

### 5.1 后续建设或评估

| 内容 | 后续安排 |
| --- | --- |
| 真实OMS客户端与货主自助端 | OMS客户端在二期建设，具体对客功能和接入深度在二期明确。 |
| 客户退货与增值服务 | 客户退货接收、退货质检、重新入库，以及换标、换包装、FBA逆向等留到后续阶段（与蓝图排除项一致）。 |
| 商业计费与结算 | 是否建设及系统归属后续评估。 |
| 深圳宝安国内自营主仓 | 接入WMS的阶段后续确定。 |

客户把货退回仓库的入库业务，与已收货物按新指令从仓库退回仓外的出库业务方向不同。前者不在一期，后者属于一期退回出库。

### 5.2 由其他系统承担的业务

渠道经营、采购与销售业务管理、集团全局库存协同决策、调拨计划与在途运输、跨仓差异跟进、仓外配送及正式财务核算，不属于WMS的仓内执行职责。WMS分别记录本仓的调拨出入库结果，不承接跨仓调拨主链。

### 5.3 一期暂不覆盖的能力与真实集成

一期不建设人员派工和大促产能方案，不提供WMS自行导入上游业务指令的能力，也不做打印机、电子秤的真实集成。打印和称重使用模拟或手工数据，承运商使用Mock数据；PDA仓内作业属于WMS本身的一期功能。

## 六、一期交付目标

一期交付可运行的演示系统，能通过操作查看业务执行、库存变化和结果交接。交付目标与**一期完成的宏观判断**以[阶段规划与交付边界](04-阶段规划与交付边界.md#一期完成的宏观判断)为准；本节只保留项目级摘要：

- 四仓分别跑通收存发主链，一期各业务类型均有演示路径。
- 多货主归属清楚，关键异常与处置可追溯到原业务与库存流水。
- 管理端与PDA共用记录，上游 Mock 交接与重试可验证。

具体案例与预期结果由[需求分析总览](../03-需求调研和分析/00-项目总览/02-需求分析总览.md)及各模块文档维护，走查场景见[业务场景设计](../04-业务分析和设计/06-海外仓典型业务场景与方案.md#84-关键走查场景)。允许分批开发与验证，完成全部一期范围才算一期完成。演示通过不表示真实仓库已部署上线，也不表示真实接口、设备或峰值性能已经验证。

## 七、必要术语

- 货主：仓内货物的业务归属，包括强盛自营和外部品牌客户。
- 平台仓转运：从本项目仓库发往电商平台仓库（如Amazon FBA）的业务。
- 调拨出库／调拨入库：目标四仓（香港、美西、美东、德国）之间，或上游以调拨类指令下发的其他仓端出入库；WMS只在**本仓**分别执行调出、调入，不建跨仓主单、在途账或两端配对。
- 退回出库：见上表；与买家／平台退回本仓的「客户退货入库」方向相反，业务蓝图亦称[正常品已收退回](../04-业务分析和设计/00-业务蓝图.md#12-一期闭环与后续业务)。
- SKU：区分商品规格的库存管理单位。
- SN：单品序列号，按商品启用，用于收发采集和单品库存追溯。
