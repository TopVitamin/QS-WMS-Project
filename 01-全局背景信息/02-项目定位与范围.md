# 02 强盛WMS项目定位与范围

## 项目定位与交付目标

强盛WMS是本项目正式名称，旧资料中的QS-WMS为旧称。

强盛WMS服务强盛自营与第三方货主共享的仓网，负责仓内空间、实物作业和库存记录。项目交付为可运行的演示系统，使用课程沙盘数据展示业务执行与结果变化，不代表生产系统已经上线。

整个项目分阶段建设：一期完成WMS业务闭环，二期建设作为WMS客户端的OMS。退货、增值服务、深圳仓及商业计费按后续阶段评估。阶段安排统一见[05-阶段规划与交付边界](05-阶段规划与交付边界.md)。

## 一期范围

| 维度 | 已确认范围 |
| --- | --- |
| 仓网 | 香港、美西、美东、德国四仓，同时纳入一期上线范围；系统从开始建设时兼容四仓，不设先后试点。 |
| 服务对象 | 强盛自营与外部品牌货主；服务强盛自有仓网，不建设面向其他仓储运营商的软件产品。 |
| 商品 | 包括3C及类似轻小件，也包含大件、异形货。具体仓储、安全和追溯规则进入后续调研设计。 |
| 基础能力 | 支撑仓库、库区、货位、货主、商品及实物库存的基本管理。 |
| 入库 | 接收上游业务指令，完成到货、收货及入仓相关业务。 |
| 库存与仓内作业 | 支撑仓内货物管理、库存查询及作业记录；具体业务清单与规则在需求分析和业务设计中展开。 |
| 出库 | 覆盖买家包裹履约、平台仓转运和当地B2B批发。 |
| 仓间调拨 | 覆盖调拨涉及的仓库执行业务；不承担集团全局库存调度决策或仓外运输管理。 |
| 业务入口 | 由Mock模拟上游数据推送到WMS；一期暂不支持WMS自行导入上游业务指令。 |
| 使用端 | WMS管理端与仓内作业端；具体设备接入方式尚未确定。 |

一期不包含退货接收、退货质检、换标、换包装及退货重新入库，也不包含商业计费和结算引擎。这里排除的是退货业务，不排除正常入库的验收业务。

“Mock推送”限定上游业务指令的演示入口，不据此推导基础资料维护、仓内业务操作是否允许新建或导入；这些事项在对应设计中确定。

## 系统职责边界

| 系统 | 职责 | 与强盛WMS的关系 |
| --- | --- | --- |
| 强盛自研ERP | 采购、供应链计划等业务管理，以及ERP层面的全局库存协同。 | 提供自营业务背景及需求；具体接入方案后续设计，一期不依赖真实ERP接入。 |
| OMS客户端 | 面向货主的业务接入与协作，向WMS提供业务指令并查看执行结果。 | 二期建设；更细的功能范围在二期需求设计中确定，不直接照搬竞品OMS功能全集。 |
| 强盛WMS | 仓内空间、收发存及实物作业记录。 | 接收业务指令并记录仓内执行结果；实物作业覆盖到仓接收至出仓交接，系统可在到货前接收相关指令。 |
| 承运商及物流系统 | 运单服务、仓外运输与配送。 | 与仓库交接，按出库需要提供物流服务；演示接入方式待确定。 |
| 集团财务ERP | 存货成本、总账、税务及正式财务核算。 | 与自研业务ERP是两套系统；WMS提供相关业务结果，不承担财务核算。 |

渠道经营、集团全局库存协同决策、仓外运输跟踪与配送、法定财务核算均不属于WMS职责。OMS客户端属于项目后续交付，但其对客功能不因此并入WMS作业端。

## 必要术语

- 货主：仓内货物的业务归属主体，包括强盛自营和外部品牌客户。
- 平台仓转运：从本项目仓库向电商平台仓库发货的业务。
- SKU：用于区分商品规格的库存管理单位。
- SN：单品序列号，具体适用商品和追溯要求在后续调研设计中确定。
