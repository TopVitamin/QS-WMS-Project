## 一、公司概况

深圳市强盛科技有限公司（QS-Tech）2016年成立，总部位于深圳。公司以3C数码硬件和配件为主，自己做研发设计和品牌运营，生产委托代工厂，向供应商采购成品后销售。

自营商品包括快充设备、移动电源、线缆及拓展配件。公司通过Amazon欧美站、Shopify品牌独立站、天猫和京东店铺销售，也开展B2B批发。国内与海外业务采用不同的仓储履约安排。

WMS项目接着原ERP项目继续发展。ERP背景中的国内采购、渠道销售和跨境备货构成这次仓储建设的业务基础；本次重点是公司自行运营仓库后的仓内收、存、发。

## 三、为什么建设强盛WMS

使用第三方海外仓时，仓内实物与现场作业由服务商管理，强盛需要通过双方的业务交接掌握库存和履约结果。海外仓系统由服务商维护，质检、库存占用和出库规则的调整，需要依赖服务商的系统能力和改动安排。

公司决定走向自行运营仓库，先租赁仓库，再建设一套自研WMS。租仓后，收货、存放、拣货、出仓交接和库存记录都需要由强盛组织和管理，系统要支撑这些日常作业，并向业务端反馈执行结果。

对外提供仓配服务从一开始就纳入经营计划，但使用顺序是先让自营业务用起来，再拓展外部品牌客户。后续接入外部货主时，同一仓库将同时存放不同客户的商品，商品、库存和作业记录需要明确归属。WMS因此按未来多货主经营需要建设。

## 四、仓储业务的主要特点

目标仓网覆盖香港、美西、美东和德国。各仓服务地区、商品及履约安排可能不同，需要在共同业务框架下管理，同时保留各仓差异。

自营货盘以3C为主。拓展外部客户后，计划覆盖轻小件、大件、异形货，以及需要批次、生产日期、有效期或保质期管理的商品。带电属性和单品序列号（SN）也会影响部分商品的收发与追溯要求。

计划承接的履约形态包括包裹履约、发往平台仓的备货转运、当地B2B批发和仓间调拨。包裹、整箱和托盘的组织方式不同，仓库需要将实际接收、存放和发出的商品数量，与各自业务指令对应起来。

未来自营仓若只记商品总量、不记录位置和占用，可能出现账面安排发货时实物已被其他业务提走、找不到存放位置等问题；接入多货主后还需防止库存混记和错发。这些是设计中要防范的风险，不是强盛立项时已经发生的自营海外仓事故。

## 五、货盘与作业量级

| 维度 | 参考设定 |
| --- | --- |
| 自营商品 | 原ERP背景中的活跃SKU约3500个；现有WMS沙盘以常年动销核心约300—500个作为商品量级参考。 |
| 货主 | 初始服务强盛自营，后续拓展外部品牌。原沙盘按100家货主作规划参考，具体接入数量与节奏尚未确定。 |
| 大促出库 | 原沙盘以单日破万包裹作为峰值讨论场景，仓库范围、持续时间和准确峰值尚未核定。 |
| 履约时效 | 不同业务需按渠道要求完成仓内履约；原ERP资料中的约48小时指国内电商，不能直接作为海外四仓的服务承诺。WMS演示采用的时长及起算规则由业务设计维护。 |
| 流转单位 | 单件、包裹、箱和托盘，用于理解不同收发作业形态。 |

跨境补货经历国内采购、集货和仓外运输，周期较长；海外仓收到货后的仓储与履约，是本次WMS要支撑的业务环节。

## 六、主要干系人

| 群体 | 关注的问题 |
| --- | --- |
| 仓储物流团队及未来各仓作业人员 | 收发存如何组织，货物与记录能否对应，库存数量和位置是否清楚。 |
| 强盛自营业务团队 | 自营货物的仓储与履约能否用起来，库存和执行结果是否可靠。 |
| 未来外部品牌货主 | 自己的商品与库存能否按归属管理，收发结果能否查询和核对。 |
| 数字化团队 | WMS如何支撑现场作业，并与业务系统交接指令及执行结果。 |
| 集团管理与财务人员 | 仓储经营与业务记录是否可信，能否为后续经营分析和财务核算提供依据。 |
