## PDA 库存查询、移库、盘点（2026-10-21 第二轮）

**起因**：第一轮管理端完成后，PDA 首页「库内」三个宫格仍是「即将上线」，移库只能看种子记录，实盘只能在管理端录。

**文档**：[PDA库存查询](../../../05-应用设计方案/20261002-MVP版本/需求文档PRD/7-PDA作业端/库存查询/PDA库存查询前端Demo版PRD.md)、[PDA移库](../../../05-应用设计方案/20261002-MVP版本/需求文档PRD/7-PDA作业端/移库作业/PDA移库前端Demo版PRD.md)、[PDA盘点](../../../05-应用设计方案/20261002-MVP版本/需求文档PRD/7-PDA作业端/盘点作业/PDA盘点前端Demo版PRD.md) Demo PRD 按实现回写：实际步骤与入口，文案键改为 `pdaQuery`／`pdaMove`／`pdaStocktake` 分组（`pda.move`、`pda.count` 已是首页宫格名，再作分组会互相覆盖）。《PDA作业端设计规范》§9 三行改为已实现，§10 补库内商品块组件。

**代码**：

- **共用**：`lib/pda-inventory-scan.ts` 扫码识别（库位 → SKU 编码／货主条码／主条码 → SN，编码不区分大小写，同一编码几个货主时全部返回由页面让人选）；`lib/pda-stocktake.ts` 把待核对来源换成发现环节；`hooks/use-inventory-state.ts`；`components/pda/pda-stock.tsx`（商品块、关键数量、库位）。
- **动作补缺**：库位校验、一库位一货主、移库目标位校验抽成 `locationInfo`／`occupiedByOtherOwner`／`moveTargetIssue`，PDA 扫目标位和提交时用同一套；移库提交遇到盘点中、SN 不符时错误带行号，PDA 据此标出失败行；新增实盘行查重 SN（同一 SN 只能盘在一行），库位有他货主库存时给专门提示。
- **库存查询** `/pda/inventory`：扫描 → 整屏选择 → 结果（库位明细、SKU 三量与库位分布、SN 状态与最近轨迹）；结果屏直接扫下一个码即换结果。
- **移库** `/pda/move`：扫源位 → 扫商品／SN → 数量与目标位 → 待提交清单 → 确认 → 结果；整次提交走 `SUBMIT_MOVE`，同一请求号重复提交返回原 MV 号；「账实不符」标记待核对后转发起盘点，清单有其他行时先提交或放弃。
- **盘点** `/pda/stocktake`：选盘点单 → 扫库位 → 扫商品／SN → 录入（盲盘，只显示已数）→ 核对差异保存（`SAVE_COUNTS`／`ADD_COUNT_LINE`，只记实盘）；快照外实物按账面 0 新增。首页另列本仓待核对、未在盘点中的商品，点开进 `/pda/stocktake/start` 发起盘点，有进行中任务时列出原因不建单，已在盘点中则追加发现依据。
- **草稿**：`stores/pda-move-session.ts`（当前行与清单）、`stores/pda-stocktake-session.ts`（未保存的一行），刷新可续，重置演示数据时清空。文案在 `i18n/locales/pda-inventory.ts`。

## 管理端库存页面（2026-10-21 第一轮）

**起因**：库存管理菜单原来只有库存查询、库存流水两个简版页和一个只支撑出库待核对解除的简版盘点页，没有移库作业和品质转换；流水类型、数量口径与库存 PRD 不一致（分配写了流水，转移没有成对流水）。

**文档**：库存查询、库存流水、移库作业、盘点单、品质转换各自的主PRD、页面骨架、前端Demo版PRD补齐；[字段清单合集／库存与库内](../../../05-应用设计方案/20261002-MVP版本/字段清单合集/04-库存与库内/README.md)各对象初稿、详细稿补齐；系统架构设计、PDA盘点 Demo PRD、项目文档走查记录同步。实现后回写：库存查询抽屉参数改为 `skuId`／`inventoryId`／`serialId`，抽屉宽度统一 880px，库位显示为「编码＋用途」；库存查询、库存流水只把筛选写入 URL（分页、排序不写，与其他模块一致）；盘点单「发现环节」补「移库时账实不符」（移库主PRD 已要求现场发现差异就停下发起盘点）；《PDA作业端设计规范》§9 移库、盘点、库存查询三行写明管理端现状；本目录《01-项目规划》菜单名改为「移库作业」。

**代码**：

- **库内动作**：`mock/inventory-actions.ts` 的 `applyInventoryAction` 一处实现品质转换、移库提交、差异上报、盘点建单／实盘／新增实盘行／确认差异／取消，管理端经 `db.inventoryAction` 调用并写操作日志，PDA 下一轮接同一入口。任一校验不过整次不生效并返回原因；品质转换、移库按请求号、盘点确认按单号，重复提交只返回原结果。
- **库存流水**：类型收为收货、上架、拣货、返库上架、品质转换、移库、盘点调整、出库、预占、释放十类。上架、拣货、返库上架、品质转换、移库都记一减一加两条，共用业务动作标识并互相指向；订单占用记在 SKU 层（预占、释放、出库扣减），分配和其他出库指定不再写流水。流水号按写入顺序显示 6 位数字，不带业务前缀。出库、收货、上架动作同步改写，盘点中冻结改为读盘点单。
- **库存数据**：`lib/inventory-derive.ts` 统一算 SKU 库存三量（实际、预占、可用，可用可为负）、库存明细（已分配、可分配、暂存库位正常品计入可用但不参与分配、普通出库可分配、可转换数量、效期等级按仓库当地日期）、SN 库存（在库、已盘亏、已出库及轨迹）和盘点阻断原因；页面只读这些结果，不在组件里另算。
- **页面**：
  - 库存查询：SKU库存、库存明细、SN库存三个视角，各自筛选写入 URL，切换视角保留 SKU 关键字和货主；三种详情抽屉；库存明细详情发起品质转换（SN 商品勾选 SN，提交前展示本行与 SKU 前后值，可用转负只提示不阻断），成功后在抽屉顶部列出本次两条成对流水。
  - 库存流水：列表＋详情抽屉（变动、余额维度、来源与成对流水、原因与留痕），从库存查询带条件跳入。
  - 移库作业：只读列表与详情（移库明细、库存流水、操作日志），管理端不新建，提交在 PDA。
  - 盘点单：列表、创建计划盘点（按货主、库区缩小候选，选中即列阻断原因，有阻断整次不建）、详情（盘点明细、SN、发现依据、操作日志）、Web 实盘录入（逐行录入、可分次保存、新增账面 0 的实盘行）、确认差异（汇总盘盈盘亏与正常／不良变化，提示确认后可用为负的 SKU 和将解除的待核对）、取消（必填原因，不调账）。
  - 原简版 `count-page.tsx`、`services/inventory.ts`、`hooks/use-inventory.ts` 删除；页面公共部分按出库模块的写法拆成组件（`inventory-shared.tsx`）、函数（`inventory-helpers.ts`）、列定义（`inventory-columns.tsx`）。
- **种子**：`mock/inventory-seed.ts` 先把收货记录、已完成上架单和出库种子的初始预占回放成流水，再走页面同一套动作。出库种子直接写入的演示库存算作期初，前后数量从期初接起。每仓：三条移库（单行、转不良后移入不良隔离库位、多行含批次和 SN）、一次在库受损转换、一张已完成计划盘点（盘亏使可用为负、不良品短少、盘盈临期新批次；洛杉矶以外三仓另含 SN 盘亏）、一张发现账实不符后取消的盘点和随后进行中的计划盘点；演示商品 HOMY-003 再接一张批发单，同时显示待核对、盘点中、可用 0。新泽西仓另提交一张返库上架单。持久化版本 31。

修掉的缺陷（本轮走查发现）：

- 品质转换按钮、SN 库存「在库状态」表头和筛选显示 i18n 报错：文案里 `convert`、`serialStatus`、`usage` 既是单条文案又是分组名，后者覆盖前者。改名后加了文案键覆盖测试。
- 种子流水首尾接不上：出库种子的演示库存没有流水，叠到入库库存上后前后数量差 30；非批次商品收货登记的批次被当成库存维度，暂存库位的收货与上架对不上。改为按期初回放，非批次、非效期商品不按批次分行。
- 库存明细「创建时间」显示的是沿用来源的首次入库时间；按字段清单改为首笔形成本行余额的流水时间。
- 盘点单没有原业务记录时，「关联原业务记录」显示了库位；改为「-」。
- 移库作业操作日志的说明只有行数；改为每行目标库位与数量。
- 库存明细「分配状态」显示「没有待核对」文字；改为与列表一致的「正常」标签。
