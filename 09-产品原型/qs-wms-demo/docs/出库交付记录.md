## PDA 按库位作业与 Web 端补录（2026-10-18 第四轮）

**起因**（走查意见）：① 只有 PDA 能拣货、返库，管理端缺少不用 PDA 时的入口；② PDA 拣货要先选行再逐步扫，不会自动跳到下一个库位，也看不到这个库位要拣哪些商品；③ PDA 出库页面字号、卡片、页宽和上架作业不一致：底部有内容宽度的「返回」「返回上一步」小按钮，主按钮不通栏，行卡没有商品名称，库位后面拖着空批次的「·」。

**文档**：拣货任务、返库上架单的主 PRD、页面骨架、Demo PRD 加入 Web 端录入页并改写 PDA 规则（主 PRD 各加 2026-10-18 修订说明）；PDA 拣货、返库上架、复核的 Demo PRD 与骨架重写为 V0.2；《PDA作业端设计规范》新增 §4.6 按库位作业、§4.7 处理连续扫码，§5、§9、§10 同步；出库 README 与种子表（0019、0020）更新；本目录《02-设计规范》§5.6、§8 补充约定。

**代码**：

- PDA 出库原来 1000 多行的单文件 `outbound-page.tsx` 按上架作业的写法拆成 `pick/*`、`return-putaway/*`、`verify/*`，每个作业 `xxx-page.tsx` 按 `step` 分发、`use-xxx-flow.ts` 放共用数据与动作。
- **拣货**：选任务 → 按库位逐站（`PdaStopCard` 显示前往库位与下一站，本站待拣商品带名称与大号待拣数）→ 扫库位到站 → 扫商品计数（SN 扫 SN），数满自动 `PICK` 并在本站拣完后自动跳站 → 缺货屏（已数先下架再报缺货，toast 写换位结果）→ 全部拣完屏（暂存库位 + 提交）。同库位同商品多批次才要求扫批次或点选。
- **返库上架**：同一套按库位作业；可改放到其他合法库位；数满自动 `SAVE_PUTBACK`；已保存落位可重录；全部保存后提交。`SAVE_PUTBACK` 新增可选 `serialNos`，记作业员实际扫到的 SN。
- **复核**：逐件扫描计数不用先选行，扫齐自动进入装箱屏；行、默认装箱、装箱校验抽到 `lib/outbound-verify.ts`，复核工作台改用同一份。
- **Web 端**：新增 `pick-entry-page.tsx`（拣货录入：逐行录实拣、缺货与原因、SN，保存即下架，按路径自动切下一行，录满提交）和 `putback-entry-page.tsx`（返库录入：目标库位默认建议库位、可还原，SN 默认带出，重录本行，录满提交）；拣货任务、返库上架单的列表行与详情页头、波次详情页头加「Web 端 xx」「PDA xx」两个入口。
- 组件：`ScanInput` 增加 `message`（结果写在框下一行），闪色不再重挂输入框、拉回焦点不滚动；`QtyStepper` 增加 `hideLabel`；新增 `PdaStopCard`；新增 `lib/outbound-pick-route.ts`、`stores/pda-outbound-session.ts`（重置演示数据一并清空，复核工作台草稿也一并清空）。
- 种子：洛杉矶仓新增 0019（两个库位待拣）、0020（拣后取消，两行返库）；每仓 SN 商品库存 8 件、序列号从 SN00000011 起；入库种子上架的 SN 商品库存补上序列号。持久化版本 27。

修掉的缺陷：

- 入库种子上架的 SN 商品库存没有序列号，且与出库种子的 SN00000001 重号：分配先选中这一行后 SN 商品无法拣货（0006 批发单生成任务后也会卡住）。

- `order-list-page.tsx` 数量列 id 类型漏了「缺货」「待拣」，`tsc -b` 构建失败（本轮之前已存在）。

## 运行与样例

进入原型目录执行`npm run dev`，访问终端给出的地址。管理端入口`#/wms/outbound/orders`，PDA入口`#/pda`。走查修订轮在5180端口起过本机服务做浏览器抽查，端口以`npm run dev`输出为准。

每仓预置两张B2C单、FBA缺量单、调拨单、采购退货单和SN批发单；另有不良品库存供创建其他出库。演示资料均为课程样例。原型沿用运营仓编码US-LA-01、US-NJ-01、DE-FRA-01，并补HK-WH-01；基础资料中的美西／美东／德国仓编码仍为既有US-WH-LA／US-WH-NY／DE-WH-FRA，本次未批量迁移既有入库记录和资料编码。

在出库单列表选两张同仓同货主B2C单组波，或者进入详情分配。按任务进入PDA扫码；复核后主管确认出库。已拣后取消会生成返库单，返库保存、刷新再提交可检查草稿与库存生效时点。若SKU待核对，须完成该SKU既有上架、拣货与返库，再创建盘点；主管确认后恢复分配。收件方与地址的样例本次按业务类型与仓库城市改写，数据库版本未变，浏览器里已有旧数据需点一次「重置演示数据」才能看到新样例。

## 验证边界

JSON是逻辑消息样例，当前Mock弹窗展开填写字段，不提供上传JSON或HTTP接口。运单、重量与回传均为本机模拟；一期不做登录与角色权限，服务端鉴权、真实OMS／承运商、打印称重设备、多设备并发与生产环境没有验收。库存计划盘点、批量移库与完整退货页面不在本次出库实现范围内。PDA 端不提供确认出库入口（架构允许管理端或 PDA），确认出库的「同时登记交接」只在管理端；出库单字段清单暂无「取消原因」，与入库单存在一处字段代差。
