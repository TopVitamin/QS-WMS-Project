# 业务组件与主数据页面

> 沉淀自仓库、库区、货位主数据 Demo（`warehouse-*`、`zone-*`、`location-*`）。后续货主、物流渠道等基础资料页优先复用本表组件、hooks 与路由/页签约定；全局视觉与密度仍见 [《02-设计规范》](02-设计规范.md)。写《前端 Demo 版 PRD》时的布局/占位硬规则见 [《需求文档 PRD / AGENTS.md》](../../../05-应用设计方案/20261002-MVP版本/需求文档PRD/AGENTS.md)。

## 1. 主数据页面结构

| 页面 | 路由模式 | 页签标题（i18n） | 样板 |
| --- | --- | --- | --- |
| 列表 | 菜单 path，如 `/wms/master/warehouses`、`/wms/master/locations` | 菜单 `titleKey`（`PageContainer title={t('menu.*')}`，勿另起 `listTitle`） | `warehouse-list-page.tsx`、`location-list-page.tsx` |
| 新增 | `…/new`（字面量，排在 `:id` 前） | 页签 `*.tabCreate`、页头 `createTitle`（须带对象，如「新增仓库」）；列表主按钮用 `*.create`（统一「新增」） | `warehouse-create-page.tsx` |
| 详情 | `…/:code` | 固定文案，如 `tabDetail` | `warehouse-detail-page.tsx` |
| 编辑 | `…/:code/edit` | 固定文案，如 `tabEdit` | `warehouse-edit-page.tsx` |

**页签**：在 `config/page-tabs.ts` 的 `resolvePageTab` 为子路由注册**完整 pathname**，不要复用列表 path。`WmsLayout` 仅调用 `resolvePageTab`，不用 `findMenuLeaf` 开 tab。

**列表「新增」 vs 页签文案**（三模块一致，勿混用同一 key）：

| 场景 | i18n key | 中文示例 |
| --- | --- | --- |
| 列表页头主按钮 | `masterWarehouse.create` / `masterZone.create` / `masterLocation.create` | 新增 |
| 顶栏页签 + 新增页 `PageContainer` 标题 | `*.tabCreate`、`*.createTitle` | 新增仓库 / 新增库区 / 新增货位 |

**列表页头**：主数据常见组合为 **`新增`（primary，`Plus`）在左** + `导出`（outline）在右；与入库列表「新建在左」一致。

## 2. 布局与字段展示

| 区域 | 约定 |
| --- | --- |
| 列表 | `PageContainer fill` + 筛选 `Panel` + 表格 `Panel`；**主数据列表统一** `FilterBar columns={6}`：**常显最多 5 个**筛选项 + 第 6 列查询/重置；**第 6 个及以后**才放进 `advanced` 并显示「展开」；≤5 个条件时不要写 `advanced`（参考仓库 5 项无展开） |
| 详情 | 分组 `Panel` + `Descriptions columns={4}`；长字段 `DescriptionItem` 设 `multiline` 或 `col-span-*` |
| 新增/编辑 | 共享 `warehouse-form-fields` 类拆分：`WarehouseFormFields` + `mode: 'create' \| 'edit'`；栅格 `xl:grid-cols-4` |
| 只读系统字段 | 放在详情「维护信息」；**不要**在新增/编辑表单（含承运商/渠道 Dialog）里维护使用状态；新建默认启用，启停走列表/详情操作 |
| 启用／停用 | **列表操作列**与**详情页头**（各模块薄封装 `use*MasterStatusToggle`，内核 `useMasterUsageStatusToggle`）；列表 `StatusBadge` 与筛选联动 |
| 必填 | `FormFieldLabel required` → 红色 `*`；校验错误字段下 `text-destructive` 文案 |
| 占位提示 | 可编辑 `Input`/`Textarea`：编码/名称用各模块 `*Placeholder` 或 `common.inputPlaceholder`；`Select` 的 `SelectValue` 统一 `placeholder={t('common.selectPlaceholder')}`；只读字段不设 placeholder |

## 3.1 主数据跨模块复用（hooks / lib）

| 能力 | 路径 | 用法 |
| --- | --- | --- |
| 筛选项「全部」、仓维度 `?wh=`、行 id、按修改时间排序 | `lib/master-data.ts` | `FILTER_ALL`、`parseWarehouseScopeQuery`、`masterCompositeRowId`、`sortByUpdatedAtDesc` |
| 列表 draft / filters | `hooks/use-master-list-filters.ts` | `const { filters, draft, setDraft, applySearch, reset } = useMasterListFilters(empty)` |
| 新增/编辑取消 | `hooks/use-master-discard-navigate.ts` | `useMasterDiscardNavigate('masterWarehouse')` → `leave(path, dirty)` |
| 启用/停用 | `hooks/use-master-usage-status-toggle.ts` | 模块 hook 内调用；库区停用前校验用 `beforeDisable` |
| 表单字段错误行 | `hooks/use-master-form-field-error.tsx` | `useMasterFormFieldError(scope)` + `fieldError(errors, key)` |

i18n 命名空间须为 `masterWarehouse` / `masterZone` / `masterLocation`（或扩展 `MasterDataI18nScope`），并包含 `discard*`、`statusChangeSuccess`、`error.*`、启停确认文案。

**仍按模块保留**：`*-form-fields.tsx`、`lib/*-master.ts` 校验与路径、页面内 `match*` 筛选函数（字段组合各异，暂不抽通用 FilterBar 配置）。

## 5. 写新主数据模块时的检查单

1. 在 `page-tabs.ts` 增加 `new` / `:id` / `:id/edit` 解析与页签文案 key。
2. 在 `router.tsx` 注册路由顺序：`new` → `edit` → `detail`。
3. Demo PRD 单文件写清：FilterBar **一律 6 列**、无 StatusTabs、是否支持新增、详情 4 列、状态字段展示位置。
4. 主 PRD / 字段 TSV 同步「新增页可编辑列」；避免 TSV 仍写「不提供」而 Demo 已支持新增。
5. `zh-CN.ts` / `en-US.ts` 同步 `tabDetail`、`tabEdit`、`tabCreate` 等固定页签标题。

## 6. 与单据列表的差异（避免混用）

| 项 | 入库等业务列表 | 基础资料列表 |
| --- | --- | --- |
| `StatusTabs` | 常用 | **不用** |
| 行勾选 | 常用 | 仓库 Demo **不用** |
| 详情 | 多为 `Sheet` | 主数据用**独立路由页** |
| 筛选列数 | 常 4 列 + 展开 | 仓库为 **6 列**（含按钮列） |
