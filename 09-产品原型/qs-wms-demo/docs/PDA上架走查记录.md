## 按库位逐站上架（2026-10-19）

**起因**：出库的 PDA 拣货、返库上架已按库位逐站作业（2026-10-18）；用户要求「无论是上架还是拣货，都需要自动跳转到下一个库位，并显示该库位有哪些 SKU」。入库 PDA 上架当时仍是「扫库位 → 进落位录入屏选商品填数量 → 回上架单作业」，本轮把同一套逻辑带到入库上架，版式沿用上架作业。

**文档**：[《PDA上架前端Demo版PRD》](../../../05-应用设计方案/20261002-MVP版本/需求文档PRD/7-PDA作业端/上架作业/PDA上架前端Demo版PRD.md)升到 V0.2、[《PDA上架页面骨架》](../../../05-应用设计方案/20261002-MVP版本/需求文档PRD/7-PDA作业端/上架作业/PDA上架页面骨架.md)升到 V0.3；《PDA作业端设计规范》§4.6 加入上架，§9、§10、§11 同步；《上架单主PRD》加 2026-10-19 修订说明、第四节「PDA 上架」与两条验收（保存与提交校验不变）；入库单、上架单 Demo PRD 的种子表加 0011；本目录《02-设计规范》§8 把上架列为按库位作业样板。

**代码**：

- `lib/putaway.ts` 新增 `putawayStops`：还没落满的应上架行按推荐库位分组、按库位编号自然顺序排；没有推荐库位的行归最后一站（`NO_SUGGESTED_STOP`，扫任一可用库位）。当前站与下一站复用 `lib/outbound-pick-route.ts` 的 `currentAndNextStop`。
- `pages/pda/putaway/`：步骤改为 `list` → `work` → `done`，删掉 `place-step.tsx`。`work-step.tsx` 一屏一站：`PdaStopCard`（前往库位 / 已到达库位 / 改放库位（推荐 X），右侧下一站）→ 扫码框（结果写在框下一行）→ 本库位待放行卡 → 已录落位（撤销）；底部只有通栏主按钮，计数中左侧出数量框。`done-step.tsx` 为汇总提交屏。
- 计数草稿新增 `stores/pda-putaway-session.ts`（按「仓库:上架单号」），重置演示数据时一并清空。扫码处理按 snapshot + ref 读最新数据。
- SN 行逐件扫 SN：有实收 SN 时只认来源暂存库存上的 SN；Demo 收货尚未采集 SN，按商品资料的 SN 规则认；本次已扫与本单已保存的 SN 都拦。
- 选上架单的扫码错误改为框下红字；管理端上架单列表、详情的「PDA上架」现在直接进入该单（原来带了单号但落在列表）。
- 文案：`pdaPutaway` 新增按库位作业的中英文 key，删掉只给旧落位录入屏用的 key（Web 端上架仍在用的保留）。
- 种子：洛杉矶仓新增入库单 0011 → 上架单 `PA-20261011-0001`（容器 C-M01：CABLE-01 × 2 推荐 A-01-01；ANKR-001 × 1、ANKR-002 × 6 推荐 B-01-03），持久化版本 28。出库种子结果不变（只多了暂存库存行，按序号生成的库存 ID 后移）。

- 扫完库位紧跟一枪扫商品时，「回到计数所在那一站」的纠正逻辑拿渲染时的旧 `at` 判断，把刚扫的目标库位 `to` 从路由里冲掉（计数本身正确）。改为按 ref 判断。
- 扫到本单已全部落位的商品，提示成「不是本单要上架的商品」；改为「X 已全部落位，不用再扫」。
- 剩下的商品没有推荐库位时，跳站提示写成「前往 无推荐」；改为「剩下的商品没有推荐库位」。
