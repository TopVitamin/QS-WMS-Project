# 作业台设计规范

> 管理端里给**现场作业员**用的页面：收货作业台，以及后续的打包台、复核台、称重台等。和普通后台页面（列表、详情、表单）用的是同一套颜色和组件，但**字更大、信息更少、反馈更明显**。
> 普通页面的规范见[《02-设计规范》](02-设计规范.md)；PDA 端见[《PDA作业端设计规范》](../../../05-应用设计方案/20261002-MVP版本/需求文档PRD/7-PDA作业端/PDA作业端设计规范.md)。作业台的反馈分级与 PDA 保持一致。
> 样板：`pages/wms/inbound/inbound-order-receive-page.tsx`。

## 1. 和普通后台页面有什么不同

| 维度 | 普通后台页面 | 作业台 |
| --- | --- | --- |
| 谁在用 | 坐在工位上的文员、主管 | 站在工作台前、一手拿货一手拿扫描枪的作业员，离屏幕 0.5～1 米 |
| 输入方式 | 鼠标 + 键盘 | **扫描枪优先**，键盘录数量，鼠标兜底 |
| 看什么 | 尽量多的字段，便于查询核对 | 只看「现在该做什么、当前对象是谁、还差多少」 |
| 反馈 | toast 足够 | 必须在视线里、写清原因和下一步、配声音 |
| 字号 | 12～16px，统计数字 20px | 最小 14px，正文 16px，提示 20px，当前对象 24px |
| 密度 | 控件 32px、行高 40px | 扫码框与主按钮 48～56px、行高 48px |

## 2. 五条原则

1. **一眼知道现在该做什么**：页面顶部永远有一条「步骤提示」，用一句话写下一步动作（「扫描商品条码」），不靠作业员自己判断。
2. **只放作业要用的信息**：单头只留货主和「还剩多少」；柜号、运单号、创建时间等去详情页看。说明文字不超过一行。
3. **站远了也看得清**：当前对象和关键数字放大加粗；不出现 12px 文字。
4. **反馈在视线里**：扫码结果写在扫码框上方的提示条里，扫码框同时闪色、响提示音；不用会自己消失的 toast 传达错误。
5. **扫描枪的每一枪都不能丢**：扫码框始终拿着焦点；任何操作结束、弹窗关闭后焦点回到扫码框。

## 3. 页面骨架

```text
页头：作业名 · 单号（尾号加粗）[状态]                     [返回详情] [返回列表]
┌─────────────────────────────────────────────┬────────────────────────┐
│ 上下文一行：货主 · SKU 种类 · 剩余待收（数字 20px） │ 本次作业（SummaryCard） │
│ ┌ 步骤提示条（WorkbenchPrompt，20px）─────────┐ │  对象列表（可点回修改、 │
│ │ ⓘ 扫描商品条码                              │ │  可移除）              │
│ │   每扫一件良品 +1；整批可点表格行改数量      │ │                        │
│ └─────────────────────────────────────────────┘ │  合计（size="lg"）     │
│ ┃ 当前容器  BOX-A  1 个 SKU · 12 件 [新增容器] │ │                        │
│ [扫] 扫描或输入商品编码 / 条码（h-14，18px）   │ │ [提交收货（2 个容器）] │
│ 录入表（行高 48px，录入列不横向滚动）          │ │  清空本次              │
└─────────────────────────────────────────────┴────────────────────────┘
```

- 左边是「正在做的事」，右边 320px 是「这次已经做了什么」。一次作业只涉及一个对象时可以不要右栏，主按钮放录入区底部右侧。
- **一个扫码框**：按当前步骤切换用途（没有当前容器时扫箱号，有时扫商品），不要并排放两个扫码框让作业员选。
- 主按钮写明数量和对象：「提交收货（2 个容器）」，不写「确认」「提交」。
- 1440 宽屏（侧栏展开）下，录入列（数量、原因）不横向滚动就能看到：编码、名称、条码合成一列（编码一行、名称 · 条码一行）。

## 4. 字号与视觉

作业台在 02 规范四档字号之外，额外允许 `text-lg`（18px）与 `text-2xl`（24px），只用于下表位置：

| 用途 | 字号 | 写法 |
| --- | --- | --- |
| 当前对象（容器号、库位、包裹号） | 24px 粗体 | `<WorkbenchCurrent>` 自带；编码用 `<BizCode className="text-2xl">` |
| 步骤提示 / 操作结果 | 20px 半粗 | `<WorkbenchPrompt>` 自带 |
| 关键数字（剩余待收、合计、本容器可收） | 18～20px 半粗 | `text-lg` / `text-xl font-semibold tabular-nums` |
| 扫码框输入 | 18px | `<ScanField>` 自带 |
| 正文、表格内容、按钮、说明第二句 | 16px | `text-base` |
| 标签、表头、辅助说明 | 14px | `text-sm`；**作业台不用 `text-xs`**（状态徽标、数量角标除外） |

颜色只用语义色，作业台里含义固定：

| 颜色 | 含义 | 用在 |
| --- | --- | --- |
| 蓝 `primary` | 当前步骤、当前对象 | 提示条（普通）、当前对象左色条、选中行 |
| 橙 `warning` | 等你去做 | 提示条（还没绑定容器、等下一个容器） |
| 绿 `success` | 刚刚成功 | 提示条（扫码命中、提交成功）、良品合计 |
| 红 `destructive` | 出错、被拦住 | 提示条（扫错、超量）、扫码框红闪、拒收数量 |

- 当前对象卡片：白底、左侧 4px 主色条、图标 24px，和普通文字一眼区分。
- 空态给图标 + 一句「下一步做什么」（「还没有容器，扫描箱号 / 托唛开始收货」），不写「暂无数据」。
- 不可录入的输入框显示为空，不显示 0，避免看起来像能填。

## 5. 反馈分级

与 PDA 规范 §5 同一套分级，管理端实现如下：

| 级别 | 场景举例 | 界面 | 声音 | 消失 |
| --- | --- | --- | --- | --- |
| 成功 | 扫码命中、绑定容器、提交成功 | 提示条变绿，写结果和数字；扫码框绿闪 | 短高音 | 下一次操作替换 |
| 扫码 / 录入错误 | 条码不在本单、超过可收、没选拒收原因 | 提示条变红，写原因和下一步；扫码框红闪；自动切到出问题的行 | 长低音 | 下一次操作替换 |
| 业务阻断 | 容器在本单已收过、提交被服务端拒绝 | 「知道了」弹窗，写清原因和下一步；弹窗打开时扫码框让出焦点 | 长低音 | 必须点「知道了」 |
| 需确认 | 移除有录入的容器、清空本次 | 确认弹窗，写清会丢掉什么 | 无 | 手动 |

- **toast 只在要离开作业台时用**（如整单收完自动返回列表），因为提示条跟不过去。
- 提示条没有新结果时，显示当前步骤的默认提示（橙色「扫描作业容器的箱号 / 托唛」→ 蓝色「扫描商品条码」）。

### 5.1 提示文案写法

一条提示两句话：**第一句 = 对象 + 发生了什么（带数字），第二句 = 原因或下一步**。

| 场景 | ✗ 不要这样写 | ✓ 这样写 |
| --- | --- | --- |
| 扫错条码 | 未匹配到本单待收商品 | **没找到这个商品：6901234000**／它不是本单待收的商品。请核对条码，或确认实物是否属于这张入库单 |
| 超量 | 超过本行可收数量 | **CABLE-01 超出可收数量**／本容器最多还能收 195 件（未收 395，其他容器已录 200）。数量已保留原值 |
| 扫码成功 | 已定位 CABLE-01 | **CABLE-01 良品 +1**／本容器已录 12 件，这个商品还可收 183 件 |
| 容器复用 | 容器在本单已确认收货，请更换作业容器 | **容器 BOX-A 在本单已经收过货**／同一张入库单里，一个容器只能收一次。请换一个新容器，或选择「无容器收货」 |
| 漏填 | 请填写拒收原因 | **BOX-A · CABLE-01 拒收 3 件还没选原因**／在该行「拒收原因」里选一个原因，再提交 |
| 提交成功 | 收货成功 | **已提交收货：2 个容器，共 390 件**／已生成 1 条收货记录和对应上架单；可以扫描下一个容器 |

- 用作业员的话，不出现接口字段、错误码、「非法」「异常」等词。
- 出错时保留作业员已录的内容，并在文案里说「数量已保留原值」「本次录入都还在」。

## 6. 交互约定

| 规则 | 说明 |
| --- | --- |
| 焦点 | 进入页面自动聚焦扫码框；扫码、绑定、新增对象、移除、数量框回车后都回到扫码框（`refocusScan`） |
| 焦点兜底 | 焦点不在任何输入框、也没有弹窗时，敲下的字符直接进扫码框（`<ScanField>` 内置） |
| 弹窗 | 业务阻断弹窗不抢焦点（防止扫描枪的回车误点「知道了」），同时让扫码框失焦，避免回车重复触发 |
| 数量框 | 回车确认并回到扫码框；超过上限拒绝并保留原值，不静默截断 |
| 未提交内容 | 放 zustand persist store（如 `stores/web-receive-session.ts`），切页签、刷新不丢；提交成功或「清空本次」后移除 |
| 危险动作 | 移除有录入的对象、清空本次：二次确认，写清会丢掉什么 |
| 出错定位 | 提交校验不过时，自动切到出问题的对象和行，作业员直接就能补 |
| 切换语言 | 提示条里的结果文案在发生时翻译；切换语言时清掉结果，回到按当前语言渲染的默认步骤提示 |

## 7. 组件

| 组件 | 文件 | 用途 |
| --- | --- | --- |
| `WorkbenchPrompt` | `components/biz/workbench.tsx` | 步骤提示条：info / success / warning / error 四种色调，标题 20px、说明 16px |
| `WorkbenchCurrent` | `components/biz/workbench.tsx` | 当前对象卡片：图标 + 标签 + 24px 对象号 + 右侧操作 |
| `ScanField` | `components/biz/scan-field.tsx` | 扫码框：`flash` 闪色 + 提示音、自动聚焦、`inputRef` 拉回焦点、失焦兜底 |
| `SummaryCard size="lg"` / `SummaryMetrics size="lg"` | `components/biz/summary-card.tsx` | 右侧「本次作业」卡与大号合计 |
| `beep` | `lib/scan-beep.ts` | 提示音（PDA 与管理端共用） |
| `useConfirm` | `hooks/use-confirm.tsx` | 业务阻断用 `hideCancel` + `confirmText: t('pda.gotIt')` |

## 8. 自检清单（新增或改作业台时逐条过）

- [ ] 页面顶部有步骤提示条，任何时刻都能回答「现在该做什么」
- [ ] 只有一个扫码框；进入页面、每次操作后、弹窗关闭后焦点都在扫码框
- [ ] 没有 12px 文字；当前对象 24px、提示 20px、关键数字 ≥ 18px
- [ ] 单头上下文 ≤ 3 项，说明文字不超过一行
- [ ] 每条错误都写了对象、数字和下一步；扫错有红闪和低音
- [ ] 错误不靠 toast；toast 只在离开页面时用
- [ ] 主按钮写明数量和对象；不可点时说明缺什么（提示条会写）
- [ ] 1440 宽屏下录入列不横向滚动
- [ ] 未提交内容刷新不丢；危险动作二次确认
- [ ] 中英文各看一遍，英文长文案不撑破提示条和按钮
