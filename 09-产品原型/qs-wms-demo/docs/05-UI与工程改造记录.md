## 2. 这轮定下来的取舍

### 2.1 没有拆 `outbound-actions.ts`

它仍是 1,295 行的出库领域 reducer，25 项测试压在这条链路上。按对象拆会增加跨 case 的参数传递和回归面，当前收益主要是文件长度，不是行为清晰度。本轮只删掉 `supervisor()`、`role()` 两个空实现。等下一个出库对象或命令进来时再拆，拆之前先补该链路的验收场景。

### 2.2 主数据筛选仍然只存在页面内

统一 hook 已支持 `syncUrl`，业务单据（入库单、上架单、出库单）继续写 URL；主数据列表保持本地状态。原因是主数据筛选字段本身有 `status`，和页签参数冲突；另外主数据详情的“返回列表”是固定路径，单独开 URL 会出现“刷新保留、返回丢失”的半套体验。要做的话，需要同时改 7 个列表的跳转 state 和 7 个详情的返回链接，单独排一轮。

### 2.3 `FilterBar columns={6}` 保留

PRD 里大量用 `FilterBar columns={6}` 描述 6 列栅格。代码保留这个参数，只接受 6，布局固定 6 列；它不再被当成可配置项，也不再是“看起来能配、实际不生效”的未知行为。

### 2.4 `components/ui` 是上游生成源码，不追着格式化

这层保持 shadcn 的写法和导入方式，整体不参与设计检查。页面优先用 `components/biz`；必须改上游默认值（字号、日历语言、焦点样式）时只做小改，原因写在 `src/components/ui/README.md`。本轮改了 `Button size="sm"` 的 12.8px 和 `Calendar` 的星期字号。

### 2.5 Prettier 没有全仓重排

配置和脚本已加，但 160 个存量文件没有一次性重排，避免机械 diff 和工作区里未提交的 PDA 上架改动混在一起。后续单独做一次 `npm run format` 提交。

## 5. 遗留

1. 17 条 lint warning 还在，主要是弹窗打开时同步表单的 `set-state-in-effect`，以及 Fast Refresh/Compiler 提示。不影响运行，改动弹窗时顺手收敛。
2. 全仓 Prettier 基线未执行，见 2.5。
3. 主数据筛选 URL、`outbound-actions` 拆分、`verify-station` 进一步拆 hook，见 2.1、2.2。
4. `services` 层与页面直接 `useDb` 仍并存（61 个页面文件、223 处直接 `useDb`，4 个文件走 `services`）。接真实后端前要定一条边界：保留 `services` 作为唯一读接口，或承认这是纯前端 Demo 并删掉薄包装。
5. 基础资料的库区、货位仍是独立演示数据，不驱动作业端库位；仓库编码已经对齐，边界写在[《01-项目规划》](01-项目规划.md)第 3 节。
6. oxlint 的 `jsx_a11y` 规则还没有启用。目前靠 `FormField`、`StatusTabs`、`DataTable` 的组件契约和 7 项组件测试兜底；启用前先跑一遍基线，避免一次冒出大量 warning。
