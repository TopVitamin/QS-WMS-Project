# QS-WMS 前端设计与开发规范

写给后续生成页面的 AI 和开发者。新增页面前先读完这份文档，再打开对应的样板页照着写。组件、hooks 的完整清单和主数据页面检查单见[《03-业务组件与主数据页面》](03-业务组件与主数据页面.md)；页面布局的产品约定见[《需求文档 PRD / AGENTS.md》](../../../05-应用设计方案/20261002-MVP版本/需求文档PRD/AGENTS.md)。

本规范里能机器检查的部分已写进 `npm run lint:design`（第 9 节），提交前必须通过。

## 1. 设计基调

中国 SaaS 后台风格：信息密度中等，白底卡片放在浅灰画布上，蓝色主色，少装饰。

| 项 | 规定 |
|---|---|
| 主色 | `primary`（蓝），只用于主按钮、选中态、链接 |
| 画布 | 页面背景 `bg-canvas`；内容块用 `<Panel>` / `<Section>`（白底、1px 边框、8px 圆角） |
| 遮罩 | 弹窗/抽屉遮罩统一 `bg-black/35`（组件自带），不用毛玻璃 |
| 图标 | 只用 `lucide-react`；按钮内图标加 `data-icon="inline-start"` |
| 暗色 | 不做暗色主题；`index.css` 里不维护 `.dark` token |

## 2. 设计 token

改颜色、字号只改 `src/index.css` 和本节，页面里不写十六进制色值，也不写 Tailwind 原始色（`bg-blue-500`、`text-amber-600`、`bg-white` 等）。

### 2.1 颜色

| token | 用途 |
|---|---|
| `primary` | 主按钮、链接、选中态、进行中状态 |
| `destructive` | 危险按钮、错误提示、异常状态 |
| `success` / `success-text` | 完成类状态：前者做圆点、进度条、图标底，后者做文字 |
| `warning` / `warning-text` | 待处理类状态：同上 |
| `tone-cyan` / `tone-cyan-text` | 状态专用：阶段完成、等下一环节 |
| `tone-purple` / `tone-purple-text` | 状态专用：特殊流程 |
| `muted` / `muted-foreground` | 次要底色、辅助文字、未开始状态 |
| `border` / `input` | 分割线、输入框描边 |
| `canvas` | 页面画布 |
| `row-hover` | 表格行悬停底色（不透明，固定列不会透底） |

**两档原则**：浅底（`/10`）或白底上的文字一律用 `-text` 档，保证对比度 ≥ 4.5:1（WCAG AA）。原来直接用填充色做文字时，橙色徽标只有 2.4:1、青色 2.3:1。`primary`、`destructive`、`muted-foreground` 本身已达标，填充和文字共用。

唯一例外是打印区域（入库标签）：固定黑白，不跟随 token。

### 2.2 字号

管理端只用四档，禁止 `text-[13px]` 这类任意字号：

| 字号 | class | 用于 |
|---|---|---|
| 12px | `text-xs` | 辅助信息、表头、字段标签、徽标 |
| 14px | `text-sm` | 正文、表格、按钮、区块标题（`font-medium`） |
| 16px | `text-base` | 页面标题（`font-semibold`）、弹窗/抽屉标题 |
| 20px | `text-xl` | 统计数字（`font-semibold`） |

PDA 字号见第 8 节；作业台额外允许 18px / 24px，见[《04-作业台设计规范》](04-作业台设计规范.md)第 4 节。

### 2.3 字体

| 内容 | 写法 |
|---|---|
| 正文、中文 | `font-sans`（Geist + 苹方/雅黑/Noto Sans SC，见 `index.css`） |
| 数量、金额、单号、编码 | sans + `tabular-nums`，用 `<Num>` `<DocNo>` `<BizCode>` |
| 等宽 `font-mono` | **仅** PDA 编码、条码打印、快捷键 `kbd`；管理端列表/详情/表单不用 |

### 2.4 圆角与阴影

| 档位 | class | 用于 |
|---|---|---|
| 小 | `rounded` | 状态徽标、标签 |
| 中（8px） | `rounded-lg` | 按钮、输入框、面板、表格容器（shadcn nova 预设下控件与面板同为 8px） |
| 大（12px） | `rounded-xl` | 弹窗、抽屉、PDA 卡片与扫码框 |

不要用 `rounded-2xl` 及以上（PDA 演示外框除外）。默认不用阴影；下拉、弹窗由组件自带，固定列有分隔阴影，PDA 卡片用 `shadow-xs`。

### 2.5 间距与密度

| 位置 | 规定 |
|---|---|
| 页面 | 内边距 `p-4`，块间距 `gap-3` |
| 面板 / 区块 | 内边距 `p-4`，标题与内容间距 12px（`<Section>` 自带） |
| 表单栅格 | 列间距 16px、行间距 12px（`<FormGrid>` 自带） |
| 标签与控件 | 6px（`<FormField>` 自带） |

三档密度，按场景选，不要混用：

| 密度 | 控件高 | 表格行高 | 场景 |
|---|---|---|---|
| 管理端 | 32px（`h-8`，shadcn 默认） | 40px | 列表、详情、表单 |
| 作业台 | 56px（`h-14`） | 48px | 管理端扫码作业（收货作业台） |
| PDA | 按钮 48px（`h-12`），列表行 ≥ 56px | — | 手持终端 |

侧边栏展开 224px / 收起 56px。

## 3. 状态颜色

状态统一用 `<StatusBadge meta={…} />`，映射集中写在 `src/config/status.ts`，页面里不自己拼颜色。**同一个状态文案在任何单据上颜色相同**。

| tone | 语义 | 例子 |
|---|---|---|
| gray | 未开始（等外部）、已取消 | 待收货、已取消、停用 |
| orange | 待我方处理（已具备作业条件、等人处理） | 待上架、待打单 |
| blue | 作业进行中 | 收货中、上架中、拣货中 |
| cyan | 阶段完成、等下一环节 | 已拣货 |
| green | 最终完成、启用 | 已完成、已发货、启用 |
| red | 异常、拦截 | 已拦截 |
| purple | 特殊流程 | 打包中 |

- 生命周期状态用 `<StatusBadge>`（带圆点）；枚举属性（品质、业务类型）用 `<TagLabel meta={…} />`（无圆点），映射同样写在 `status.ts`（`qualityMeta`、`inboundBizTypeMeta`）。
- 新单据的状态机先在 `types/wms.ts` 定义枚举，再在 `config/status.ts` 加 `xxxStatusMeta`，文案 key 放在 `status.xxx` 下。
- 统计卡片的图标色取它所统计状态的 tone（见工作台）。

## 4. 显示规则

同一种数据永远长一个样，组件都在 `components/biz/display.tsx`：

| 数据 | 写法 |
|---|---|
| 单号、编码 | `<DocNo>`（可点打开详情）/ `<BizCode>`（只读） |
| 编码 + 名称 | `<CodeName code name />`：表格里单行（编码正文色 + 名称灰色截断，保持 40px 行高），详情和 PDA 可 `layout="stacked"`；下拉选项、只读输入框用 `codeNameText(code, name)`，格式 `编码 · 名称` |
| 空值 | `<Empty />`，全站统一「—」；只能放字符串的地方用 `EMPTY_TEXT`。不要手写 `'-'` |
| 数量 | `<Num>`，右对齐（列 `meta: { align: 'right' }`） |
| 金额 | `<Money>`，显示原币，悬停看折算 |
| 时间 | `<DateTime>`，按仓库/本地时区；空值、非法值自动显示占位符 |
| 重量、尺寸 | `<Weight>`、`<Dimension>` |
| 进度 | `<ProgressCell done total pct />`：细条 + 已完成/总数 |
| 地址 | `formatFullAddress(地址, t(countryLabelKey(国家)))`；表单和详情里用 `<WarehouseFullAddressPreview>` |
| 只读值（表单内） | `<Input readOnly>`，自动灰底；时间等需格式化的值先格式化成字符串 |

## 5. 页面模板

### 5.1 列表页

样板：业务单据 `pages/wms/inbound/inbound-order-list-page.tsx`（含状态页签、筛选写进 URL）；主数据 `pages/wms/master/warehouse-list-page.tsx`。

```
PageContainer fill（标题 + 右上角操作）
├─ Panel p-4：FilterBar
└─ Panel flex-1：[StatusTabs] + DataTable
```

- **筛选区**：`<FilterBar>` 固定 6 列栅格（可写 `columns={6}` 与 PRD 写法一致，写 4 会类型报错），常显最多 5 个筛选项，第 6 列放查询/重置；第 6 个及以后的条件放 `advanced`，出现「展开」。下拉用 `<OptionSelect allOption>`，启停用 `<UsageStatusFilter>`，是否用 `<YesNoFilter>`（配合 `matchYesNo`）。
- **草稿与生效**：`useListFilters(empty)` 管理 draft / filters，点「查询」才生效，「重置」两份都清空。需要写进 URL 时参照入库单列表。
- **列定义**：`createDataColumns<T>()` 写在 `useMemo` 里。编码列 `meta: { pin: 'left' }`（它前面可以有所属仓库、货主等上下文列，横向滚动时前面的列先滚出视口再吸附）；操作列 `pin: 'right'`；数字列右对齐；排序默认关闭，只给日期/数字列开 `enableSorting: true`。
- **含翻译的文本在 `cell` 里算**：accessor 的结果按行缓存，切换语言不会重算。
- **行操作**：`<RowActions actions={[…]} />`，横排，最多露 2 个，其余收进「更多」；停用、删除等标 `danger`，并走二次确认。不满足条件的操作用 `hidden` 隐藏，不用 disabled。

```tsx
const columns = useMemo(() => {
  const col = createDataColumns<InboundOrder>()
  return col.columns([
    col.accessor('inboundNo', {
      header: t('inbound.inboundNo'),
      meta: { pin: 'left' },
      cell: ({ getValue }) => <DocNo onClick={() => open(getValue())}>{getValue()}</DocNo>,
    }),
    col.accessor('customerId', {
      header: t('common.customer'),
      cell: ({ getValue }) => <CodeName code={customerCode(getValue())} name={customerName(getValue())} />,
    }),
    col.accessor('plannedQty', {
      header: t('inbound.plannedQty'),
      meta: { align: 'right' },
      cell: ({ getValue }) => <Num value={getValue()} />,
    }),
    col.display({
      id: 'actions',
      header: t('common.actions'),
      meta: { pin: 'right' },
      cell: ({ row }) => <RowActions actions={[/* 最常用的放前面 */]} />,
    }),
  ])
}, [t])
```

### 5.2 详情页

样板：主数据 `warehouse-detail-page.tsx`；业务单据 `inbound-order-detail-page.tsx`。

- **标题**：`<DetailTitle title code status />`，渲染为「固定文案 · 编码 [状态]」。固定文案来自 i18n（主数据「查看库区详情」，单据「入库单」），编码和状态单独传，不拼进文案。
- **页头操作**：主数据用 `<MasterDetailActions>`，顺序固定为「返回列表 → 启用/停用 → 编辑」，主按钮在最右；有额外主操作（如承运商「新增渠道」）时传 `extra`，编辑自动降为次要按钮。
- **字段区**：每组一个 `<Section title>` + `<Descriptions columns={4}>`；长字段用 `multiline` 或 `col-span-*`。最后放 `<MasterAuditPanel>`（维护信息）。
- **子表**：`<Section flush title extra>` 里直接放 `<DataTable>`，表格贴边；空数据用 `emptyText` 给出具体提示。

**业务单据详情**（有进度、有多类子记录的单据，样板 `inbound-order-detail-page.tsx`）在上面基础上改用「概览卡 + 多页签」：

```
PageContainer（DetailTitle + 页头操作）
├─ DetailOverview（两栏等高，窄屏堆叠）
│   ├─ Section「基本信息」+ Descriptions columns={3}   ← 单头字段合成一张卡，状态已在标题里，不重复
│   └─ SummaryCard（右侧 320px）
│       ├─ SummaryProgress × n（收货进度、上架进度…）
│       └─ SummaryMetrics（计划 / 已完成 / 待处理…，按状态 tone 上色，0 值可 hidden）
└─ DetailTabs param="tab"（明细 / 作业记录 / 异常 / 操作日志，页签带条数）
```

- 单据明细放第一个页签，不再单独一个 `<Section>`；子记录多于 1 类就进页签，不要上下堆多个表。
- `DetailTabs` 传 `param` 时当前页签写进 URL（`?tab=receipts`），刷新和返回仍停在原页签；抽屉里的页签不传。
- 页签内容默认是贴边表格；放说明文字或字段时给该项 `padded`。
- 表格的列设置（和 `toolbar` 批量操作）自动挪到页签栏右侧，表格紧贴页签栏，不再单占一行；`<Section flush title>` 里的表格同理放到标题行右侧。只有列表页的表格保留自己的工具栏行。
- 进度条只用 blue（进行中的第一段作业）、green（后续/完成）两色；数量清单的颜色与状态色语义一致（待处理 orange、完成 green、异常 red）。

### 5.3 新增 / 编辑页

样板：`warehouse-create-page.tsx`、`warehouse-edit-page.tsx` + `warehouse-form-fields.tsx`。

- 标题用 `createTitle` / `editTitle`；页头「取消」（次要）+「保存」（主按钮，最右）。取消时有改动走 `useMasterDiscardNavigate` 二次确认。
- 字段区：`<Section title>` + `<FormGrid>`（4 列，md 2 列）+ `<FormField label required error span>`。不要手写 grid class 和标签结构。
- 必填红 `*`、校验错误在字段下方 12px 红字（`useMasterFormFieldError`）；可编辑控件都要写 placeholder（`common.inputPlaceholder` / `common.selectPlaceholder` 或模块专用 key），只读字段不写。
- **使用状态不进表单**：新建默认启用，启停只在列表操作列和详情页头，并经过停用前校验（如库区下有占用货位不能停用）。
- 共享字段块放 `pages/wms/master/*-form-fields.tsx`，`mode` 区分新增与编辑；空表单初始值写在 `lib/*-master.ts`（`createEmpty*Form`）。
- 路由：新增 `…/new`，编辑 `…/:code/edit`。例外：货主按其 PRD 不提供新增与独立编辑路由，用详情同路由 `?edit=1`。

### 5.4 弹窗与抽屉

| 场景 | 用什么 |
|---|---|
| 二次确认 | `useConfirm()`，不要手写 Dialog |
| 小表单、PRD 指定的主数据弹窗维护（承运商、渠道、商品条码） | `Dialog` + `<FormGrid columns={2}>` |
| 边看列表边查看子记录（收货记录、上架单） | `<DetailSheet>`（右侧 880px） |
| 复杂新建/编辑、主单据详情 | 独立页面（页签） |
| 操作结果反馈 | `toast.success` / `toast.error` |

- 弹窗宽度一律写 `sm:max-w-*`：确认/小表单 `sm:max-w-md`，含表格或多分组 `sm:max-w-lg`。不带 `sm:` 的 `max-w-*` 会被组件自带的 `sm:max-w-sm` 覆盖，桌面端只有 384px。
- 内容可能超出一屏的弹窗加 `max-h-[90vh] overflow-y-auto`。

### 5.5 统计卡片与汇总卡

详情页右侧的进度汇总用 `<SummaryCard>`（见 5.2），不要拿多个 `StatCard` 拼。


`<StatCard label value icon? tone? to? />`：标签 12px 灰 + 数字 20px 半粗；工作台 KPI 带图标并可跳转，页面顶部概览不带图标。样板：`dashboard-page.tsx`、`stock-page.tsx`。

### 5.6 作业台（管理端扫码作业）

> 完整规范（原则、骨架、字号、反馈分级、文案写法、自检与走查记录）见[《04-作业台设计规范》](04-作业台设计规范.md)，本节只留要点。

样板：`inbound-order-receive-page.tsx`。用作业台密度（第 2.5 节）：扫码框用 `<ScanField>`（外观与 PDA 扫码框一致），主按钮 `h-14`，录入表格 48px 行高。

- 一次作业含多个对象（如多个容器）时：左边录入当前对象，右边 320px `<SummaryCard>` 列出本次已录对象（可点回修改、可移除）和合计，提交按钮放在卡片底部并写明数量（「提交收货（2 个容器）」）。
- 一个扫码框按当前步骤切换用途（没有当前容器时扫箱号，有时扫商品），不并排放两个扫码框。
- 本次作业未提交的录入放 zustand persist store（如 `stores/web-receive-session.ts`），切页签、刷新不丢。
- 录入列在 1440 宽屏内不横向滚动即可见：编码、名称、条码合成一列。

## 6. 交互规则

| 规则 | 说明 |
|---|---|
| 页头按钮 | 列表页按 PRD：「新增」（主按钮）在左、「导出」在右；详情/编辑页：次要按钮在左，主按钮在最右。一个页头只有一个主按钮 |
| 打开详情 | 点编号即打开（`<DocNo onClick>`），不另设「查看」按钮。主单据、主数据开新页签路由；子记录开 `<DetailSheet>` |
| 危险操作 | `destructive` 按钮 + `useConfirm` 二次确认（停用、删除、重置演示数据） |
| 数量超上限 | 拒绝并提示，保留原值，不静默截断（管理端与 PDA 一致） |
| 校验失败 | 字段下方红字 + `toast.error` 汇总提示 |
| 页签 | 菜单入口只占列表路径；详情/编辑等子路由用完整 pathname 在 `config/page-tabs.ts` 登记 |

## 7. 国际化与数据

| 类型 | 存储 | 显示 |
|---|---|---|
| 文字 | 语言包 key | `t('module.key')`，禁止在代码里写死中文或英文（语言名称按原文显示除外） |
| 金额 | `{ amount, currency }` | `<Money>`；汇总先 `convertMoney` 折到显示币别再相加 |
| 时间 | UTC ISO 字符串 | `<DateTime>`，自动按仓库时区或本地时区 |
| 重量 / 尺寸 | 克 / 厘米 | `<Weight>` / `<Dimension>`，自动公制/英制 |
| 国家/地区 | 国家代码 | `t(countryLabelKey(code))` |

- 新增文案时 `zh-CN.ts` 和 `en-US.ts` 同时加，`Messages` 类型会在漏写时报错。英文比中文长，按钮和表头要留宽度。aria-label 也走语言包。
- 业务数据按当前仓库过滤：`useCurrentWarehouse()`，再按 `warehouseCode` 过滤。
- 类型写在 `src/types/`；演示数据写在 `src/mock/`，用 `createRandom` 保证每次生成一致，数据之间要对得上。
- 改了种子数据或数据结构，把 `mock/db.ts` 里 persist 的 `version` 加 1。
- 会改数据的操作写成 `useDb` 里的 action，返回 `{ ok: true } | { ok: false, errorKey }`，页面据此弹 toast。页面不直接改 store。
- 读取货主名、SKU 信息用 `useLookups()`。

## 8. PDA 规范

产品规则以[《PDA作业端设计规范》](../../../05-应用设计方案/20261002-MVP版本/需求文档PRD/7-PDA作业端/PDA作业端设计规范.md)为准，各作业的交互见同目录的 PDA Demo 版 PRD。本节只写实现约定。

样板：`src/pages/pda/receive-page.tsx` + `receive/*`（多步作业、本机暂存）、`putaway-page.tsx` + `putaway/*`（按业务单据作业）。

- **页面结构**：`PdaHeader`（返回 · 作业名 · 仓库）→ `PdaContextBar`（单据、容器等上下文）→ 主区（提示语 + `ScanInput` + 当前对象/列表，可滚动）→ `PdaFooter`（固定；`hint` 写主按钮不可用的原因）。不用步骤条。
- **组件**（`components/pda/`）：信息卡片 `PdaCard`；可点列表行 `PdaListItem`（`chevron` 表示进入下一步，`selectable` + `selected` 做单选/多选）；分组标题 `PdaSection`；大按钮 `PdaButton`（48px，宽度由调用方给 `flex-1` / `w-24`）；扫码 `ScanInput`；数量 `QtyStepper`；6 个以内的枚举 `PdaChoiceGroup`。
- **步骤与返回**：一个作业一个路由，步骤用 `usePdaStep(steps, firstStep)` 写进路由参数 `step`；前进 `go`，回到之前的步骤 `returnTo`，标题栏返回 `back`。
- **作业页拆分**：`xxx-page.tsx` 只按 `step` 分发；共用数据与动作放 `xxx/use-xxx-flow.ts`，每一步一个组件文件；进入步骤时校验路由参数，对不上就 `replace` 到能继续的步骤。
- **扫码**：每个扫码步骤用 `<ScanInput>`（自动聚焦、回车提交、`onScan` 返回 `false` 时红闪 + 提示音，并给出「模拟扫码」候选值）。没有扫码框的步骤用 `usePdaScanListener(onScan)`。有弹窗时不接收扫码。
- **数量**：`<QtyStepper>`；超过 `max` 拒绝并提示；数量框收到扫码内容不写入数量，交给 `onScanText`。
- **反馈**：扫码错误用扫码框红闪 + `toast.error`；业务阻断用 `confirm({ hideCancel: true, confirmText: t('pda.gotIt') })`；需确认的操作用 `confirm`。
- **草稿**：还没成为业务记录的录入放 zustand persist store（如 `stores/pda-receive-session.ts`）；已保存到业务单据的进度不另存草稿。
- **文字与触控**：正文 15～16px，关键信息（单号尾号、货位、数量、SKU）18～24px 粗体，编码用 `font-mono`；字号下限 12px；可点元素（含标题栏返回键）不小于 48px，列表行不小于 56px。
- **颜色**：只用语义色和状态色调；首页功能宫格按分组取色（入库蓝、库内青、出库紫）。

## 9. 规范检查与自检

`npm run lint`（oxlint + 设计检查）或单独 `npm run lint:design`，脚本在 `scripts/lint-design.mjs`：

| 规则 | 拦截 |
|---|---|
| `raw-color` | Tailwind 原始色（`bg-blue-500`、`text-amber-600`、`bg-white` 等） |
| `arbitrary-font-size` | `text-[13px]` 这类任意字号 |
| `admin-font-mono` | 管理端的 `font-mono`（PDA、kbd、打印标签除外） |
| `cjk-literal` | 代码里写死的中文（注释除外） |
| `dialog-width` | `DialogContent` 上不带 `sm:` 的 `max-w-*` |
| `empty-placeholder` | 手写的 `'-'` / `'—'` 空值 |
| `link-button` | 页面里用 `Button variant="link"` 做行内操作 |

确属例外的行加注释 `design-lint-ignore 原因`（如语言名称按原文显示）。

完成前自检：

1. `npx tsc -p tsconfig.app.json --noEmit`、`npm run lint`、`npm test`、`npm run build` 全部通过。
2. 浏览器里切换中英文、切换一个欧洲仓（`DE-FRA-01`，欧元、公制、柏林时区）各看一遍。

## 10. 新增一个页面的步骤

1. 在 `config/menu.ts` 找到对应菜单项（没有就加），记下 `path`。
2. 在 `types/` 补类型，`mock/` 造数据，`mock/db.ts` 加动作。
3. 在 `pages/wms/<模块>/` 下新建页面，照着第 5 节对应样板写，只用第 4 节的显示组件和第 3 节的状态映射。
4. 在 `app/router.tsx` 注册路由（主数据子页走 `new` / `:code` / `:code/edit`，并在 `config/page-tabs.ts` 登记）；菜单页可在 `pages/wms/registry.ts` 映射。
5. 两个语言包补齐文案。
6. 按第 9 节自检。
