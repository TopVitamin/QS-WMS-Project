# QS-WMS 前端设计与开发规范

写给后续生成页面的 AI 和开发者。新增页面前先读完这份文档，再打开对应的样板页照着写。基础资料（主数据）列表/新增/详情/编辑的组件表与检查单见 [《03-业务组件与主数据页面》](03-业务组件与主数据页面.md)。

## 1. 设计基调

中国 SaaS 后台风格：信息密度中等，白底卡片放在浅灰画布上，蓝色主色，少装饰。

| 项 | 规定 |
|---|---|
| 主色 | `primary`，蓝 `oklch(0.55 0.2 259)`，只用于主按钮、选中态、链接 |
| 画布 | 页面背景用 `bg-canvas`，内容块用 `<Panel>`（白底、1px 边框、圆角 8px） |
| 圆角 | 控件 `rounded-md`，卡片 `rounded-lg`，不要用 `rounded-2xl` 以上 |
| 阴影 | 默认不用阴影，下拉/弹窗由组件自带 |
| 字号 | 正文 14px（`text-sm`），辅助信息/表头 12px（`text-xs`），页面标题 16px 半粗 |
| 字体栈 | 全局 `font-sans`：Geist + 苹方/雅黑/Noto Sans SC；`font-mono`：Geist Mono（见 `index.css`） |
| 数字与编码 | 数量、金额、**管理端单号/仓库编码**：`tabular-nums` + **sans**（`DocNo` / `BizCode` / `lib/typography.ts`）；**仅** PDA 扫码、条码打印、快捷键 `kbd` 用 `font-mono` |
| 文字链 | 表格操作、可点单号统一 `textLink`（`text-sm text-primary hover:underline`），与 `DocNo` 点击态一致 |
| 图标 | 只用 `lucide-react`，按钮内图标加 `data-icon="inline-start"` |
| 遮罩 | 弹窗/抽屉遮罩统一 `bg-black/35`，不用毛玻璃 |

颜色一律用语义 token：`primary`、`muted-foreground`、`destructive`、`success`、`warning`、`border`。不要写 `bg-blue-500`、`text-gray-400` 这类原始色（状态色映射除外，见第 3 节）。

## 2. 密度与尺寸

| 元素 | 尺寸 |
|---|---|
| 输入框、下拉、按钮 | 高 32px（shadcn 默认 `h-8`） |
| 表头 | 高 36px，12px 灰字，浅灰底 |
| 表格行 | 高 40px |
| 侧边栏 | 展开 224px / 收起 56px |
| 页面内边距 | `p-4`，块间距 `gap-3` |
| 筛选区 | 默认 4 列 +「展开」；基础资料可用 `FilterBar columns={6}`：**5 个筛选项 + 第 6 列**底对齐放查询/重置（日期范围可合并占 1 列） |
| 基础资料详情/编辑 | 字段区统一 **4 列**：详情 `Descriptions columns={4}`，编辑 `xl:grid-cols-4`；必填用 `FormFieldLabel required`；**只读且不可操作字段（如使用状态）仅列表/详情展示，不进新增/编辑表单** |
| 日期筛选 | 单日 `DatePickerField`；范围 `DateRangePickerField`（一个控件 + range 日历），不用原生 `input[type=date]` |
| 下拉 `Select` | 筛选区触发器加 `w-full`；`SelectContent` 默认 `position=popper`、`align=start`，与触发器左缘对齐（勿用 item-aligned） |
| 表单占位 | 新增/编辑：空 `Input`/`Textarea` 须有 placeholder（`common.inputPlaceholder` 或模块 `*Placeholder`）；`SelectValue` 用 `common.selectPlaceholder`（有默认值的下拉会显示选项文案，仍建议写上） |
| 表格排序 | `DataTable` 默认关闭排序；仅对日期/时间/数字列显式 `enableSorting: true` |
| PDA 触控目标 | 不小于 48px 高，主按钮 `h-12` 占满宽度 |

## 3. 状态颜色

状态统一用 `<StatusBadge tone=... />`，状态到颜色的映射集中写在 `src/config/status.ts`，页面里不要自己拼颜色。

| tone | 含义 | 例子 |
|---|---|---|
| gray | 未开始 / 已取消 | 待入库、已取消 |
| blue | 进行中 | 收货中、拣货中 |
| cyan | 阶段完成、等下一步 | 已签收、已拣货 |
| orange | 等待处理、需注意 | 待打单、部分上架 |
| green | 最终完成 | 已完成、已发货 |
| red | 异常、拦截 | 异常待确认、已拦截 |
| purple | 特殊流程 | 打包中 |

新单据的状态机要先在 `types/wms.ts` 定义枚举，再在 `config/status.ts` 加 `xxxStatusMeta`，文案 key 放在 `status.xxx` 下。

## 4. 页面模板

### 4.1 列表页（最常见）

样板（列表结构 + StatusTabs）：`src/pages/wms/inbound/inbound-list-page.tsx`（**M0 占位，业务与状态以入库单 PRD 为准**；目标页 `inbound-order-list-page.tsx`）。FilterBar 6 列行为对齐 `warehouse-list-page.tsx`。

结构自上而下固定为：

```
PageContainer fill（标题 + 右上角操作：导出 / 新建）
├─ Panel：FilterBar（常用条件 ≤ 3 个，其余放 advanced）
└─ Panel flex-1：StatusTabs（带数量） + DataTable（toolbar 放批量操作）
```

规则：

- 筛选条件分"草稿"和"已生效"两份 state，点"查询"才生效，"重置"同时清空两份。
- 单号搜索框支持空格分隔的多个单号。
- 列定义用 `createDataColumns<T>()`，写在 `useMemo` 里：

```tsx
const columns = useMemo(() => {
  const col = createDataColumns<InboundOrder>()
  return col.columns([
    col.accessor('inboundNo', {
      header: t('inbound.inboundNo'),
      meta: { pin: 'left' },            // 首列固定在左
      cell: ({ getValue }) => <DocNo onClick={() => open(getValue())}>{getValue()}</DocNo>,
    }),
    col.accessor('plannedQty', {
      header: t('inbound.plannedQty'),
      meta: { align: 'right' },          // 数字列右对齐
      cell: ({ getValue }) => <Num value={getValue()} />,
    }),
    col.display({
      id: 'actions',
      header: t('common.actions'),
      meta: { pin: 'right' },            // 操作列固定在右
      cell: ({ row }) => /* 最多 2 个文字按钮 + "更多"下拉 */,
    }),
  ])
}, [t])
```

- 固定列（`pin`）单元格默认 `bg-card` 防横向滚动透底；行悬停/选中底色由 `DataTable` 用 `hover:[&>td]:…` 一次性刷到**所有** `td`，不要同时在 `tr` 和固定列上各涂一层半透明，否则首尾会偏深。
- 操作列最多露出 2 个文字按钮，其余收进"更多"下拉；危险操作（取消、删除）必须二次确认。
- 单号列默认打开详情抽屉、不跳新页面（**基础资料**编码列跳详情路由，见第 4.5 节）。
- **业务单据例外（入库单）**：列表入库单号列跳转独立详情路由 `/wms/inbound/orders/:inboundNo`（见《入库单前端Demo版PRD_详情页》）；单次收货/上架单「查看」仍用右侧 Sheet（§4.2）。

### 4.2 详情

- 字段不多、以查看为主：右侧 `Sheet` 抽屉，宽 880px。样板：`inbound-detail-sheet.tsx`（**M0**；入库单主详情用独立路由，见上条例外）。
  - 改宽度要用 `data-[side=right]:w-[880px] data-[side=right]:sm:max-w-[92vw]`，否则会被组件默认样式覆盖。
- 表单很长、需要分步骤或多个明细表：新开页签路由（**入库单详情**、主数据详情均属此类）。
- 顶部 `WmsTabsBar`：`WmsLayout` 用 `resolvePageTab(pathname)` 打开页签；菜单入口只占列表路径，详情/编辑等子路由用**完整 pathname** 单独开 tab（见 `config/page-tabs.ts`），避免子页面仍挂在列表 tab 上且选中态丢失。

### 4.3 弹窗与抽屉怎么选

| 场景 | 用什么 |
|---|---|
| 二次确认、1~3 个字段的小表单 | `Dialog` |
| 查看详情、边看列表边处理 | `Sheet`（右侧） |
| 复杂新建/编辑 | 独立页面（页签） |
| 操作结果反馈 | `toast`（sonner），成功 `toast.success`，失败 `toast.error` |

### 4.4 统计卡片

数字概览放在页面顶部，用 `Panel` + 标签（12px 灰）+ 数字（20px 半粗）。样板：`stock-page.tsx`、`dashboard-page.tsx`。

### 4.5 主数据（基础资料）页面

样板：**仓库资料** `pages/wms/master/warehouse-*-page.tsx`。

- 列表：无 `StatusTabs`、通常无行勾选；页头「导出 + 新增」；`FilterBar columns={6}` 时第 6 列放查询/重置。
- 详情/编辑/新增：独立路由 + 顶栏多页签（`resolvePageTab`）；详情标题用固定文案（如「查看仓库详情」），动态编码放在字段区。
- 地址类只读拼接：表单/详情用 `WarehouseFullAddressPreview`，勿用裸 `<p>` 造成与输入框行高不齐。
- 共享表单块按模块抽 `*-form-fields.tsx`，`mode` 区分新增与编辑（编码可编/只读）。

## 5. 国际化规则（必须遵守）

| 类型 | 存储 | 显示 |
|---|---|---|
| 文字 | 语言包 key | `t('module.key')`，禁止在 JSX 里写死中文或英文 |
| 金额 | `{ amount, currency }` | `<Money value={...} />`，显示原币，悬停看折算 |
| 汇总金额 | 先 `convertMoney` 折到显示币别再相加 | `formatMoney` |
| 时间 | UTC ISO 字符串 | `<DateTime value={...} />`，自动按仓库时区或本地时区 |
| 重量 | 克（number） | `<Weight grams={...} />`，自动公制/英制 |
| 尺寸 | 厘米 | `<Dimension l={} w={} h={} />` |
| 数量 | number | `<Num value={...} />`（千分位） |

新增文案时 `zh-CN.ts` 和 `en-US.ts` 必须同时加，`Messages` 类型会在漏写时报错。英文比中文长，按钮和表头要留宽度，必要时用更短的英文。

所有业务数据按当前仓库过滤：`const warehouse = useCurrentWarehouse()`，再用 `warehouseCode` 过滤。

## 6. 数据与业务动作

- 类型写在 `src/types/wms.ts`。
- 演示数据写在 `src/mock/seed.ts`，用 `createRandom` 保证每次生成结果一样。数据之间要互相对得上（例如已完成的入库单一定有库存和流水）。
- 改了 `seed.ts` 或数据结构，把 `mock/db.ts` 里 persist 的 `version` 加 1，浏览器里的旧数据会自动换成新种子。
- 会改数据的操作写成 `useDb` 里的 action，返回 `{ ok: true } | { ok: false, errorKey }`，页面根据结果弹 toast。页面组件里不要直接改 store 数据。
- 读取货主名、SKU 信息用 `useLookups()`。

## 7. PDA 规范

产品规则以[《PDA作业端设计规范》](../../../05-应用设计方案/20261002-MVP版本/需求文档PRD/7-PDA作业端/PDA作业端设计规范.md)为准（设备基线 360×560、扫码优先、反馈分级、返回与草稿、触控与字号），各作业的交互见同目录的 PDA Demo 版 PRD。本节只写实现约定。

样板：`src/pages/pda/receive-page.tsx` + `receive/*`（多步作业、本机暂存）、`putaway-page.tsx` + `putaway/*`（按业务单据作业）。

- **页面结构**：`PdaHeader`（返回 · 作业名 · 仓库） → `PdaContextBar`（单据、容器等上下文） → 主区（提示语 + `ScanInput` + 当前对象 / 列表，可滚动） → `PdaFooter`（固定；`hint` 写主按钮不可用的原因）。不用步骤条。
- **步骤与返回**：一个作业一个路由，步骤用 `usePdaStep(steps, firstStep)` 写进路由参数 `step`；前进用 `go`，回到之前的步骤用 `returnTo`（后退到该步那条历史，避免重复入栈），标题栏返回用 `back`。安卓返回键因此逐步回退。
- **作业页拆分**：`xxx-page.tsx` 只按 `step` 分发；共用数据与动作放 `xxx/use-xxx-flow.ts`，每一步一个组件文件；进入步骤时校验路由参数，与数据对不上就 `replace` 到能继续的步骤。
- **扫码**：每个扫码步骤用 `<ScanInput>`（自动聚焦、回车提交、`onScan` 返回 `false` 时红闪 + 提示音，并给出「模拟扫码」候选值）；焦点不在扫码框时由它内置的页面级监听接收。没有扫码框的步骤用 `usePdaScanListener(onScan)`。有弹窗时不接收扫码。
- **数量**：用 `<QtyStepper>`；超过 `max` 拒绝并提示，不截断；数量框收到扫码内容（含非数字或超过 6 位）不写入数量，交给 `onScanText`。
- **枚举**：6 个以内用 `<PdaChoiceGroup>` 大按钮，不用下拉。
- **反馈**：扫码错误用扫码框红闪 + `toast.error`；业务阻断用 `confirm({ hideCancel: true, confirmText: t('pda.gotIt') })`（阻断弹窗不自动聚焦按钮，避免扫描头的回车把它直接关掉）；需确认的操作用 `confirm`。
- **草稿**：还没成为业务记录的录入放 zustand persist store（如 `stores/pda-receive-session.ts`）；已保存到业务单据的进度（如上架单实际明细）不另存草稿。
- **文字与触控**：正文 15～16px，关键信息（单号尾号、货位、数量、SKU）18～24px 粗体，编码用 `font-mono`；可点元素不小于 48px。
- PDA 路由写在 `app/router.tsx` 的 `/pda` 下，首页功能入口在 `pda-home-page.tsx`。

## 8. 新增一个页面的步骤

1. 在 `config/menu.ts` 找到对应菜单项（没有就加），记下 `path`。
2. 在 `types/` 补类型，`mock/seed.ts` 造数据，`mock/db.ts` 加动作。
3. 在 `pages/wms/<模块>/` 下新建页面，照着第 4 节对应样板写。
4. 在 `app/router.tsx` 注册路由（主数据子页走 `new` / `:code` / `:code/edit`，并在 `config/page-tabs.ts` 登记）；菜单页可在 `pages/wms/registry.ts` 映射。
5. 两个语言包补齐文案。
6. 跑 `npx tsc -p tsconfig.app.json --noEmit` 和 `npm run build`，再在浏览器里切换中英文、切换一个欧洲仓各看一遍。
