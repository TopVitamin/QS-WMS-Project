# QS-WMS 前端设计与开发规范

写给后续生成页面的 AI 和开发者。新增页面前先读完这份文档，再打开对应的样板页照着写。

## 1. 设计基调

中国 SaaS 后台风格：信息密度中等，白底卡片放在浅灰画布上，蓝色主色，少装饰。

| 项 | 规定 |
|---|---|
| 主色 | `primary`，蓝 `oklch(0.55 0.2 259)`，只用于主按钮、选中态、链接 |
| 画布 | 页面背景用 `bg-canvas`，内容块用 `<Panel>`（白底、1px 边框、圆角 8px） |
| 圆角 | 控件 `rounded-md`，卡片 `rounded-lg`，不要用 `rounded-2xl` 以上 |
| 阴影 | 默认不用阴影，下拉/弹窗由组件自带 |
| 字号 | 正文 14px（`text-sm`），辅助信息/表头 12px（`text-xs`），页面标题 16px 半粗 |
| 数字 | 数量、金额右对齐并用 `tabular-nums`；单号、条码、货位用 `font-mono` |
| 图标 | 只用 `lucide-react`，按钮内图标加 `data-icon="inline-start"` |
| 遮罩 | 弹窗/抽屉遮罩统一 `bg-black/35`，不用毛玻璃 |

颜色一律用语义 token：`primary`、`muted-foreground`、`destructive`、`success`、`warning`、`border`。不要写 `bg-blue-500`、`text-gray-400` 这类原始色（状态色映射除外，见第 3 节）。

## 2. 密度与尺寸

| 元素 | 尺寸 |
|---|---|
| 输入框、下拉、按钮 | 高 32px（shadcn 默认 `h-8`） |
| 表头 | 高 36px，12px 灰字，浅灰底 |
| 表格行 | 高 40px |
| 侧边栏 | 展开 224px / 收起 56px |
| 页面内边距 | `p-4`，块间距 `gap-3` |
| 筛选区 | 4 列栅格，多余条件收进"展开" |
| PDA 触控目标 | 不小于 48px 高，主按钮 `h-12` 占满宽度 |

## 3. 状态颜色

状态统一用 `<StatusBadge tone=... />`，状态到颜色的映射集中写在 `src/config/status.ts`，页面里不要自己拼颜色。

| tone | 含义 | 例子 |
|---|---|---|
| gray | 未开始 / 已取消 | 待入库、已取消 |
| blue | 进行中 | 收货中、拣货中 |
| cyan | 阶段完成、等下一步 | 已签收、已拣货 |
| orange | 等待处理、需注意 | 待打单、部分上架 |
| green | 最终完成 | 已完成、已发货 |
| red | 异常、拦截 | 异常待确认、已拦截 |
| purple | 特殊流程 | 打包中 |

新单据的状态机要先在 `types/wms.ts` 定义枚举，再在 `config/status.ts` 加 `xxxStatusMeta`，文案 key 放在 `status.xxx` 下。

## 4. 页面模板

### 4.1 列表页（最常见）

样板：`src/pages/wms/inbound/inbound-list-page.tsx`

结构自上而下固定为：

```
PageContainer fill（标题 + 右上角操作：导出 / 新建）
├─ Panel：FilterBar（常用条件 ≤ 3 个，其余放 advanced）
└─ Panel flex-1：StatusTabs（带数量） + DataTable（toolbar 放批量操作）
```

规则：

- 筛选条件分"草稿"和"已生效"两份 state，点"查询"才生效，"重置"同时清空两份。
- 单号搜索框支持空格分隔的多个单号。
- 列定义用 `createDataColumns<T>()`，写在 `useMemo` 里：

```tsx
const columns = useMemo(() => {
  const col = createDataColumns<InboundOrder>()
  return col.columns([
    col.accessor('inboundNo', {
      header: t('inbound.inboundNo'),
      meta: { pin: 'left' },            // 首列固定在左
      cell: ({ getValue }) => <DocNo onClick={() => open(getValue())}>{getValue()}</DocNo>,
    }),
    col.accessor('plannedQty', {
      header: t('inbound.plannedQty'),
      meta: { align: 'right' },          // 数字列右对齐
      cell: ({ getValue }) => <Num value={getValue()} />,
    }),
    col.display({
      id: 'actions',
      header: t('common.actions'),
      meta: { pin: 'right' },            // 操作列固定在右
      cell: ({ row }) => /* 最多 2 个文字按钮 + "更多"下拉 */,
    }),
  ])
}, [t])
```

- 操作列最多露出 2 个文字按钮，其余收进"更多"下拉；危险操作（取消、删除）必须二次确认。
- 单号列点击打开详情抽屉，不跳新页面。

### 4.2 详情

- 字段不多、以查看为主：右侧 `Sheet` 抽屉，宽 880px。样板：`inbound-detail-sheet.tsx`。
  - 改宽度要用 `data-[side=right]:w-[880px] data-[side=right]:sm:max-w-[92vw]`，否则会被组件默认样式覆盖。
- 表单很长、需要分步骤或多个明细表：新开页签路由（后续 M1 新建入库单会给样板）。

### 4.3 弹窗与抽屉怎么选

| 场景 | 用什么 |
|---|---|
| 二次确认、1~3 个字段的小表单 | `Dialog` |
| 查看详情、边看列表边处理 | `Sheet`（右侧） |
| 复杂新建/编辑 | 独立页面（页签） |
| 操作结果反馈 | `toast`（sonner），成功 `toast.success`，失败 `toast.error` |

### 4.4 统计卡片

数字概览放在页面顶部，用 `Panel` + 标签（12px 灰）+ 数字（20px 半粗）。样板：`stock-page.tsx`、`dashboard-page.tsx`。

## 5. 国际化规则（必须遵守）

| 类型 | 存储 | 显示 |
|---|---|---|
| 文字 | 语言包 key | `t('module.key')`，禁止在 JSX 里写死中文或英文 |
| 金额 | `{ amount, currency }` | `<Money value={...} />`，显示原币，悬停看折算 |
| 汇总金额 | 先 `convertMoney` 折到显示币别再相加 | `formatMoney` |
| 时间 | UTC ISO 字符串 | `<DateTime value={...} />`，自动按仓库时区或本地时区 |
| 重量 | 克（number） | `<Weight grams={...} />`，自动公制/英制 |
| 尺寸 | 厘米 | `<Dimension l={} w={} h={} />` |
| 数量 | number | `<Num value={...} />`（千分位） |

新增文案时 `zh-CN.ts` 和 `en-US.ts` 必须同时加，`Messages` 类型会在漏写时报错。英文比中文长，按钮和表头要留宽度，必要时用更短的英文。

所有业务数据按当前仓库过滤：`const warehouse = useCurrentWarehouse()`，再用 `warehouseCode` 过滤。

## 6. 数据与业务动作

- 类型写在 `src/types/wms.ts`。
- 演示数据写在 `src/mock/seed.ts`，用 `createRandom` 保证每次生成结果一样。数据之间要互相对得上（例如已完成的入库单一定有库存和流水）。
- 改了 `seed.ts` 或数据结构，把 `mock/db.ts` 里 persist 的 `version` 加 1，浏览器里的旧数据会自动换成新种子。
- 会改数据的操作写成 `useDb` 里的 action，返回 `{ ok: true } | { ok: false, errorKey }`，页面根据结果弹 toast。页面组件里不要直接改 store 数据。
- 读取货主名、SKU 信息用 `useLookups()`。

## 7. PDA 规范

样板：`src/pages/pda/receive-page.tsx`（三步流程）、`putaway-page.tsx`。

- 页面结构：`PdaHeader`（标题 + 返回） → `StepBar` → 当前步骤内容 → 底部主按钮。
- 每一步的输入都用 `<ScanInput>`：自动聚焦，回车提交，`onScan` 返回 `false` 时红色闪烁 + 提示音。它下面会列出可点击的"模拟扫码"候选，方便演示。
- 数量输入用 `<QtyStepper>`，不要用普通小输入框。
- 一屏只做一件事；扫错时停在当前步骤，不要清空已经扫对的内容。
- 文字比后台大一号（正文 15~16px），关键信息（单号、货位、数量）用大号粗体。
- PDA 路由写在 `app/router.tsx` 的 `/pda` 下，首页功能入口在 `pda-home-page.tsx`。

## 8. 新增一个页面的步骤

1. 在 `config/menu.ts` 找到对应菜单项（没有就加），记下 `path`。
2. 在 `types/` 补类型，`mock/seed.ts` 造数据，`mock/db.ts` 加动作。
3. 在 `pages/wms/<模块>/` 下新建页面，照着第 4 节对应样板写。
4. 在 `app/router.tsx` 的 `wmsPages` 里把 `path` 映射到新页面。
5. 两个语言包补齐文案。
6. 跑 `npx tsc -p tsconfig.app.json --noEmit` 和 `npm run build`，再在浏览器里切换中英文、切换一个欧洲仓各看一遍。
