# 退货管理交付记录

2026-10-22，按[退货管理 PRD 套件](../../../05-应用设计方案/20261002-MVP版本/需求文档PRD/4-退货管理/README.md)补齐原型的半成品。此前退货单列表、详情、OMS Mock 预报、取消、Web/PDA 收货和共用上架已有基础流程，但收货只支持单个容器、没有原出库 SN 核对，派送失败也只能在预报弹窗里手工填原出库单号。

## 本轮完成

| 方向 | 结果 |
| --- | --- |
| 多容器收货 | 一次提交可含 1～N 个容器；收货明细按容器、SKU、批次/效期拆行；一条收货记录，按容器×品质生成共用上架单 |
| 容器校验 | 同一次提交容器号不得重复；已在本退货单收过货的容器不能再次使用；无容器收货最多一组 |
| SN 核对 | 有原出库可对核时，良品/不良品 SN 必须来自原出库已发 SN；不一致只能放入拒收 SN，并记录 `serialCheckBasis=ORIGINAL_OUTBOUND`；无原单依据时记录 `NO_REFERENCE` |
| 派送失败建单 | PDA 扫原 B2C 出库运单，校验已出库、同仓、无活跃退货单后，按原单已发数量生成退货单；预报弹窗只保留客户退货和平台仓退件 |
| 结果重试 | `retryReturnResult` 只重交已有结果；详情页在结果为 FAILED 时显示重试按钮，不重复上架或扣库 |
| 草稿恢复 | 新增 `stores/return-receive-session.ts`，Web/PDA 按“端＋仓库＋退货单”保存未提交容器与明细，刷新可续，提交或重置演示数据后清空 |
| 页面 | Web 退货收货改为多容器作业台；PDA 支持扫退货单/退货运单/原出库运单、派送失败建单、多容器、SN 拒收与草稿 |
| 种子 | 保留客户退货、派送失败、平台仓退件三类来源；派送失败单关联原出库单 |

## 验证

- `npm run check`：`tsc -b`、oxlint、设计规范检查、Vitest、构建全部通过；18 个测试文件、145 项测试。
- 新增测试覆盖：多容器生成一条收货记录与多张上架单、容器重复/复用、派送失败按原出库已发数量建单、SN 不一致只能拒收、OMS Mock 基础资料推送接受/拒绝留痕、自营/大件/异形/带电/美东德国库区种子。
- 浏览器（本机 5199）：Web 退货收货页正常渲染，未绑定容器时录入区禁用；PDA 退货收货列表与扫码入口正常。未用真实扫描枪逐枪验收。

## 边界

- 派送失败预计数量暂按原出库 `shippedQty` 生成，一单多包裹拆分仍待业务确认。
- 退货预报仍为单行 Mock 表单，多明细预报待补。
- 退货结果重试入口只在结果为 FAILED 时出现；Mock 默认结果为 SENT。
- 容器档案已改为基础资料与库存维度；容器管理列表/详情、收货自动建档、上架状态回写已在原型实现，容器字段落到库存明细代码、按容器预占/盘点仍未实现，见[容器档案与容器库存](../../../05-应用设计方案/20261002-MVP版本/系统架构设计/07-容器档案与容器库存.md)。
